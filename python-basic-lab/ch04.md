# 4장. 함수

[파이썬 기초](README.md) 과정의 네 번째 장이다. 3장까지는 프로그램을 위에서 아래로 한 줄씩 써 내려갔다. 같은 계산이 세 번 필요하면 같은 코드를 세 번 썼고, 한 군데를 고치려면 세 군데를 모두 찾아 고쳐야 했다. 이 장에서는 **코드 덩어리에 이름을 붙여 두고 필요할 때 불러 쓰는 방법**, 즉 함수를 배운다.

- **함수 정의와 호출** — `def`로 함수를 만들고, 값을 넘겨 주고(인자), 결과를 돌려받는다(`return`). 함수에 설명(독스트링)을 붙인다.
- **인자 전달 방식** — 위치 인자와 키워드 인자, 기본값을 쓴다. "기본값으로 빈 리스트를 쓰면 생기는 버그"를 이해하고 피한다. 개수가 정해지지 않은 인자를 받는다(`*args`, `**kwargs`).
- **변수의 범위** — 함수 안의 변수와 바깥 변수가 어떻게 다른지 알고, 리스트를 함수에 넘겼을 때 바깥에 미치는 영향을 설명한다.
- **람다와 함수 객체** — 함수도 숫자나 문자열처럼 "값"이라는 것을 알고, 함수를 다른 함수에 넘긴다.
- **내장 함수 활용** — 파이썬에 처음부터 들어 있는 함수들을 제대로 쓰고, `sorted()`의 `key`로 정렬 기준을 바꾼다.
- **모듈 가져다 쓰기** — `import`로 파이썬에 들어 있는 도구 모음(모듈)을 가져와 쓰고, 공식 문서에서 사용법을 찾는다.

AI 엔지니어의 코드는 대부분 함수의 모음이다. "사용자 질문을 받아 프롬프트를 만드는 함수", "LLM API를 호출하는 함수", "응답에서 필요한 부분만 꺼내는 함수"처럼 일을 잘게 나누어 함수로 만들고, 그것들을 조합해 서비스를 만든다. LLM 라이브러리를 쓸 때도 `client.chat.completions.create(model="...", messages=[...], temperature=0.7)`처럼 **키워드 인자를 잔뜩 넘기는 함수 호출**을 계속 만나게 된다. 이 장을 마치면 그런 호출을 보고 "무엇을 넘기고 무엇을 돌려받는지" 읽을 수 있고, 자신의 코드를 함수로 나누어 정리할 수 있게 된다.

## 학습 목표

이 장을 마치면 다음을 할 수 있다.

- `def`로 함수를 정의하고, 인자를 넘겨 호출하고, `return`으로 결과를 돌려받을 수 있다.
- `return`이 없는 함수가 `None`을 돌려준다는 것을 알고, `print()`와 `return`의 차이를 설명할 수 있다.
- 함수에 독스트링을 쓰고, `help()`로 함수의 설명을 확인할 수 있다.
- 위치 인자, 키워드 인자, 기본값을 구분해 쓰고, 가변 객체를 기본값으로 쓰면 생기는 문제를 `None` 기본값 패턴으로 피할 수 있다.
- `*args`와 `**kwargs`로 개수가 정해지지 않은 인자를 받을 수 있다.
- 지역 변수와 전역 변수를 구분하고, `global` 대신 인자와 반환값으로 데이터를 주고받도록 함수를 설계할 수 있다.
- 리스트나 딕셔너리를 함수에 넘겼을 때 함수 안의 변경이 호출한 쪽에 보이는 이유를 3장의 "이름표와 객체"로 설명할 수 있다.
- 함수를 변수에 담고 다른 함수에 인자로 넘길 수 있고, 간단한 람다 표현식을 쓸 수 있다.
- `sorted()`, `min()`, `max()`의 `key`로 원하는 기준에 따라 정렬하고 찾을 수 있다.
- `import`, `from ... import`, `as`로 모듈을 가져와 `math`, `random`, `datetime`을 쓸 수 있고, 공식 문서에서 필요한 기능을 찾을 수 있다.
- VS Code 디버거의 "한 단계씩 들어가기"로 함수 안으로 들어가 실행을 따라갈 수 있다.

## 4.1 함수 정의와 호출

**함수**(function)는 어떤 일을 하는 코드 덩어리에 **이름을 붙여 둔 것**이다. 우리는 이미 함수를 많이 써 왔다. `print()`, `input()`, `len()`, `int()`, `sorted()`는 모두 파이썬이 미리 만들어 둔 함수다. 이름 뒤에 괄호를 붙여 쓰면 그 함수가 하는 일이 실행된다. 이 절에서는 함수를 **직접 만드는** 방법을 배운다.

### 4.1.1 왜 함수가 필요한가

세 반의 점수 평균을 출력하는 프로그램을 생각해 보자.

```python
# without_function.py
class_a = [85, 92, 78]
class_b = [90, 88, 95, 72]
class_c = [65, 80]

total = 0
for score in class_a:
    total += score
print(f"A반 평균: {total / len(class_a):.1f}")

total = 0
for score in class_b:
    total += score
print(f"B반 평균: {total / len(class_b):.1f}")

total = 0
for score in class_c:
    total += score
print(f"C반 평균: {total / len(class_c):.1f}")
```

```
A반 평균: 85.0
B반 평균: 86.2
C반 평균: 72.5
```

같은 모양의 코드가 세 번 반복된다. 이런 코드에는 문제가 세 가지 있다.

1. **길다.** 반이 열 개면 같은 코드를 열 번 써야 한다.
2. **고치기 어렵다.** "평균을 소수점 둘째 자리까지 출력하라"는 요구가 오면 세 군데를 모두 고쳐야 한다. 한 군데라도 빠뜨리면 반마다 출력 형식이 달라진다.
3. **읽기 어렵다.** 코드를 끝까지 읽어야 "아, 평균을 구하는 거구나" 하고 알 수 있다.

반복되는 부분을 함수로 묶으면 이렇게 된다.

```python
# with_function.py
def print_average(class_name, scores):
    total = 0
    for score in scores:
        total += score
    print(f"{class_name} 평균: {total / len(scores):.1f}")


print_average("A반", [85, 92, 78])
print_average("B반", [90, 88, 95, 72])
print_average("C반", [65, 80])
```

출력은 같다. 평균을 구하는 방법은 함수 안에 **한 번만** 쓰여 있고, 아래 세 줄은 "A반 평균을 출력하라", "B반 평균을 출력하라"처럼 **무엇을 하는지만** 말한다. 출력 형식을 바꾸려면 함수 안의 한 줄만 고치면 된다.

이것이 함수의 핵심이다. **반복을 없애고, 일에 이름을 붙인다.** 이름이 붙은 일은 다시 쓸 수 있고, 고칠 곳이 한 군데로 모이고, 코드를 읽는 사람은 이름만 보고도 무엇을 하는지 알 수 있다.

### 4.1.2 `def`로 함수 정의하기

함수를 만드는 것을 **함수를 정의한다**(define)고 한다. 모양은 다음과 같다.

```python
def 함수이름(매개변수1, 매개변수2, ...):
    실행할 코드
    실행할 코드
```

- `def`로 시작하고, 함수 이름 뒤에 괄호와 콜론(`:`)을 쓴다.
- 함수가 할 일(**본문**, body)은 `if`나 `for`처럼 **들여쓰기**로 구분한다. 들여쓰기가 끝나는 곳에서 함수 정의도 끝난다.
- 함수 이름은 변수 이름과 같은 규칙(2.1.2)을 따른다. 소문자와 밑줄을 쓰는 snake_case로 짓고, **무엇을 하는지 드러나는 동사**로 시작하는 것이 좋다. `print_average`, `get_total`, `is_valid_email`처럼.

가장 간단한 함수부터 만들어 보자. 대화형 셸에 입력한다.

```python
>>> def say_hello():
...     print("안녕하세요!")
...     print("파이썬 함수의 세계에 오신 것을 환영합니다.")
...
```

Enter를 눌러 정의를 끝내도 **아무것도 출력되지 않는다.** 함수를 정의하는 것은 "이런 일을 `say_hello`라는 이름으로 기억해 두라"는 뜻일 뿐, 그 일을 실행하라는 뜻이 아니기 때문이다. 요리책에 조리법을 적어 두는 것과 실제로 요리를 하는 것이 다른 것과 같다.

### 4.1.3 함수 호출하기

정의한 함수를 실행하는 것을 **호출한다**(call)고 한다. 함수 이름 뒤에 괄호를 붙인다.

```python
>>> say_hello()
안녕하세요!
파이썬 함수의 세계에 오신 것을 환영합니다.
>>> say_hello()
안녕하세요!
파이썬 함수의 세계에 오신 것을 환영합니다.
```

한 번 정의한 함수는 몇 번이든 호출할 수 있다. 호출할 때마다 본문이 처음부터 끝까지 실행된다.

**괄호를 빠뜨리면 호출되지 않는다.** 괄호 없이 이름만 쓰면 함수를 실행하는 것이 아니라 함수 그 자체를 가리킨다.

```python
>>> say_hello
<function say_hello at 0x1029f8fe0>
```

"`say_hello`라는 이름의 함수가 메모리 어딘가에 있다"는 뜻이다. (뒤의 숫자는 3장에서 본 `id()`처럼 실행할 때마다 다르다.) 스크립트 파일에서 `say_hello`라고만 쓰면 오류도 없이 아무 일도 일어나지 않으므로, 함수가 실행되지 않으면 괄호를 빠뜨리지 않았는지 먼저 확인하자. "함수 그 자체"가 무엇인지는 4.4에서 자세히 다룬다.

**정의가 호출보다 먼저 실행되어야 한다**

스크립트 파일은 위에서 아래로 실행된다. 함수를 정의하는 `def` 문도 실행되어야 비로소 그 이름이 생긴다. 그래서 정의보다 위에서 호출하면 오류가 난다.

```python
# call_before_def.py
say_hello()

def say_hello():
    print("안녕하세요!")
```

```
Traceback (most recent call last):
  File "/Users/본인계정/python-lab/ch04/call_before_def.py", line 1, in <module>
    say_hello()
    ^^^^^^^^^
NameError: name 'say_hello' is not defined
```

1장에서 본 `NameError`다. 1번째 줄을 실행하는 시점에는 아직 `say_hello`라는 이름이 없다. 그래서 스크립트는 보통 **함수 정의를 파일 위쪽에 모두 쓰고, 호출하는 코드를 아래쪽에** 둔다.

**함수 사이의 빈 줄**

`with_function.py`에서 함수 정의와 아래 코드 사이에 빈 줄을 **두 줄** 넣었다. 파이썬 코드 스타일 가이드(PEP 8)의 권장 사항이다. 함수 정의의 앞뒤에는 빈 줄 두 줄, 함수 안에서 단락을 나눌 때는 빈 줄 한 줄을 쓴다. 1장에서 설정한 Ruff 포매터가 저장할 때 자동으로 맞춰 주므로 신경 쓰지 않아도 된다.

### 4.1.4 매개변수와 인자

`say_hello()`는 언제 호출해도 똑같은 일을 한다. 대부분의 함수는 호출할 때마다 **다른 값**을 받아 처리한다. `print_average()`가 반 이름과 점수 목록을 받은 것처럼.

```python
>>> def greet(name):
...     print(f"안녕하세요, {name}님!")
...
>>> greet("철수")
안녕하세요, 철수님!
>>> greet("영희")
안녕하세요, 영희님!
```

여기서 두 가지 용어를 구분하자.

- **매개변수**(parameter): 함수를 **정의할 때** 괄호 안에 쓰는 이름. 위에서 `name`이다. "이 함수는 값을 하나 받아서 `name`이라고 부르겠다"는 뜻이다.
- **인자**(argument): 함수를 **호출할 때** 괄호 안에 넣는 값. 위에서 `"철수"`, `"영희"`다.

`greet("철수")`를 호출하면 파이썬은 함수 본문을 실행하기 전에 `name = "철수"`를 한 것처럼 **매개변수 이름표를 인자 객체에 붙인다.** 3장의 "변수는 객체에 붙인 이름표"가 여기서도 그대로 적용된다. 이 사실은 4.3에서 아주 중요해진다.

```
greet("철수")  ──▶  name = "철수" 을 한 뒤 본문 실행
```

(실무에서는 두 용어를 섞어 쓰는 사람도 많다. "인자를 받는다"고 말하면 대개 매개변수를 뜻한다. 정확한 구분이 필요할 때만 신경 쓰면 된다.)

매개변수는 쉼표로 구분해 여러 개 둘 수 있다. 인자는 **순서대로** 매개변수에 짝지어진다.

```python
>>> def introduce(name, age):
...     print(f"{name}은(는) {age}살입니다.")
...
>>> introduce("철수", 17)
철수은(는) 17살입니다.
>>> introduce(17, "철수")
17은(는) 철수살입니다.
```

두 번째 호출은 오류 없이 실행되지만 결과가 이상하다. 파이썬은 인자의 **의미**를 모른다. 첫 번째 값을 첫 번째 매개변수에, 두 번째 값을 두 번째 매개변수에 넣을 뿐이다. 이런 실수를 막는 방법(키워드 인자)은 4.2에서 배운다.

**인자 개수가 맞지 않으면** 오류가 난다.

```python
>>> greet()
Traceback (most recent call last):
  File "<python-input-5>", line 1, in <module>
    greet()
    ~~~~~^^
TypeError: greet() missing 1 required positional argument: 'name'
>>> greet("철수", "영희")
Traceback (most recent call last):
  File "<python-input-6>", line 1, in <module>
    greet("철수", "영희")
    ~~~~~^^^^^^^^^^^^^^^^
TypeError: greet() takes 1 positional argument but 2 were given
```

첫 번째는 "필요한 인자 1개(`name`)가 빠졌다", 두 번째는 "인자를 1개 받는데 2개가 들어왔다"는 뜻이다. 함수를 호출하다가 `TypeError`가 나면 메시지의 `missing`, `takes ... but ... were given`을 보고 인자 개수부터 확인하자.

### 4.1.5 `return`으로 결과 돌려주기

지금까지 만든 함수는 결과를 화면에 **출력**했다. 그런데 우리가 써 온 `len()`이나 `int()`는 출력하지 않는다. 결과를 **돌려주고**, 우리는 그 결과를 변수에 담거나 다른 계산에 썼다.

```python
>>> n = len("hello")
>>> n * 2
10
```

함수가 결과를 돌려주게 하려면 `return` 문을 쓴다. 함수가 돌려주는 값을 **반환값**(return value) 또는 **리턴값**이라고 한다.

```python
>>> def square(x):
...     return x * x
...
>>> square(5)
25
>>> result = square(3)
>>> result
9
>>> square(2) + square(3)
13
>>> square(square(2))
16
```

`square(5)`라는 호출식은 실행이 끝나면 **반환값 `25`로 바뀐다**고 생각하면 된다. 그래서 `square(2) + square(3)`은 `4 + 9`가 되고, `square(square(2))`는 안쪽부터 계산되어 `square(4)`, 즉 `16`이 된다. 반환값은 숫자나 문자열 같은 값이 쓰일 수 있는 곳이면 어디든 쓸 수 있다.

**`print()`와 `return`은 다르다**

입문자가 가장 많이 헷갈리는 부분이다. 두 함수를 비교해 보자.

```python
>>> def add_print(a, b):
...     print(a + b)
...
>>> def add_return(a, b):
...     return a + b
...
>>> add_print(2, 3)
5
>>> add_return(2, 3)
5
```

대화형 셸에서는 둘 다 `5`가 보인다. 하지만 속사정이 다르다. `add_print`는 `5`를 **화면에 출력**했고, `add_return`은 `5`를 **돌려주었으며**, 돌려받은 값을 셸이 대신 보여 준 것이다. 결과를 변수에 담아 보면 차이가 드러난다.

```python
>>> x = add_print(2, 3)
5
>>> y = add_return(2, 3)
>>> print(x)
None
>>> print(y)
5
>>> y * 10
50
>>> x * 10
Traceback (most recent call last):
  File "<python-input-9>", line 1, in <module>
    x * 10
    ~~^~~~
TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'
```

`x = add_print(2, 3)`을 실행하는 순간 `5`가 출력되지만, `x`에 담긴 것은 `None`이다. 출력된 `5`는 화면에 그려진 글자일 뿐 프로그램이 다시 쓸 수 있는 값이 아니다. 반면 `y`에는 `5`가 담겨서 계산에 쓸 수 있다.

| | `print()` | `return` |
|---|---|---|
| 하는 일 | 값을 **화면에 보여 준다** | 값을 **호출한 쪽에 돌려준다** |
| 받는 대상 | 사람(화면을 보는 사용자) | 코드(함수를 호출한 곳) |
| 결과를 다시 쓸 수 있나 | 없다 | 변수에 담거나 계산에 쓸 수 있다 |

**계산하는 함수는 출력하지 말고 돌려주자.** 결과를 출력할지, 파일에 저장할지, 다른 계산에 쓸지는 호출한 쪽이 정하게 하는 것이 좋다. `print_average()`도 평균을 돌려주는 함수로 바꾸면 훨씬 쓸모가 많아진다.

```python
>>> def average(scores):
...     total = 0
...     for score in scores:
...         total += score
...     return total / len(scores)
...
>>> average([85, 92, 78])
85.0
>>> a = average([85, 92, 78])
>>> b = average([90, 88, 95, 72])
>>> f"A반이 B반보다 {a - b:.1f}점 낮다"
'A반이 B반보다 -1.2점 낮다'
```

평균을 출력만 하는 함수였다면 두 반의 평균을 비교하는 이런 계산은 할 수 없었다. (부호가 이상한 문장은 실습 4-1에서 고쳐 보자.)

**`return`을 만나면 함수는 즉시 끝난다**

`return`은 값을 돌려주는 동시에 **함수 실행을 그 자리에서 끝낸다.** 반복문의 `break`와 비슷하다. `return` 아래에 있는 코드는 실행되지 않는다.

```python
>>> def check_age(age):
...     if age < 0:
...         return "나이는 음수일 수 없습니다."
...     if age < 20:
...         return "미성년자"
...     return "성인"
...
>>> check_age(-3)
'나이는 음수일 수 없습니다.'
>>> check_age(15)
'미성년자'
>>> check_age(30)
'성인'
```

`check_age(-3)`은 첫 번째 `return`에서 끝나므로 아래 `if`는 검사하지도 않는다. 이렇게 함수 앞부분에서 **예외적인 경우를 먼저 처리하고 바로 `return`하면**, `elif`와 `else`를 겹겹이 쓰지 않아도 되어 코드가 평평하고 읽기 쉬워진다. 이것을 **조기 반환**(early return)이라고 하며 아주 자주 쓰는 패턴이다.

반복문 안에서 `return`하면 반복도 함께 끝난다. "찾으면 바로 돌려주는" 함수에 쓴다.

```python
>>> def find_first_negative(numbers):
...     for n in numbers:
...         if n < 0:
...             return n
...     return None
...
>>> find_first_negative([3, 5, -2, 8, -7])
-2
>>> print(find_first_negative([1, 2, 3]))
None
```

`-2`를 찾는 순간 `return`으로 함수가 끝나므로 `-7`까지 가지 않는다. 끝까지 찾지 못하면 반복이 끝난 뒤 마지막 줄의 `return None`에 도달한다.

**여러 값 돌려주기**

3.3.5에서 미리 본 것처럼, `return` 뒤에 쉼표로 값을 나열하면 **튜플 하나**로 패킹되어 돌아간다. 받는 쪽에서 언패킹하면 여러 값을 받은 것처럼 쓸 수 있다.

```python
>>> def min_max(numbers):
...     return min(numbers), max(numbers)
...
>>> min_max([3, 9, 1, 7])
(1, 9)
>>> low, high = min_max([3, 9, 1, 7])
>>> low
1
>>> high
9
```

몫과 나머지, 최솟값과 최댓값, "성공 여부와 메시지"처럼 **함께 다니는 몇 개의 값**을 돌려줄 때 쓴다. 다만 돌려주는 값이 서너 개를 넘어가면 받는 쪽에서 순서를 기억하기 어려워진다. 그럴 때는 딕셔너리로 돌려주거나, 5장에서 배울 데이터 클래스를 쓰는 것이 좋다.

### 4.1.6 `return`이 없으면 `None`을 돌려준다

`add_print()`의 결과를 담은 `x`가 `None`이었던 이유를 정리하자. **파이썬 함수는 항상 무언가를 돌려준다.** `return` 문이 없거나, `return` 뒤에 값을 쓰지 않으면 `None`을 돌려준다. 2장에서 "값이 없음"을 나타내는 `None`을 배울 때 예고했던 내용이다.

```python
>>> def no_return():
...     x = 1
...
>>> def empty_return():
...     return
...
>>> print(no_return())
None
>>> print(empty_return())
None
```

대화형 셸은 반환값이 `None`이면 아무것도 보여 주지 않는다. 그래서 `no_return()`이라고만 입력하면 화면에 아무것도 나오지 않는다. 반환값을 확인하려면 `print()`로 감싸자.

3장에서 `cart = cart.append("빵")`이 `cart`를 `None`으로 만들어 버린 것도 같은 이유다. `append()`는 원본 리스트를 바꾸는 것이 목적인 메서드라서 `return` 없이 끝나고, 결과적으로 `None`을 돌려준다. 이 장에서 우리도 그런 함수를 만들게 된다(4.3.5).

> **`return`이 있는 경로와 없는 경로가 섞이지 않게**
> 다음 함수는 양수일 때만 값을 돌려준다.
> ```python
> def sign(n):
>     if n > 0:
>         return "양수"
>     elif n < 0:
>         return "음수"
> ```
> `sign(0)`은 어느 `return`에도 도달하지 못하고 끝나서 `None`을 돌려준다. 호출한 쪽에서 `sign(0) + "입니다"` 같은 계산을 하면 그제야 `TypeError`가 난다. 값을 돌려주는 함수라면 **모든 경로가 `return`으로 끝나는지** 확인하자. 위 함수는 마지막에 `return "0"`을 추가하면 된다. "찾지 못하면 `None`"처럼 일부러 `None`을 돌려줄 때는 `find_first_negative()`처럼 `return None`을 **명시적으로** 써서 의도를 드러낸다.

### 4.1.7 독스트링 — 함수에 설명 붙이기

함수 이름만으로 무엇을 하는지 알 수 있으면 가장 좋지만, 매개변수에 무엇을 넣어야 하는지, 무엇을 돌려주는지까지 이름에 담기는 어렵다. 함수 본문의 **첫 줄에 문자열**을 쓰면 그것이 함수의 설명이 된다. 이것을 **독스트링**(docstring, documentation string)이라고 한다. 2.3.7에서 배운 세 따옴표 문자열을 쓴다.

```python
>>> def average(scores):
...     """점수 리스트의 평균을 돌려준다.
...
...     scores는 비어 있지 않은 숫자 리스트여야 한다.
...     """
...     total = 0
...     for score in scores:
...         total += score
...     return total / len(scores)
...
```

독스트링은 주석(`#`)과 비슷해 보이지만 다른 점이 있다. 주석은 파이썬이 완전히 무시하지만, 독스트링은 **함수에 붙어서 저장된다.** 그래서 `help()`로 꺼내 볼 수 있다.

```python
>>> help(average)
Help on function average in module __main__:

average(scores)
    점수 리스트의 평균을 돌려준다.

    scores는 비어 있지 않은 숫자 리스트여야 한다.
```

(`help()` 화면은 `q`를 눌러 빠져나온다.) VS Code에서도 함수 이름에 마우스를 올리거나 함수를 호출하려고 괄호를 여는 순간 독스트링이 말풍선으로 나타난다. 함수를 만든 사람이 아니라도, 몇 달 뒤의 자신이라도, 함수 본문을 읽지 않고 사용법을 알 수 있다.

독스트링 쓰는 방법의 기본 관례(PEP 257)는 다음과 같다.

- 큰따옴표 세 개(`"""`)로 감싼다.
- 첫 줄에 **함수가 하는 일을 한 문장으로** 요약한다. "~한다", "~를 돌려준다"처럼 쓴다.
- 설명이 더 필요하면 한 줄을 비우고 이어서 쓴다. 매개변수의 조건, 반환값, 주의할 점 등.
- 짧은 함수라면 한 줄 독스트링으로 충분하다: `"""두 수의 합을 돌려준다."""`

1장 VS Code 설정에서 편집기에 72번째 칸 안내선을 그어 둔 것은 PEP 8이 독스트링과 주석의 한 줄을 72자 이내로 권장하기 때문이다.

> **독스트링과 AI**
> AI 코딩 도구에게 "이 함수에 독스트링을 써 줘"라고 하면 상당히 잘 써 준다. 반대로 함수 이름과 독스트링을 먼저 쓰고 본문을 비워 둔 채 "독스트링대로 구현해 줘"라고 하면, AI가 의도를 정확히 파악해 훨씬 좋은 코드를 만든다. 독스트링은 사람과 AI 모두에게 주는 **함수의 사용 설명서이자 명세서**다. 이 장의 종합 실습(실습 4-7)이 바로 이 방식이다.

**`pass` — 아직 비어 있는 함수**

함수 이름과 독스트링만 먼저 정해 두고 본문은 나중에 쓰고 싶을 때가 있다. 그런데 파이썬은 콜론 뒤에 들여쓴 본문이 없으면 `IndentationError`를 낸다. 이럴 때 "아무 일도 하지 않는다"는 뜻의 `pass`를 쓴다. 독스트링이 있으면 그 자체로 본문이 되므로 `pass` 없이도 된다.

```python
def calculate_shipping(weight):
    pass


def calculate_tax(price):
    """세금을 계산해 돌려준다. (아직 구현하지 않음)"""
```

두 함수 모두 호출하면 아무 일도 하지 않고 `None`을 돌려준다.

### 4.1.8 디버거로 함수 안에 들어가기

1장과 2장에서 디버거의 **단계 실행**(Step Over, `F10`)으로 한 줄씩 실행하는 법을 익혔다. 그런데 `F10`은 함수를 호출하는 줄을 만나면 함수 전체를 한 번에 실행하고 다음 줄로 넘어간다. 함수 **안으로 들어가서** 따라가려면 새로운 단추가 필요하다.

| 단추 | 단축키 | 하는 일 |
|---|---|---|
| 단계 실행(Step Over) | `F10` | 현재 줄을 실행한다. 함수 호출은 **한 번에** 실행하고 다음 줄에서 멈춘다 |
| 한 단계씩 코드 실행(Step Into) | `F11` | 현재 줄이 함수 호출이면 그 **함수 안으로 들어가** 첫 줄에서 멈춘다 |
| 단계 출력(Step Out) | `Shift + F11` | 지금 있는 함수의 나머지를 실행하고, **호출한 곳으로 돌아가** 멈춘다 |

`ch04` 폴더에 `debug_function.py`를 만든다.

```python
# debug_function.py
def average(scores):
    total = 0
    for score in scores:
        total += score
    return total / len(scores)


def grade(avg):
    if avg >= 90:
        return "A"
    if avg >= 80:
        return "B"
    return "C"


my_scores = [85, 92, 78]
avg = average(my_scores)
letter = grade(avg)
print(f"평균 {avg:.1f}, 학점 {letter}")
```

1. 17번째 줄(`avg = average(my_scores)`)에 중단점을 찍고 `F5`로 디버깅을 시작한다.
2. 멈춘 상태에서 `F11`을 누른다. 실행 위치가 `average()` 함수 안의 첫 줄(`total = 0`)로 **들어간다.** 변수 패널을 보면 `scores`에 `[85, 92, 78]`이 들어 있다. 호출할 때 넘긴 인자가 매개변수에 담긴 것이다.
3. 왼쪽 디버그 패널의 **호출 스택**(Call Stack)을 본다. 맨 위에 `average`, 그 아래에 `<module>`이 있다. "지금 `average` 함수 안에 있고, 이 함수는 파일의 최상위(`<module>`)에서 호출되었다"는 뜻이다.
4. `F10`으로 반복문을 몇 바퀴 따라가며 `total`이 늘어나는 것을 본다.
5. `Shift + F11`을 누른다. 함수의 나머지가 실행되고 17번째 줄로 돌아온다. `F10`을 한 번 더 누르면 `avg`에 반환값 `85.0`이 담긴 것이 보인다.
6. 18번째 줄에서 이번에는 `F10`을 누른다. `grade()` 안으로 들어가지 않고 한 번에 실행되어 `letter`에 `"B"`가 담긴다.

> **`F11`을 `print()`에서 누르면?**
> 들어가지 않고 `F10`처럼 다음 줄로 넘어간다. VS Code의 파이썬 디버거는 기본적으로 **내가 작성한 코드 안으로만** 들어가도록 설정되어 있기 때문이다. `print()` 같은 내장 함수나 4.6에서 배울 표준 모듈은 따라가지 않는다. 혹시 낯선 파일로 들어가 버렸다면 당황하지 말고 `Shift + F11`로 빠져나오면 된다.

호출 스택은 오류가 났을 때 특히 쓸모가 있다. 다음 절의 트레이스백과 같은 정보를 보여 주기 때문이다.

### 4.1.9 함수 안에서 난 오류의 트레이스백 읽기

함수가 다른 함수를 호출하는 프로그램에서 오류가 나면 트레이스백이 여러 층으로 나온다.

```python
# traceback_demo.py
def average(scores):
    return sum(scores) / len(scores)


def report(scores):
    avg = average(scores)
    print(f"평균: {avg:.1f}")


report([])
```

```

    report([])

  File "/Users/본인계정/python-lab/ch04/traceback_demo.py", line 2, in average

ZeroDivisionError: division by zero
```

`File ... line ..., in ...` 줄이 세 개다. 각 줄 끝의 `in` 뒤에 있는 것이 **그 줄이 들어 있는 함수 이름**이다. 첫 줄의 첫 문장 `most recent call last`는 "가장 최근의 호출이 마지막에 온다"는 뜻이므로, 위에서 아래로 읽으면 호출된 순서가 된다.

1. 파일 최상위(`<module>`)의 10번째 줄에서 `report([])`를 호출했고,
2. `report` 함수의 6번째 줄에서 `average(scores)`를 호출했고,
3. `average` 함수의 2번째 줄에서 0으로 나누다가 오류가 났다.

오류가 **직접 난 곳**은 마지막 `File` 줄(`average`의 2번째 줄)이다. 하지만 **원인**은 거기에 있지 않을 수도 있다. `average()`는 빈 리스트를 받으면 안 되는 함수이고, 진짜 문제는 빈 리스트를 넘긴 쪽(10번째 줄)일 수도 있다. 트레이스백을 아래에서 위로 거슬러 올라가며 "이 값은 어디서 왔지?"를 따라가 보자. 디버거의 호출 스택이 보여 주는 것도 바로 이 목록이다.

1장에서 말했듯이, AI에게 오류를 물을 때는 마지막 줄만이 아니라 **트레이스백 전체**를 보여 주자. 함수가 여러 층으로 호출되는 프로그램일수록 중간 층의 정보가 원인을 찾는 데 결정적이다.

## 4.2 인자 전달 방식

4.1에서는 인자를 **순서대로** 넘겼다. 파이썬은 이 밖에도 인자에 이름을 붙여 넘기는 방법, 인자를 생략하면 미리 정해 둔 값을 쓰는 방법, 개수가 정해지지 않은 인자를 받는 방법을 제공한다. 라이브러리 함수를 쓸 때 가장 자주 만나는 문법이므로 하나씩 정확히 익혀 두자.

### 4.2.1 위치 인자

4.1에서 쓴 방식이다. 인자를 쓴 **위치**(순서)에 따라 매개변수와 짝지어지므로 **위치 인자**(positional argument)라고 한다.

```python
>>> def introduce(name, age, city):
...     print(f"{name}({age}세, {city})")
...
>>> introduce("철수", 17, "서울")
철수(17세, 서울)
```

위치 인자는 짧고 편리하지만, 매개변수가 많아지면 몇 번째 자리에 무엇을 넣어야 하는지 기억하기 어렵다. 4.1.4에서 본 것처럼 순서를 바꿔 넣어도 파이썬은 알려 주지 않는다.

### 4.2.2 키워드 인자

호출할 때 `매개변수이름=값` 모양으로 넘기면, 순서가 아니라 **이름**으로 짝지어진다. 이것을 **키워드 인자**(keyword argument)라고 한다.

```python
>>> introduce(name="철수", age=17, city="서울")
철수(17세, 서울)
>>> introduce(city="서울", name="철수", age=17)
철수(17세, 서울)
```

순서를 바꿔도 결과가 같다. 무엇보다 **호출하는 코드만 보고도 각 값의 의미를 알 수 있다**는 것이 큰 장점이다. 다음 두 줄을 비교해 보자.

```python
send_message("철수", "회의 시간 변경", True, False)
send_message(to="철수", text="회의 시간 변경", urgent=True, save_copy=False)
```

첫 줄의 `True, False`가 무슨 뜻인지는 함수 정의를 찾아봐야 알 수 있지만, 둘째 줄은 읽기만 해도 알 수 있다. 특히 `True`/`False`나 숫자처럼 **값만 보고는 의미를 알 수 없는 인자**는 키워드 인자로 넘기는 것이 좋다.

우리는 이미 키워드 인자를 써 왔다. 2장의 `print(i, end=" ")`, 3장의 `sorted(nums, reverse=True)`가 그것이다. 1단계에서 본 LLM API 호출 코드도 키워드 인자의 모음이다.

```python
response = client.chat.completions.create(
    model="모델이름",
    messages=[{"role": "user", "content": "안녕"}],
    temperature=0.7,
)
```

`model`, `messages`, `temperature`는 모두 `create()` 함수의 매개변수 이름이다. 이런 함수는 매개변수가 수십 개라서 위치 인자로는 도저히 쓸 수 없다.

**위치 인자와 키워드 인자 섞어 쓰기**

둘을 섞어 쓸 수 있지만 규칙이 있다. **위치 인자를 먼저, 키워드 인자를 나중에** 쓴다.

```python
>>> introduce("철수", city="서울", age=17)
철수(17세, 서울)
>>> introduce(name="철수", 17, "서울")
  File "<python-input-4>", line 1
    introduce(name="철수", 17, "서울")
                                 ^
SyntaxError: positional argument follows keyword argument
```

키워드 인자 뒤에 위치 인자가 오면 몇 번째 자리인지 정할 수 없기 때문에 실행 전에 `SyntaxError`가 난다.

같은 매개변수에 값을 두 번 넣거나, 없는 이름을 쓰면 `TypeError`가 난다.

```python
>>> introduce("철수", 17, name="영희")
Traceback (most recent call last):
  File "<python-input-5>", line 1, in <module>
    introduce("철수", 17, name="영희")
    ~~~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^^
TypeError: introduce() got multiple values for argument 'name'
>>> introduce("철수", 17, cty="서울")
Traceback (most recent call last):
  File "<python-input-6>", line 1, in <module>
    introduce("철수", 17, cty="서울")
    ~~~~~~~~~^^^^^^^^^^^^^^^^^^^^^^^^
TypeError: introduce() got an unexpected keyword argument 'cty'. Did you mean 'city'?
```

첫 번째는 `"철수"`가 위치 인자로 이미 `name`에 들어갔는데 `name="영희"`가 또 들어와서 난 오류다. 두 번째는 오타다. 파이썬 3.13부터는 `Did you mean 'city'?`처럼 비슷한 매개변수 이름을 제안해 준다. (3.12에서는 제안 없이 `unexpected keyword argument 'cty'`까지만 나온다.)

### 4.2.3 기본값

매개변수에 `=값`을 붙여 정의하면, 호출할 때 그 인자를 **생략할 수 있고**, 생략하면 정해 둔 값이 들어간다. 이것을 **기본값**(default value)이라고 한다.

```python
>>> def greet(name, greeting="안녕하세요"):
...     print(f"{greeting}, {name}님!")
...
>>> greet("철수")
안녕하세요, 철수님!
>>> greet("철수", "반갑습니다")
반갑습니다, 철수님!
>>> greet("철수", greeting="환영합니다")
환영합니다, 철수님!
```

`greeting`을 생략하면 기본값 `"안녕하세요"`가 쓰이고, 넘기면 넘긴 값이 쓰인다. 기본값이 없는 `name`은 반드시 넘겨야 한다.

기본값은 **대부분의 경우에 쓰는 값**을 정해 두고, 특별한 경우에만 바꿔 쓰게 하는 장치다. `print()`가 좋은 예다. `help(print)`를 입력하면 첫 줄에 이렇게 나온다.

```
print(*args, sep=' ', end='\n', file=None, flush=False)
```

`sep`(값 사이에 넣을 문자)의 기본값은 공백, `end`(마지막에 붙일 문자)의 기본값은 줄바꿈이다. 그래서 평소에는 `print("a", "b")`처럼 쓰고, 필요할 때만 바꾼다. (`*args`는 4.2.6에서 배운다.)

```python
>>> print("2026", "10", "31")
2026 10 31
>>> print("2026", "10", "31", sep="-")
2026-10-31
```

**기본값이 있는 매개변수는 뒤에 둔다**

위치로 넘길 수 있는 매개변수에서는, 기본값이 없는 매개변수가 기본값이 있는 매개변수 뒤에 오면 안 된다.

```python
>>> def greet(greeting="안녕하세요", name):
  File "<python-input-11>", line 1
    def greet(greeting="안녕하세요", name):
                                ^^^^
SyntaxError: parameter without a default follows parameter with a default
```

`greet("철수")`라고 호출했을 때 `"철수"`가 `greeting`에 들어가야 할지 `name`에 들어가야 할지 정할 수 없기 때문이다. **반드시 받아야 하는 매개변수를 앞에, 생략할 수 있는 매개변수를 뒤에** 둔다. (이 규칙은 위치로 넘길 수 있는 매개변수에만 해당한다. 4.2.6과 4.2.9에서 배울 `*` 뒤의 매개변수는 키워드로만 넘기므로 이름으로 짝지어진다. 그래서 `def f(a=1, *, b):`처럼 기본값 없이 뒤에 와도 된다.)

### 4.2.4 기본값은 언제 만들어지는가

이제 이 장에서 가장 중요한 내용 중 하나를 볼 차례다. 기본값은 **함수를 호출할 때마다 새로 계산되는 것이 아니라, 함수를 정의할 때(`def` 문이 실행될 때) 딱 한 번 계산**되어 함수에 저장된다. 다음 실험으로 확인해 보자.

```python
>>> def make_default():
...     print("기본값을 만든다!")
...     return 10
...
>>> def show(x=make_default()):
...     print(f"x = {x}")
...
기본값을 만든다!
>>> show()
x = 10
>>> show()
x = 10
>>> show(5)
x = 5
```

`"기본값을 만든다!"`는 `show()`를 호출할 때가 아니라 `def show(...)`를 **정의하는 순간** 한 번 출력되었다. 그 뒤로 `show()`를 몇 번 호출해도 다시 출력되지 않는다. 정의할 때 만든 값 `10`을 저장해 두었다가 계속 그 객체를 쓰는 것이다.

함수에 저장된 기본값은 `__defaults__`로 직접 들여다볼 수 있다. (이름 앞뒤의 밑줄 두 개는 "파이썬이 내부적으로 쓰는 특별한 이름"이라는 표시다. 평소에 쓸 일은 없고 지금은 확인용으로만 본다.)

```python
>>> show.__defaults__
(10,)
```

기본값이 숫자, 문자열, `None`처럼 **불변 객체**이면 이 사실은 아무 문제가 되지 않는다. 같은 `10`을 계속 써도 `10`이 바뀔 일은 없기 때문이다. (튜플도 불변이지만, 3.3.6에서 본 것처럼 안에 리스트 같은 가변 객체를 품고 있으면 그 리스트는 바뀔 수 있다. 튜플 기본값은 안에 든 것도 모두 불변일 때만 안전하다.) 문제는 기본값이 **가변 객체**일 때 생긴다.

### 4.2.5 가변 객체를 기본값으로 쓰면 생기는 문제

장바구니에 상품을 담는 함수를 만들어 보자. 장바구니를 넘기지 않으면 빈 장바구니에서 시작하도록 기본값을 `[]`로 정했다.

```python
>>> def add_item(item, cart=[]):
...     cart.append(item)
...     return cart
...
>>> add_item("우유")
['우유']
>>> add_item("빵")
['우유', '빵']
>>> add_item("계란")
['우유', '빵', '계란']
```

두 번째 호출의 결과가 `['빵']`일 것으로 기대했지만 `['우유', '빵']`이 나왔다. 호출할 때마다 **새로운 빈 장바구니**가 만들어지는 것이 아니라, 하나의 장바구니가 계속 쌓이고 있다. 3장의 3.2 "변수와 객체"로 설명해 보자.

1. `def add_item(item, cart=[]):`가 실행될 때 빈 리스트 객체가 **딱 한 개** 만들어져 함수에 저장된다.
2. `add_item("우유")`를 호출하면 `cart` 이름표가 **그 리스트**에 붙는다. `cart.append("우유")`는 그 리스트를 직접 바꾼다(리스트는 가변 객체다).
3. 함수가 끝나면 `cart` 이름표는 사라지지만, 리스트 객체는 함수의 기본값으로 여전히 남아 있다. 이제 그 리스트는 `['우유']`다.
4. `add_item("빵")`을 호출하면 `cart` 이름표가 **같은 리스트**에 다시 붙는다. 그래서 `['우유', '빵']`이 된다.

```
 함수에 저장된 기본값 ──────▶ ['우유', '빵', '계란']
 1번째 호출의 cart ────────────┘   (모든 호출이 같은 리스트를 공유한다)
 2번째 호출의 cart ────────────┘
 3번째 호출의 cart ────────────┘
```

`__defaults__`로 확인하면 기본값 자체가 바뀌어 있다.

```python
>>> add_item.__defaults__
(['우유', '빵', '계란'],)
```

3장의 `b = a`와 같은 상황이다. 이름표는 여러 번 붙었지만 객체는 하나뿐이다. 이 버그가 무서운 이유는 **첫 번째 호출은 늘 정상**이라는 점이다. 한 번만 시험해 보면 문제를 발견할 수 없고, 프로그램이 한참 돌아간 뒤에야 "가끔 다른 사람의 장바구니 내용이 보인다" 같은 이상한 증상으로 나타난다.

**해결: `None`을 기본값으로 쓰고, 함수 안에서 새로 만든다**

가변 객체가 필요한 기본값은 `None`으로 정해 두고, 함수 안에서 `None`인지 확인해 **호출할 때마다 새 객체를 만든다.** 파이썬에서 아주 널리 쓰는 패턴이다.

```python
>>> def add_item(item, cart=None):
...     if cart is None:
...         cart = []
...     cart.append(item)
...     return cart
...
>>> add_item("우유")
['우유']
>>> add_item("빵")
['빵']
>>> my_cart = ["사과"]
>>> add_item("배", my_cart)
['사과', '배']
>>> my_cart
['사과', '배']
```

`cart = []`는 함수 **본문** 안에 있으므로 호출할 때마다 실행되어 새 리스트가 만들어진다. 기본값 `None`은 불변 객체라서 공유되어도 아무 문제가 없다. 장바구니를 직접 넘기면(`my_cart`) 그 리스트에 담는다. (넘긴 리스트가 함수 밖에서도 바뀌는 이유는 4.3.5에서 다룬다.)

> **왜 `if not cart:`가 아니라 `if cart is None:`인가**
> `if not cart:`라고 쓰면 빈 리스트도 거짓이므로(2.4.5) `None`과 같이 취급된다. 그러면 호출한 사람이 "이 빈 리스트에 담아 달라"고 넘긴 리스트를 무시하고 새 리스트를 만들어 버린다.
> ```python
> >>> def add_item_wrong(item, cart=None):
> ...     if not cart:
> ...         cart = []
> ...     cart.append(item)
> ...     return cart
> ...
> >>> empty_cart = []
> >>> add_item_wrong("우유", empty_cart)
> ['우유']
> >>> empty_cart
> []
> ```
> `empty_cart`에 담기를 기대했지만 그대로 비어 있다. "인자를 넘기지 않았다"는 것을 정확히 확인하려면 2.2.8에서 배운 대로 `is None`을 쓴다.

정리하면 다음과 같다.

| 기본값 | 안전한가 | 예 |
|---|---|---|
| 불변 객체(튜플은 안에 든 것도 모두 불변일 때) | 안전하다 | `0`, `""`, `"안녕하세요"`, `None`, `True`, `()`, `(1, 2)` |
| 가변 객체, 가변 객체를 품은 튜플 | **위험하다** — `None` 기본값 패턴을 쓴다 | `[]`, `{}`, `set()`, `([],)` |

딕셔너리도 마찬가지다. `def make_profile(name, tags={})`, `def count_words(text, counts={})` 같은 정의를 보면 바로 의심하자. AI가 만들어 준 코드에도 가끔 이런 실수가 섞여 있다.

### 4.2.6 `*args` — 위치 인자를 개수 제한 없이 받기

`print()`는 인자를 몇 개든 받는다. `print("a")`, `print("a", "b", "c")` 모두 된다. 이런 함수를 만들려면 매개변수 이름 앞에 `*`를 붙인다.

```python
>>> def total(*numbers):
...     print(f"받은 값: {numbers}")
...     result = 0
...     for n in numbers:
...         result += n
...     return result
...
>>> total(1, 2, 3)
받은 값: (1, 2, 3)
6
>>> total(10)
받은 값: (10,)
10
>>> total()
받은 값: ()
0
```

`*numbers`는 "남는 위치 인자를 모두 모아 **튜플**로 만들어 `numbers`에 담으라"는 뜻이다. 3.3.3의 `first, *rest = ...`에서 `*`가 "나머지를 모아 담기"였던 것과 같은 생각이다. 인자가 하나도 없으면 빈 튜플이 된다.

관례적으로 이 매개변수의 이름은 `args`(arguments의 줄임)라고 짓는 경우가 많아서 이 문법을 흔히 `*args`라고 부른다. 하지만 이름은 자유이므로 `*numbers`, `*names`처럼 의미가 드러나는 이름을 쓰는 편이 읽기 좋다.

일반 매개변수와 함께 쓸 수도 있다. 앞의 매개변수가 먼저 채워지고, 나머지가 `*` 매개변수로 모인다.

```python
>>> def report(title, *scores):
...     print(f"[{title}] {len(scores)}명, 최고 {max(scores)}점")
...
>>> report("중간고사", 85, 92, 78)
[중간고사] 3명, 최고 92점
```

`*` 매개변수 **뒤에** 오는 매개변수는 위치로는 채울 수 없으므로 반드시 키워드 인자로 넘겨야 한다. `print()`의 `sep`, `end`가 바로 그런 매개변수다. `print("a", "b", "-")`라고 쓰면 `"-"`도 출력할 값으로 모일 뿐 `sep`에 들어가지 않는다.

```python
>>> def join_words(*words, sep=" "):
...     return sep.join(words)
...
>>> join_words("나는", "파이썬을", "배운다")
'나는 파이썬을 배운다'
>>> join_words("2026", "10", "31", sep="-")
'2026-10-31'
```

### 4.2.7 `**kwargs` — 키워드 인자를 개수 제한 없이 받기

매개변수 이름 앞에 `**`를 붙이면, 정의되지 않은 이름의 키워드 인자를 모두 모아 **딕셔너리**로 받는다. 관례적인 이름은 `kwargs`(keyword arguments)다.

```python
>>> def make_profile(name, **info):
...     profile = {"name": name}
...     for key, value in info.items():
...         profile[key] = value
...     return profile
...
>>> make_profile("철수", age=17, city="서울")
{'name': '철수', 'age': 17, 'city': '서울'}
>>> make_profile("영희", hobby="독서")
{'name': '영희', 'hobby': '독서'}
>>> make_profile("민수")
{'name': '민수'}
```

`age=17, city="서울"`이 `{'age': 17, 'city': '서울'}`로 모여 `info`에 담겼다. 키워드 인자의 **이름이 키**(문자열), **값이 값**이 된다.

`*args`와 `**kwargs`를 모두 쓰면 매개변수 순서는 다음과 같다.

```python
def 함수(일반, 기본값=..., *args, 키워드전용=..., **kwargs):
```

처음부터 이 모든 것을 섞어 쓸 일은 거의 없다. 우리가 직접 함수를 만들 때는 대부분 일반 매개변수와 기본값만으로 충분하다. `*args`와 `**kwargs`는 주로 **남이 만든 함수의 정의를 읽을 때** 만난다. `def log(message, *args, **kwargs):` 같은 정의를 보면 "아, 이것저것 더 넘길 수 있구나" 하고 읽을 수 있으면 된다.

### 4.2.8 호출할 때 `*`와 `**`로 풀어서 넘기기

`*`와 `**`는 **호출할 때도** 쓸 수 있다. 이때는 반대로 "모으기"가 아니라 **"풀어 넣기"**다.

- `함수(*리스트)`: 리스트(또는 튜플)의 요소를 하나씩 풀어 **위치 인자**로 넘긴다.
- `함수(**딕셔너리)`: 딕셔너리의 키-값을 풀어 **키워드 인자**로 넘긴다.

```python
>>> def introduce(name, age, city):
...     print(f"{name}({age}세, {city})")
...
>>> data = ["철수", 17, "서울"]
>>> introduce(*data)
철수(17세, 서울)
>>> info = {"name": "영희", "age": 16, "city": "부산"}
>>> introduce(**info)
영희(16세, 부산)
```

`introduce(*data)`는 `introduce("철수", 17, "서울")`과 같고, `introduce(**info)`는 `introduce(name="영희", age=16, city="부산")`과 같다. 딕셔너리의 키는 매개변수 이름과 정확히 일치해야 한다.

`print(*리스트)`는 리스트의 요소를 공백으로 구분해 출력하는 간단한 방법이다.

```python
>>> nums = [1, 2, 3]
>>> print(nums)
[1, 2, 3]
>>> print(*nums)
1 2 3
>>> print(*nums, sep=", ")
1, 2, 3
```

`**`로 풀어 넣는 방법은 설정값을 딕셔너리에 모아 두고 함수에 한꺼번에 넘길 때 자주 쓴다. LLM API 코드에서 이런 모양을 보게 될 것이다.

```python
params = {"model": "모델이름", "temperature": 0.7, "max_tokens": 500}
response = client.chat.completions.create(messages=messages, **params)
```

### 4.2.9 함수 정의 읽기 — `/`와 `*`

`help(sorted)`를 입력하면 첫 줄에 이런 정의가 나온다.

```
sorted(iterable, /, *, key=None, reverse=False)
```

매개변수 사이에 `/`와 `*`만 덩그러니 있다. 이것은 매개변수가 아니라 **표시**다.

- `/` **앞**의 매개변수는 **위치 인자로만** 넘길 수 있다. (`sorted(iterable=nums)`는 안 된다.)
- `*` **뒤**의 매개변수는 **키워드 인자로만** 넘길 수 있다. (`sorted(nums, None, True)`는 안 된다.)

그래서 `sorted()`는 반드시 `sorted(nums, reverse=True)`처럼 호출해야 한다.

```python
>>> sorted([3, 1, 2], True)
Traceback (most recent call last):
  File "<python-input-30>", line 1, in <module>
    sorted([3, 1, 2], True)
    ~~~~~~^^^^^^^^^^^^^^^^^
TypeError: sorted expected 1 argument, got 2
```

`True`만 보고는 그것이 무슨 뜻인지 알 수 없으니, 함수를 만든 사람이 일부러 키워드로만 받도록 막아 둔 것이다. 우리가 직접 이런 표시를 쓸 일은 드물지만, `help()`나 공식 문서에서 함수 정의를 읽을 때는 자주 만난다. 4.5.4에서 `help()`를 읽는 법을 다시 정리한다.

## 4.3 변수의 범위

함수 안에서 만든 변수는 함수 밖에서 쓸 수 있을까? 함수 밖에서 만든 변수를 함수 안에서 바꿀 수 있을까? 변수 이름이 **어디에서 통하는지**를 그 변수의 **범위**(scope, 스코프)라고 한다. 이 절에서는 범위의 규칙과, 함수에 리스트를 넘겼을 때 일어나는 일을 배운다.

### 4.3.1 지역 변수 — 함수 안에서 만든 이름

함수 안에서 만든 변수는 **그 함수 안에서만** 통한다. 이런 변수를 **지역 변수**(local variable)라고 한다.

```python
>>> def calc():
...     result = 10 * 2
...     print(f"함수 안: {result}")
...
>>> calc()
함수 안: 20
>>> result
Traceback (most recent call last):
  File "<python-input-2>", line 1, in <module>
    result
NameError: name 'result' is not defined
```

`result`는 `calc()`가 실행되는 동안에만 존재하다가, 함수가 끝나면 사라진다. 함수 밖에서는 그런 이름이 없다. 함수 안의 값을 밖에서 쓰고 싶으면 `return`으로 돌려주고, 호출한 쪽에서 변수에 받아야 한다. 이것이 `return`이 필요한 또 하나의 이유다.

**매개변수도 지역 변수다.** `def greet(name):`의 `name`은 호출될 때 만들어져 함수가 끝나면 사라진다.

그리고 **함수를 호출할 때마다 지역 변수는 새로 만들어진다.** 이전 호출의 지역 변수는 남아 있지 않다.

```python
>>> def counter():
...     count = 0
...     count += 1
...     return count
...
>>> counter()
1
>>> counter()
1
```

호출할 때마다 `count = 0`부터 새로 시작하므로 항상 `1`이다. 함수는 호출이 끝나면 지역 변수를 모두 잊으므로, 앞선 호출에서 만든 지역 변수가 다음 호출에 영향을 주지 않는다. 그렇다고 함수가 항상 같은 결과를 내는 것은 아니다. 함수 안에서 전역 변수(4.3.2)나 현재 시각, 무작위 수(4.6)를 읽으면 같은 인자를 넣어도 결과가 달라질 수 있다. 결과가 **인자로 받은 값에만** 달려 있도록 함수를 만들면 같은 인자에 늘 같은 결과가 나오므로, 함수만 따로 떼어 시험하기 쉽다. 그렇게 만드는 방법은 4.3.4에서 다룬다.

> **디버거로 확인하기**
> 4.1.8에서처럼 `F11`로 함수 안에 들어가면, 변수 패널에 **Locals**(지역)와 **Globals**(전역) 두 묶음이 따로 보인다. 함수 안에 있을 때 Locals에는 매개변수와 함수 안에서 만든 변수만 있다. `Shift + F11`로 빠져나오면 그 변수들이 사라지는 것을 확인할 수 있다.

### 4.3.2 전역 변수 — 파일 최상위에서 만든 이름

함수 밖, 파일의 최상위에서 만든 변수를 **전역 변수**(global variable)라고 한다. 전역 변수는 파일 안의 **어느 함수에서든 읽을 수 있다.**

```python
>>> TAX_RATE = 0.1
>>> def price_with_tax(price):
...     return price + price * TAX_RATE
...
>>> price_with_tax(10000)
11000.0
```

`price_with_tax()` 안에는 `TAX_RATE`라는 지역 변수가 없다. 파이썬은 이름을 찾을 때 **먼저 지역에서 찾고, 없으면 전역에서 찾는다.** 그래서 전역 변수 `TAX_RATE`를 찾아 썼다. (전역에도 없으면 마지막으로 `print`, `len` 같은 **내장 이름**에서 찾는다. 거기에도 없으면 `NameError`다.)

```
 이름을 찾는 순서:  지역(함수 안)  →  전역(파일 최상위)  →  내장(print, len, ...)
```

이렇게 **바뀌지 않는 설정값(상수)을 전역에 두고 함수에서 읽어 쓰는 것**은 흔하고 괜찮은 방법이다. 2장에서 배운 대로 상수의 이름은 대문자로 쓴다. 3장 종합 실습의 `PRODUCTS`가 그런 예다.

### 4.3.3 함수 안에서 할당하면 지역 변수가 된다

그렇다면 함수 안에서 전역 변수에 **값을 할당**하면 어떻게 될까?

```python
>>> message = "전역"
>>> def change():
...     message = "지역"
...     print(f"함수 안: {message}")
...
>>> change()
함수 안: 지역
>>> message
'전역'
```

전역 변수 `message`는 바뀌지 않았다. 함수 안에서 `message = "지역"`이라고 할당하는 순간, 파이썬은 **같은 이름의 지역 변수를 새로 만든다.** 이름은 같지만 전혀 다른 변수다. 함수 안에서는 지역 변수가 전역 변수를 가린다. 함수가 끝나면 지역 `message`는 사라지고, 전역 `message`는 처음 그대로 남는다.

이 규칙 때문에 다음과 같은 오류가 생긴다. 방문자 수를 세는 함수를 만들어 보자.

```python
# visit_counter.py
count = 0


def add_visit():
    count = count + 1


add_visit()
print(count)
```

```
Traceback (most recent call last):
  File "/Users/본인계정/python-lab/ch04/visit_counter.py", line 8, in <module>
    add_visit()
    ~~~~~~~~~^^
  File "/Users/본인계정/python-lab/ch04/visit_counter.py", line 5, in add_visit
    count = count + 1
            ^^^^^
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

"지역 변수 `count`에 아직 값이 연결되지 않았는데 쓰려고 했다"는 오류다. 4.3.2에서는 전역 변수를 잘 읽었는데, 왜 이번에는 안 될까?

파이썬은 함수를 **실행하기 전에** 함수 본문 전체를 훑어보고, 함수 안 **어디에서든** 할당(`=`, `+=` 등)되는 이름은 그 함수 전체에서 **지역 변수**로 정해 둔다. `add_visit()` 안에 `count = ...`가 있으므로 `count`는 처음부터 지역 변수다. 그런데 오른쪽의 `count + 1`을 계산하려는 시점에는 지역 `count`에 아직 아무 값도 없다. 그래서 전역의 `count`를 찾으러 가지 않고 바로 오류를 낸다.

`count += 1`이라고 써도 같은 오류가 난다. `+=`도 할당이기 때문이다.

### 4.3.4 `global` — 그리고 그것을 피해야 하는 이유

함수 안에서 전역 변수에 할당하려면 `global` 문으로 "이 이름은 전역 변수다"라고 알려 주면 된다.

```python
# visit_counter_global.py
count = 0


def add_visit():
    global count
    count = count + 1


add_visit()
add_visit()
print(count)
```

```
2
```

동작은 한다. 하지만 **`global`은 가능하면 쓰지 않는 것이 좋다.** 이유는 다음과 같다.

1. **값이 어디서 바뀌었는지 추적하기 어렵다.** 전역 변수를 바꾸는 함수가 여러 개이면, `count`가 이상한 값일 때 어느 함수가 언제 바꿨는지 프로그램 전체를 뒤져야 한다.
2. **함수만 따로 떼어 쓸 수 없다.** `add_visit()`은 바깥에 `count`라는 전역 변수가 있어야만 동작한다. 함수 정의만 봐서는 그런 조건이 있다는 것이 드러나지 않는다.
3. **같은 인자에 같은 결과가 나오지 않는다.** 전역 상태에 따라 결과가 달라지므로 시험하기 어렵다. 4.3.1에서 말한, 결과가 인자에만 달려 있는 함수의 장점이 사라진다.
4. **여러 개를 동시에 다룰 수 없다.** 방문자 수를 페이지마다 따로 세고 싶으면 전역 변수와 함수를 페이지 수만큼 만들어야 한다.

대신 **필요한 값은 인자로 받고, 결과는 `return`으로 돌려준다.** 바꾼 값을 저장하는 것은 호출한 쪽의 몫으로 남긴다.

```python
# visit_counter_better.py
def add_visit(count):
    return count + 1


home_count = 0
about_count = 0

home_count = add_visit(home_count)
home_count = add_visit(home_count)
about_count = add_visit(about_count)
print(home_count, about_count)
```

```
2 1
```

함수는 "받은 수에 1을 더해 돌려준다"는 일만 하고, 값을 어디에 저장할지는 호출한 쪽이 정한다. 함수 정의만 읽어도 무엇이 들어가고 무엇이 나오는지 다 보인다. 페이지가 몇 개든 같은 함수를 쓸 수 있다.

정리하면 다음과 같다.

| | 괜찮은가 | 예 |
|---|---|---|
| 함수에서 전역 **상수**를 읽는다 | 괜찮다 | `TAX_RATE`, `PRODUCTS` |
| 함수에서 바뀌는 전역 변수를 읽는다 | 피한다 — 인자로 받는다 | |
| 함수에서 `global`로 전역 변수를 바꾼다 | 피한다 — `return`으로 돌려준다 | |

> **상태를 계속 들고 다녀야 한다면**
> 프로그램이 커지면 "장바구니", "로그인한 사용자"처럼 여러 함수가 함께 다루는 상태가 생긴다. 이때도 `global`보다는 그 상태를 딕셔너리 등에 담아 **인자로 넘기는** 편이 낫다(실습 4-7에서 이렇게 한다). 상태와 그 상태를 다루는 함수를 한 덩어리로 묶는 더 좋은 방법이 5장에서 배울 **클래스**다.

### 4.3.5 가변 객체를 인자로 넘기면

3장 마지막에 예고했던 내용이다. 리스트를 함수에 넘기고, 함수 안에서 그 리스트를 바꿔 보자.

```python
>>> def add_bonus(scores):
...     for i in range(len(scores)):
...         scores[i] += 5
...
>>> my_scores = [80, 90, 70]
>>> add_bonus(my_scores)
>>> my_scores
[85, 95, 75]
```

`add_bonus()`는 아무것도 돌려주지 않았는데 **함수 밖의 `my_scores`가 바뀌었다.** 4.1.4에서 "호출하면 매개변수 이름표를 인자 객체에 붙인다"고 한 것을 떠올리자. `add_bonus(my_scores)`는 `scores = my_scores`를 한 것과 같다. 3장 3.2.2에서 배운 대로 이것은 복사가 아니라 **같은 리스트에 이름표를 하나 더 붙인 것**이다.

```
 호출한 쪽:   my_scores ──────▶ [85, 95, 75]
 함수 안:     scores ──────────────┘
```

리스트는 하나, 이름표는 둘이다. 함수 안에서 `scores[i] += 5`로 리스트 **객체를 직접 고쳤으므로**, 같은 객체를 가리키는 `my_scores`로 보아도 바뀐 내용이 보인다. 딕셔너리와 집합도 마찬가지다. `append()`, `remove()`, `sort()`, `d[key] = value`처럼 객체를 직접 고치는 동작은 모두 호출한 쪽에 보인다.

**이름표를 옮기는 것은 바깥에 영향이 없다**

그런데 함수 안에서 매개변수에 **새 객체를 할당**하면 이야기가 달라진다.

```python
>>> def reset(scores):
...     scores = [0, 0, 0]
...     print(f"함수 안: {scores}")
...
>>> my_scores = [80, 90, 70]
>>> reset(my_scores)
함수 안: [0, 0, 0]
>>> my_scores
[80, 90, 70]
```

`scores = [0, 0, 0]`은 새 리스트를 만들어 `scores` 이름표를 **그쪽으로 옮긴** 것이다. `my_scores`는 여전히 원래 리스트에 붙어 있고, 원래 리스트는 아무도 고치지 않았다.

```
 호출 직후:      my_scores ──▶ [80, 90, 70] ◀── scores

 할당 후:        my_scores ──▶ [80, 90, 70]
                 scores ─────▶ [0, 0, 0]       (함수가 끝나면 사라진다)
```

정수나 문자열 같은 **불변 객체**는 애초에 고칠 수 없으므로, 함수 안에서 무엇을 하든 호출한 쪽의 값이 바뀌는 일은 없다.

```python
>>> def add_one(n):
...     n += 1
...     return n
...
>>> x = 10
>>> add_one(x)
11
>>> x
10
```

`n += 1`은 정수 `10`을 고친 것이 아니라 새 정수 `11`을 만들어 `n` 이름표를 옮긴 것이다(3.2.3). `x`는 여전히 `10`을 가리킨다.

정리하면 하나의 원칙이다. **파이썬은 인자를 넘길 때 객체를 복사하지 않고, 매개변수 이름표를 같은 객체에 붙인다.** 그 결과로 다음과 같이 된다.

| 함수 안에서 한 일 | 호출한 쪽에 보이는가 | 예 |
|---|---|---|
| 가변 객체를 **고쳤다** | 보인다 | `scores.append(1)`, `scores[0] = 1`, `d["k"] = 1` |
| 매개변수에 **새 객체를 할당**했다 | 보이지 않는다 | `scores = []`, `n = n + 1` |
| 불변 객체를 받았다 | 고칠 방법 자체가 없다 | 정수, 문자열, 가변 객체를 품지 않은 튜플 |
| 튜플 안의 가변 객체를 **고쳤다** | 보인다(튜플은 불변이어도 안의 리스트는 가변이다, 3.3.6) | `t[1].append(4)` |

> **Python Tutor로 보기**
> 3장에서 소개한 [Python Tutor](https://pythontutor.com/python-compiler.html)에 `add_bonus`와 `reset` 예제를 넣고 한 줄씩 실행해 보자. 함수가 호출되면 오른쪽에 함수의 **틀**(frame)이 새로 생기고, 그 안의 `scores` 화살표가 호출한 쪽과 **같은 리스트**를 가리키는 것이 보인다. `reset`에서는 `scores = [0, 0, 0]` 줄에서 화살표만 새 리스트로 옮겨 가는 것을 볼 수 있다.

### 4.3.6 원본을 바꾸는 함수, 새 객체를 돌려주는 함수

가변 객체를 받는 함수를 만들 때는 두 가지 설계 중 하나를 **의도적으로** 고른다.

**방법 1: 원본을 바꾸고 `None`을 돌려준다**

`add_bonus()`처럼 받은 객체를 직접 고친다. 3장의 `list.sort()`, `list.append()`가 이 방식이다. 큰 데이터를 복사하지 않아도 되는 장점이 있다. 이런 함수는 **바꾼 객체를 다시 돌려주지 않고 `None`을 돌려주는 것이 파이썬의 관례**다. 원본을 바꾸면서 그 객체까지 돌려주면, 호출한 사람이 "원본은 그대로이고 새 결과가 나온 것"으로 착각하기 쉽기 때문이다. (4.2.5의 `add_item()`은 기본값의 동작을 눈으로 보이려고 바꾼 리스트를 돌려주었지만, 실제로 만든다면 둘 중 하나만 하는 것이 좋다. 실습 4-7의 `borrow()`처럼 화면에 보여 줄 **결과 메시지**를 돌려주는 것은 이와 다르다.) 이름이나 독스트링에 "원본을 바꾼다"는 사실을 드러내자.

**방법 2: 원본은 그대로 두고, 새 객체를 만들어 돌려준다**

`sorted()`처럼 결과를 담을 새 객체를 만들어 돌려준다.

```python
>>> def with_bonus(scores, bonus=5):
...     """각 점수에 bonus를 더한 새 리스트를 돌려준다. 원본은 바꾸지 않는다."""
...     result = []
...     for score in scores:
...         result.append(score + bonus)
...     return result
...
>>> my_scores = [80, 90, 70]
>>> new_scores = with_bonus(my_scores)
>>> new_scores
[85, 95, 75]
>>> my_scores
[80, 90, 70]
```

원본이 그대로 남으므로 "보너스 전 점수와 후 점수를 비교"하는 일도 할 수 있고, 함수를 몇 번 호출해도 원본이 망가질 걱정이 없다. **어느 쪽을 써야 할지 모르겠으면 방법 2를 쓰자.** 함수가 넘겨받은 데이터를 몰래 바꾸는 것은 가장 찾기 어려운 버그의 원인 중 하나다.

| | 방법 1: 원본을 바꾼다 | 방법 2: 새 객체를 돌려준다 |
|---|---|---|
| 내장 예 | `lst.sort()`, `lst.append(x)` | `sorted(lst)`, `s.upper()` |
| 돌려주는 값 | `None` | 새 객체 |
| 호출 모양 | `add_bonus(scores)` | `scores = with_bonus(scores)` 또는 `new = with_bonus(scores)` |
| 장점 | 복사가 없어 빠르고 메모리를 덜 쓴다 | 원본이 안전하다. 결과를 이어서 계산하기 쉽다 |

3장 3.6.4에서 "템플릿 딕셔너리를 복사해 쓰면 안쪽 리스트가 공유된다"는 문제를 보고, 해결 방법으로 "매번 새로 만든다"를 골랐다. 함수를 쓰면 이것을 깔끔하게 할 수 있다. 함수 본문은 호출할 때마다 실행되므로, 그 안에서 만든 리스트와 딕셔너리는 **호출마다 새 객체**다.

```python
>>> def new_student(name):
...     return {"name": name, "scores": []}
...
>>> s1 = new_student("철수")
>>> s2 = new_student("영희")
>>> s1["scores"].append(90)
>>> s2
{'name': '영희', 'scores': []}
```

4.2.5의 기본값 `[]`는 **정의할 때** 한 번 만들어져 공유되었고, 여기서 본문의 `[]`는 **호출할 때마다** 새로 만들어진다. 이 차이를 구분할 수 있다면 이 절의 내용을 모두 이해한 것이다.

> **함수에 넘기기 전에 복사하기**
> 원본을 바꾸는 함수(방법 1)를 써야 하는데 원본은 지키고 싶다면, 넘길 때 복사본을 넘기면 된다: `add_bonus(my_scores.copy())`. 단, 3.2.5에서 배운 것처럼 `copy()`는 얕은 복사이므로, 중첩된 리스트나 딕셔너리를 고치는 함수라면 `copy.deepcopy()`가 필요할 수 있다.

**2) `bank.py` — `global` 없애기**

다음 프로그램은 `global`로 잔액을 관리한다. `global`을 쓰지 않도록 고친다. `deposit(balance, amount)`와 `withdraw(balance, amount)`가 새 잔액을 돌려주게 하고, 출금액이 잔액보다 크면 잔액을 바꾸지 않고 "잔액이 부족합니다."를 출력한 뒤 원래 잔액을 돌려준다.

```python
balance = 0


def deposit(amount):
    global balance
    balance += amount


def withdraw(amount):
    global balance
    if amount > balance:
        print("잔액이 부족합니다.")
    else:
        balance -= amount


deposit(10000)
withdraw(3000)
withdraw(50000)
print(f"잔액: {balance:,}원")
```

```
잔액이 부족합니다.
잔액: 7,000원
```

고친 뒤에는 통장 두 개(`my_balance`, `your_balance`)를 같은 함수로 따로 관리할 수 있는지 확인한다.

**3) `normalize.py` — 원본을 지키는 함수**

- `remove_negatives(numbers)`: 음수를 뺀 **새 리스트**를 돌려준다. 원본은 바꾸지 않는다.
- `remove_negatives_inplace(numbers)`: 원본 리스트에서 음수를 **직접 지운다.** 아무것도 돌려주지 않는다.

```python
data = [3, -1, 4, -5, 9]
print(remove_negatives(data))
print(data)
remove_negatives_inplace(data)
print(data)
```

```
[3, 4, 9]
[3, -1, 4, -5, 9]
[3, 4, 9]
```

힌트: 3.1.8에서 "순회 중인 리스트에서 요소를 지우면 안 된다"고 배웠다. `remove_negatives_inplace()`는 먼저 `remove_negatives()`로 남길 요소들의 새 리스트를 만든 뒤, 원본 리스트의 **내용을 통째로 바꾸면** 된다. 슬라이스 할당 `numbers[:] = 새리스트`는 이름표를 옮기지 않고 원본 리스트 안의 요소를 모두 바꾼다. `numbers = 새리스트`와 무엇이 다른지 4.3.5를 떠올리며 비교해 보자.

## 4.4 람다와 함수 객체

4.1.3에서 괄호 없이 함수 이름만 쓰면 `<function say_hello at 0x...>`가 나온다고 했다. 이 절에서는 그것이 무엇인지 알아본다. 결론부터 말하면 **함수도 숫자, 문자열, 리스트와 같은 객체**다. 그래서 변수에 담을 수 있고, 리스트나 딕셔너리에 넣을 수 있고, 다른 함수에 인자로 넘길 수도 있다. 4.5에서 배울 `sorted()`의 `key`가 바로 이 성질을 이용한다.

### 4.4.1 함수도 값이다

`def` 문이 하는 일을 3장의 눈으로 다시 보자. `def greet(name): ...`이 실행되면 파이썬은 **함수 객체**를 하나 만들고, 거기에 `greet`라는 **이름표를 붙인다.** `x = 10`이 정수 객체 `10`에 `x`라는 이름표를 붙이는 것과 같은 일이다.

```python
>>> def greet(name):
...     return f"안녕하세요, {name}님!"
...
>>> greet
<function greet at 0x1029f9120>
>>> type(greet)
<class 'function'>
>>> type(len)
<class 'builtin_function_or_method'>
```

`greet`는 `function` 자료형의 객체를 가리키는 이름이다. `len` 같은 내장 함수는 자료형 이름이 조금 다르지만 역시 객체다.

**함수에 이름표 하나 더 붙이기**

함수 객체에 다른 이름을 붙일 수 있다. 3.2.2의 `b = a`와 똑같다.

```python
>>> say = greet
>>> say("철수")
'안녕하세요, 철수님!'
>>> say is greet
True
```

`say = greet`는 함수를 **호출한 것이 아니라**(괄호가 없다), `greet`가 가리키는 함수 객체에 `say`라는 이름표를 하나 더 붙인 것이다. 이제 `say(...)`로도 같은 함수를 호출할 수 있다. 괄호의 의미를 정확히 구분하자.

| 코드 | 의미 | 결과 |
|---|---|---|
| `greet` | 함수 **그 자체** | 함수 객체 |
| `greet("철수")` | 함수를 **호출한 결과** | 반환값 `'안녕하세요, 철수님!'` |
| `say = greet` | 함수 객체에 이름표를 하나 더 붙인다 | |
| `msg = greet("철수")` | 함수를 호출하고, 반환값에 이름표를 붙인다 | |

> **내장 함수 이름을 덮어쓰면**
> 함수 이름도 그냥 이름표이므로, 같은 이름에 다른 값을 할당하면 원래 함수를 잃어버린다. 2장에서 "내장 함수 이름을 변수 이름으로 쓰지 말라"고 한 이유가 이것이다.
> ```python
> # shadow_sum.py
> sum = 0
> for n in [1, 2, 3]:
>     sum += n
> print(sum([4, 5]))
> ```
> ```
> Traceback (most recent call last):
>   File "/Users/본인계정/python-lab/ch04/shadow_sum.py", line 4, in <module>
>     print(sum([4, 5]))
>           ~~~^^^^^^^^
> TypeError: 'int' object is not callable
> ```
> 1번째 줄에서 `sum` 이름표를 정수 `0`에 붙였기 때문에 4번째 줄의 `sum`은 더 이상 내장 함수가 아니라 정수 `6`이다. 정수는 호출할 수 없으므로 "`int` 객체는 호출할 수 없다(not callable)"는 오류가 난다. `'... object is not callable'`이라는 오류를 보면, 그 이름에 무엇이 담겨 있는지 확인하자. 대화형 셸에서 이런 일이 생겼다면 `del sum`으로 내가 만든 이름표를 지우면 내장 `sum`이 다시 보인다. (`list`, `dict`, `str`, `max`, `min`, `input`, `id`, `type`도 자주 덮어쓰는 이름이다.)

### 4.4.2 함수를 자료구조에 담기

함수는 객체이므로 리스트나 딕셔너리에 넣을 수 있다. 특히 **"명령 이름 → 실행할 함수"를 연결한 딕셔너리**는 쓸모가 많다.

```python
>>> def add(a, b):
...     return a + b
...
>>> def subtract(a, b):
...     return a - b
...
>>> def multiply(a, b):
...     return a * b
...
>>> operations = {"+": add, "-": subtract, "*": multiply}
>>> operations["+"]
<function add at 0x1029f93a0>
>>> operations["+"](3, 4)
7
>>> op = "*"
>>> operations[op](3, 4)
12
```

`operations["+"]`는 함수 객체 `add`이고, 뒤에 `(3, 4)`를 붙이면 그 함수를 호출한 것이 된다. `operations[op](3, 4)`는 두 단계로 나누어 읽으면 쉽다.

```python
func = operations[op]   # 1) 딕셔너리에서 함수를 꺼낸다
result = func(3, 4)     # 2) 꺼낸 함수를 호출한다
```

이 방법을 쓰면 `if op == "+": ... elif op == "-": ... elif ...`를 길게 늘어놓지 않아도 된다. 연산을 추가할 때는 함수를 하나 만들고 딕셔너리에 한 줄만 추가하면 된다. 실습 4-4와 4-7에서 이 방법으로 명령을 처리한다.

### 4.4.3 함수를 인자로 넘기기

함수를 다른 함수의 **인자로** 넘길 수도 있다. 리스트의 모든 요소에 "어떤 처리"를 하는 함수를 만들어 보자. 어떤 처리를 할지는 호출하는 쪽이 함수로 정해서 넘긴다.

```python
>>> def apply_to_all(func, items):
...     """items의 각 요소에 func를 적용한 결과를 새 리스트로 돌려준다."""
...     result = []
...     for item in items:
...         result.append(func(item))
...     return result
...
>>> def double(x):
...     return x * 2
...
>>> apply_to_all(double, [1, 2, 3])
[2, 4, 6]
>>> apply_to_all(len, ["apple", "kiwi", "banana"])
[5, 4, 6]
>>> apply_to_all(str, [1, 2, 3])
['1', '2', '3']
>>> apply_to_all(int, ["10", "20", "30"])
[10, 20, 30]
```

`apply_to_all()`은 `func`가 무엇인지 모른다. "받은 함수를 각 요소에 적용한다"는 **틀**만 정해 두었다. 그 틀에 `double`을 넣으면 두 배로, `len`을 넣으면 길이로, `int`를 넣으면 정수로 바꾸는 함수가 된다. 2장부터 써 온 `str()`, `int()`도 함수처럼 넘길 수 있다는 점에 주목하자.

**문자열 메서드를 함수로 넘기기**

`"hello".upper()`처럼 쓰던 메서드도 `str.upper`라고 쓰면 "문자열 하나를 받아 대문자로 바꾸는 함수"로 넘길 수 있다. `str.upper("hello")`는 `"hello".upper()`와 같다. (자세한 원리는 5장 클래스에서 배운다.)

```python
>>> str.upper("hello")
'HELLO'
>>> apply_to_all(str.upper, ["a", "b", "c"])
['A', 'B', 'C']
>>> apply_to_all(str.strip, ["  철수 ", "영희  "])
['철수', '영희']
```

**자주 하는 실수: 괄호를 붙여 넘기기**

함수를 넘길 때는 **괄호 없이** 이름만 쓴다. 괄호를 붙이면 함수를 먼저 호출해 버리고, 그 **반환값**을 넘기게 된다.

```python
>>> apply_to_all(double(), [1, 2, 3])
Traceback (most recent call last):
  File "<python-input-17>", line 1, in <module>
    apply_to_all(double(), [1, 2, 3])
                 ~~~~~~^^
TypeError: double() missing 1 required positional argument: 'x'
```

`double()`이 먼저 실행되다가 인자가 없어서 오류가 났다. "함수를 넘긴다"는 것은 "나중에 필요할 때 호출할 수 있도록 함수 자체를 건네준다"는 뜻이다. 호출은 받은 쪽(`apply_to_all` 안의 `func(item)`)이 한다.

이렇게 함수를 인자로 받거나 함수를 돌려주는 함수를 **고차 함수**(higher-order function)라고 한다. 이름은 어렵지만, 4.5에서 배울 `sorted()`, `max()`, `map()`, `filter()`가 모두 고차 함수이고 우리는 그것들을 쓰기만 하면 된다.

### 4.4.4 람다 표현식

`apply_to_all(double, ...)`을 쓰려고 `double`이라는 함수를 따로 정의했다. 한 번 쓰고 말 아주 짧은 함수라면 이름을 붙여 정의하는 것이 번거롭다. 이럴 때 **람다**(lambda) 표현식으로 이름 없는 함수를 그 자리에서 만들 수 있다.

```python
lambda 매개변수: 식
```

`lambda x: x * 2`는 "`x`를 받아 `x * 2`를 돌려주는 함수"다. 다음 두 코드는 같은 일을 한다.

```python
def double(x):
    return x * 2

lambda x: x * 2
```

- `lambda` 뒤에 매개변수를 쓰고 콜론을 찍는다. 괄호는 쓰지 않는다.
- 콜론 뒤에는 **식 하나**만 쓴다. 그 식의 값이 자동으로 반환된다. `return`은 쓰지 않는다.
- 람다는 **식**이므로 함수 객체가 들어갈 수 있는 곳이면 어디든 바로 쓸 수 있다.

```python
>>> apply_to_all(lambda x: x * 2, [1, 2, 3])
[2, 4, 6]
>>> apply_to_all(lambda x: x ** 2, [1, 2, 3])
[1, 4, 9]
>>> apply_to_all(lambda name: name + "님", ["철수", "영희"])
['철수님', '영희님']
```

매개변수가 여러 개이거나 없어도 된다. 2.4.6의 조건 표현식도 식이므로 람다 안에 쓸 수 있다.

```python
>>> (lambda a, b: a + b)(3, 4)
7
>>> apply_to_all(lambda n: "짝수" if n % 2 == 0 else "홀수", [1, 2, 3])
['홀수', '짝수', '홀수']
```

(첫 줄은 람다를 만들자마자 호출해 본 것이다. 실제로 이렇게 쓸 일은 없다.)

**람다는 언제 쓰고 언제 피하나**

람다는 **다른 함수에 넘길 짧은 함수를 그 자리에서 만들 때** 쓴다. 4.5의 `sorted(..., key=lambda ...)`가 가장 대표적인 쓰임이다. 다음 경우에는 `def`를 쓴다.

- **식 하나로 표현할 수 없을 때.** 람다 안에는 `if` 문, `for` 문, 할당, `return`을 쓸 수 없다.
- **이름을 붙여 여러 번 쓸 때.** 람다를 변수에 담는 것(`double = lambda x: x * 2`)은 PEP 8이 권장하지 않는 방식이다. 이름을 붙일 거라면 `def`가 더 읽기 쉽고, 오류가 났을 때 트레이스백에 함수 이름도 제대로 나온다. 1장에서 설정한 Ruff도 이런 코드에 경고(E731)를 표시한다.
- **식이 길어서 한눈에 읽히지 않을 때.** 람다가 한 줄을 넘어가기 시작하면 `def`로 바꾸자.

```python
>>> f = lambda x: x * 2
>>> f
<function <lambda> at 0x1029f9580>
>>> def double(x):
...     return x * 2
...
>>> double
<function double at 0x1029f9620>
```

람다로 만든 함수의 이름은 모두 `<lambda>`라서 구분이 되지 않는다.

> **람다를 읽는 법**
> AI가 만든 코드나 라이브러리 문서에서 람다를 만나면 `lambda`를 "~를 받아서", 콜론을 "~를 돌려주는 함수"로 바꿔 읽으면 된다. `lambda item: item["price"]`는 "`item`을 받아서 `item["price"]`를 돌려주는 함수"다.

## 4.5 내장 함수 활용

**내장 함수**(built-in function)는 파이썬에 처음부터 들어 있어서 아무 준비 없이 바로 쓸 수 있는 함수다. `print()`, `len()`, `int()`가 모두 내장 함수다. 파이썬에는 70개 정도의 내장 함수가 있는데, 자주 쓰는 것은 그중 일부다. 이 절에서는 지금까지 써 온 내장 함수를 정리하고, 함수를 인자로 받는 내장 함수(`sorted`의 `key`, `map`, `filter`)를 배운다. 그리고 모르는 함수를 만났을 때 스스로 사용법을 찾는 방법(`help()`, `dir()`)을 익힌다.

### 4.5.1 지금까지 만난 내장 함수

| 분류 | 함수 | 배운 곳 |
|---|---|---|
| 입출력 | `print()`, `input()` | 1장 |
| 자료형 확인·변환 | `type()`, `int()`, `float()`, `str()`, `bool()` | 2장 |
| 자료구조 만들기 | `list()`, `tuple()`, `dict()`, `set()` | 3장 |
| 반복 도우미 | `range()`, `enumerate()`, `zip()` | 2장 |
| 숫자 | `round()`, `abs()`, `divmod()` | 2장, 3장, 이 장 |
| 객체 | `id()`, `hash()` | 3장 |
| 묶음 다루기 | `len()`, `sorted()`, `sum()`, `min()`, `max()` | 2장, 3장, **이 절** |
| 이 절에서 새로 | `isinstance()`, `help()`, `dir()`, `map()`, `filter()` | **이 절** |

전체 목록은 공식 문서의 [내장 함수](https://docs.python.org/ko/3/library/functions.html) 페이지에 있다. 처음부터 다 읽을 필요는 없지만, 한 번쯤 훑어보며 "이런 것도 있구나" 정도만 알아 두면 나중에 필요할 때 찾을 수 있다.

### 4.5.2 `len`, `sum`, `min`, `max`

**`len()` — 개수**

문자열이면 글자 수, 리스트·튜플·집합이면 요소 수, 딕셔너리면 **키의 개수**를 돌려준다.

```python
>>> len("파이썬")
3
>>> len([10, 20, 30])
3
>>> len({"a": 1, "b": 2})
2
>>> len(set())
0
```

**`sum()` — 합계**

숫자가 담긴 묶음의 합을 돌려준다. 4.1에서 반복문으로 직접 만든 합계 계산을 한 줄로 할 수 있다.

```python
>>> scores = [85, 92, 78]
>>> sum(scores)
255
>>> sum(scores) / len(scores)
85.0
>>> sum([])
0
```

빈 리스트의 합은 `0`이다. 하지만 빈 리스트의 평균을 `sum(scores) / len(scores)`로 구하면 `0 / 0`이 되어 `ZeroDivisionError`가 난다(4.1.9). 평균을 구하기 전에 비어 있는지 먼저 확인하자.

`sum()`은 숫자만 더한다. 문자열을 이어 붙이려면 2장에서 배운 `join()`을 쓴다.

```python
>>> sum(["a", "b"])
Traceback (most recent call last):
  File "<python-input-6>", line 1, in <module>
    sum(["a", "b"])
    ~~~^^^^^^^^^^^^
TypeError: unsupported operand type(s) for +: 'int' and 'str'
>>> "".join(["a", "b"])
'ab'
```

오류 메시지에 `'int' and 'str'`이 나오는 이유는 `sum()`이 `0`에서 시작해 요소를 하나씩 더하기 때문이다. 첫 덧셈이 `0 + "a"`가 되어 오류가 난다.

**`min()`, `max()` — 최솟값, 최댓값**

두 가지 방법으로 쓸 수 있다. 값을 여러 개 넘기거나, 묶음 하나를 넘긴다.

```python
>>> max(3, 7, 2)
7
>>> max([3, 7, 2])
7
>>> min("banana", "apple", "cherry")
'apple'
>>> max("python")
'y'
```

문자열끼리는 사전 순서(3.1.7)로 비교한다. 문자열 하나를 넘기면 글자 하나하나를 비교한다.

빈 묶음을 넘기면 최솟값·최댓값이 없으므로 `ValueError`가 난다. `default`를 키워드 인자로 넘기면 비어 있을 때 그 값을 돌려준다.

```python
>>> max([])
Traceback (most recent call last):
  File "<python-input-12>", line 1, in <module>
    max([])
    ~~~^^^^
ValueError: max() iterable argument is empty
>>> max([], default=0)
0
>>> print(max([], default=None))
None
```

`min()`과 `max()`도 `sorted()`처럼 `key`를 받는다. 4.5.5에서 함께 다룬다.

### 4.5.3 `isinstance()` — 자료형 확인하기

`isinstance(값, 자료형)`은 값이 그 자료형이면 `True`를 돌려준다.

```python
>>> isinstance(10, int)
True
>>> isinstance("10", int)
False
>>> isinstance([1, 2], list)
True
>>> isinstance(3.5, (int, float))
True
```

자료형 자리에 **튜플**을 넘기면 "그중 하나라도 맞으면" `True`다. 마지막 예는 "정수이거나 실수인가?"를 묻는다.

함수가 **여러 종류의 값을 받을 수 있게** 만들 때 쓴다. 예를 들어 이름 하나(문자열) 또는 이름 여러 개(리스트)를 모두 받는 함수를 만들어 보자.

```python
>>> def greet_all(names):
...     if isinstance(names, str):
...         names = [names]
...     for name in names:
...         print(f"안녕하세요, {name}님!")
...
>>> greet_all("철수")
안녕하세요, 철수님!
>>> greet_all(["영희", "민수"])
안녕하세요, 영희님!
안녕하세요, 민수님!
```

`isinstance()` 검사가 없으면 `greet_all("철수")`는 문자열 `"철수"`를 글자 단위로 반복해서 `"철님"`, `"수님"`에게 인사한다. 문자열도 반복할 수 있기 때문에(2.5.1) 생기는 흔한 실수다.

**`type(x) == int`보다 `isinstance()`를 쓴다**

2장에서는 `type()`으로 자료형을 확인했다. 자료형을 **보고 싶을 때**는 `type()`, 자료형을 **검사할 때**는 `isinstance()`를 쓰는 것이 관례다. `isinstance()`는 튜플로 여러 자료형을 한 번에 검사할 수 있고, 5장에서 배울 **상속**까지 고려해 판단하기 때문이다.

그 영향을 지금도 하나 볼 수 있다. 파이썬에서 `bool`은 `int`를 바탕으로 만들어진 자료형이라서, `True`는 정수 `1`처럼 취급된다.

```python
>>> isinstance(True, int)
True
>>> True + True
2
```

그래서 "정수만 받고 불리언은 받지 않겠다"는 검사를 하려면 `isinstance(x, int) and not isinstance(x, bool)`처럼 써야 한다. 이런 경우는 드물지만, `isinstance()`가 "자료형이 정확히 같은가"가 아니라 "그 자료형의 한 종류인가"를 묻는다는 점은 기억해 두자. 자세한 것은 5장 "상속"에서 다룬다.

> **`isinstance()`는 꼭 필요할 때만**
> 모든 함수의 첫머리에서 인자의 자료형을 검사할 필요는 없다. 파이썬에서는 대개 "필요한 동작을 할 수 있으면 자료형은 묻지 않는다"는 방식으로 코드를 쓴다. 예를 들어 `sum()`은 리스트든 튜플이든 집합이든 숫자를 하나씩 꺼낼 수만 있으면 동작한다. `greet_all()`처럼 **자료형에 따라 처리 방법이 달라져야 할 때** `isinstance()`를 쓰자.

### 4.5.4 `help()`와 `dir()` — 사용법 스스로 찾기

처음 보는 함수나 메서드를 만나면 대화형 셸에서 두 가지를 해 보자.

**`help()` — 설명 읽기**

```python
>>> help(len)
Help on built-in function len in module builtins:

len(obj, /)
    Return the number of items in a container.
```

설명은 영어로 나오지만 첫 줄의 **함수 정의**만 읽어도 많은 것을 알 수 있다. 4.2에서 배운 내용으로 함수 정의를 읽어 보자.

| 함수 정의 | 읽는 법 |
|---|---|
| `len(obj, /)` | 인자 하나를 위치로만 받는다 |
| `print(*args, sep=' ', end='\n', file=None, flush=False)` | 출력할 값을 몇 개든 받는다. 나머지는 기본값이 있고 `*args` 뒤에 있으므로 키워드로만 넘긴다 |
| `sorted(iterable, /, *, key=None, reverse=False)` | 묶음 하나는 위치로, `key`와 `reverse`는 키워드로만 받는다. 둘 다 생략할 수 있다 |
| `split(self, /, sep=None, maxsplit=-1)` | `self`는 메서드가 붙은 문자열 자신이다(5장에서 배운다). `sep`과 `maxsplit`은 생략할 수 있다 |
| `max(iterable, *[, default=obj, key=func])` | 묶음을 받고, `default`와 `key`는 키워드로만 넘기며 생략할 수 있다. 대괄호 `[...]`는 "생략할 수 있다"는 표시다. 내장 함수 중 일부는 이렇게 옛날 방식으로 표기되어 있다 |

메서드의 설명을 보려면 `help(str.split)`, `help(list.append)`처럼 **자료형.메서드이름**을 넘긴다. 변수에 담긴 값으로도 된다: `help(my_list.append)`. 직접 만든 함수는 4.1.7에서 본 것처럼 독스트링이 나온다. (`help()` 화면은 `q`로 빠져나온다.)

**`dir()` — 무엇을 할 수 있는지 목록 보기**

`dir(값)`은 그 값에 붙어 있는 이름(메서드 등)의 목록을 돌려준다.

```python
>>> dir(list)
['__add__', '__class__', '__class_getitem__', '__contains__', '__delattr__', '__delitem__', '__dir__', '__doc__', '__eq__', '__format__', '__ge__', '__getattribute__', '__getitem__', '__getstate__', '__gt__', '__hash__', '__iadd__', '__imul__', '__init__', '__init_subclass__', '__iter__', '__le__', '__len__', '__lt__', '__mul__', '__ne__', '__new__', '__reduce__', '__reduce_ex__', '__repr__', '__reversed__', '__rmul__', '__setattr__', '__setitem__', '__sizeof__', '__str__', '__subclasshook__', 'append', 'clear', 'copy', 'count', 'extend', 'index', 'insert', 'pop', 'remove', 'reverse', 'sort']
```

앞뒤에 밑줄 두 개가 붙은 이름(`__add__` 등)은 파이썬 내부에서 쓰는 특별한 이름이므로 지금은 건너뛴다. **뒤쪽의 밑줄 없는 이름**이 우리가 쓰는 메서드다. 리스트에는 `append`부터 `sort`까지 11개의 메서드가 있다. 3장에서 모두 만나 보았다.

`dir()`을 인자 없이 호출하면 **지금 쓸 수 있는 이름**(대화형 셸에서 만든 변수와 함수 등)의 목록을 보여 준다. 셸에서 무엇을 만들었는지 잊었을 때 쓸모가 있다.

> **모르는 함수를 만났을 때의 순서**
> 1. VS Code에서 함수 이름에 마우스를 올려 설명(독스트링)을 본다.
> 2. 대화형 셸에서 `help()`로 함수 정의를 읽고, 작은 값으로 직접 호출해 본다.
> 3. 공식 문서에서 찾는다(4.6.10).
> 4. AI에게 묻는다. 이때 "이 함수가 뭐야?"보다 "`sorted(iterable, /, *, key=None, reverse=False)`에서 `/`와 `*`는 무슨 뜻이야?"처럼 **구체적으로** 물으면 훨씬 정확한 답을 얻는다.
>
> 2번까지만 해도 대부분은 해결된다. 직접 호출해 보는 것이 설명을 읽는 것보다 빠를 때가 많다.

### 4.5.5 `sorted()`의 `key` — 정렬 기준 바꾸기

3장에서 미뤄 두었던 내용이다. `sorted()`는 기본적으로 값 자체를 비교해 정렬한다. 숫자는 크기순, 문자열은 사전 순서다. 다른 기준으로 정렬하고 싶으면 `key`에 **함수**를 넘긴다.

**`key`가 하는 일**

`sorted(words, key=len)`은 다음과 같이 동작한다.

1. 각 요소에 `key` 함수를 적용해 **비교용 값**을 구한다. `len("kiwi")`는 `4`, `len("banana")`는 `6`.
2. 요소를 비교할 때 요소 자체가 아니라 **비교용 값**을 비교한다.
3. 결과에는 비교용 값이 아니라 **원래 요소**가 들어간다.

```python
>>> words = ["banana", "kiwi", "apple", "fig"]
>>> sorted(words)
['apple', 'banana', 'fig', 'kiwi']
>>> sorted(words, key=len)
['fig', 'kiwi', 'apple', 'banana']
```

| 요소 | `"banana"` | `"kiwi"` | `"apple"` | `"fig"` |
|---|---|---|---|---|
| `len(요소)` (비교용 값) | 6 | 4 | 5 | 3 |

비교용 값 `3, 4, 5, 6` 순서로 원래 요소를 늘어놓은 것이 결과다. `key`에는 `len`처럼 **괄호 없이** 함수를 넘긴다(4.4.3). `sorted()`가 각 요소마다 그 함수를 호출한다.

**기존 함수를 `key`로 쓰기**

```python
>>> sorted(["banana", "Apple", "cherry"])
['Apple', 'banana', 'cherry']
>>> sorted(["banana", "Cherry", "apple"])
['Cherry', 'apple', 'banana']
>>> sorted(["banana", "Cherry", "apple"], key=str.lower)
['apple', 'banana', 'Cherry']
>>> sorted([3, -10, 5, -1], key=abs)
[-1, 3, 5, -10]
```

3장에서 대문자가 소문자보다 앞에 온다고 했다. `key=str.lower`는 "모두 소문자로 바꾼 값으로 비교하라"는 뜻이라서 대소문자를 구분하지 않고 정렬한다. 결과에는 원래 문자열(`'Cherry'`)이 그대로 들어 있다는 점에 주목하자. `key=abs`는 절댓값 기준이다.

**람다를 `key`로 쓰기 — 튜플과 딕셔너리 정렬**

`key`가 가장 빛나는 곳은 튜플이나 딕셔너리의 리스트를 정렬할 때다. 3장에서는 `(이름, 점수)` 튜플을 점수순으로 정렬하려고 튜플의 순서를 `(점수, 이름)`으로 바꿔야 했다. `key`를 쓰면 그럴 필요가 없다.

```python
>>> students = [("철수", 85), ("영희", 92), ("민수", 78)]
>>> sorted(students)
[('민수', 78), ('영희', 92), ('철수', 85)]
>>> sorted(students, key=lambda s: s[1])
[('민수', 78), ('철수', 85), ('영희', 92)]
>>> sorted(students, key=lambda s: s[1], reverse=True)
[('영희', 92), ('철수', 85), ('민수', 78)]
```

`lambda s: s[1]`은 "튜플 `s`를 받아 두 번째 요소(점수)를 돌려주는 함수"다. 이렇게 **짧은 함수를 한 번만 넘기는 곳**이 람다를 쓰기 가장 좋은 곳이다.

딕셔너리의 리스트도 같은 방법으로 정렬한다. 3장에서 본 "딕셔너리의 리스트"는 API 응답에서 가장 흔한 모양이다.

```python
>>> products = [
...     {"name": "펜", "price": 1500},
...     {"name": "노트", "price": 3000},
...     {"name": "지우개", "price": 800},
... ]
>>> for p in sorted(products, key=lambda p: p["price"]):
...     print(p["name"], p["price"])
...
지우개 800
펜 1500
노트 3000
```

**딕셔너리를 값 기준으로 정렬하기**

`{이름: 점수}` 딕셔너리를 점수순으로 출력하려면 `items()`로 `(키, 값)` 튜플의 묶음을 만들어 두 번째 요소 기준으로 정렬한다. 3장의 개수 세기 결과에서 "가장 많이 나온 순서"를 구할 때 자주 쓴다.

```python
>>> counts = {"사과": 3, "바나나": 5, "포도": 1}
>>> sorted(counts.items(), key=lambda item: item[1], reverse=True)
[('바나나', 5), ('사과', 3), ('포도', 1)]
>>> for fruit, count in sorted(counts.items(), key=lambda item: item[1], reverse=True):
...     print(f"{fruit}: {count}")
...
바나나: 5
사과: 3
포도: 1
```

**여러 기준으로 정렬하기**

"점수 높은 순, 점수가 같으면 이름 가나다순"처럼 기준이 여러 개이면 `key` 함수가 **튜플**을 돌려주게 한다. 튜플끼리는 첫 번째 요소부터 비교하고, 같으면 두 번째 요소를 비교한다.

```python
>>> scores = [("철수", 85), ("영희", 92), ("민수", 85), ("지수", 92)]
>>> sorted(scores, key=lambda s: (-s[1], s[0]))
[('영희', 92), ('지수', 92), ('민수', 85), ('철수', 85)]
```

점수는 높은 순(내림차순), 이름은 가나다순(오름차순)으로 방향이 다르다. `reverse=True`는 전체를 뒤집으므로 쓸 수 없다. 그래서 점수에 **마이너스**를 붙였다. `-92`가 `-85`보다 작으므로 92점이 앞에 온다. 숫자 기준을 반대로 하고 싶을 때 쓰는 간단한 방법이다.

> **같은 값은 원래 순서를 지킨다**
> `sorted()`는 비교용 값이 같은 요소들의 **원래 순서를 바꾸지 않는다.** 이런 정렬을 **안정 정렬**(stable sort)이라고 한다. `sorted(scores, key=lambda s: s[1])`에서 85점인 `철수`와 `민수`는 원래 리스트에 나온 순서대로 `철수`, `민수`로 남는다. "같으면 먼저 들어온 순서대로"를 원하면 따로 처리할 필요가 없다.

**`list.sort()`, `min()`, `max()`에도 `key`를 쓴다**

`key`는 `sorted()`만의 기능이 아니다. 원본을 정렬하는 `list.sort()`, 그리고 `min()`, `max()`도 같은 방식으로 `key`를 받는다. 특히 `max()`와 `min()`에 `key`를 쓰면 "**무엇을 기준으로** 가장 큰 것"을 찾을 수 있고, 결과는 비교용 값이 아니라 **원래 요소**다.

```python
>>> students = [("철수", 85), ("영희", 92), ("민수", 78)]
>>> max(students, key=lambda s: s[1])
('영희', 92)
>>> name, score = min(students, key=lambda s: s[1])
>>> f"최저: {name} ({score}점)"
'최저: 민수 (78점)'
>>> max(["banana", "kiwi", "apple"], key=len)
'banana'
>>> words = ["banana", "kiwi", "apple"]
>>> words.sort(key=len)
>>> words
['kiwi', 'apple', 'banana']
```

2장 종합 실습에서는 최고 점수와 그 학생 이름을 찾으려고 변수 두 개를 반복문에서 함께 갱신했다. `max(..., key=...)` 한 줄이면 된다. 최댓값이 여러 개이면 **먼저 나온 것**을 돌려준다.

> **딕셔너리에서 값이 가장 큰 키 찾기**
> `counts = {"사과": 3, "바나나": 5, "포도": 1}`에서 개수가 가장 많은 과일은 `max(counts, key=counts.get)`으로 찾을 수 있다. 딕셔너리를 그대로 반복하면 키가 나오고(3.4.4), `counts.get`은 "키를 받아 값을 돌려주는 함수"다. 즉 "키들 중에서, `counts.get(키)`가 가장 큰 키"를 찾는다. 결과는 `'바나나'`다. `max(counts.items(), key=lambda item: item[1])`로 `('바나나', 5)`를 얻는 방법도 있다.

### 4.5.6 `map()`과 `filter()`

함수를 받는 내장 함수가 두 개 더 있다.

- `map(함수, 묶음)`: 묶음의 각 요소에 함수를 적용한 결과들을 만든다. 4.4.3의 `apply_to_all()`과 같은 일이다.
- `filter(함수, 묶음)`: 묶음의 요소 중 함수의 결과가 참인 것만 남긴다. 실습 4-4의 `count_if()`가 세던 그 요소들이다.

```python
>>> nums = [1, 2, 3, 4, 5]
>>> map(lambda x: x * 10, nums)
<map object at 0x1029e3f10>
>>> list(map(lambda x: x * 10, nums))
[10, 20, 30, 40, 50]
>>> list(filter(lambda x: x % 2 == 0, nums))
[2, 4]
```

`map()`의 결과를 그대로 출력하면 `<map object ...>`만 보인다. `range()`처럼(3.1.1), `map()`과 `filter()`는 결과를 미리 다 만들어 두지 않고 **꺼낼 때마다 하나씩 계산하는 객체**를 돌려준다. 내용을 보려면 `list()`로 감싸거나 `for`로 꺼낸다.

```python
>>> for x in map(str.upper, ["a", "b"]):
...     print(x)
...
A
B
```

**한 번 꺼내면 끝이다**

`map()`과 `filter()`가 돌려준 객체는 **한 번만** 꺼낼 수 있다. 다 꺼낸 뒤에 다시 꺼내면 아무것도 나오지 않는다.

```python
>>> doubled = map(lambda x: x * 2, [1, 2, 3])
>>> list(doubled)
[2, 4, 6]
>>> list(doubled)
[]
```

두 번째 `list(doubled)`는 오류도 없이 빈 리스트가 된다. 결과를 여러 번 쓸 거라면 처음부터 `doubled = list(map(...))`처럼 리스트로 만들어 두자.

**자주 쓰는 모양: 문자열을 숫자 묶음으로**

`map()`이 가장 자주 쓰이는 곳은 입력받은 문자열을 숫자 묶음으로 바꿀 때다. 3장 실습 3-1의 `score_stats.py`에서 반복문으로 하던 일이다.

```python
>>> text = "85 92 78"
>>> text.split()
['85', '92', '78']
>>> list(map(int, text.split()))
[85, 92, 78]
>>> a, b = map(int, "3 4".split())
>>> a + b
7
```

`map(int, ...)`은 "각 조각에 `int()`를 적용하라"는 뜻이다. 마지막 예처럼 `map()`의 결과를 바로 언패킹할 수도 있다. `a, b = map(int, input().split())`은 "한 줄에 숫자 두 개를 입력받는" 관용구로 자주 보게 된다.

**`filter()`에 `None`을 넘기면**

`filter(None, 묶음)`은 함수 대신 "값 자체가 참인가"로 거른다. 빈 문자열, `0`, `None` 같은 거짓 값(2.4.5)을 한 번에 없앨 때 쓴다.

```python
>>> list(filter(None, ["철수", "", "영희", "", "민수"]))
['철수', '영희', '민수']
```

> **`map`/`filter`와 반복문, 무엇을 쓸까**
> `map()`과 `filter()`로 할 수 있는 일은 모두 `for` 반복문과 `append()`로도 할 수 있다. 짧고 단순한 변환이면 `map()`/`filter()`가 간결하고, 처리가 복잡하거나 람다가 길어지면 반복문이 읽기 쉽다. 파이썬에는 같은 일을 더 간결하게 쓰는 **리스트 내포**(list comprehension)라는 문법도 있는데, 실무에서는 `map()`/`filter()`보다 이쪽을 더 많이 쓴다. 이후 과정에서 배운다. 지금은 `map()`과 `filter()`를 보면 "각각에 적용", "조건에 맞는 것만"이라고 읽을 수 있으면 충분하다.

## 4.6 모듈 가져다 쓰기

내장 함수만으로는 할 수 있는 일이 많지 않다. 제곱근을 구하거나, 무작위로 하나를 고르거나, 오늘 날짜를 알아내는 함수는 내장 함수에 없다. 이런 기능은 **모듈**에 들어 있다. 이 절에서는 파이썬에 기본으로 들어 있는 모듈을 가져다 쓰는 방법을 배운다. 모듈을 직접 만드는 방법은 8장 "모듈/패키지"에서 다룬다.

### 4.6.1 모듈이란

**모듈**(module)은 함수와 변수 등을 모아 둔 **파이썬 파일**이다. 관련된 기능끼리 묶여 있다. 수학 계산은 `math` 모듈에, 무작위 수는 `random` 모듈에, 날짜와 시간은 `datetime` 모듈에 들어 있다.

파이썬을 설치하면 이런 모듈 수백 개가 함께 설치된다. 이것을 **표준 라이브러리**(standard library)라고 한다. "파이썬에는 건전지가 들어 있다(batteries included)"는 말이 있을 정도로, 웬만한 기능은 따로 설치하지 않아도 표준 라이브러리에서 찾을 수 있다. 3장에서 쓴 `copy`와 `pprint`도 표준 라이브러리의 모듈이다. (표준 라이브러리에 없는 모듈은 인터넷에서 내려받아 설치해 쓰는데, 9장 "가상환경"에서 배운다.)

내장 함수와 달리 모듈의 기능은 **가져오기**(import)를 해야 쓸 수 있다. 가져오지 않고 쓰면 그런 이름이 없다는 오류가 난다.

```python
>>> math.sqrt(16)
Traceback (most recent call last):
  File "<python-input-0>", line 1, in <module>
    math.sqrt(16)
    ^^^^
NameError: name 'math' is not defined. Did you forget to import 'math'?
```

파이썬도 `Did you forget to import 'math'?`("`math`를 가져오는 것을 잊었나요?")라고 알려 준다.

### 4.6.2 `import 모듈`

가장 기본적인 방법이다.

```python
>>> import math
>>> math.sqrt(16)
4.0
>>> math.pi
3.141592653589793
```

`import math`는 `math` 모듈을 불러와서 `math`라는 **이름표를 붙인다.** 모듈도 객체다.

```python
>>> math
<module 'math' (built-in)>
>>> type(math)
<class 'module'>
```

(파이썬을 설치한 방식에 따라 첫 줄이 `<module 'math' from '...'>`처럼 파일 경로로 보이기도 한다. 어느 쪽이든 모듈 객체라는 뜻이다.)

모듈 안의 함수나 변수는 `모듈이름.이름` 모양으로 점(`.`)을 찍어 쓴다. `math.sqrt`는 "`math` 모듈 안의 `sqrt`"라는 뜻이다. 2장에서 문자열 메서드를 `s.upper()`처럼 점을 찍어 쓴 것과 같은 문법이다. 무엇이 들어 있는지는 4.5.4의 `dir()`과 `help()`로 볼 수 있다.

```python
>>> help(math.sqrt)
Help on built-in function sqrt in module math:

sqrt(x, /)
    Return the square root of x.
```

모듈을 한 번 가져오면 그 셸(또는 파일) 안에서는 계속 쓸 수 있다. 같은 모듈을 여러 번 `import`해도 처음 한 번만 실제로 불러오고, 그다음부터는 이미 불러온 모듈을 그대로 쓴다.

여러 모듈을 가져올 때는 한 줄에 하나씩 쓰는 것이 관례다.

```python
import math
import random
```

### 4.6.3 `from 모듈 import 이름`

모듈 안의 특정 이름만 골라서 가져올 수도 있다. 이렇게 가져온 이름은 모듈 이름을 붙이지 않고 바로 쓴다.

```python
>>> from math import sqrt, pi
>>> sqrt(25)
5.0
>>> pi
3.141592653589793
```

3장에서 `from pprint import pprint`라고 쓴 것이 이 방법이다. `pprint` 모듈 안의 `pprint` 함수를 가져온 것이다(모듈 이름과 함수 이름이 같다).

두 방법은 장단점이 있다.

| | `import math` | `from math import sqrt` |
|---|---|---|
| 쓰는 모양 | `math.sqrt(2)` | `sqrt(2)` |
| 장점 | 어느 모듈의 기능인지 코드에 드러난다. 이름이 겹칠 걱정이 없다 | 짧다. 자주 쓰는 함수에 편리하다 |
| 단점 | 매번 모듈 이름을 써야 한다 | 어디서 온 이름인지 알기 어렵다. 내 변수 이름과 겹칠 수 있다 |

처음에는 `import 모듈`을 기본으로 쓰고, 이름이 길거나 아주 자주 쓰는 몇 개만 `from ... import`로 가져오자. 실무 코드에서는 `from datetime import datetime`, `from pathlib import Path`처럼 모듈 안의 **자료형**(5장에서 배울 클래스)을 가져올 때 `from`을 많이 쓴다.

> **`from 모듈 import *`는 쓰지 않는다**
> `from math import *`라고 쓰면 모듈 안의 이름을 **전부** 가져온다. 편해 보이지만 무엇을 가져왔는지 코드에 드러나지 않고, 내 변수나 다른 모듈의 이름을 모르는 사이에 덮어쓸 수 있다. 4.4.1의 `sum = 0`과 같은 사고가 보이지 않는 곳에서 일어나는 셈이다. 인터넷의 예제 코드에서 보더라도 따라 쓰지 말자.

### 4.6.4 `as` — 별칭 붙이기

가져온 모듈이나 이름에 **다른 이름표**를 붙일 수 있다.

```python
>>> import datetime as dt
>>> dt.date(2026, 10, 31)
datetime.date(2026, 10, 31)
>>> from math import factorial as fact
>>> fact(5)
120
```

이름이 길 때 줄여 쓰거나, 두 모듈에서 가져온 이름이 겹칠 때 구분하려고 쓴다. 이후 과정에서 데이터를 다룰 때 다음과 같은 별칭을 거의 모든 코드에서 보게 된다. 이것은 사람들이 널리 지키는 **약속**이므로 다른 별칭을 붙이지 말고 그대로 쓰는 것이 좋다.

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
```

(아직 설치하지 않은 모듈이라 지금 실행하면 `ModuleNotFoundError`가 난다. 모양만 기억해 두자.)

### 4.6.5 `import`는 어디에 쓰나

`import` 문은 **파일 맨 위**에 모아 쓰는 것이 관례(PEP 8)다. 파일을 열자마자 이 프로그램이 무엇을 가져다 쓰는지 한눈에 볼 수 있기 때문이다. 독스트링이나 주석이 있다면 그 바로 아래에 쓴다.

```python
# dice_game.py
import random
from datetime import date


def roll():
    return random.randint(1, 6)


print(f"{date.today()} 주사위: {roll()}")
```

여러 종류를 가져올 때는 **표준 라이브러리 → 설치한 외부 라이브러리 → 내가 만든 모듈** 순서로 묶고, 묶음 사이에 빈 줄을 하나 둔다. 1장에서 설정한 Ruff가 저장할 때 이 순서를 자동으로 맞춰 준다(`source.organizeImports.ruff`). 가져와 놓고 쓰지 않는 `import`가 있으면 Ruff가 흐리게 표시해 알려 준다.

**모듈을 찾지 못하면**

모듈 이름에 오타가 있거나, 설치하지 않은 외부 모듈을 가져오려 하면 `ModuleNotFoundError`가 난다.

```python
>>> import maths
Traceback (most recent call last):
  File "<python-input-9>", line 1, in <module>
    import maths
ModuleNotFoundError: No module named 'maths'
```

표준 라이브러리 모듈인데 이 오류가 나면 이름의 오타를 확인한다. 외부 모듈(예: `requests`)인데 이 오류가 나면 설치하지 않았거나 다른 파이썬에 설치한 것이다. 9장에서 자세히 다룬다.

`import random`이 표준 라이브러리의 `random`이 아니라 **같은 폴더의 내 `random.py`를 가져왔다.** 첫 줄에 `random 모듈 연습`이 출력된 것이 증거다. 파이썬은 모듈을 찾을 때 **실행한 파일이 있는 폴더를 먼저** 찾아보기 때문이다. 내 `random.py`에는 `randint`가 없으니 `AttributeError`("그런 속성이 없다")가 난다.

### 4.6.7 `math` — 수학 함수

| 이름 | 하는 일 | 예 | 결과 |
|---|---|---|---|
| `math.sqrt(x)` | 제곱근 | `math.sqrt(2)` | `1.4142135623730951` |
| `math.ceil(x)` | 올림 (x 이상인 가장 작은 정수) | `math.ceil(3.2)` | `4` |
| `math.floor(x)` | 내림 (x 이하인 가장 큰 정수) | `math.floor(3.8)` | `3` |
| `math.isclose(a, b)` | 두 실수가 (오차 범위 안에서) 같은가 | `math.isclose(0.1 + 0.2, 0.3)` | `True` |
| `math.gcd(a, b)` | 최대공약수 | `math.gcd(12, 18)` | `6` |
| `math.prod(묶음)` | 모두 곱한 값 | `math.prod([2, 3, 4])` | `24` |
| `math.factorial(n)` | 팩토리얼 | `math.factorial(5)` | `120` |
| `math.pi`, `math.e` | 원주율, 자연상수 (함수가 아니라 값) | `math.pi` | `3.141592653589793` |

2장 2.2.4에서 "실수는 `==`로 비교하지 않는다"고 하면서 미뤄 둔 `math.isclose()`가 여기 있다.

```python
>>> import math
>>> 0.1 + 0.2 == 0.3
False
>>> math.isclose(0.1 + 0.2, 0.3)
True
```

**올림과 내림은 실생활 계산에 자주 쓴다.** "사람 23명이 5인승 차를 타려면 몇 대가 필요한가?"는 `23 / 5 = 4.6`을 **올림**한 5대다.

```python
>>> math.ceil(23 / 5)
5
>>> math.floor(-3.5)
-4
>>> int(-3.5)
-3
```

`math.floor()`는 "아래쪽 정수"이므로 음수에서는 `-4`가 된다. 2장에서 배운 `int()`는 소수점 아래를 **버리는** 것이라 `-3`이다. 양수에서는 둘이 같지만 음수에서는 다르다.

### 4.6.8 `random` — 무작위

| 이름 | 하는 일 |
|---|---|
| `random.randint(a, b)` | a 이상 **b 이하**의 정수 하나 (`range()`와 달리 b를 포함한다) |
| `random.random()` | 0 이상 1 미만의 실수 하나 |
| `random.choice(묶음)` | 묶음에서 하나를 무작위로 고른다 |
| `random.sample(묶음, k)` | 묶음에서 k개를 골라 **새 리스트**로 돌려준다. 한 번 뽑은 자리는 다시 뽑지 않는다 |
| `random.shuffle(리스트)` | 리스트의 순서를 **원본에서** 섞는다. `None`을 돌려준다 |
| `random.seed(값)` | 무작위 수의 출발점을 정한다 (아래 설명) |

```python
>>> import random
>>> menu = ["김밥", "라면", "떡볶이", "돈가스", "비빔밥"]
>>> random.choice(menu)
'돈가스'
>>> random.sample(range(1, 46), 6)
[12, 38, 3, 27, 41, 19]
>>> cards = [1, 2, 3, 4, 5]
>>> random.shuffle(cards)
>>> cards
[3, 5, 1, 4, 2]
```

(무작위이므로 결과는 실행할 때마다 다르다.) `random.sample(range(1, 46), 6)`은 1~45에서 6개를 고르는 로또 번호 생성기다. `sample()`은 한 번 뽑은 자리를 다시 뽑지 않고 `range(1, 46)`의 수는 모두 다르므로, 번호가 겹치지 않는다. 다만 원본에 같은 값이 여러 개 들어 있으면 결과에도 같은 값이 나올 수 있다. 예를 들어 `random.sample(["A", "A", "B"], 2)`는 `['A', 'A']`가 나올 수도 있다.

`random.shuffle()`의 반환값에 주목하자. 4.3.6의 "원본을 바꾸는 함수는 `None`을 돌려준다"는 관례를 따른다. 그래서 `cards = random.shuffle(cards)`는 3장의 `nums = nums.sort()`와 같은 버그다. 원본을 지키면서 섞인 새 리스트를 얻고 싶으면 `random.sample(cards, len(cards))`를 쓴다.

**`random.seed()` — 같은 무작위를 다시 만들기**

컴퓨터의 무작위 수는 정해진 계산으로 만들어 내는 "무작위처럼 보이는 수"다. 계산의 **출발점**(seed, 씨앗)을 같게 정하면 매번 똑같은 순서의 수가 나온다.

```python
>>> random.seed(42)
>>> random.randint(1, 6), random.randint(1, 6), random.randint(1, 6)
(6, 1, 1)
>>> random.seed(42)
>>> random.randint(1, 6), random.randint(1, 6), random.randint(1, 6)
(6, 1, 1)
```

같은 seed에서 시작해 **같은 순서로** 무작위 함수를 호출하면, 같은 파이썬 버전에서는 컴퓨터가 달라도 같은 결과가 나온다. 중간에 무작위 함수를 추가로 호출하면 난수 생성 상태가 달라져, 이후 결과가 기존 실행과 달라질 수 있다. 파이썬 버전이 바뀌면 `randint()`나 `sample()` 같은 함수의 결과도 달라질 수 있다. 공식 문서는 `random.random()`의 결과만 버전이 바뀌어도 같다고 보장한다. 위 예의 결과는 파이썬 3.12와 3.13에서 확인한 것이다. 무작위가 들어간 프로그램을 **시험하거나 디버깅할 때**, 버그가 났던 상황을 똑같이 다시 만들 수 있어서 유용하다. AI 분야에서도 실험 결과를 다시 만들 수 있도록 코드 맨 앞에 seed를 정해 두는 일이 아주 흔하다. 실제로 매번 다른 결과가 필요한 프로그램에서는 seed를 정하지 않는다.

### 4.6.9 `datetime` — 날짜와 시간

`datetime` 모듈에는 날짜와 시간을 다루는 자료형이 들어 있다. 이 장에서는 세 가지를 쓴다.

| 자료형 | 나타내는 것 | 예 |
|---|---|---|
| `date` | 날짜 (연, 월, 일) | 2026년 10월 31일 |
| `datetime` | 날짜와 시각 | 2026년 10월 31일 14시 30분 5초 |
| `timedelta` | 시간의 **길이**(간격) | 14일, 3시간 40분 |

모듈 이름과 그 안의 자료형 이름이 똑같이 `datetime`이라서 헷갈리기 쉽다. 그래서 보통 필요한 자료형을 `from`으로 가져와 쓴다.

```python
>>> from datetime import date, datetime, timedelta
```

**오늘과 지금**

```python
>>> date.today()
datetime.date(2026, 10, 31)
>>> print(date.today())
2026-10-31
>>> now = datetime.now()
>>> print(now)
2026-10-31 14:30:05.123456
>>> now.year, now.month, now.day, now.hour
(2026, 10, 31, 14)
```

(실행하는 날짜와 시각에 따라 결과가 다르다.) 셸에 값을 그대로 입력하면 `datetime.date(2026, 10, 31)`처럼 "만드는 방법" 모양으로 보이고, `print()`하면 `2026-10-31`처럼 읽기 좋은 모양으로 보인다. 둘 다 같은 값이다. (이 차이는 5장의 `__repr__`과 `__str__`에서 배운다.)

**날짜 만들기와 계산하기**

`date(연, 월, 일)`로 원하는 날짜를 만든다. 날짜에 `timedelta`를 더하거나 빼면 그만큼 지난(앞선) 날짜가 되고, 날짜끼리 빼면 `timedelta`가 된다.

```python
>>> d = date(2026, 10, 31)
>>> d + timedelta(days=14)
datetime.date(2026, 11, 14)
>>> d - timedelta(weeks=1)
datetime.date(2026, 10, 24)
>>> christmas = date(2026, 12, 25)
>>> christmas - d
datetime.timedelta(days=55)
>>> (christmas - d).days
55
>>> d < christmas
True
```

10월 31일에 14일을 더하면 달이 바뀌어 11월 14일이 된다. 달마다 날수가 다른 것, 윤년 같은 복잡한 계산을 `datetime`이 알아서 해 준다. 날짜는 `<`, `>`로 비교할 수도 있다. 이 계산들은 실습 4-7의 도서 대출 관리에서 반납 기한과 연체일을 구할 때 쓴다.

`timedelta`는 `days`, `weeks`, `hours`, `minutes`, `seconds`를 **키워드 인자**로 받는다. 모두 기본값이 0이라서 필요한 것만 넘기면 된다.

```python
>>> timedelta(hours=3, minutes=40)
datetime.timedelta(seconds=13200)
>>> print(timedelta(days=1, hours=2))
1 day, 2:00:00
```

**요일**

`weekday()` 메서드는 요일을 숫자로 돌려준다. 월요일이 `0`, 일요일이 `6`이다. 한글 요일이 필요하면 튜플에서 꺼낸다.

```python
>>> d.weekday()
5
>>> WEEKDAYS = ("월", "화", "수", "목", "금", "토", "일")
>>> WEEKDAYS[d.weekday()]
'토'
```

**날짜를 문자열로, 문자열을 날짜로**

날짜를 원하는 모양의 문자열로 바꾸려면 `strftime()`(string format time) 메서드에 **형식 코드**를 넘긴다. 반대로 문자열을 날짜로 바꾸려면 `fromisoformat()`이나 `strptime()`(string parse time)을 쓴다.

| 형식 코드 | 뜻 | 예 |
|---|---|---|
| `%Y` | 연도 4자리 | `2026` |
| `%m` | 월 2자리 | `10` |
| `%d` | 일 2자리 | `31` |
| `%H` | 시 (24시간제) 2자리 | `14` |
| `%M` | 분 2자리 | `30` |
| `%S` | 초 2자리 | `05` |

```python
>>> t = datetime(2026, 10, 31, 14, 30, 5)
>>> t.strftime("%Y년 %m월 %d일 %H:%M")
'2026년 10월 31일 14:30'
>>> t.strftime("%Y%m%d")
'20261031'
>>> date.fromisoformat("2026-11-15")
datetime.date(2026, 11, 15)
>>> datetime.strptime("2026/11/15 09:00", "%Y/%m/%d %H:%M")
datetime.datetime(2026, 11, 15, 9, 0)
```

`fromisoformat()`은 `2026-11-15`처럼 국제 표준(ISO 8601) 모양의 문자열만 받는다. 다른 모양의 문자열은 `strptime()`에 **그 문자열이 어떤 모양인지** 형식 코드로 알려 주어야 한다. 문자열이 형식에 맞지 않으면 `ValueError`가 난다(6장에서 처리 방법을 배운다). 형식 코드는 외울 필요 없이 필요할 때 공식 문서에서 찾아 쓰면 된다.

> **`import datetime`과 `from datetime import datetime`**
> 인터넷의 예제 코드에는 두 가지 모양이 섞여 있다.
> ```python
> import datetime
> now = datetime.datetime.now()      # 모듈.자료형.메서드
>
> from datetime import datetime
> now = datetime.now()               # 자료형.메서드
> ```
> 둘 다 맞지만, 첫 번째 방식으로 가져와 놓고 `datetime.now()`라고 쓰면 `AttributeError: module 'datetime' has no attribute 'now'`가 난다. 모듈 `datetime`에는 `now`가 없고, 그 안의 **자료형** `datetime`에 있기 때문이다. 이 오류를 보면 위쪽 `import` 줄이 어느 모양인지 확인하자.

> **기본값으로 `datetime.now()`를 쓰면**
> 4.2.4에서 기본값은 함수를 **정의할 때 한 번** 계산된다고 배웠다. 그래서 `def log(message, when=datetime.now()):`라고 정의하면, 몇 시에 호출하든 `when`은 **함수를 정의한 시각**에 고정된다. 가변 객체 기본값과 같은 방법으로 해결한다: `when=None`으로 두고 함수 안에서 `if when is None: when = datetime.now()`.

### 4.6.10 공식 문서에서 모듈 사용법 찾기

모듈의 기능은 너무 많아서 외울 수 없다. 필요할 때 찾아 쓰는 능력이 중요하다. 가장 정확한 곳은 공식 문서다.

- 파이썬 표준 라이브러리 문서: [https://docs.python.org/ko/3/library/](https://docs.python.org/ko/3/library/)
- 주소의 `ko`는 한국어 번역판이라는 뜻이다. 번역이 덜 된 부분은 영어로 나온다. 영어 원문은 `ko/`를 뺀 주소다.
- 페이지 왼쪽 위에서 파이썬 버전을 고를 수 있다. 내가 쓰는 버전(1장에서 확인한 버전)과 맞춰 읽자.

모듈 문서 페이지는 대개 다음과 같이 구성되어 있다. `random` 모듈 페이지([https://docs.python.org/ko/3/library/random.html](https://docs.python.org/ko/3/library/random.html))를 열어 함께 살펴보자.

1. **맨 위의 설명**: 이 모듈이 무엇을 하는지. 처음에는 첫 문단만 읽어도 된다.
2. **함수 목록**: `random.randint(a, b)`처럼 **함수 정의**가 굵게 나오고, 그 아래에 설명이 있다. 4.5.4에서 배운 대로 정의를 먼저 읽는다.
3. **버전 표시**: "버전 3.x에 추가" 또는 "버전 3.x에서 변경"이라고 적힌 부분이 있다. 내 파이썬 버전보다 나중에 추가된 기능은 쓸 수 없다.
4. **예제**: 페이지 아래쪽에 예제가 모여 있는 경우가 많다. 예제를 대화형 셸에 그대로 입력해 보는 것이 가장 빨리 익히는 방법이다.

**찾는 순서 연습**: "리스트에서 무작위로 **여러 개**를 고르는데, **같은 것이 다시 뽑혀도 된다**"는 기능이 필요하다고 하자.

1. `random` 모듈 페이지의 함수 목록을 훑는다. 시퀀스(리스트처럼 순서가 있는 묶음)를 다루는 함수들을 모아 둔 부분에 `choice`, `choices`, `shuffle`, `sample`이 있다.
2. `sample`은 4.6.8에서 "한 번 뽑은 자리는 다시 뽑지 않는다"고 했다. 이름이 비슷한 `choices(population, weights=None, *, cum_weights=None, k=1)`의 설명을 읽으면 "with replacement"(뽑은 것을 다시 넣고 뽑는다)라고 되어 있다. 즉 **같은 자리를 여러 번 뽑을 수 있어서**, 원본의 값이 모두 달라도 결과에 같은 값이 나올 수 있다.
3. 정의를 보니 `k`는 `*` 뒤에 있으므로 **키워드로** 넘겨야 한다. 셸에서 `random.choices(["가위", "바위", "보"], k=5)`를 실행해 확인한다.

대화형 셸에서는 `help(random.choices)`로 같은 설명을 볼 수 있다. 공식 문서가 어렵게 느껴지면 AI에게 "파이썬 `random.choices`와 `random.sample`의 차이를 예제로 보여 줘"처럼 물은 뒤, **답을 공식 문서와 대조해 확인**하는 습관을 들이자. AI는 가끔 존재하지 않는 함수나 매개변수를 지어내기도 하는데, 공식 문서는 그런 일이 없다.

- `overdue_days()`는 날짜의 뺄셈(4.6.9)으로 구한 `timedelta`의 `.days`를 쓴다. 음수가 되면 0을 돌려주어야 한다. `max()`를 쓰면 한 줄로 쓸 수 있다.

- `loan_lines()`에서 `loans.items()`를 정렬할 때 `key`에 람다를 쓴다. 기한이 같으면 도서 코드 순이라는 조건은 튜플 키 `(기한, 코드)`로 해결된다. 연체 목록은 연체일수 내림차순이므로 `-overdue_days(...)`를 키로 쓰거나 `reverse=True`를 쓴다. 연체일수가 같은 도서의 순서는 어떻게 되는지 4.5.5의 "안정 정렬"을 떠올려 보자.
- `main()`에서는 입력 한 줄을 `split()`한 뒤 첫 단어가 명령, 나머지가 인자다. `command, *args = words`(3.3.3)를 쓰면 편리하다. 각 명령은 인자 개수를 확인한 뒤 알맞은 함수를 호출하고 결과를 출력하기만 한다. **`main()`에는 계산이 거의 없고, 계산은 모두 위의 함수들이 한다**는 점을 의식하며 작성하자.
- `날짜 N` 명령은 `main()` 안의 지역 변수 `today`에 새 날짜를 할당한다. `today`는 `main()`의 지역 변수이므로 `global`이 필요 없다.

## 정리

| 항목 | 핵심 |
|---|---|
| 함수 | 코드 덩어리에 이름을 붙인 것. 반복을 없애고, 고칠 곳을 한 군데로 모으고, 일에 이름을 붙인다 |
| 정의와 호출 | `def 이름(매개변수):`로 정의(실행은 안 함), `이름(인자)`로 호출. 괄호가 없으면 함수 그 자체. 정의가 호출보다 먼저 실행되어야 한다 |
| 매개변수와 인자 | 정의의 이름이 매개변수, 호출할 때 넘기는 값이 인자. 호출하면 매개변수 이름표를 인자 객체에 붙인다 |
| `return` | 값을 돌려주고 함수를 즉시 끝낸다. 계산하는 함수는 출력하지 말고 돌려준다. `return a, b`는 튜플 하나 |
| `None` 반환 | `return`이 없거나 값 없이 `return`하면 `None`. 값을 돌려주는 함수는 모든 경로가 `return`으로 끝나는지 확인 |
| 독스트링 | 함수 본문 첫 줄의 `"""..."""`. 첫 줄에 한 문장 요약. `help()`와 VS Code 말풍선에 나온다 |
| 트레이스백 | 위에서 아래로 호출 순서. 마지막 `File` 줄이 오류가 난 곳, 원인은 그 위쪽에 있을 수도 있다 |
| 디버거 | `F11` 함수 안으로, `Shift + F11` 함수 밖으로, 호출 스택으로 위치 확인 |
| 위치·키워드 인자 | 위치는 순서로, 키워드(`이름=값`)는 이름으로 짝짓는다. 위치 인자를 먼저 쓴다. 의미가 안 보이는 값은 키워드로 |
| 기본값 | `def f(a, b=1)`. 위치로 전달할 수 있는 매개변수에서는 기본값 있는 매개변수를 뒤에 둔다. 기본값은 **정의할 때 한 번** 계산된다 |
| 가변 기본값 | `def f(x=[])`는 모든 호출이 같은 리스트를 공유하는 버그. `x=None` + `if x is None: x = []` |
| `*args` / `**kwargs` | 남는 위치 인자를 튜플로 / 남는 키워드 인자를 딕셔너리로 모은다. 호출할 때 `*`, `**`는 풀어 넣기 |
| 함수 정의 읽기 | `/` 앞은 위치로만, `*` 뒤는 키워드로만. `[...]`는 생략 가능 |
| 지역·전역 | 함수 안에서 만든 이름은 지역(호출마다 새로, 끝나면 사라짐). 이름은 지역 → 전역 → 내장 순으로 찾는다 |
| 할당하면 지역 | 함수 안 어디서든 할당하는 이름은 함수 전체에서 지역 변수. 그래서 `count += 1`은 `UnboundLocalError` |
| `global` | 피한다. 필요한 값은 인자로 받고 결과는 `return`. 전역 상수를 읽는 것은 괜찮다 |
| 가변 객체 인자 | 함수 안에서 **고치면** 호출한 쪽에 보인다. 매개변수에 **새 객체를 할당**하면 보이지 않는다 |
| 함수 설계 | 원본을 바꾸는 함수(`sort` 방식) 또는 새 객체를 돌려주는 함수(`sorted` 방식). 모르겠으면 새 객체를 돌려준다 |
| 함수 객체 | 함수도 객체. 변수에 담고(`f = greet`), 딕셔너리에 넣고, 인자로 넘긴다(괄호 없이!) |
| 람다 | `lambda x: x * 2`. 식 하나, `return` 없음. 다른 함수에 넘길 짧은 함수에만. 이름 붙일 거면 `def` |
| 내장 함수 | `len`, `sum`, `min`/`max`(빈 묶음은 `default=`), `isinstance(x, (int, float))`. 내장 이름을 변수로 덮어쓰지 않는다 |
| `help()` / `dir()` | 함수 정의와 설명 읽기 / 쓸 수 있는 이름 목록. 밑줄 두 개 이름은 건너뛴다 |
| `key` | `sorted`, `sort`, `min`, `max`에 비교 기준 함수를 넘긴다. 여러 기준은 튜플, 반대 방향은 `-`. 안정 정렬 |
| `map` / `filter` | 각각에 적용 / 조건에 맞는 것만. 결과는 한 번만 꺼낼 수 있다. `list()`로 감싸 확인. `list(map(int, s.split()))` |
| `import` | `import math` → `math.sqrt()`, `from math import sqrt` → `sqrt()`, `import datetime as dt`. 파일 맨 위에, `import *`는 금지 |
| 파일 이름 | `random.py`, `math.py`처럼 표준 모듈과 같은 이름으로 짓지 않는다 |
| `math` | `sqrt`, `ceil`(올림), `floor`(내림), `isclose`, `pi` |
| `random` | `randint(a, b)`(b 포함), `choice`, `sample`(새 리스트), `shuffle`(원본, `None`), `seed`(재현) |
| `datetime` | `date.today()`, `datetime.now()`, `date(y, m, d)`, `+ timedelta(days=...)`, 날짜끼리 빼기 → `.days`, `strftime`, `fromisoformat`, `strptime` |
| 공식 문서 | `docs.python.org/ko/3/library/`. 함수 정의 → 설명 → 버전 표시 → 예제 순으로 읽는다. AI의 답은 공식 문서로 확인 |
