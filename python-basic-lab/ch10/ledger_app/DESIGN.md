# 설계 노트 — 가계부 요약

## 목적과 범위

한 달 동안의 수입과 지출을 적은 CSV 파일을 받아 수입·지출·잔액과 지출 분류별 합계를
보여 주고, 분류별 합계를 CSV 파일로 저장한다. 잘못 적은 줄이 있으면 어느 줄이 왜
잘못되었는지 알려 주고 요약은 만들지 않는다.

하지 않는 것: 거래 추가·수정(파일은 엑셀이나 편집기로 고친다), 여러 달 비교, 예산,
그래프, 대화형 명령.

## 구조

| 층 | 모듈 | 하는 일 | 가져오는 것 |
|---|---|---|---|
| 3 | `main.py` | 시작. rich가 없을 때 안내 | cli |
| 2 | `ledger/cli.py` | 명령행 인자, 화면 출력, 결과 파일 이름, 종료 코드 | core, storage, models, rich |
| 1 | `ledger/core.py` | 요약 계산 | models |
| 1 | `ledger/storage.py` | CSV 읽기·검사·쓰기, DataFileError | models |
| 0 | `ledger/models.py` | 데이터의 모양과 가계부 규칙 | (없음) |

규칙
- 아래층은 위층을 가져오지 않는다. core와 storage는 서로를 가져오지 않는다.
- rich는 cli에서만 가져온다. core는 파일(csv, pathlib)과 화면을 모른다.
- sys.exit()는 cli.main()에서만 부른다. 아래층은 예외만 일으킨다.

## 주요 클래스와 함수

| 이름 | 하는 일 |
|---|---|
| `models.Transaction` | 가계부 규칙에 맞는 거래 한 건. 만들 때 자료형과 구분·분류·금액을 검사한다 |
| `models.Summary` | 요약 결과. 잔액(`balance`)과 비율(`share()`)을 계산해 준다 |
| `core.summarize()` | Transaction의 리스트 → Summary. 빈 리스트는 ValueError |
| `storage.load_transactions()` | CSV 경로 → Transaction의 리스트. CSV 문법 오류는 바로, 값 오류는 모두 모아 DataFileError |
| `storage.parse_row()` | CSV 한 줄 → Transaction. 칸 수, 날짜·금액 형식(쉼표 위치 포함)을 검사하고 공백을 정리 |
| `storage.write_summary()` | Summary를 받은 경로에 CSV로 저장 |
| `cli.main()` | 흐름: 인자 확인 → 읽기 → 요약 → 출력 → 저장. 실패하면 종료 코드 1·2 |

## 실패 처리

상황별 메시지와 종료 코드는 README.md의 "입력에 따른 동작" 표에 있다. 원칙은 다음과 같다.
- 결과는 표준 출력, 문제는 표준 오류로 보낸다.
- 값이 잘못된 줄이 있으면 모두 모아 줄 번호와 함께 알리고 멈춘다. 화면에는 앞의 10건
  (cli.MAX_PROBLEMS)과 나머지 건수를 보여 준다. 요약 파일은 쓰지 않는다.
- CSV 문법이 깨졌으면(큰따옴표의 짝) 그 자리에서 대략의 줄 번호와 함께 알리고 멈춘다.
- 프로그래머의 실수(예: summarize()에 빈 리스트)는 트레이스백으로 드러낸다.

## 결정과 이유

1. **수입·지출을 kind 열로 구분한다.** 대안은 지출을 음수로 쓰는 것. 손으로 쓰는
   파일에서는 `-`를 빠뜨리기 쉽고 빠뜨려도 티가 나지 않는다. 글자로 쓰면 오타가 검사에 걸린다.
2. **잘못된 줄은 모두 모아 알리고 멈춘다.** 첫 오류에서 멈추면 잘못이 여러 개일 때 여러 번
   실행해야 한다. 건너뛰면 합계가 조용히 틀린다. 요약에서 틀린 합계는 합계가 없는 것보다 나쁘다.
3. **CSV 문법 오류는 줄마다 모으지 않고 그 자리에서 멈춘다.** DictReader에 strict=True를
   준다. 기본 설정은 `"9500"0`을 95000으로 읽는 등 깨진 줄도 조용히 읽어 낸다. 따옴표가
   깨지면 어디서 칸이 나뉘는지 알 수 없으므로, 그 뒤를 계속 검사해도 믿을 수 없다.
4. **금액의 쉼표는 세 자리마다만 허용한다.** 쉼표만 지우고 int()에 넘기면 `12,00`이
   1200이 된다. 읽은 정수를 다시 쉼표 넣은 모양으로 바꿔 원문과 비교한다.
5. **0바이트 파일은 오류, 첫 줄만 있는 파일은 정상(거래 0건)이다.** 첫 줄만 있는 파일은
   올바른 형식의 빈 가계부이고, 0바이트 파일은 엉뚱한 파일이거나 망가진 파일일 가능성이 높다.
6. **검사를 두 곳에 나눈다.** 문자열 → 값(날짜·정수 형식, 칸 수)과 공백 정리는 파일에 관한
   지식이므로 storage가, 값이 규칙에 맞는지(자료형, 구분, 분류, 금액 ≥ 1)는
   Transaction.__post_init__이 한다. 타입 힌트는 실행 중에 검사되지 않으므로 자료형도 직접
   검사한다. 입력이 CSV가 아니게 되어도 규칙 검사는 그대로 쓸 수 있다. 단, 공백 정리 같은
   값 다듬기는 Transaction이 하지 않으므로 새 입구를 만들면 거기서도 해야 한다.
7. **요약은 함수(summarize)로 만든다.** 상태가 없고 한 번 계산하면 끝나는 일이다. 클래스로
   감쌀 이유가 없다.
8. **errors.py를 두지 않는다.** 예외가 DataFileError 하나이고 storage만 일으킨다.
9. **결과 파일은 입력 파일 옆에 `이름_summary.csv`로 저장하고, 이름은 cli가 정한다.**
   storage.write_summary()는 받은 경로에 쓰기만 한다.
10. **실행 방법은 `python main.py 파일` 하나다.** `python -m ledger`는 필요해지면 더한다.

## 바뀔 때 고칠 곳

| 바뀌는 것 | 고칠 곳 |
|---|---|
| 금액에 `원`을 붙여 써도 받는다 | storage.parse_amount() |
| 요약 파일을 reports 폴더에 저장 | cli.summary_path() |
| 표 대신 그래프 | cli |
| JSON 입력도 받는다 | storage(읽기 함수 추가), cli(고르기) |
| 수입도 분류별로 | models.Summary, core.summarize(), cli, storage.write_summary() |
| 구분에 '이체'를 더한다 | models.KINDS, core.summarize() (아래 한계 1 참고) |

## 한계

1. core.summarize()는 수입이 아니면 모두 지출로 센다. KINDS에 구분을 더할 때는
   summarize()도 함께 고쳐야 한다.
2. 파일 대신 폴더를 넘기면 트레이스백이 난다(macOS IsADirectoryError, Windows PermissionError).
3. 지출이 없는 파일이면 분류별 표에 합계 줄(0원, 0.0%)만 보인다.
4. check_samples.py는 storage와 core의 결과만 비교한다. 화면 출력과 요약 파일은 확인하지 않는다.
