# 1장. 시작하기

[파이썬 기초](README.md) 과정의 첫 장이다. 이 장에서는 파이썬 코드를 쓰기 전에 필요한 세 가지를 익힌다.

- **터미널 최소 조작** — 터미널을 열고, 지금 어느 폴더에 있는지 확인하고, 원하는 폴더로 이동하고, 명령을 실행한 결과를 읽는다.
- **파이썬 설치와 실행** — 파이썬을 설치하고, 대화형 셸과 스크립트 파일 두 가지 방식으로 실행하고, VS Code에서 실행·디버깅한다.
- **첫 프로그램** — `print()`와 `input()`으로 간단한 프로그램을 만들고, 주석과 들여쓰기 규칙을 익히고, 오류 메시지를 읽는다.

## 학습 목표

이 장을 마치면 다음을 할 수 있다.

- 터미널에서 현재 위치를 확인하고 실습 폴더로 이동할 수 있다.
- 설치된 파이썬의 버전을 확인하고, `.py` 파일을 터미널과 VS Code 양쪽에서 실행할 수 있다.
- 키보드로 값을 입력받아 화면에 출력하는 프로그램을 작성할 수 있다.
- 오류 메시지에서 "어느 파일의 몇 번째 줄에서, 어떤 종류의 오류가" 났는지 찾아낼 수 있다.

## 실습 환경

이 교재는 macOS와 Windows 11을 기준으로 설명한다. 두 환경에서 명령이 다를 때는 다음과 같이 나누어 표기한다.

- **macOS** — 기본 "터미널" 앱(zsh)
- **Windows** — "Windows PowerShell" 또는 "터미널" 앱(PowerShell)

VS Code 내장 터미널도 각 OS의 기본 셸을 사용하므로 같은 방식으로 따라 하면 된다.

> **1단계를 마친 사람에게**
> 1단계 바이브 코딩에서 AI 도구가 터미널 명령을 대신 실행해 주었을 것이다. 이번 장에서는 그 명령을 직접 입력한다. AI가 하던 일을 한 번 손으로 해 보면, 이후 AI가 무엇을 하는지 훨씬 잘 보인다.

## 1.1 터미널 최소 조작

### 1.1.1 터미널이란

터미널(terminal)은 마우스로 클릭하는 대신 **문자로 명령을 입력해서** 컴퓨터를 조작하는 프로그램이다. 파이썬 프로그램을 실행하는 가장 기본적인 방법이 터미널에서 명령을 입력하는 것이므로, 최소한의 조작은 알아야 한다.

이 절에서 다루는 것은 딱 네 가지다.

| 하고 싶은 일 | macOS | Windows |
|---|---|---|
| 지금 어느 폴더에 있는지 확인 | `pwd` | `pwd` |
| 폴더 안의 내용 보기 | `ls` | `dir` 또는 `ls` |
| 다른 폴더로 이동 | `cd 폴더이름` | `cd 폴더이름` |
| 새 폴더 만들기 | `mkdir 폴더이름` | `mkdir 폴더이름` |

Windows PowerShell에서는 `pwd`, `ls`, `cd`, `mkdir`가 모두 동작한다. 이 교재에서는 두 OS에서 똑같이 쓸 수 있는 이 명령들을 사용한다. (`dir`는 `ls`와 같은 역할이다.)

본격적인 터미널 사용법은 다음 과정 "개발 도구"에서 다룬다. 여기서는 파이썬 실습에 필요한 만큼만 익힌다.

### 1.1.2 터미널 열기

**macOS**

- `Cmd + Space`로 Spotlight를 열고 `터미널`(또는 `terminal`)을 입력한 뒤 Enter
- 또는 Finder → 응용 프로그램 → 유틸리티 → 터미널

**Windows**

- `Win` 키를 누르고 `powershell`을 입력한 뒤 Enter
- 또는 시작 메뉴에서 "터미널"(Windows Terminal) 실행 — 기본 탭이 PowerShell이다

**VS Code 내장 터미널** (두 OS 공통)

- 메뉴 보기(View) → 터미널(Terminal)
- 또는 단축키: macOS ``Ctrl + ` ``, Windows ``Ctrl + ` `` (백틱 키는 보통 `1` 왼쪽, `Tab` 위에 있다)

터미널을 열면 아래와 비슷한 한 줄이 나타난다. 이것을 **프롬프트**(prompt)라고 하며, "명령을 입력할 준비가 되었다"는 뜻이다.

```
# macOS
jinyoung@MacBook ~ %

# Windows
PS C:\Users\jinyoung>
```

프롬프트 모양은 OS와 설정에 따라 다르지만, 공통적으로 **현재 위치(폴더)** 가 표시된다. macOS의 `~`와 Windows의 `C:\Users\jinyoung`은 모두 "내 홈 폴더"를 뜻한다.

> 이 교재에서 명령 예시는 프롬프트를 생략하고 입력할 명령만 적는다. 결과는 바로 아래에 적는다.

### 1.1.3 현재 위치 확인: `pwd`

터미널은 항상 "어떤 폴더 안에서" 동작한다. 이 폴더를 **현재 디렉터리**(current directory, 작업 디렉터리)라고 한다. 디렉터리(directory)는 폴더(folder)의 다른 이름이다.

`pwd`(print working directory)를 입력하면 현재 디렉터리의 전체 경로가 출력된다.

```
pwd
```

```
# macOS
/Users/jinyoung

# Windows
Path
----
C:\Users\jinyoung
```

**왜 중요한가?** 나중에 `python hello.py`라고 실행하면 터미널은 **현재 디렉터리에서** `hello.py` 파일을 찾는다. 파일은 분명히 만들었는데 "파일을 찾을 수 없다"는 오류가 나는 경우, 대부분 현재 디렉터리가 파일이 있는 곳과 다르기 때문이다.

### 1.1.4 폴더 내용 보기: `ls`

```
ls
```

```
Desktop     Documents   Downloads   Music       Pictures
```

현재 디렉터리에 있는 파일과 폴더의 이름이 출력된다. Windows PowerShell에서는 `ls`가 표 형태로 더 자세히 보여 준다.

### 1.1.5 폴더 이동: `cd`

`cd`(change directory) 뒤에 이동할 폴더 이름을 적는다.

```
cd Documents
pwd
```

```
/Users/jinyoung/Documents
```

자주 쓰는 이동 방법 세 가지:

| 명령 | 의미 |
|---|---|
| `cd 폴더이름` | 현재 디렉터리 안에 있는 그 폴더로 이동 |
| `cd ..` | 한 단계 위(부모) 폴더로 이동 |
| `cd ~` | 홈 폴더로 이동 (Windows에서도 `cd ~`가 동작한다) |

**이름에 공백이 있는 폴더**는 따옴표로 감싼다.

```
cd "My Project"
```

**Tab 자동 완성**: 폴더 이름의 앞 몇 글자만 치고 `Tab` 키를 누르면 나머지가 자동으로 완성된다. 오타를 줄이는 가장 좋은 방법이므로 처음부터 습관을 들이자.

### 1.1.6 경로 지정

경로(path)는 파일이나 폴더의 위치를 글자로 표현한 것이다. 두 종류가 있다.

- **절대 경로** — 맨 위(루트)부터 전부 적는다. 어디서 실행해도 같은 곳을 가리킨다.
  - macOS: `/Users/jinyoung/python-lab/ch01/hello.py`
  - Windows: `C:\Users\jinyoung\python-lab\ch01\hello.py`
- **상대 경로** — 현재 디렉터리를 기준으로 적는다. 현재 디렉터리가 바뀌면 가리키는 곳도 바뀐다.
  - `hello.py` — 현재 디렉터리에 있는 hello.py
  - `ch01/hello.py` — 현재 디렉터리 안의 ch01 폴더 안에 있는 hello.py
  - `../hello.py` — 한 단계 위 폴더에 있는 hello.py

경로 구분자는 macOS가 `/`, Windows가 `\`이다. 다만 Windows PowerShell에서도 `/`를 쓸 수 있으므로, 이 교재의 상대 경로 예시는 `/`로 통일한다.

### 1.1.7 명령 실행과 결과 읽기

명령을 입력하고 Enter를 누르면 터미널이 명령을 실행하고 결과를 출력한 뒤, 다시 프롬프트를 보여 준다. 결과를 읽을 때 세 가지 경우를 구분하자.

**1) 성공하고 결과가 출력된 경우**

```
ls
```
```
hello.py
```

**2) 성공했지만 아무것도 출력되지 않은 경우**

```
cd ch01
```

`cd`, `mkdir`처럼 "무언가를 바꾸는" 명령은 성공하면 아무 말도 하지 않는다. 오류 메시지가 없으면 성공한 것이다. 확인하고 싶으면 `pwd`나 `ls`를 이어서 실행한다.

**3) 오류가 난 경우**

```
cd ch99
```
```
# macOS
cd: no such file or directory: ch99

# Windows
Set-Location : 'C:\Users\jinyoung\ch99' 경로는 존재하지 않으므로 찾을 수 없습니다.
```

오류 메시지는 대부분 "무엇이 문제인지"를 그대로 말해 준다. `no such file or directory` / `경로는 존재하지 않으므로`는 "그런 폴더가 없다"는 뜻이다. 폴더 이름의 오타이거나, 현재 디렉터리가 생각과 다른 곳인 경우가 대부분이다.

처음 보는 오류를 만나면 **메시지를 그대로 복사해서** 검색하거나 AI에게 물어보면 된다. 1단계에서 했던 것과 같다. 단, 이번에는 메시지를 먼저 한 번 읽고 나서 묻자.

### 실습 1-1. 실습 폴더 만들기

이 과정의 실습 파일을 모아 둘 폴더를 만든다. 홈 폴더 아래 `python-lab`, 그 안에 장별 폴더(`ch01`, `ch02`, …)를 둔다.

1. 터미널을 연다.
2. 홈 폴더로 이동하고 위치를 확인한다.
   ```
   cd ~
   pwd
   ```
3. 실습 폴더를 만들고 들어간다.
   ```
   mkdir python-lab
   cd python-lab
   mkdir ch01
   cd ch01
   pwd
   ```
4. `pwd` 결과가 아래처럼 나오면 성공이다.
   ```
   # macOS
   /Users/본인계정/python-lab/ch01

   # Windows
   C:\Users\본인계정\python-lab\ch01
   ```
5. 한 단계 위로 올라갔다가 다시 들어와 본다.
   ```
   cd ..
   ls
   cd ch01
   ```

> 앞으로 "실습 폴더"라고 하면 이 `python-lab` 폴더를 말한다. 터미널을 새로 열 때마다 `cd ~/python-lab/ch01`처럼 해당 장의 폴더로 이동한 뒤 실습을 시작한다.

## 1.2 파이썬 설치와 실행

### 1.2.1 파이썬 설치

이 교재는 **파이썬 3.12 이상**을 기준으로 한다. 설치 파일은 공식 사이트에서 받는다.

- https://www.python.org/downloads/

페이지 상단의 **Download Python 3.x.x** 버튼이 현재 사용 중인 OS용 최신 안정 버전이다. 특별한 이유가 없으면 그 버튼을 누르면 된다.

**macOS**

1. 내려받은 `.pkg` 파일을 더블클릭하고 "계속"을 눌러 설치한다.
2. 설치가 끝나면 Finder의 응용 프로그램 폴더에 `Python 3.x` 폴더가 생긴다. 이 폴더는 열어 볼 필요 없다.
3. **터미널을 새로 연다.** (설치 전에 열어 둔 터미널은 새 파이썬을 모를 수 있다.)

> macOS에는 `python3`라는 명령이 미리 있을 수 있지만, 이것은 Xcode 개발 도구에 딸린 것이라 버전이 오래되었거나 처음 실행 시 추가 설치를 요구한다. 공식 사이트에서 설치하는 것을 권장한다.

**Windows**

1. 내려받은 `.exe` 파일을 실행한다.
2. 첫 화면 아래쪽의 **"Add python.exe to PATH"** 체크박스를 **반드시 체크**한다. 이것을 빼먹으면 터미널에서 `python`을 찾지 못한다.
3. "Install Now"를 누른다.
4. 설치가 끝나면 **터미널을 새로 연다.**

> Windows에서 파이썬을 설치하지 않은 상태로 `python`을 입력하면 Microsoft Store가 열린다. Store에서 설치해도 동작은 하지만, 이 교재는 공식 사이트 설치를 기준으로 한다. 이미 Store 버전을 설치했다면 그대로 써도 된다.

### 1.2.2 버전 확인

설치가 제대로 되었는지 터미널에서 확인한다.

```
# macOS
python3 --version

# Windows
python --version
```

```
Python 3.13.2
```

버전 번호가 출력되면 성공이다. (숫자는 설치한 버전에 따라 다르다.)

**명령 이름에 대하여**: macOS에서는 `python3`, Windows에서는 `python`이 기본 명령 이름이다. 이 교재의 예시는 **`python`으로 통일**해서 적는다. macOS 사용자는 `python`을 `python3`로 바꿔 읽으면 된다. (macOS에서 `python`도 동작하도록 설정하는 방법은 "가상환경" 장에서 다룬다. 가상환경을 켜면 두 OS 모두 `python`으로 통일된다.)

**버전이 출력되지 않는 경우**

- `command not found: python` (macOS) / `'python' 용어가 … 인식되지 않습니다` (Windows): 터미널이 파이썬을 찾지 못한 것이다. 터미널을 새로 열어 다시 시도한다. Windows라면 설치 시 "Add python.exe to PATH"를 체크했는지 확인하고, 안 했다면 설치 파일을 다시 실행해 "Modify" → "Add Python to environment variables"를 체크한다.
- 버전이 너무 낮게 나오는 경우(예: `Python 2.7.x`): 다른 파이썬이 먼저 잡힌 것이다. macOS에서 `python3 --version`으로 다시 확인한다.

### 1.2.3 대화형 셸(REPL)

파이썬을 실행하는 첫 번째 방법은 **대화형 셸**이다. 한 줄 입력하면 바로 결과를 보여 준다. REPL(Read-Eval-Print Loop: 읽고, 계산하고, 출력하기를 반복)이라고도 부른다.

터미널에서 아무 인자 없이 `python`을 실행한다.

```
python
```

```
Python 3.13.2 (main, ...) on darwin
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

프롬프트가 `>>>`로 바뀌었다. 지금부터 입력하는 것은 터미널 명령이 아니라 **파이썬 코드**다.

```python
>>> 1 + 2
3
>>> 7 * 6
42
>>> "안녕" + "하세요"
'안녕하세요'
>>> print("Hello, Python!")
Hello, Python!
```

대화형 셸은 "이 코드가 어떻게 동작하지?"를 바로 확인하는 데 매우 유용하다. 앞으로 새 문법을 배울 때마다 여기서 한 줄씩 실험해 보자.

대화형 셸을 끝내려면 다음 중 하나를 입력한다.

```python
>>> exit()
```

또는 macOS `Ctrl + D`, Windows `Ctrl + Z` 후 Enter. 프롬프트가 다시 터미널 프롬프트(`%` 또는 `>`)로 돌아오면 빠져나온 것이다.

> **자주 하는 실수**: 대화형 셸(`>>>`) 안에서 `python hello.py` 같은 **터미널 명령**을 입력하면 `SyntaxError`가 난다. 반대로 터미널(`%`, `>`)에서 `print("hi")` 같은 **파이썬 코드**를 입력하면 `command not found`가 난다. 지금 프롬프트가 `>>>`인지 아닌지 항상 확인하자.

### 1.2.4 스크립트 파일 실행

두 번째 방법은 코드를 **파일에 저장해 두고** 한 번에 실행하는 것이다. 실제 프로그램은 이 방식으로 만든다. 파이썬 코드 파일은 확장자가 `.py`이며, **스크립트**(script)라고 부른다.

**1) 파일 만들기**

VS Code를 열고 실습 폴더 `python-lab/ch01`에 `hello.py` 파일을 만든다. (VS Code 사용법은 다음 절에서 자세히 다룬다. 지금은 파일 → 폴더 열기로 `python-lab`을 연 뒤, `ch01` 폴더에서 새 파일을 만들면 된다.)

```python
# hello.py
print("Hello, Python!")
print("첫 번째 스크립트입니다.")
```

저장한다(`Cmd + S` / `Ctrl + S`).

**2) 실행하기**

터미널에서 파일이 있는 폴더로 이동한 뒤 `python 파일이름`을 실행한다.

```
cd ~/python-lab/ch01
python hello.py
```

```
Hello, Python!
첫 번째 스크립트입니다.
```

**실행 흐름**: `python hello.py`는 "파이썬 인터프리터야, hello.py 파일을 읽어서 위에서 아래로 한 줄씩 실행해 줘"라는 뜻이다. 대화형 셸과 달리 결과는 `print()`로 출력한 것만 보인다. (대화형 셸에서는 `1 + 2`만 쳐도 `3`이 보였지만, 스크립트에서는 `print(1 + 2)`라고 써야 보인다.)

**3) 파일을 찾지 못할 때**

```
python hello.py
```
```

```

가장 흔한 오류다. 메시지의 경로를 보면 터미널이 `/Users/jinyoung/`에서 파일을 찾고 있다. 즉 **현재 디렉터리가 `ch01`이 아니다.** `pwd`로 위치를 확인하고 `cd`로 이동한 뒤 다시 실행한다. 또는 현재 위치에서 상대 경로로 지정해도 된다.

```
python python-lab/ch01/hello.py
```

### 1.2.5 VS Code에서 파이썬 실행

VS Code는 파일 편집, 터미널, 실행, 디버깅을 한 창에서 할 수 있는 편집기다. 1단계에서 이미 써 봤다면 파이썬 확장만 추가하면 된다.

**1) 설치**

- https://code.visualstudio.com/ 에서 내려받아 설치한다.

**2) Python 확장과 Ruff 확장 설치**

1. 왼쪽 세로 막대의 확장(Extensions) 아이콘(네모 블록 모양)을 클릭하거나 `Cmd + Shift + X` / `Ctrl + Shift + X`.
2. 검색창에 `Python`을 입력한다.
3. Microsoft가 만든 **Python** 확장을 설치한다. (Pylance, Python Debugger가 함께 설치된다.)
4. 검색창에 `Ruff`를 입력하고, Astral Software가 만든 **Ruff** 확장(ID: `charliermarsh.ruff`)을 설치한다.

**Ruff**는 파이썬 코드의 모양을 자동으로 정리해 주는 **포매터**(formatter)이자, 실수나 문제가 될 만한 코드를 찾아 알려 주는 **린터**(linter)다. 띄어쓰기, 따옴표, 줄바꿈 같은 코드 모양을 사람이 일일이 신경 쓰지 않아도 저장할 때마다 일정한 규칙으로 맞춰 준다. 확장 안에 Ruff 프로그램이 들어 있으므로 따로 설치할 것은 없다.

**3) 편집기 설정(settings.json)**

1.3.4에서 배우겠지만 파이썬은 **들여쓰기가 문법**이다. 들여쓰기가 공백 4칸으로 일정하게 들어가고 탭과 공백이 섞이지 않도록, 그리고 파일을 저장할 때 Ruff가 코드 모양을 자동으로 정리하도록 편집기를 미리 설정해 두자.

VS Code의 설정은 `settings.json` 파일에 저장된다. 설정 화면(GUI)에서 하나씩 바꿀 수도 있지만, 파일을 직접 열어 한 번에 붙여 넣는 편이 빠르고 정확하다.

1. `Cmd + Shift + P` / `Ctrl + Shift + P`로 명령 팔레트를 연다.
2. `settings json`을 입력하고 **Preferences: Open User Settings (JSON)**(한국어 UI: **기본 설정: 사용자 설정 열기(JSON)**)을 선택한다.
3. 열린 `settings.json`에 아래 내용을 추가하고 저장한다.

```jsonc
{
  // 모든 파일에 적용
  "files.encoding": "utf8",              // 파일 읽기·쓰기의 기본 인코딩
  "editor.renderWhitespace": "boundary", // 단어 사이의 공백 한 개를 제외한 공백 문자 표시

  // 파이썬 파일(.py)에만 적용
  "[python]": {
    "editor.tabSize": 4,                  // 들여쓰기 한 단계 = 4칸
    "editor.insertSpaces": true,          // Tab 키를 누르면 공백 4개 입력
    "editor.detectIndentation": false,    // 파일 내용으로 들여쓰기를 추측하지 않음
    "editor.defaultFormatter": "charliermarsh.ruff", // Ruff를 기본 포매터로 사용
    "editor.formatOnSave": true,          // 저장할 때 포매팅 적용
    "editor.rulers": [72, 88],            // 주석·docstring 참고선, 코드 참고선
    "editor.codeActionsOnSave": {
      "source.fixAll.ruff": "explicit",          // 저장할 때 자동 수정 가능한 문제 고치기
      "source.organizeImports.ruff": "explicit"  // 저장할 때 import 문 정리
    },
    "files.trimTrailingWhitespace": true, // 저장할 때 줄 끝 공백 제거
    "files.insertFinalNewline": true      // 저장할 때 파일 마지막에 줄바꿈 문자 보장
  }
}
```

각 설정의 의미는 다음과 같다.

**들여쓰기와 공백 표시**

| 설정 | 값 | 이유 |
|---|---|---|
| `files.encoding` | `"utf8"` | 한글이 들어간 파일을 어느 OS에서 열어도 깨지지 않게 한다. VS Code의 기본값이지만 명시해 둔다. (인코딩은 7장 "파일 입출력"에서 다룬다) |
| `editor.renderWhitespace` | `"boundary"` | 줄 앞의 공백은 점(`·`), 탭은 화살표(`→`)로 보여 준다. 탭과 공백이 섞였는지 눈으로 확인할 수 있다 |
| `editor.tabSize` | `4` | 파이썬 공식 스타일 가이드(PEP 8)가 권장하는 들여쓰기 크기다 |
| `editor.insertSpaces` | `true` | `Tab` 키를 눌러도 탭 문자 대신 공백 4개가 들어간다 |
| `editor.detectIndentation` | `false` | 이 값이 `true`(기본값)이면 VS Code가 파일 내용을 보고 들여쓰기 방식을 추측한다. 인터넷에서 복사한 2칸 들여쓰기 파일을 열면 그 파일만 2칸이 되는 일이 생기므로 끈다 |
| `files.trimTrailingWhitespace` | `true` | 눈에 보이지 않는 줄 끝 공백을 저장할 때 지운다 |
| `files.insertFinalNewline` | `true` | 파일의 마지막 줄 뒤에 줄바꿈을 넣는다. 많은 도구가 이 형식을 기대한다 |

**Ruff 포매터와 저장 시 자동 정리**

| 설정 | 값 | 이유 |
|---|---|---|
| `editor.defaultFormatter` | `"charliermarsh.ruff"` | 파이썬 파일을 정리할 때 Ruff 확장을 쓴다. 값은 확장의 ID다 |
| `editor.formatOnSave` | `true` | 저장(`Cmd + S` / `Ctrl + S`)할 때마다 Ruff가 코드 모양을 정리한다 |
| `editor.rulers` | `[72, 88]` | 편집 영역에 세로 안내선 두 개를 표시한다. 88은 Ruff가 기본으로 쓰는 한 줄 최대 길이이고, 72는 PEP 8이 주석과 docstring(4장에서 배운다)에 권장하는 길이다 |
| `source.fixAll.ruff` | `"explicit"` | 저장할 때 Ruff가 자동으로 고칠 수 있는 문제를 고친다. 예를 들어 `import`해 놓고 쓰지 않는 모듈을 지운다 |
| `source.organizeImports.ruff` | `"explicit"` | 저장할 때 `import` 문을 정해진 순서로 정렬한다. (`import`는 4장 "모듈 가져다 쓰기"에서 배운다) |

`codeActionsOnSave`의 값 `"explicit"`는 "사용자가 직접 저장했을 때만" 실행하라는 뜻이다. 자동 저장(Auto Save) 기능이 켜져 있어도 입력 도중에 코드가 바뀌는 일이 없다.

`"[python]": { ... }`처럼 대괄호로 언어 이름을 감싼 블록 안의 설정은 **그 언어의 파일에만** 적용된다. 그래서 HTML이나 JSON 파일의 들여쓰기는 그대로 두고 파이썬 파일만 4칸으로 맞추고 Ruff로 정리할 수 있다.

**`settings.json`에 이미 내용이 있는 경우**

파일을 열었을 때 `{ }` 안에 다른 설정이 이미 들어 있을 수 있다. 이때는 전체를 덮어쓰지 말고, **바깥쪽 `{ }`는 그대로 둔 채 안쪽 줄만** 기존 설정 뒤에 붙여 넣는다. 각 설정 사이에는 쉼표(`,`)가 있어야 한다.

```jsonc
{
  "workbench.colorTheme": "Default Dark Modern",   // ← 기존 설정. 끝에 쉼표를 추가한다
  "files.encoding": "utf8",
  "editor.renderWhitespace": "boundary",
  "[python]": {
    ...
  }
}
```

이미 `"[python]"` 블록이 있다면 블록을 하나 더 만들지 말고 기존 블록 안에 설정을 합친다. 같은 설정이 두 번 나오면 뒤에 있는 것만 적용된다.

쉼표가 빠지거나 괄호가 맞지 않으면 해당 위치에 빨간 물결 밑줄이 생기고 설정이 적용되지 않는다. 저장한 뒤 빨간 밑줄이 없는지 확인하자. (`//`로 시작하는 주석은 VS Code의 `settings.json`에서만 허용되는 것이므로 그대로 둬도 된다.)

**설정 확인**

`ch01` 폴더에 `format_test.py`를 만들고, 아래 코드를 **모양 그대로** 입력한다. 띄어쓰기가 제멋대로이고 작은따옴표와 큰따옴표가 섞여 있다.

```python
name=input( '이름: ' )
print( "안녕하세요," ,name )
total=1+2*3
print('합계:',total)
```

저장(`Cmd + S` / `Ctrl + S`)하는 순간 코드가 다음과 같이 바뀌면 Ruff 설정이 제대로 된 것이다.

```python
name = input("이름: ")
print("안녕하세요,", name)
total = 1 + 2 * 3
print("합계:", total)
```

- `=`와 `+`, `*` 같은 연산자 앞뒤에 공백이 한 칸씩 들어간다.
- 괄호 안쪽의 불필요한 공백이 없어지고, 쉼표 뒤에는 공백이 한 칸 들어간다.
- 문자열 따옴표가 큰따옴표(`"`)로 통일된다.

실행 결과는 바뀌지 않는다. 포매터는 **코드의 모양만** 바꾸고 동작은 바꾸지 않는다.

이어서 다음도 확인한다.

- 창 오른쪽 아래 상태 표시줄에 **`Spaces: 4`**(한국어 UI: **`공백: 4`**)가 보인다.
- 아무 줄 맨 앞에서 `Tab` 키를 누르면 점 4개(`····`)가 표시된다. 공백 4개가 들어갔다는 뜻이다.
- 편집 영역 오른쪽에 세로 안내선 두 개(72칸, 88칸)가 보인다.

> **포매터가 고칠 수 없는 것**: 포매터는 코드를 먼저 읽고(해석하고) 나서 모양을 다시 쓴다. 그래서 괄호를 닫지 않았거나 들여쓰기가 틀린 것처럼 **문법 오류가 있는 코드는 정리하지 못하고 그대로 둔다.** 저장했는데 코드가 정리되지 않으면 문법 오류가 있는지 먼저 의심하자. 반대로 문법만 맞으면 탭으로 들여쓴 줄도 저장할 때 공백 4칸으로 바꿔 준다.

> **Ruff 린터의 밑줄**: Ruff는 저장하지 않아도 문제가 될 만한 코드 아래에 물결 밑줄을 그어 준다. 예를 들어 만든 적 없는 변수 이름을 쓰면 밑줄이 생기고, 마우스를 올리면 `Undefined name` 같은 설명이 나온다. Python 확장(Pylance)도 비슷한 밑줄을 표시한다. 밑줄은 실행 전에 실수를 알려 주는 힌트이므로, 밑줄이 보이면 마우스를 올려 설명을 읽는 습관을 들이자.

> **사용자 설정과 작업 영역 설정**: 여기서 연 것은 **사용자 설정**으로, 이 컴퓨터에서 VS Code로 여는 모든 폴더에 적용된다. 특정 프로젝트에만 적용하고 싶으면 그 프로젝트 폴더 안의 `.vscode/settings.json`(작업 영역 설정)에 쓰면 되며, 두 곳에 같은 설정이 있으면 작업 영역 설정이 우선한다. 이 과정에서는 사용자 설정만 쓴다.

**4) 폴더 열기**

- 파일(File) → 폴더 열기(Open Folder…) → `python-lab` 선택

VS Code는 "폴더" 단위로 작업한다. 파일 하나만 열지 말고 실습 폴더 전체를 열자. 왼쪽 탐색기에 `ch01` 폴더와 `hello.py`가 보인다.

**5) 인터프리터 선택**

`.py` 파일을 열면 창 **오른쪽 아래 상태 표시줄**에 `3.13.2` 같은 파이썬 버전이 표시된다. 이것이 VS Code가 사용할 파이썬(인터프리터)이다.

- 표시되지 않거나 다른 버전이면: `Cmd + Shift + P` / `Ctrl + Shift + P`로 명령 팔레트를 열고 `Python: Select Interpreter`를 입력한 뒤, 1.2.2에서 확인한 버전을 선택한다.

> 컴퓨터에 파이썬이 여러 개 설치되어 있으면 "터미널의 python"과 "VS Code가 선택한 python"이 다를 수 있다. 지금은 버전이 같은지만 확인하자. 이 문제는 "가상환경" 장에서 정식으로 다룬다.

**6) 실행**

`hello.py`를 연 상태에서 **오른쪽 위의 ▷(실행) 버튼**을 클릭한다. 아래쪽에 터미널 패널이 열리면서 결과가 출력된다.

```
/usr/local/bin/python3 /Users/jinyoung/python-lab/ch01/hello.py
Hello, Python!
첫 번째 스크립트입니다.
```

첫 줄을 보면 VS Code가 하는 일도 결국 터미널에서 `python 파일경로`를 실행하는 것임을 알 수 있다. 다만 **절대 경로**로 실행하기 때문에 현재 디렉터리가 어디든 상관없다.

**7) 디버깅**

디버깅(debugging)은 프로그램을 **한 줄씩 멈춰 가며** 실행해서 변수 값이 어떻게 바뀌는지 들여다보는 것이다. 코드가 왜 기대와 다르게 동작하는지 찾을 때 가장 강력한 도구다. 지금은 사용법만 익히고, 변수를 배운 뒤 본격적으로 쓴다.

`ch01` 폴더에 `debug_demo.py`를 만든다.

```python
# debug_demo.py
a = 10
b = 20
c = a + b
print(c)
```

1. **중단점 찍기**: 3번째 줄(`c = a + b`) 줄 번호 왼쪽의 빈 공간을 클릭한다. 빨간 점이 생긴다. "여기서 멈춰라"는 표시다.
2. **디버그 시작**: `F5`를 누른다. "디버그 구성 선택" 창이 뜨면 **Python File**을 고른다.
3. 프로그램이 3번째 줄에서 **멈춘다.** 왼쪽 "변수(Variables)" 패널에 `a = 10`, `b = 20`이 보인다. `c`는 아직 없다 — 그 줄이 아직 실행되지 않았기 때문이다.
4. 위쪽에 나타난 디버그 도구 모음에서 **단계 실행(Step Over, `F10`)** 을 누른다. 3번째 줄이 실행되고 4번째 줄에서 멈춘다. 변수 패널에 `c = 30`이 추가된다.
5. **계속(Continue, `F5`)** 을 누르면 끝까지 실행되고 터미널에 `30`이 출력된다.

디버그 도구 모음의 버튼은 지금 세 개만 기억하면 된다.

| 버튼 | 단축키 | 의미 |
|---|---|---|

## 1.3 첫 프로그램

### 1.3.1 `print()`로 출력

`print()`는 괄호 안의 값을 화면에 출력한다. 가장 먼저 배우고, 가장 많이 쓰는 함수다.

```python
print("Hello, Python!")
print(42)
print(3.14)
print(1 + 2)
```

```
Hello, Python!
42
3.14
3
```

**문자열은 따옴표로 감싼다.** `"Hello"`처럼 따옴표 안에 있는 것은 글자 그대로 출력되고, `1 + 2`처럼 따옴표가 없으면 계산한 결과가 출력된다. 큰따옴표(`"`)와 작은따옴표(`'`) 둘 다 쓸 수 있지만, 여는 것과 닫는 것이 같아야 한다.

```python
print("안녕하세요")
print('안녕하세요')
print("It's OK")        # 문자열 안에 '가 있으면 "로 감싼다
```

> 1.2.5에서 Ruff 포매터를 설정했다면, 이 코드를 저장하는 순간 `print('안녕하세요')`가 `print("안녕하세요")`로 바뀐다. Ruff는 따옴표를 큰따옴표로 통일하기 때문이다. 두 코드는 완전히 같은 문자열을 출력하므로 걱정하지 않아도 된다. 이 교재의 예제도 큰따옴표를 기본으로 쓴다.

**여러 값을 한 번에 출력**하려면 쉼표로 구분한다. 값 사이에 공백 한 칸이 자동으로 들어간다.

```python
print("합계:", 1 + 2)
print("이름", "나이", "직업")
```

```
합계: 3
이름 나이 직업
```

**아무것도 넣지 않으면** 빈 줄이 출력된다. 출력을 구분할 때 쓴다.

```python
print("첫 줄")
print()
print("셋째 줄")
```

> 문자열 포매팅(f-string), 숫자와 문자열을 이어 붙이는 방법 등은 2장 "문자열"에서 다룬다. 지금은 쉼표로 나열하는 방법만 알면 충분하다.

### 1.3.2 `input()`으로 입력

`input()`은 사용자가 키보드로 입력한 값을 받아 온다. 괄호 안의 문자열은 입력을 안내하는 메시지로 먼저 출력된다.

```python
# greet.py
name = input("이름을 입력하세요: ")
print("안녕하세요,", name, "님!")
```

```
python greet.py
```
```
이름을 입력하세요: 홍길동
안녕하세요, 홍길동 님!
```

실행하면 `이름을 입력하세요: `까지 출력하고 **멈춰서 기다린다.** 값을 입력하고 Enter를 누르면 그 값이 `name`에 저장되고 다음 줄로 넘어간다.

`name = input(...)`에서 `name`은 **변수**다. 나중에 쓰기 위해 입력받은 값에 이름을 붙이는 것이다. 

**`input()`은 항상 문자열을 돌려준다.** 숫자를 입력해도 문자열 `"25"`가 된다. 그래서 다음 코드는 기대와 다르게 동작한다.

```python
age = input("나이: ")
print(age + 1)
```

```
나이: 25
Traceback (most recent call last):
  File "/Users/jinyoung/python-lab/ch01/age.py", line 2, in <module>
    print(age + 1)
          ~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

문자열 `"25"`에 숫자 `1`을 더할 수 없다는 오류다. 숫자로 계산하려면 `int()`로 변환해야 한다.

```python
age = int(input("나이: "))
print("내년 나이:", age + 1)
```

```
나이: 25
내년 나이: 26
```

> `int()`가 무엇인지, 문자열과 숫자가 어떻게 다른지는 2장 "변수와 자료형"에서 다룬다. 지금은 "`input()`으로 받은 숫자는 `int()`로 감싸야 계산할 수 있다"만 기억하자.

### 1.3.3 주석

`#` 뒤에 적은 내용은 파이썬이 **무시한다.** 이것을 **주석**(comment)이라고 하며, 코드를 읽는 사람을 위한 설명이다.

```python
# 이 줄은 주석이다. 실행되지 않는다.
print("Hello")  # 줄 끝에도 주석을 쓸 수 있다

# 아래 줄은 잠시 실행하지 않으려고 주석 처리했다
# print("나중에 다시 켤 코드")
```

주석을 쓰는 세 가지 경우:

1. **왜** 이렇게 했는지 설명할 때 (무엇을 하는지는 코드가 이미 말해 준다)
2. 코드를 잠시 **꺼 둘** 때 ("주석 처리한다"고 한다)
3. 파일 맨 위에 이 파일이 **무엇을 하는 파일인지** 적을 때

VS Code에서 줄을 선택하고 `Cmd + /` / `Ctrl + /`를 누르면 주석을 켜고 끌 수 있다.

> 1단계에서 AI가 만들어 준 코드에 주석이 많았을 것이다. 주석은 코드를 읽는 첫 번째 단서다. 앞으로 AI가 만든 코드를 읽을 때 주석부터 읽는 습관을 들이자.

### 1.3.4 들여쓰기 규칙

파이썬에서 **들여쓰기**(indentation, 줄 앞의 공백)는 꾸밈이 아니라 **문법**이다. 다른 언어가 `{ }`로 코드 묶음을 표시하는 자리에서 파이썬은 들여쓰기를 쓴다.

지금 당장 이해하지 않아도 되는 코드지만, 모양만 봐 두자. (`if`는 2장 "조건문"에서 배운다.)

```python
score = int(input("점수: "))
if score >= 60:
    print("합격")          # 이 두 줄은 if에 속한다
    print("축하합니다")
print("프로그램 종료")      # 이 줄은 if에 속하지 않는다
```

```
점수: 80
합격
축하합니다
프로그램 종료
```
```
점수: 40
프로그램 종료
```

규칙은 세 가지다.

1. 줄 끝에 **콜론(`:`)** 이 있으면 다음 줄부터 들여쓴다.
2. 들여쓰기는 **공백 4칸**이 표준이다. 1.2.5에서 VS Code를 설정해 두었으므로 `Tab` 키를 누르면 공백 4칸이 들어간다.
3. 같은 묶음에 속한 줄은 **들여쓰기 깊이가 같아야** 한다. 들여쓰기를 되돌리면 묶음이 끝난다.

들여쓰기가 틀리면 실행조차 되지 않는다.

```python
print("시작")
    print("잘못된 들여쓰기")
```

```
  File "/Users/jinyoung/python-lab/ch01/indent.py", line 2
    print("잘못된 들여쓰기")
IndentationError: unexpected indent
```

`unexpected indent`는 "여기 들여쓰기가 있을 이유가 없다"는 뜻이다. 반대로 콜론 뒤에 들여쓰기를 안 하면 `expected an indented block`(들여쓴 묶음이 있어야 한다)이 난다.

> 코드를 복사해 붙여 넣을 때 들여쓰기가 흐트러지는 경우가 많다. 특히 **탭과 공백이 섞이면** 눈으로는 같아 보여도 오류가 난다. 1.2.5에서 `editor.renderWhitespace`를 설정해 두었으므로 줄 앞의 공백은 점(`·`), 탭은 화살표(`→`)로 보인다. 다른 곳에서 가져온 코드가 이상하면 들여쓰기부터 의심하고, 화살표가 섞여 있는지 확인하자. 문법이 맞는 코드라면 저장할 때 Ruff가 탭을 공백 4칸으로 바꿔 주지만, 들여쓰기 오류가 있는 코드는 Ruff도 정리하지 못한다.

### 1.3.5 오류 메시지 읽는 법

프로그램을 만들다 보면 오류는 매일 만난다. 오류 메시지는 **파이썬이 보내는 가장 친절한 힌트**이므로, 겁내지 말고 읽는 법을 익히자.

**1) 트레이스백의 구조**

```python
# error_demo.py
print("시작")
message = "안녕하세요"
print(messge)
print("끝")
```

```
시작
Traceback (most recent call last):
  File "/Users/jinyoung/python-lab/ch01/error_demo.py", line 4, in <module>
    print(messge)
          ^^^^^^
NameError: name 'messge' is not defined. Did you mean: 'message'?
```

이 출력을 **트레이스백**(traceback)이라고 한다. 읽는 순서는 다음과 같다.

| 순서 | 볼 곳 | 이 예에서 |
|---|---|---|
| ① | **마지막 줄** — 오류 종류와 설명 | `NameError`: 이름을 찾을 수 없다. `'messge'`라는 이름은 정의된 적이 없다 (`message`를 잘못 쓴 것 아니냐고 제안까지 해 준다) |
| ② | **`File "...", line N`** — 어느 파일 몇 번째 줄인지 | `error_demo.py` 4번째 줄 |
| ③ | **그 아래 코드와 `^` 표시** — 줄 안에서 정확히 어디인지 | `messge` 부분 |

항상 **마지막 줄부터** 읽는다. 그다음 파일명과 줄 번호로 코드를 찾아간다. 오류가 난 줄 **앞**까지는 정상 실행되었다는 것도 확인할 수 있다(`시작`은 출력되었다).

> `Did you mean: 'message'?` 같은 제안은 파이썬 3.10부터 추가된 것이다. 비슷한 이름이 있을 때만 나오며, 오타를 찾는 데 큰 도움이 된다.

**2) 자주 만나는 오류**

| 오류 | 뜻 | 흔한 원인 |
|---|---|---|
| `SyntaxError: invalid syntax` | 문법이 틀렸다 | 콜론 빠짐, 대화형 셸에 터미널 명령 입력 |
| `SyntaxError: '(' was never closed` | 괄호를 열고 닫지 않았다 | 닫는 괄호 `)` 빠짐 |
| `SyntaxError: unterminated string literal` | 문자열이 끝나지 않았다 | 닫는 따옴표 빠짐 |
| `IndentationError` | 들여쓰기가 틀렸다 | 1.3.4 참고 |
| `NameError: name 'x' is not defined` | `x`라는 이름이 없다 | 변수 이름 오타, 변수를 만들기 전에 사용 |
| `TypeError: can only concatenate str (not "int") to str` | 문자열과 숫자를 더하려 했다 | `input()` 결과를 `int()` 없이 계산 |
| `ValueError: invalid literal for int() with base 10: 'abc'` | 숫자로 바꿀 수 없는 값이다 | `int("abc")`처럼 숫자가 아닌 입력 |
| `FileNotFoundError` / `can't open file` | 파일이 없다 | 현재 디렉터리가 다름, 파일명 오타 |

`SyntaxError`와 `IndentationError`는 **실행 전에** 파일 전체를 검사하다가 나므로 `Traceback` 없이 바로 파일명과 줄이 표시된다. 그 외의 오류는 **실행 중에** 그 줄에 도달했을 때 난다.

**3) 오류를 만났을 때 할 일**

1. 마지막 줄을 읽고 오류 종류를 확인한다.
2. 파일명과 줄 번호로 코드를 찾아간다.
3. 위 표에서 흔한 원인을 떠올려 본다. `SyntaxError`는 표시된 줄의 **바로 앞 줄**에 원인이 있는 경우도 많다(앞 줄에서 괄호를 안 닫았을 때).
4. 그래도 모르겠으면 **트레이스백 전체**와 **오류가 난 줄 주변 코드**를 함께 AI에게 보여 주고 묻는다. 마지막 줄만 보내는 것보다 훨씬 정확한 답을 얻는다.

1단계에서는 4번만 했을 것이다. 이제 1~3번을 먼저 하자. 대부분의 오류는 3번까지에서 해결된다.

| 항목 | 핵심 |
|---|---|
| 터미널 | `pwd`로 위치 확인, `cd`로 이동, `ls`로 내용 확인. 명령은 **현재 디렉터리**를 기준으로 동작한다 |

| `input()` | 항상 **문자열**을 돌려준다. 숫자 계산은 `int()`로 변환 |
| 주석 | `#` 뒤는 무시된다. "왜"를 적는다 |
| 들여쓰기 | 문법이다. 콜론 뒤 공백 4칸, 같은 묶음은 같은 깊이 |
| 오류 메시지 | **마지막 줄**(종류) → **파일·줄 번호**(위치) → **`^` 표시**(지점) 순으로 읽는다 |
