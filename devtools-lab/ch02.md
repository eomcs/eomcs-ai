# 2장. 터미널 기본기

[개발 도구](README.md) 과정의 두 번째 장이다. 기초 과정 1.1 "터미널 최소 조작"에서는 `pwd`, `cd`, `ls`, `mkdir`만으로 폴더를 옮겨 다니며 파이썬을 실행했다. 이 장에서는 터미널을 본격적으로 배운다. 다음 장(3장)에서 명령을 서로 잇고, 환경을 바꾸고, AI가 실행하려는 명령을 읽으려면 그 전에 손에 익어 있어야 할 것들이다.

- **셸과 터미널** — 터미널과 셸이 서로 다른 프로그램이라는 것, zsh·bash·PowerShell의 관계, 프롬프트 읽기, 같은 이름의 명령이 셸마다 다르게 동작하는 지점
- **명령의 구조와 도움말** — 명령·옵션·인자, 처음 보는 명령의 사용법을 스스로 찾는 순서
- **빠르게 입력하기** — 자동 완성, 명령 기록, 멈추기, 줄 편집 단축키
- **파일과 폴더 다루기, 파일 내용 보기** — 만들기·복사·이동·지우기, 숨김 파일, 긴 파일과 늘어나는 로그 파일 읽기
- **경로와 이름의 함정** — 공백·한글·따옴표, 와일드카드를 누가 처리하는지, 대소문자
- **터미널에서 쓰는 편집기** — `git commit`이 열어 주는 Vim에서 빠져나오기

## 학습 목표

이 장을 마치면 다음을 할 수 있다.

- 터미널과 셸의 차이를 설명하고, 지금 쓰는 셸과 명령의 종류(셸 내장 명령, cmdlet, 함수, 별칭, 외부 프로그램)를 확인할 수 있다.
- 프롬프트를 보고 현재 위치, 가상환경 활성화 여부, 명령 입력이 덜 끝난 상태를 알아챌 수 있다.
- 명령을 명령·옵션·인자로 나누어 읽고, `--help`, `man`, `Get-Help`로 처음 보는 명령의 사용법을 찾을 수 있다.
- Tab 자동 완성, 명령 기록 검색(`Ctrl+R`), 실행 중인 명령 멈추기(`Ctrl+C`)를 습관처럼 쓸 수 있다.
- 파일과 폴더를 터미널에서 만들고·복사하고·옮기고·지울 수 있고, 지운 파일이 휴지통에 가지 않는다는 것을 알고 지우기 전에 확인할 수 있다.
- `less`, `head`, `tail`(PowerShell은 `Get-Content`)로 긴 파일의 필요한 부분만 보고, 늘어나는 로그 파일을 지켜볼 수 있다.
- 공백·한글이 든 경로를 따옴표로 다루고, 와일드카드가 zsh와 PowerShell에서 다르게 처리되는 것을 파이썬 프로그램으로 확인하고, 운영체제에 상관없이 동작하게 고칠 수 있다.
- Vim이 열렸을 때 저장하고 나가거나, 저장하지 않고 나갈 수 있다.

## 실습 환경

1장과 같다. macOS는 터미널 앱의 zsh, Windows는 터미널 앱의 **PowerShell 7**이다. Windows 사용자는 시작하기 전에 `$PSVersionTable.PSVersion`의 `Major`가 `7`인지 확인한다(1.2.3). 이 장에는 PowerShell 5.1과 7에서 결과가 다른 명령이 있다.

실습 폴더는 `~/devtools-lab/ch02`다.

```
cd ~/devtools-lab
mkdir ch02
cd ch02
```

이 장의 실습에서 쓸 파일은 파이썬 스크립트로 한 번에 만든다. VS Code로 `ch02` 폴더를 열고(`code .`), `make_files.py`를 다음과 같이 만든다.

```python
# make_files.py — 2장 실습 파일을 만든다
from pathlib import Path
import random

random.seed(2)

base = Path("practice")
(base / "data").mkdir(parents=True, exist_ok=True)
(base / "내 문서").mkdir(exist_ok=True)

for month in ["2026-09", "2026-10", "2026-11"]:
    lines = ["date,category,amount"]
    for day in range(1, 11):
        lines.append(f"{month}-{day:02d},식비,{random.randint(5, 30) * 1000}")
    (base / "data" / f"{month}.csv").write_text("\n".join(lines) + "\n", encoding="utf-8", newline="\n")

(base / "data" / "memo.txt").write_text("9월은 식비가 많았다.\n", encoding="utf-8", newline="\n")
(base / "내 문서" / "계획.txt").write_text("다음 달 예산 세우기\n", encoding="utf-8", newline="\n")
(base / ".settings").write_text("theme=dark\n", encoding="utf-8", newline="\n")

levels = ["INFO"] * 8 + ["WARNING", "ERROR"]
log_lines = []
for i in range(1, 501):
    level = random.choice(levels)
    log_lines.append(f"2026-11-13 09:{i // 60:02d}:{i % 60:02d} {level} 요청 {i} 처리")
(base / "server.log").write_text("\n".join(log_lines) + "\n", encoding="utf-8", newline="\n")

print("practice 폴더를 만들었다.")
```

실행한다. 가상환경은 필요 없다.

```
# macOS
python3 make_files.py

# Windows
python make_files.py
```

```
practice 폴더를 만들었다.
```

만들어진 파일은 다음과 같다. 지금은 이런 구조라는 것만 보아 둔다. 이 장을 진행하며 하나씩 열어 본다.

```
practice/
├── .settings          ← 이름이 .으로 시작하는 파일
├── server.log         ← 500줄짜리 로그 파일
├── data/
│   ├── 2026-09.csv
│   ├── 2026-10.csv
│   ├── 2026-11.csv
│   └── memo.txt
└── 내 문서/            ← 이름에 공백과 한글이 있는 폴더
    └── 계획.txt
```

> **파일을 왜 `>`가 아니라 파이썬으로 만드나**
> 1.2.3에서 본 것처럼, Windows에서 파이썬 3.14 이하의 출력을 `>`로 파일에 저장하면 한글이 cp949로 저장될 수 있다. `write_text(..., encoding="utf-8")`로 직접 쓰면 운영체제와 파이썬 버전에 관계없이 UTF-8 파일이 된다. 함께 적은 `newline="\n"`은 줄바꿈을 운영체제에 관계없이 LF(`\n`)로 쓰라는 뜻이다. 이것을 빼면 Windows에서는 줄바꿈이 CRLF(`\r\n`)로 저장되어 2.4.6의 파일 크기가 줄 수만큼 커진다. 줄바꿈 문자의 차이는 5장에서 Git의 줄 끝 설정과 함께 다시 다룬다. `>`는 3장에서 정식으로 배운다.

## 2.1 셸과 터미널

### 2.1.1 터미널과 셸은 다른 프로그램이다

기초 과정에서는 "터미널에 명령을 입력한다"고 했다. 정확히 말하면 명령을 받는 프로그램은 두 개다.

- **터미널**(terminal) — 글자를 보여 주고 키보드 입력을 받는 **창**이다. macOS의 "터미널" 앱, Windows의 "터미널" 앱(Windows Terminal), VS Code의 통합 터미널, iTerm2 같은 프로그램이 모두 터미널이다. 글꼴, 색, 탭, 창 분할, 복사·붙여 넣기는 터미널이 하는 일이다.
- **셸**(shell) — 터미널 안에서 실행되며 **입력한 명령을 해석하고 실행하는** 프로그램이다. macOS의 zsh, 리눅스의 bash, Windows의 PowerShell이 셸이다. `~`를 홈 폴더로 바꾸고, `*.csv`를 파일 이름으로 바꾸고, `git`이라는 프로그램을 찾아 실행하는 것은 셸이 하는 일이다.

명령 하나가 실행되는 흐름은 다음과 같다.

```
 [터미널 창]  ──키 입력──▶  [셸(zsh / pwsh)]  ──실행──▶  [프로그램(git, python, ...)]
      ▲                         │                              │
      └──────────── 화면에 보여 줄 글자 ◀────────────────────────┘
```

1. 터미널은 내가 누른 키를 셸에 넘긴다.
2. 셸은 Enter가 들어오면 그 줄을 해석한다. 명령 이름을 찾고, 옵션과 인자를 나누고, `~`나 `*`를 바꾼다.
3. 셸이 직접 처리하는 명령(`cd` 등)이 아니면, 해당 프로그램을 찾아 실행한다. 1장에서 본 것처럼 `PATH`의 폴더를 앞에서부터 찾는다.
4. 프로그램이 출력한 글자는 터미널이 화면에 보여 준다.

이 구분을 알면 무엇을 어디서 바꿔야 하는지가 보인다.

| 하고 싶은 일 | 바꾸는 곳 |
|---|---|
| 글꼴 크기, 색, 창 분할, 복사·붙여 넣기 단축키 | 터미널 앱의 설정 |
| 명령 별칭, 프롬프트 모양, 환경 변수 | 셸 설정 파일(`~/.zshrc`, `$PROFILE` — 3장) |
| 새 탭을 열 때 어떤 셸이 뜨는지 | 터미널 앱의 설정(1.2.4에서 기본 프로필을 PowerShell 7로 바꾼 것) |

1.2.4에서 Windows 터미널의 기본 프로필을 "Windows PowerShell"에서 "PowerShell"로 바꾼 것은, **같은 터미널 창**에서 **다른 셸**이 뜨도록 바꾼 것이다.

### 2.1.2 zsh, bash, PowerShell

| 셸 | 어디서 만나나 | 계열 |
|---|---|---|
| zsh | macOS의 기본 셸(이 교재의 macOS 기준) | 유닉스 셸 |
| bash | 리눅스 서버, Docker 컨테이너, GitHub Actions, 인터넷의 설치 안내 대부분 | 유닉스 셸 |
| PowerShell 7(`pwsh`) | 이 교재의 Windows 기준 | PowerShell |

zsh와 bash는 같은 계열이라서 이 장과 3장에서 배우는 명령은 거의 그대로 통한다. 이 교재에서 "zsh"라고 적은 명령은 리눅스 서버의 bash에서도 쓸 수 있다고 생각해도 된다. 다른 점이 있으면 따로 적는다.

PowerShell은 계열이 다르다. 유닉스 셸이 프로그램 사이에 **글자**를 주고받는다면, PowerShell은 **객체**(object)를 주고받는다. 예를 들어 `Get-ChildItem`(PowerShell의 `ls`)은 파일 이름 글자가 아니라 이름·크기·수정 시각을 속성으로 가진 파일 객체를 내보낸다. 기초 과정에서 파이썬 객체의 속성을 꺼내 쓴 것과 비슷하다. 이 차이는 3장의 파이프에서 본격적으로 드러난다. 이 장에서는 "명령 이름과 옵션 모양이 다르다" 정도만 느끼면 된다.

### 2.1.3 프롬프트 읽기

프롬프트는 "명령을 입력할 준비가 되었다"는 표시이면서, 지금 상태를 알려 주는 정보판이다.

```
# macOS (zsh 기본 모양)
jinyoung@MacBook-Pro ch02 %

# Windows (PowerShell 기본 모양)
PS C:\Users\jinyoung\devtools-lab\ch02>
```

| 부분 | zsh | PowerShell |
|---|---|---|
| 사용자 이름과 컴퓨터 이름 | `jinyoung@MacBook-Pro` | 표시하지 않는다 |
| 현재 폴더 | 마지막 폴더 이름만(`ch02`), 홈이면 `~` | 전체 경로 |
| 끝 기호 | `%`(일반 사용자), `#`(관리자 root) | `>` |
| 셸 이름 | 표시하지 않는다 | 앞의 `PS` |

프롬프트가 바뀌면 상태가 바뀐 것이다. 자주 만나는 경우가 세 가지 있다.

**1. 가상환경이 켜져 있다.** 기초 과정 9장에서 본 것처럼 앞에 `(.venv)`가 붙는다.

```
(.venv) jinyoung@MacBook-Pro ledger_app %
(.venv) PS C:\Users\jinyoung\python-lab\ch10\ledger_app>
```

**2. 명령 입력이 덜 끝났다.** 따옴표를 열고 닫지 않은 채 Enter를 누르면, 셸은 명령이 아직 끝나지 않았다고 보고 **다음 줄을 더 입력하라는** 프롬프트를 띄운다.

```
echo "안녕
```

```
# macOS
dquote>

# Windows
>>
```

`dquote>`(큰따옴표가 열려 있다), `quote>`(작은따옴표가 열려 있다), `>>`(PowerShell의 이어서 입력)가 보이면 무언가 덜 닫힌 것이다. 처음 보면 터미널이 멈춘 것처럼 보인다. 당황하지 말고 `Ctrl+C`를 눌러 그 입력을 취소한 뒤 명령을 고쳐서 다시 입력한다(`Ctrl+C`는 2.3.3).

**3. 프롬프트가 나타나지 않는다.** 명령이 아직 실행 중이라는 뜻이다. 오래 걸리는 설치이거나, 입력을 기다리는 프로그램(기초 과정의 `input()`)이거나, 끝나지 않는 서버 프로그램이다. 기다리거나, 입력하거나, `Ctrl+C`로 멈춘다.

> 프롬프트 모양은 셸 설정으로 바꿀 수 있다. Oh My Zsh 같은 도구를 쓰면 Git 브랜치 이름이나 아이콘이 표시되기도 한다. 이 교재의 설명과 모양이 달라도 위의 정보가 어디 있는지 찾아 읽으면 된다.

### 2.1.4 명령의 종류 — 내장 명령, cmdlet, 함수, 별칭, 외부 프로그램

셸에 입력하는 명령은 모두 같아 보이지만, 정체는 여러 가지다. zsh에서는 주로 셸 내장 명령과 외부 프로그램을, PowerShell에서는 cmdlet·함수·별칭과 외부 프로그램을 만난다.

| 종류 | 무엇인가 | 예 |
|---|---|---|
| 셸 내장 명령 | zsh 안에 들어 있는 명령. 따로 실행 파일이 없다 | zsh의 `cd`, `echo`, `type`, `history` |
| cmdlet | PowerShell에 들어 있는 `동사-명사` 꼴의 명령. "커맨드릿"이라고 읽는다 | `Get-ChildItem`, `Set-Location`, `Copy-Item` |
| 함수(function) | 셸 안에 정의된 명령 묶음. 대개 다른 명령을 불러 쓴다 | PowerShell의 `mkdir`(→ `New-Item -ItemType Directory`를 부른다), `help` |
| 별칭(alias) | 다른 명령을 가리키는 짧은 이름 | PowerShell의 `ls`(→ `Get-ChildItem`), `cd`(→ `Set-Location`), `cp`(→ `Copy-Item`) |
| 외부 프로그램 | `PATH`의 폴더에 있는 실행 파일 | `git`, `python`, `code`, macOS의 `ls`(`/bin/ls`) |

zsh에서도 함수와 별칭을 직접 만들 수 있다. 셸 설정 파일에 별칭을 두는 방법은 3장에서 다룬다.

명령의 정체는 zsh에서는 `type`, PowerShell에서는 `Get-Command`로 확인한다.

```
# macOS
type cd ls mkdir git

# Windows
Get-Command cd, ls, mkdir, git
```

```
# macOS
cd is a shell builtin
ls is /bin/ls
mkdir is /bin/mkdir
git is /opt/homebrew/bin/git

# Windows
CommandType     Name                Version    Source
-----------     ----                -------    ------
Alias           cd -> Set-Location
Alias           ls -> Get-ChildItem
Function        mkdir
Application     git.exe             2.51.0.1   C:\Program Files\Git\cmd\git.exe
```

여기서 중요한 사실이 하나 드러난다. **같은 `ls`인데 정체가 다르다.** macOS의 `ls`는 `/bin/ls`라는 외부 프로그램이고, PowerShell의 `ls`는 `Get-ChildItem`이라는 PowerShell 명령(cmdlet, "커맨드릿"이라고 읽는다)의 별칭이다. PowerShell은 유닉스 셸에 익숙한 사람을 위해 `ls`, `cd`, `cp`, `mv`, `rm`, `cat` 같은 이름을 별칭으로 만들어 두었다. 이름만 빌려 왔을 뿐 속은 PowerShell 명령이다. `mkdir`는 별칭이 아니라 **함수**다. 이름은 같아도 실제로는 `New-Item -ItemType Directory`를 불러서 폴더를 만든다(2.4.1). `CommandType` 열이 그 이름의 정체를 알려 준다. 어느 쪽이든 그래서 **유닉스 셸의 옵션은 통하지 않는다.**

```
ls -la
```

```
# macOS — 숨김 파일까지 자세히 보여 준다
total 8
drwxr-xr-x   5 jinyoung  staff  160 Nov 13 09:30 .
...

# Windows
Get-ChildItem: A parameter cannot be found that matches parameter name 'la'.
```

PowerShell은 `-la`를 `Get-ChildItem`의 매개변수로 해석하려다 그런 이름이 없어서 오류를 냈다. 오류 메시지 맨 앞에 별칭이 아닌 **진짜 이름**(`Get-ChildItem`)이 나온다는 점도 눈여겨본다. 인터넷이나 AI가 알려 준 bash 명령이 PowerShell에서 이런 오류를 내면 "이름은 같지만 다른 명령이구나"라고 알아채면 된다.

> **`which`와 `type`, `Get-Command`**
> 1장에서 위치를 확인할 때 쓴 `which`도 zsh에서는 내장 명령이며 `type`과 비슷한 일을 한다. 외부 프로그램의 위치를 찾을 때는 둘 다 쓸 수 있다. `type`은 셸 내장 명령이나 별칭까지 알려 주므로 "이 이름이 정체가 뭔지"를 물을 때 더 정확하다. PowerShell에서는 어느 경우든 `Get-Command`를 쓴다. 별칭이 무엇을 가리키는지만 보고 싶으면 `Get-Alias ls`도 된다.

### 2.1.5 셸에 따라 명령이 달라지는 지점과 이 교재의 표기

정리하면, zsh와 PowerShell 7 사이에서 명령은 세 가지 경우로 나뉜다.

| 경우 | 예 | 이 교재의 표기 |
|---|---|---|
| 두 셸에서 똑같이 쓴다 | `cd 폴더`, `pwd`, `mkdir 폴더`, 옵션 없는 `ls`, `cat 파일`, `git`, `python` 같은 외부 프로그램 | 한 번만 적는다 |
| 이름은 같지만 옵션이 다르다 | `ls -a`, `rm -r`, `cp -r`, `mkdir -p` | `# macOS`, `# Windows`로 나누어 적는다. Windows는 cmdlet의 정식 이름과 매개변수로 적는다 |
| 한쪽에만 있다 | zsh의 `touch`, `head`, `tail`, `less` / PowerShell의 `Get-Content -Tail` | `# macOS`, `# Windows`로 나누어 적는다 |

Windows 명령을 `Copy-Item`처럼 정식 이름으로 적는 이유는 두 가지다. 첫째, 정식 이름은 `동사-명사` 꼴이라 처음 보는 사람도 무엇을 하는지 읽을 수 있다. 둘째, 도움말(`Get-Help`)과 공식 문서는 정식 이름으로 찾아야 나온다. 손에 익은 뒤에는 터미널에서 짧은 이름(별칭 `cp`, `ls`나 함수 `mkdir`)을 써도 된다. 다만 **스크립트나 `README.md`에 적어 남에게 줄 명령은 정식 이름으로 쓰는** 것이 좋다.

명령 이름을 몰라도 `Get-Command`로 찾을 수 있다. 동사나 명사로 검색한다.

```

```


"파일이나 폴더(Item)를 다루는 명령"이 한눈에 보인다. 2.4에서 배울 명령이 여기 다 있다.

## 2.2 명령의 구조와 도움말

### 2.2.1 명령·옵션·인자

명령 한 줄은 공백으로 나뉜 조각들로 이루어진다.

```
cp  -r  practice  backup
──  ──  ────────  ──────
명령 옵션    인자       인자
```

- **명령**(command) — 맨 앞 조각. 무엇을 실행할지 정한다.
- **옵션**(option) — `-`나 `--`로 시작하는 조각. 명령이 **어떻게** 동작할지 바꾼다. `-r`은 "폴더 안까지 모두(recursive)"라는 뜻이다. 플래그(flag), 스위치(switch)라고도 한다.
- **인자**(argument) — 명령이 **무엇에** 대해 동작할지 정한다. 여기서는 "practice를 backup으로"다.

기초 과정 8.2.2에서 `sys.argv`로 받은 것이 바로 이 조각들이다. `python main.py samples/2026-10.csv`에서 셸은 줄을 공백으로 나누어 `python` 프로그램을 찾아 실행하고, 나머지 조각을 넘긴다. 파이썬은 그중 `main.py` 뒤의 조각을 `sys.argv`에 담았다. 셸이 줄을 조각으로 나누는 기준이 **공백**이라는 사실은 2.6에서 공백이 든 경로를 다룰 때 다시 중요해진다.

Git처럼 기능이 많은 명령은 두 번째 조각이 **하위 명령**(subcommand)이다.

```
git  log  --oneline  -n  3
───  ───  ─────────  ──  ─
명령 하위  옵션         옵션 옵션의 값
     명령
```

`git log`, `git commit`, `python -m pip install`, `gh pr create`처럼 "큰 명령 + 하위 명령" 구조는 앞으로 계속 만난다. 옵션과 도움말이 하위 명령마다 따로 있다는 점을 기억해 둔다.

### 2.2.2 짧은 옵션과 긴 옵션

유닉스 셸 계열의 명령은 대부분 옵션을 두 가지 모양으로 받는다.

| | 짧은 옵션 | 긴 옵션 |
|---|---|---|
| 모양 | `-` 하나 + 글자 하나 | `--` 둘 + 단어 |
| 예 | `-a`, `-n 3` | `--all`, `--max-count=3` |
| 장점 | 빨리 입력한다 | 읽기만 해도 뜻을 안다 |

규칙 몇 가지:

- **짧은 옵션은 합쳐 쓸 수 있다.** `ls -l -a`와 `ls -la`는 같다. `-la`는 "`-l`과 `-a`"다. 그래서 2.1.4에서 PowerShell은 `-la`를 이해하지 못했다. PowerShell에는 이 규칙이 없다.
- **값을 받는 옵션이 있다.** `git log -n 3`의 `3`은 인자가 아니라 `-n` 옵션의 값이다. 긴 옵션은 `--max-count=3`처럼 `=`로 값을 붙이기도 한다.
- **같은 기능에 두 모양이 다 있는 경우가 많다.** `git log -n 3`과 `git log --max-count=3`은 같다. 터미널에서 직접 칠 때는 짧은 옵션을, `README.md`나 스크립트에 남길 때는 긴 옵션을 쓰면 읽는 사람이 편하다.
- **`--`는 "여기서부터는 옵션이 아니다"라는 표시다.** 예를 들어 이름이 `-notes.txt`처럼 `-`로 시작하는 파일을 지우려고 `rm -notes.txt`라고 하면 `rm`은 `-n`, `-o`, … 옵션으로 해석한다. `rm -- -notes.txt`라고 써야 한다. Git에서는 `git restore -- 파일`처럼 "브랜치 이름이 아니라 파일 이름이다"를 분명히 할 때 쓴다(5장).

> **옵션의 모양은 프로그램마다 다르다**
> 짧은 옵션·긴 옵션은 널리 퍼진 관례일 뿐 규칙은 아니다. 파이썬은 `python -m pip`, `python -X utf8`처럼 짧은 옵션에 값을 붙이고, `java -version`처럼 `-` 하나에 단어를 쓰는 프로그램도 있다. 결국 도움말을 보는 수밖에 없다.

### 2.2.3 PowerShell의 매개변수

PowerShell 명령(cmdlet)은 옵션을 **매개변수**(parameter)라고 부르며, 모양이 일정하다.

```
Copy-Item  -Path practice  -Destination backup  -Recurse
─────────  ──────────────  ────────────────────  ────────
명령        이름과 값          이름과 값              스위치(값 없음)
```

- 매개변수는 언제나 `-` 하나 + 단어다(`-Recurse`, `-Force`). `--`를 쓰지 않는다.
- 값을 받는 매개변수는 이름 뒤에 공백을 두고 값을 적는다(`-Path practice`). 값이 없는 매개변수는 **스위치**(switch)라고 하며, 적으면 켜진다(`-Recurse`).
- **이름을 생략할 수 있는 매개변수가 있다.** `Copy-Item practice backup`은 위와 같다. 첫째 자리가 `-Path`, 둘째 자리가 `-Destination`으로 정해져 있기 때문이다(위치 매개변수).
- **대소문자를 구분하지 않는다.** `-recurse`도 된다.
- **다른 매개변수와 겹치지 않을 만큼만 줄여 쓸 수 있다.** `-Recurse`를 `-r`로 쓸 수 있는 것은 `Copy-Item`의 매개변수 중 `r`로 시작하는 것이 `-Recurse` 하나뿐이기 때문이다. 겹치면 "모호하다"(ambiguous)는 오류가 난다. 줄여 쓰기는 터미널에서만 하고, 남에게 줄 명령에는 전체 이름을 적는다.
- 매개변수 이름도 Tab으로 자동 완성된다. `Copy-Item -R`까지 치고 Tab을 누르면 `-Recurse`가 된다.

> **외부 프로그램은 PowerShell에서도 원래 모양 그대로**
> `git log --oneline -n 3`, `python -m pip install --upgrade pip`처럼 **외부 프로그램**의 옵션은 PowerShell에서도 그 프로그램의 규칙대로 쓴다. PowerShell의 매개변수 규칙은 cmdlet에만 적용된다. 명령의 정체를 확인하는 습관(2.1.4)이 여기서 쓸모 있다.

### 2.2.4 도움말 보기

명령의 사용법은 명령 자체가 가장 정확히 알려 준다. 내 컴퓨터에 설치된 **바로 그 버전**의 설명이기 때문이다. 명령의 종류에 따라 도움말을 보는 방법이 다르다.

| 명령 | 짧은 도움말(터미널에 바로 출력) | 자세한 설명서 |
|---|---|---|
| 대부분의 외부 프로그램(`python`, `brew`, `gh`, `code`) | `--help` 또는 `-h` | 공식 문서 |
| Git | `git log -h` | `git log --help` |
| macOS의 기본 명령(`ls`, `cp`, `rm`, …) | (없음) | `man ls` |
| PowerShell cmdlet | `Copy-Item -?` | `Get-Help Copy-Item` |

**`--help`와 `-h`**

```
python3 --help
```

```
usage: python3 [option] ... [-c cmd | -m mod | file | -] [arg] ...
Options (and corresponding environment variables):
-b     : issue warnings about converting bytes/bytearray to str and comparing
...
```

하위 명령이 있는 프로그램은 하위 명령 뒤에 붙인다. `python -m pip --help`와 `python -m pip install --help`는 다른 내용을 보여 준다.

출력의 첫 줄인 **사용법**(usage) 줄을 읽는 규칙이 있다.

| 표기 | 뜻 |
|---|---|
| `[ ]` | 생략할 수 있다 |
| `...` | 여러 개 올 수 있다 |
| `\|` | 둘 중 하나 |
| `<file>`, `FILE`, 대문자나 꺾쇠 | 그 자리에 실제 값을 넣는다 |

`usage: git log [<options>] [<revision-range>] [[--] <path>...]`라면 "`git log` 뒤에 옵션, 범위, 경로를 줄 수 있는데 모두 생략할 수 있고, 경로 앞에는 `--`를 둘 수 있으며 경로는 여러 개 줄 수 있다"로 읽는다.

**Git의 `-h`와 `--help`**

Git은 두 가지를 다 쓴다. `-h`는 옵션 목록을 터미널에 짧게 보여 주고, `--help`는 전체 설명서를 연다. macOS에서는 설명서가 터미널 안에서(`man`과 같은 화면) 열리고, Windows에서는 **웹 브라우저**에서 HTML 문서로 열린다. `git help log`는 `git log --help`와 같다.

```
git log -h
```

```
usage: git log [<options>] [<revision-range>] [[--] <path>...]
   or: git show [<options>] <object>...

    -q, --[no-]quiet      suppress diff output
    ...
```

**macOS의 기본 명령은 `man`**

macOS의 `ls`, `cp`, `rm` 같은 기본 명령은 `--help`를 모른다.

```
ls --help
```

```
ls: unrecognized option `--help'
usage: ls [-@ABCFGHILOPRSTUWXabcdefghiklmnopqrstuvwxy1%,] [--color=when] [-D format] [file ...]
```

오류이긴 하지만 사용법 줄은 보여 준다. 자세한 설명은 **설명서 페이지**(manual page)를 여는 `man`으로 본다.

```
man ls
```

화면 전체가 설명서로 바뀐다. 이 화면은 2.5.2에서 배울 `less`로 보여 주는 것이라 조작법이 같다. 지금은 다음만 알면 된다.

| 키 | 하는 일 |
|---|---|
| `Space` / `b` | 다음 쪽 / 이전 쪽 |
| `/단어` + Enter | 단어 찾기. `n`은 다음 찾기 |
| `q` | 나가기 |

> **macOS의 명령과 리눅스의 명령은 옵션이 조금 다르다**
> macOS의 `ls`, `cp`, `sed` 같은 기본 명령은 BSD 계열이고, 리눅스 서버의 것은 GNU 계열이다. 이름과 주요 옵션은 같지만 세부가 다르다. 리눅스의 `ls --help`는 잘 동작하고, `ls --sort=size` 같은 긴 옵션도 리눅스에만 있다. 인터넷의 글이나 AI의 답은 리눅스(GNU) 기준인 경우가 많으므로, macOS에서 "그런 옵션이 없다"는 오류가 나면 `man`으로 macOS판 옵션을 찾는다(예: 크기 순 정렬은 macOS에서 `ls -lS`).

**PowerShell은 `Get-Help`**

PowerShell cmdlet은 `Get-Help`로 도움말을 본다. `-?`를 붙여도 같다.

```
Get-Help Copy-Item
```

```
NAME
    Copy-Item

SYNTAX
    Copy-Item [-Path] <string[]> [[-Destination] <string>] [-Container] [-Force] [-Filter <string>]
    [-Include <string[]>] [-Exclude <string[]>] [-Recurse] [-PassThru] ...

ALIASES
    cpi
    cp
    copy

REMARKS
    Get-Help cannot find the Help files for this cmdlet on this computer. It is displaying only partial help.
        -- To download and install Help files for the module that includes this cmdlet, use Update-Help.
        -- To view the Help topic for this cmdlet online, type: "Get-Help Copy-Item -Online" ...
```

PowerShell 7에는 처음에 도움말 본문이 설치되어 있지 않아서 **문법**(SYNTAX)과 별칭만 나온다. `SYNTAX`의 `[-Path]`처럼 매개변수 이름이 대괄호 안에 있으면 이름을 생략할 수 있다는 뜻이다(2.2.3의 위치 매개변수). 본문까지 보려면 도움말을 한 번 내려받는다. 시간이 조금 걸린다.

```
Update-Help -UICulture en-US
```

`-UICulture en-US`는 영어 도움말을 받으라는 뜻이다. 한국어 Windows에서 이 옵션 없이 실행하면 한국어 도움말을 찾다가 없다는 오류가 날 수 있다. 몇몇 모듈에서 오류가 나도 나머지는 설치되므로 무시해도 된다.

내려받은 뒤에는 다음과 같이 필요한 부분만 골라 본다.

```
Get-Help Copy-Item -Examples                # 예제만
Get-Help Copy-Item -Parameter Recurse       # 매개변수 하나의 설명만
Get-Help Copy-Item -Online                  # 공식 문서를 브라우저로 열기
```

`-Examples`가 특히 쓸모 있다. 설명보다 예제가 빨리 읽힌다. `-Online`은 도움말을 내려받지 않아도 쓸 수 있다.

> **`man`과 `help`는 PowerShell에도 있다**
> Windows의 PowerShell 7에서 `man Copy-Item`이나 `help Copy-Item`을 입력하면 `Get-Help`의 내용을 한 쪽씩 끊어서 보여 준다. 다만 `man ls`는 `ls`의 정체인 `Get-ChildItem`의 도움말을 보여 준다. macOS의 `man ls`와는 다른 명령의 설명서다.

### 2.2.5 처음 보는 명령의 사용법을 찾는 순서

명령을 외울 필요는 없다. 필요할 때 **찾을 수 있으면** 된다. 이 과정에서는 다음 순서로 찾는다.

**1단계 — 도움말을 본다.** `-h`, `--help`, `man`, `Get-Help`. 내 컴퓨터에 설치된 버전의 정확한 설명이고, 몇 초면 된다. 원하는 옵션이 있을 것 같은 단어로 검색한다(`man`에서 `/`).

**2단계 — 공식 문서를 본다.** 도움말이 너무 짧거나 개념 설명이 필요하면 공식 문서로 간다. 이 과정에서 자주 볼 공식 문서는 다음과 같다.

| 도구 | 공식 문서 |
|---|---|
| Git | https://git-scm.com/docs (명령별 설명서와 무료 책 *Pro Git*) |
| PowerShell | https://learn.microsoft.com/powershell (`Get-Help -Online`이 여는 곳) |
| GitHub CLI | https://cli.github.com/manual |
| 파이썬 | https://docs.python.org/ko/3/ (기초 과정 8.2.6) |

**3단계 — AI에게 묻고, 답을 도움말로 확인한다.** "무엇을 하고 싶은데 어떤 명령을 쓰나"처럼 명령 이름조차 모를 때는 AI가 가장 빠르다. 다만 두 가지를 지킨다.

- **환경을 알려 준다.** "macOS zsh에서", "Windows PowerShell 7에서"를 꼭 붙인다. 붙이지 않으면 리눅스 bash 기준 답이 나오기 쉽다.
- **받은 명령을 1단계로 확인한다.** AI가 알려 준 옵션이 내 버전에 정말 있는지, 그 옵션이 무엇을 하는지 도움말에서 찾아본다. 1.1.4의 규칙 — 실행하기 전에 그 명령이 무엇을 하는지 한 문장으로 말할 수 있어야 한다 — 이 여기서 구체화된다. 찾아보는 데 1분이면 충분하고, 그 1분이 3장의 "AI가 실행하려는 명령 읽기"의 연습이다.

예를 들어 "폴더 안의 하위 폴더까지 모든 파일 목록을 보고 싶다"면 다음과 같이 진행한다.

```
# macOS
man ls
# → /recurs 로 검색 → -R  Recursively list subdirectories encountered.
ls -R practice

# Windows
Get-Help Get-ChildItem -Parameter Recurse
Get-ChildItem practice -Recurse
```

### 실습 2-2. 도움말로 답 찾기

`~/devtools-lab/ch02`에서 한다. 각 질문의 답(옵션 이름)과, **그 답을 찾은 방법**(어떤 도움말에서 어떤 단어로 찾았는지)을 `help.md`에 적는다. AI에게 먼저 묻지 않는다.

1. `ls`(Windows `Get-ChildItem`)로 `practice` 폴더를 볼 때 **폴더는 빼고 파일만** 보려면? (macOS는 `ls`에 이 옵션이 없다. macOS 사용자는 대신 "수정 시각 순으로 정렬하는" 옵션을 찾는다.)
2. `mkdir`의 `-p` 옵션은 무엇을 하는가? (Windows는 `New-Item -ItemType Directory`가 중간 폴더를 어떻게 처리하는지 `Get-Help New-Item -Examples`에서 찾는다.)
3. `git log`에서 최근 커밋 3개만 보려면? 짧은 옵션과 긴 옵션을 모두 적는다. (`git log -h`는 Git 저장소 밖에서도 동작한다.)
4. `python -m pip install`에서 **실제로 설치하지 않고 무엇이 설치될지만** 보려면?
5. `gh` 명령에서 풀 리퀘스트(PR)를 다루는 하위 명령의 이름은? (`gh --help`) 그 하위 명령으로 PR 목록을 보려면?
6. 질문 하나를 골라 AI에게 같은 질문을 해 보고, 답이 도움말에서 찾은 것과 같은지 비교해 적는다. 질문할 때 운영체제와 셸을 밝혔는지도 적는다.

## 2.3 빠르게 입력하기

터미널이 느리고 불편하게 느껴지는 이유는 대부분 모든 글자를 한 자씩 치기 때문이다. 이 절의 기능을 쓰면 실제로 입력하는 글자는 절반 이하로 준다. 더 중요한 것은 **오타가 줄어든다**는 점이다.

### 2.3.1 Tab 자동 완성

기초 과정 1.1.5에서 폴더 이름을 Tab으로 완성하는 것을 배웠다. 자동 완성은 폴더 이름만이 아니라 거의 모든 곳에서 동작한다.

| 무엇을 | 예 |
|---|---|
| 파일·폴더 이름 | `cd pra` + Tab → `cd practice/` |
| 명령 이름 | `pyt` + Tab → `python3` |
| PowerShell cmdlet과 매개변수 | `Get-Chi` + Tab → `Get-ChildItem`, `-Rec` + Tab → `-Recurse` |
| Git의 하위 명령·브랜치 이름(설정에 따라) | `git sta` + Tab → `git status` / `git stash` |

**후보가 여럿일 때 두 셸이 다르게 행동한다.**

- **zsh** — 공통 부분까지 채우고, Tab을 한 번 더 누르면 후보 목록을 보여 준다. 목록에서 Tab을 계속 누르면 후보를 하나씩 고른다.
- **PowerShell** — Tab을 누를 때마다 후보를 **하나씩 바꿔 가며** 채운다. `Shift+Tab`은 거꾸로 간다. `Ctrl+Space`를 누르면 후보 목록을 한꺼번에 보여 준다.

Tab을 눌렀는데 **아무것도 완성되지 않으면** 그것도 정보다. 그 이름의 파일이 지금 폴더에 없거나, 앞의 글자에 오타가 있다는 뜻이다. Enter를 누르기 전에 알 수 있다.

> **이름에 공백이 있을 때도 Tab**
> `practice/내` + Tab을 누르면 zsh는 `practice/내\ 문서/`, PowerShell은 `.\practice\'내 문서'\` 같은 모양으로 완성한다. 공백 앞의 `\`나 따옴표는 셸이 공백을 이름의 일부로 보게 하는 표시다(2.6.2). 직접 따옴표를 칠 필요 없이 Tab이 알아서 넣어 준다.

### 2.3.2 명령 기록

셸은 실행한 명령을 기억한다.

| 하는 일 | zsh | PowerShell 7 |
|---|---|---|
| 이전·다음 명령 | `↑` / `↓` | `↑` / `↓` |
| 명령 기록 검색 | `Ctrl+R` 누르고 일부 입력 | `Ctrl+R` 누르고 일부 입력 |
| 기록 목록 보기 | `history` | `history` 또는 `Get-History` |

**`Ctrl+R`이 가장 쓸모 있다.** 사흘 전에 실행한 긴 명령을 `↑`로 찾으려면 수십 번 눌러야 하지만, `Ctrl+R`을 누르고 기억나는 일부(예: `check_`)를 치면 그 글자가 든 가장 최근 명령이 바로 나온다. `Ctrl+R`을 한 번 더 누르면 그보다 이전 것을 찾는다. 찾은 명령은 Enter로 바로 실행하거나, `→`(또는 `←`)를 눌러 고친 뒤 실행한다. 그만 찾으려면 `Ctrl+C`나 `Esc`다.

```
# zsh에서 Ctrl+R을 누르고 check를 입력한 화면
bck-i-search: check_
python check_samples.py && python main.py samples/2026-10.csv
```

(PowerShell은 `bck-i-search:`가 프롬프트 아래 줄에 표시된다.)

**기록 목록과 다시 실행**

```
history
```

zsh의 `history`는 최근 명령에 번호를 붙여 보여 준다(전체를 보려면 `history 1`). `!번호`로 그 명령을 다시 실행하고, `!!`는 바로 앞 명령이다. PowerShell의 `history`(`Get-History`)는 **지금 창에서 실행한 명령만** 보여 준다. 그런데 `↑`와 `Ctrl+R`은 이전 창의 명령까지 찾아 준다. PowerShell 7의 줄 편집 기능(PSReadLine)이 기록을 따로 파일에 저장하기 때문이다.

PowerShell 7에서는 입력하는 동안 기록에서 찾은 **회색 글자**가 커서 뒤에 미리 보이기도 한다(예측 입력). `→`를 누르면 그대로 받아들인다. 무시하고 계속 입력해도 된다.

> **명령 기록은 파일에 남는다**
> zsh는 `~/.zsh_history`에, PowerShell 7은 `(Get-PSReadLineOption).HistorySavePath`가 알려 주는 파일에 명령 기록을 저장한다. 명령줄에 비밀번호나 API 키를 직접 입력하면 그 값이 이 파일에 그대로 남는다. API 키를 명령줄에 적지 않고 환경 변수와 `.env` 파일로 다루는 방법은 3장과 8장에서 배운다.

### 2.3.3 실행 중인 명령 멈추기

**`Ctrl+C`** 는 지금 실행 중인 명령을 멈춘다. 끝나지 않는 프로그램, 너무 오래 걸리는 명령, 실수로 실행한 명령을 멈출 때 쓴다. 2.1.3에서 본 것처럼 덜 끝난 입력을 취소할 때도 쓴다. 파이썬 프로그램을 `Ctrl+C`로 멈추면 `KeyboardInterrupt`가 표시된다. 오류처럼 보이지만 내가 멈췄다는 기록일 뿐이다.

```
# macOS
python3 -c "while True: pass"

# Windows
python -c "while True: pass"
```

```
^CTraceback (most recent call last):
  File "<string>", line 1, in <module>
KeyboardInterrupt
```

> **zsh에서 `Ctrl+Z`는 멈추는 것이 아니다**
> zsh에서 `Ctrl+Z`를 누르면 `zsh: suspended`가 나오고 프롬프트가 돌아온다. 끝난 것처럼 보이지만 프로그램은 **일시 정지**되어 메모리에 그대로 남아 있다. 서버 프로그램을 `Ctrl+Z`로 "끈" 줄 알고 다시 실행하면 3장에서 다룰 "이미 사용 중인 포트" 오류를 만난다. 실수로 눌렀으면 `fg`를 입력해 프로그램을 다시 앞으로 가져온 뒤 `Ctrl+C`로 멈춘다. 셸을 닫으려 할 때 "you have suspended jobs"라는 경고가 나오는 것도 이 때문이다.

**복사·붙여 넣기 단축키**

`Ctrl+C`가 "멈추기"이기 때문에 터미널의 복사·붙여 넣기 단축키는 일반 프로그램과 다를 수 있다.

| | 복사 | 붙여 넣기 |
|---|---|---|
| macOS 터미널, VS Code 터미널(macOS) | `Cmd+C` | `Cmd+V` |
| Windows 터미널 | 글자를 선택한 상태의 `Ctrl+C`, 또는 `Ctrl+Shift+C` | `Ctrl+V` 또는 `Ctrl+Shift+V` |
| VS Code 터미널(Windows) | 글자를 선택한 상태의 `Ctrl+C` | `Ctrl+V` |

Windows에서는 **글자를 선택한 상태**에서 `Ctrl+C`를 누르면 복사, 선택하지 않은 상태에서 누르면 멈추기다. 오래 걸리는 명령의 출력을 복사하려고 `Ctrl+C`를 눌렀는데 선택이 풀려 있었다면 명령이 멈춘다. 복사할 때는 `Ctrl+Shift+C`를 쓰는 습관이 안전하다.

### 2.3.4 화면 지우기

| 하는 일 | zsh | PowerShell 7 |
|---|---|---|
| 화면 지우기 | `clear` 또는 `Ctrl+L` | `clear`(`Clear-Host`의 별칭) 또는 `Ctrl+L` |

`Ctrl+L`은 입력 중이던 글자를 지우지 않고 화면만 깨끗하게 한다. macOS 터미널 앱에서는 `Cmd+K`가 위로 올려서 볼 수 있는 이전 출력(스크롤 기록)까지 지운다. 화면을 지운다고 명령 기록이나 실행 결과가 사라지는 것은 아니다. 오류 메시지를 다시 찾아 읽어야 할 수 있으니, 긴 출력을 확인하기 **전에** 지우고 확인한 **뒤에는** 지우지 않는 편이 좋다.

### 2.3.5 줄 편집 단축키

긴 명령의 앞부분을 고치려고 `←`를 수십 번 누를 필요는 없다.

| 하는 일 | zsh(macOS) | PowerShell 7(Windows) |
|---|---|---|
| 줄의 맨 앞 / 맨 뒤로 | `Ctrl+A` / `Ctrl+E` | `Home` / `End` |
| 한 단어씩 이동 | `Option+←` / `Option+→`(터미널 앱 설정에 따라) | `Ctrl+←` / `Ctrl+→` |
| 커서 앞의 단어 지우기 | `Ctrl+W` | `Ctrl+Backspace` |
| 커서부터 줄 끝까지 지우기 | `Ctrl+K` | `Ctrl+End` |
| 줄 전체 지우기 | `Ctrl+U` | `Esc` |
| 실행하지 않고 입력 취소 | `Ctrl+C` | `Ctrl+C` |

전부 외울 필요는 없다. **줄의 맨 앞으로 가기**와 **줄 전체 지우기** 두 가지만 손에 익혀도 충분하다. 예를 들어 `python check_samples.py`를 실행한 뒤 같은 명령 앞에 무언가를 붙이고 싶으면, `↑` → 맨 앞으로 → 입력이다.

> VS Code 통합 터미널에서는 VS Code 자체의 단축키가 먼저 동작해서 일부 키가 셸에 전달되지 않을 수 있다(특히 Windows의 `Ctrl+` 단축키). 표의 단축키가 VS Code에서만 안 되면 바깥 터미널 앱에서 되는지 확인해 본다. 통합 터미널의 설정은 4장에서 다룬다.

### 실습 2-3. 손에 익히기

`~/devtools-lab/ch02`에서 한다. 정답을 적을 것은 없다. 각 단계를 손으로 해 본다.

1. **Tab** — 키보드로 `practice` 폴더 안의 `내 문서` 폴더로 이동한다. 이름을 한 글자도 끝까지 치지 말고 Tab으로만 완성한다. `pwd`로 확인하고, `cd ../..`로 돌아온다.
2. **Tab으로 오타 찾기** — `cd practise`(오타)까지 치고 Tab을 눌러 본다. 아무 일도 일어나지 않는 것을 확인하고, `Ctrl+U`(Windows `Esc`)로 줄을 지운다.
3. **멈추기** — 끝나지 않는 파이썬 명령(2.3.3)을 실행하고 `Ctrl+C`로 멈춘다.
4. **(macOS) 일시 정지에서 돌아오기** — 같은 명령을 실행하고 이번에는 `Ctrl+Z`를 누른다. `zsh: suspended`를 확인하고, `fg`로 다시 가져온 뒤 `Ctrl+C`로 멈춘다.
5. **기록 검색** — `Ctrl+R`을 누르고 `while`을 입력해 3번의 명령을 찾는다. 실행하지 않고 `Ctrl+C`로 빠져나온다.
6. **줄 편집** — `python3 --version`(Windows `python --version`)을 실행한다. `↑`로 불러와서 줄 맨 앞으로 가 `which `(Windows `Get-Command `)를 붙이고, 줄 끝으로 가서 ` --version`을 지운 뒤 실행한다. 즉, 위치를 확인하는 명령으로 바꿔 실행한다. (macOS에서 ` --version`을 지우지 않으면 `which`가 `--version`도 찾을 명령 이름으로 보고 `--version not found`라고 알린다.)
7. **기록 보기** — `history`를 실행해서 지금까지 한 명령이 보이는지 확인한다.

## 2.4 파일과 폴더 다루기

기초 과정에서는 파일을 VS Code나 Finder·탐색기에서 만들고 옮겼다. 그것도 좋은 방법이다. 하지만 AI 도구는 파일을 터미널 명령으로 만들고 지우고, 화면이 없는 서버에서는 명령만 쓸 수 있다. 이 절의 명령을 읽을 수 있어야 3장에서 AI가 실행하려는 명령을 판단할 수 있다.

먼저 전체를 한눈에 본다.

| 하는 일 | macOS(zsh) | Windows(PowerShell 7) | PowerShell 짧은 이름(별칭·함수) |
|---|---|---|---|
| 폴더 만들기(중간 폴더까지) | `mkdir -p a/b` | `New-Item -ItemType Directory a/b` | `mkdir a/b` |
| 빈 파일 만들기 | `touch a.txt` | `New-Item a.txt` | `ni a.txt` |
| 파일 복사 | `cp a.txt b.txt` | `Copy-Item a.txt b.txt` | `cp`, `copy` |
| 폴더 복사 | `cp -r src dst` | `Copy-Item src dst -Recurse` | `cp src dst -Recurse` |
| 옮기기·이름 바꾸기 | `mv a b` | `Move-Item a b` | `mv`, `move` |
| 이름만 바꾸기 | `mv a b` | `Rename-Item a b` | `ren` |
| 파일 지우기 | `rm a.txt` | `Remove-Item a.txt` | `rm`, `del` |
| 폴더 지우기 | `rm -r dir` | `Remove-Item dir -Recurse` | `rm dir -Recurse` |
| 숨김 항목까지 목록 | `ls -a` | `Get-ChildItem -Force` | `ls -Force` |
| 크기·수정 시각까지 목록 | `ls -l`, `ls -lh` | `Get-ChildItem` | `ls` |


### 2.4.1 만들기

**폴더**

```
# macOS
mkdir -p reports/2026/11

# Windows
New-Item -ItemType Directory reports/2026/11
```

기초 과정의 `mkdir`은 폴더를 한 단계만 만들었다. `reports`가 없는 상태에서 `mkdir reports/2026/11`을 실행하면 macOS에서는 오류가 난다. `-p`(parents)는 **중간 폴더가 없으면 함께 만들고, 이미 있으면 오류 없이 넘어간다.** 파이썬의 `Path.mkdir(parents=True, exist_ok=True)`(기초 과정 7.2)와 같다. `make_files.py`의 첫 줄이 바로 이것이다.

PowerShell의 `New-Item -ItemType Directory`는 중간 폴더를 처음부터 알아서 만든다. 대신 **이미 있으면 오류가 난다.** 오류 없이 넘어가게 하려면 `-Force`를 붙인다. PowerShell의 `mkdir`는 이 명령을 불러 주는 **함수**(2.1.4)라서 동작이 같다. `-p`라는 매개변수는 없으므로 붙이지 않는다.

**빈 파일**

```
# macOS
touch reports/todo.txt

# Windows
New-Item reports/todo.txt
```

`touch`는 원래 파일의 **수정 시각을 지금으로 바꾸는** 명령이다. 파일이 없으면 빈 파일을 만들기 때문에 빈 파일을 만드는 용도로 더 많이 쓴다. 이미 있는 파일에 `touch`를 하면 내용은 그대로이고 수정 시각만 바뀐다.

PowerShell의 `New-Item`은 이미 파일이 있으면 오류를 낸다. 여기에 `-Force`를 붙이면 **기존 파일을 빈 파일로 덮어쓰므로** 조심한다. 내용을 지우고 싶을 때가 아니면 파일에는 `-Force`를 붙이지 않는다.

실제로 내용이 있는 파일은 VS Code에서 만드는 편이 낫다. 터미널에서 `code reports/todo.txt`를 실행하면 파일이 없을 때 새로 열어 준다.

### 2.4.2 복사하기

**파일 복사**

```
cp data/memo.txt data/memo_backup.txt
```

`cp 원본 대상`이다. 대상이 **이미 있는 폴더**이면 그 안에 같은 이름으로 복사한다.

```
cp data/memo.txt reports/
```

이 명령은 두 셸에서 같다(PowerShell에서는 `cp`가 `Copy-Item`의 별칭이고, 옵션이 없기 때문이다).

**폴더 복사**

```
# macOS
cp -r data data_backup

# Windows
Copy-Item data data_backup -Recurse
```

폴더를 복사할 때는 `-r`(Windows `-Recurse`)이 필요하다. 두 셸의 동작이 조금 다르다.

- **macOS** — `-r` 없이 폴더를 복사하려 하면 `cp: data is a directory (not copied).`라는 오류가 난다.
- **Windows** — `-Recurse` 없이 `Copy-Item data data_backup`을 실행하면 **오류 없이 빈 폴더만** 만든다. 복사가 된 줄 알기 쉬우니 폴더를 복사한 뒤에는 `ls data_backup`으로 안을 확인한다.

대상 폴더가 이미 있는지에 따라 결과가 달라지는 점은 두 셸이 같다.

| `data_backup`이 | 결과 |
|---|---|
| 없을 때 | `data_backup`이 만들어지고 그 안에 `data`의 내용이 들어간다 |
| 이미 있을 때 | `data_backup/data`가 만들어진다(폴더째 안으로 들어간다) |

같은 명령을 두 번 실행하면 두 번째에는 `data_backup/data`가 생기는 이유다.

> **macOS `cp -r`의 끝 슬래시**
> macOS의 `cp -r data/ data_backup`처럼 원본 끝에 `/`를 붙이면 `data` 폴더 자체가 아니라 **`data` 안의 내용**을 복사한다. 리눅스의 `cp`는 끝 슬래시와 상관없이 같게 동작한다. 혼동을 피하려면 원본 폴더 이름 끝에 `/`를 붙이지 않는다. zsh에서 Tab으로 폴더 이름을 완성하면 끝에 `/`가 붙지만, 이어서 공백을 치면 zsh가 그 `/`를 지워 준다.

**덮어쓰기는 묻지 않는다**

`cp`와 `Copy-Item`은 대상 파일이 이미 있으면 **묻지 않고 덮어쓴다.** macOS에서는 `-i`(interactive) 옵션을 붙이면 덮어쓰기 전에 묻는다.

```
# macOS
cp -i data/memo.txt reports/memo.txt
```

```
overwrite reports/memo.txt? (y/n [n])
```

### 2.4.3 이동하기와 이름 바꾸기

옮기기와 이름 바꾸기는 같은 명령이다. 운영체제 입장에서는 "이 파일의 경로를 바꾼다"는 같은 일이기 때문이다.

```
mv data/memo_backup.txt reports/memo_old.txt     # 옮기면서 이름도 바꾸기
mv reports/todo.txt reports/할일.txt              # 같은 폴더에서 이름만 바꾸기
mv data_backup old_data                          # 폴더 이름 바꾸기
```

세 명령 모두 두 셸에서 같다. PowerShell에서는 이름만 바꿀 때 `Rename-Item`도 쓴다. `Rename-Item`의 두 번째 인자에는 경로가 아닌 **새 이름만** 적는다(`Rename-Item reports/todo.txt 할일.txt`).

`mv`는 `cp`와 달리 폴더에도 `-r`이 필요 없다. 내용을 복사하는 것이 아니라 경로만 바꾸기 때문이다.

**`mv`의 함정 두 가지**

1. **대상이 이미 있으면?** macOS의 `mv`는 묻지 않고 덮어쓴다(`-i`를 붙이면 묻는다). 덮어쓴 원래 파일은 되살릴 수 없다. PowerShell의 `Move-Item`은 대상 파일이 이미 있으면 오류를 내고 멈춘다. 덮어쓰려면 `-Force`를 붙여야 한다.
2. **폴더 안으로 옮기려 했는데 폴더가 없다면?** `mv memo.txt archive`에서 `archive` 폴더가 있으면 그 안으로 옮기지만, **없으면 `memo.txt`의 이름이 `archive`로 바뀐다.** 오류도 나지 않는다. macOS에서는 `mv memo.txt archive/`처럼 끝에 `/`를 붙이면 폴더가 없을 때 오류가 나므로 실수를 막을 수 있다. 어느 셸이든 옮기기 전에 `ls`로 대상 폴더가 있는지 확인하는 습관이 가장 확실하다.

### 2.4.4 지우기 — 휴지통은 없다

```
# 파일 지우기 — 두 셸 같음
rm reports/memo_old.txt

# 폴더 지우기
# macOS
rm -r old_data

# Windows
Remove-Item old_data -Recurse
```

**터미널에서 지운 파일은 휴지통에 가지 않는다.** Finder나 탐색기, VS Code에서 지우면 휴지통으로 가지만, `rm`과 `Remove-Item`은 그 자리에서 바로 지운다. "되돌리기"도 없다. 커밋하지 않은 코드를 실수로 지우면 되살릴 방법이 없다. 5장부터 Git을 쓰는 이유 중 하나가 이것이다. Git에 커밋해 둔 파일은 지워도 되살릴 수 있다.

두 셸은 폴더를 지울 때 행동이 다르다.

- **macOS** — `rm`은 `-r` 없이 폴더를 지우려 하면 `rm: old_data: is a directory`라는 오류를 낸다. `-r`을 붙이면 안의 내용까지 **묻지 않고** 지운다. 비어 있는 폴더만 지우는 `rmdir`도 있다.
- **Windows** — `Remove-Item`은 `-Recurse` 없이 내용이 있는 폴더를 지우려 하면 "안에 항목이 있는데 정말 지울까?"라고 **묻는다**(`[Y] Yes [A] Yes to All [N] No ...`). `-Recurse`를 붙이면 묻지 않는다.

`rm -rf`는 인터넷에서 자주 보는 명령이다. `-f`(force)는 "없는 파일이라도 오류를 내지 말고, 쓰기 금지된 파일도 묻지 말고 지워라"라는 뜻이다. `-r`과 합치면 **어떤 경우에도 묻지 않고 폴더째 지운다.** 3장에서 AI가 실행하려는 명령 중 가장 먼저 경계할 위험 신호로 다시 나온다. PowerShell에서는 `Remove-Item -Recurse -Force`가 같은 일을 한다(`rm -rf`라고 치면 `-rf`라는 매개변수가 없어서 오류가 난다).

**지우기 전에 확인하는 방법**

> **이 예제는 읽기만 한다**
> 아래 예제는 `data` 폴더의 CSV 파일을 대상으로 한다. 이 파일들은 뒤의 실습에서 계속 쓰므로 지금 실행하지 않는다. 특히 `rm -i`는 확인 질문에 `y`라고 답하면 **실제로 지운다.** 직접 해 보고 싶으면 먼저 `cp -r data data_try`(Windows `Copy-Item data data_try -Recurse`)로 복사본을 만들고, 예제의 `data`를 `data_try`로 바꿔 실행한 뒤 `data_try` 폴더를 지운다.

```
# macOS — 하나씩 물어보게 하기
rm -i data/*.csv

# Windows — 실제로 지우지 않고, 지울 대상만 보여 주기
Remove-Item data/*.csv -WhatIf
```

```
# Windows 출력
What if: Performing the operation "Remove File" on target "C:\Users\jinyoung\devtools-lab\ch02\practice\data\2026-09.csv".
What if: Performing the operation "Remove File" on target "C:\Users\jinyoung\devtools-lab\ch02\practice\data\2026-10.csv".
What if: Performing the operation "Remove File" on target "C:\Users\jinyoung\devtools-lab\ch02\practice\data\2026-11.csv".
```

PowerShell의 **`-WhatIf`** 는 무언가를 바꾸는 cmdlet 대부분에 있다. "실행하면 무슨 일이 일어날지"만 보여 주고 실제로는 아무것도 하지 않는다. macOS에는 `rm`에 이런 옵션이 없으므로, 와일드카드(`*`)로 여러 파일을 지울 때는 **같은 패턴으로 `ls`를 먼저 실행해서** 무엇이 지워질지 확인한 뒤, `↑`로 불러와 `ls`를 `rm`으로 바꿔 실행한다(2.3.5의 줄 편집).

```
ls data/*.csv      # 먼저 확인
rm data/*.csv      # ↑로 불러와서 ls만 rm으로 바꾼다
```

### 2.4.5 숨김 파일

1.3.5에서 본 것처럼 macOS와 리눅스에서는 이름이 `.`으로 시작하는 파일과 폴더가 **숨김 파일**이다. `practice` 폴더의 `.settings`가 그렇다.

```
# macOS
ls
ls -a
```

```
data            server.log      내 문서
.               ..              .settings       data            server.log      내 문서
```

`-a`(all)를 붙이면 보인다. 맨 앞의 `.`과 `..`은 "이 폴더"와 "부모 폴더"를 가리키는 특별한 이름이다(2.6.1). 이 둘이 거슬리면 `-A`를 쓴다.

Windows는 숨김의 기준이 다르다. 이름이 아니라 파일의 **숨김 속성**으로 정한다. 그래서 `.settings`는 그냥 `ls`에도 보인다. 반대로 숨김 속성이 있는 항목은 `-Force`를 붙여야 보인다.

```
# Windows
Get-ChildItem -Force
```

5장에서 `git init`을 하면 `.git`이라는 폴더가 생기는데, Windows용 Git은 이 폴더에 숨김 속성을 붙인다. 그래서 Windows에서도 `.git`은 `-Force`를 붙여야 보인다. 숨김 파일은 대부분 **설정 파일**이다(`.gitignore`, `.venv`, `.env`, `.vscode`, `.zshrc`). 프로그램이 알아서 쓰는 파일이라 평소에 가려 둔 것이지, 중요하지 않은 파일이라는 뜻이 아니다. 8장에서 다룰 API 키 파일 `.env`도 숨김 파일이다.

macOS의 `ls -l` 출력은 왼쪽부터 다음과 같다.

| 열 | 예 | 뜻 |
|---|---|---|
| 종류와 권한 | `-rw-r--r--` | 첫 글자가 `-`면 파일, `d`면 폴더. 나머지는 읽기·쓰기·실행 권한(3장에서 `chmod`와 함께) |
| 링크 수 | `1` | 지금은 무시한다 |
| 주인과 그룹 | `jinyoung staff` | 이 파일의 주인 |
| 크기 | `258B` | `-h`(human-readable)를 붙이면 `B`, `K`, `M`, `G` 단위로 보여 준다 |
| 수정 시각 | `Nov 13 09:30` | 마지막으로 내용이 바뀐 시각 |
| 이름 | `2026-09.csv` | |

PowerShell은 처음부터 이 정보를 보여 준다. `Mode`의 첫 글자가 `d`면 폴더, `a`는 "보관(archive)" 속성, `h`는 숨김 속성이다. `Length`는 바이트 단위 크기다.

크기와 수정 시각은 "파일이 정말 바뀌었나", "프로그램이 결과 파일을 썼나", "이 파일이 너무 커서 열면 안 되나"를 판단할 때 본다. 예를 들어 기초 과정 10장의 가계부 프로그램이 `*_summary.csv`를 썼는지는 수정 시각이 방금으로 바뀌었는지로 알 수 있다.

> **폴더 전체의 크기**
> `ls -l`이 보여 주는 폴더의 크기는 안에 든 파일 크기의 합이 아니다. 폴더 전체 크기는 macOS에서 `du -sh 폴더`로 본다. `.venv` 폴더가 얼마나 큰지 확인해 보면 왜 Git에 올리지 않는지 실감할 수 있다(`du -sh ~/python-lab/ch10/ledger_app/.venv`). PowerShell에서 같은 일을 하려면 3장의 파이프가 필요하다.

### 2.4.7 Finder·탐색기와 오가기

터미널과 화면을 오가며 일하는 경우가 많다.

| 하는 일 | macOS | Windows |
|---|---|---|

4. (Windows) `Copy-Item data data_copy2`처럼 `-Recurse` 없이 복사해 보고, `data_copy2` 안에 무엇이 있는지 확인한다.
5. `data/memo.txt`를 `archive` 폴더로 **옮기면서** 이름을 `2026-09-memo.txt`로 바꾼다.
6. 없는 폴더로 옮겨 본다. `mv archive/2026-09-memo.txt trash`를 실행하고, `trash`가 무엇이 되었는지 `ls -l`(Windows `Get-ChildItem`)로 확인한다. 결과를 적고, 이름을 원래대로(`archive/2026-09-memo.txt`) 되돌린다.
7. `data_copy`(와 `data_copy2`) 폴더를 지운다. 지우기 **전에** macOS는 `ls data_copy`로 안을 확인하고, Windows는 `-WhatIf`를 붙여 먼저 실행해 본다.
8. 숨김 파일을 확인한다. macOS는 `.settings`가 보이는 명령과 보이지 않는 명령을 각각 적는다. Windows는 `Get-ChildItem`과 `Get-ChildItem -Force` 모두에서 `.settings`가 보이는 것을 확인하고, 두 결과가 같은 이유를 적는다(2.4.5). Windows의 숨김 속성은 5장에서 `git init`으로 만든 `.git` 폴더로 다시 확인한다.
9. `practice` 폴더를 Finder·탐색기로 연다. 7번에서 지운 폴더가 휴지통에 있는지 확인한다.
10. 마지막으로 `ls -lh archive/2026`(Windows `Get-ChildItem archive/2026`)으로 복사한 파일의 크기와 수정 시각을 확인한다. 수정 시각이 원본과 같은지 다른지 적는다.

## 2.5 파일 내용 보기

파일 내용을 보려면 보통 VS Code에서 연다. 그런데 터미널에서 바로 보는 편이 나을 때가 있다. 파일이 아주 커서 편집기로 열기 부담스러울 때, 앞부분이나 끝부분만 보면 될 때, 프로그램이 지금 쓰고 있는 로그를 지켜볼 때, 그리고 화면이 없는 서버에서다.

| 하는 일 | macOS(zsh) | Windows(PowerShell 7) |
|---|---|---|
| 전체 출력 | `cat 파일` | `Get-Content 파일`(별칭 `cat`) |
| 쪽 단위로 넘기며 보기 | `less 파일` | `Get-Content 파일 \| more` 또는 `more 파일` |
| 앞 10줄 | `head -n 10 파일` | `Get-Content 파일 -TotalCount 10` |
| 끝 10줄 | `tail -n 10 파일` | `Get-Content 파일 -Tail 10` |
| 늘어나는 파일 지켜보기 | `tail -f 파일` | `Get-Content 파일 -Wait -Tail 10` |

### 2.5.1 `cat` — 짧은 파일 전체 보기

```
cat data/2026-10.csv
```

```
date,category,amount
2026-10-01,식비,24000
2026-10-02,식비,11000
...
```

`cat`은 파일 내용을 처음부터 끝까지 한꺼번에 출력한다. 몇십 줄 이하의 짧은 파일에 알맞다. 이름은 "이어 붙이다"(concatenate)에서 왔다. 여러 파일을 주면 이어서 출력한다. 여러 파일을 주는 문법은 셸마다 다르다.

```
# macOS
cat data/2026-09.csv data/2026-10.csv

# Windows
Get-Content data/2026-09.csv, data/2026-10.csv
```

PowerShell에서는 경로를 **쉼표**로 나열한다(별칭으로 써도 `cat data/2026-09.csv, data/2026-10.csv`). `-Path` 매개변수가 경로 목록을 받기 때문이다. zsh처럼 공백으로만 나누면 두 번째 경로를 받을 매개변수가 없다는 오류가 난다.

긴 파일에 `cat`을 쓰면 출력이 화면을 휙 지나가 버리고 끝부분만 남는다.

```
cat server.log
```

500줄이 지나간다. 이럴 때 쓰는 것이 다음 절의 `less`다.

### 2.5.2 `less` — 긴 파일을 쪽 단위로

```
# macOS
less server.log
```

화면 전체가 파일 내용으로 바뀌고 맨 아래에 `:`나 파일 이름이 표시된다. 이것을 **페이저**(pager)라고 한다. 파일을 한 화면씩 넘겨 보는 프로그램이다. 키로 조작한다.

| 키 | 하는 일 |
|---|---|
| `Space` 또는 `f` | 다음 쪽 |
| `b` | 이전 쪽 |
| `↓` / `↑`(또는 `j` / `k`) | 한 줄씩 |
| `g` / `G` | 맨 처음 / 맨 끝 |
| `/단어` + Enter | 아래로 찾기 |
| `n` / `N` | 다음 찾기 / 이전 찾기 |
| `-N` + Enter | 줄 번호 보이기·숨기기 |
| `q` | 나가기 |
| `h` | 도움말 |

예를 들어 `/ERROR` + Enter를 누르면 첫 번째 `ERROR` 줄로 가고 그 단어가 강조된다. `n`을 누를 때마다 다음 `ERROR`로 간다. 로그 파일에서 문제가 생긴 곳을 찾는 가장 빠른 방법이다.

`less`는 파일 전체를 한꺼번에 읽지 않고 필요한 부분만 읽는다. 그래서 수백 MB짜리 로그 파일도 바로 열린다. VS Code로 같은 파일을 열면 한참 걸리거나 경고가 뜬다.

**이미 `less`를 만났다**

2.2.4의 `man` 화면이 `less`다. 앞으로 만날 `git log`, `git diff`도 출력이 화면보다 길면 `less`로 보여 준다. **Windows에서도 그렇다.** Windows용 Git에는 `less`가 들어 있어서 Git의 긴 출력은 `less`로 열린다. 그러니 Windows 사용자도 이 표의 키를 익혀 둔다. 특히 **`q`로 나가기**를 모르면 `git log`를 실행한 뒤 터미널이 멈춘 것처럼 보인다.

**Windows에서 긴 파일 보기**

PowerShell에는 `less`가 없다. 대신 `more`로 쪽 단위로 본다.

```
# Windows
Get-Content server.log | more
```

`|`는 앞 명령의 출력을 뒤 명령에 넘기는 **파이프**다(3장). `more`는 `Space`로 다음 쪽, `Enter`로 다음 줄, `q`로 나가기만 된다. 뒤로 가기나 찾기는 안 된다. 긴 로그에서 무언가를 찾을 때는 PowerShell에서는 3장의 `Select-String`을 쓰거나 VS Code에서 연다.

### 2.5.3 `head`와 `tail` — 앞부분과 끝부분

```
# macOS
head -n 3 data/2026-10.csv
tail -n 3 server.log

# Windows
Get-Content data/2026-10.csv -TotalCount 3
Get-Content server.log -Tail 3
```

```
date,category,amount
2026-10-01,식비,24000
2026-10-02,식비,11000

2026-11-13 09:08:18 INFO 요청 498 처리
2026-11-13 09:08:19 INFO 요청 499 처리
2026-11-13 09:08:20 INFO 요청 500 처리
```

`-n`을 생략하면 10줄이다. PowerShell의 `-TotalCount`는 `-Head`나 `-First`로 써도 된다.

- **앞부분**은 파일의 **형식**을 확인할 때 본다. CSV 파일의 첫 줄(머리글)과 데이터 몇 줄을 보면 어떤 열이 있는지, 구분자가 무엇인지 알 수 있다. 데이터 처리 기초 과정에서 수백 MB짜리 CSV를 pandas로 읽기 전에 이렇게 먼저 본다(3장에서 줄 수 세기와 함께 다시 다룬다).
- **끝부분**은 **최근 기록**을 볼 때 본다. 로그 파일은 새 줄이 끝에 붙으므로 가장 최근 일은 끝에 있다.

### 2.5.4 늘어나는 로그 파일 지켜보기

서버 프로그램은 실행되는 동안 로그 파일에 계속 줄을 덧붙인다. 그 파일을 **실시간으로** 지켜보는 방법이 있다.

```
# macOS
tail -f app.log

# Windows
Get-Content app.log -Wait -Tail 10
```

`-f`(follow)를 붙이면 `tail`은 끝 10줄을 보여 준 뒤 **끝나지 않고 기다린다.** 파일에 새 줄이 붙으면 바로 화면에 출력한다. PowerShell의 `-Wait`도 같다(`-Tail 10`을 빼면 파일 전체를 먼저 보여 주고 기다린다). 그만 지켜보려면 `Ctrl+C`를 누른다. 프로그램이 멈추는 것이 아니라 **지켜보는 명령만** 멈춘다.

이 기능은 터미널 두 개가 필요하다. 하나에서는 로그를 쓰는 프로그램이 돌고, 다른 하나에서 지켜본다. 실습 2-5에서 직접 해 본다.

> **파이썬은 파일에 바로 쓰지 않는다**
> 파이썬의 `f.write()`는 글자를 바로 디스크에 쓰지 않고 잠시 **버퍼**(buffer)라는 메모리 공간에 모았다가 한꺼번에 쓴다. 그래서 로그를 쓰는 프로그램을 만들 때 `f.flush()`로 "지금 바로 써라"라고 하지 않으면, `tail -f`에 한참 동안 아무것도 나오지 않다가 한꺼번에 나온다. 실습 2-5의 `make_log.py`에서 `flush()`를 빼고 실행해 보면 차이를 볼 수 있다. 실제 프로그램은 파이썬의 `logging` 모듈(중급 과정)이 이 일을 대신한다.

### 실습 2-5. 로그 파일 읽기

`~/devtools-lab/ch02/practice`에서 한다. 답을 `~/devtools-lab/ch02/view.md`에 적는다.

1. `server.log`의 줄 수를 모른다고 하자. `head`(Windows `-TotalCount`)와 `tail`(Windows `-Tail`)로 첫 줄과 마지막 줄을 보고, 로그가 몇 시 몇 분부터 몇 시 몇 분까지인지 적는다.
2. (macOS) `less server.log`로 열어서 다음을 한다.
   - `/ERROR`로 첫 번째 `ERROR`를 찾고, 그 요청 번호를 적는다.
   - `n`을 눌러 다섯 번째 `ERROR`의 요청 번호를 적는다.
   - `G`로 끝으로 가서 `?ERROR`(위로 찾기)를 실행해 마지막 `ERROR`의 요청 번호를 적는다.
   - `q`로 나온다.
3. (Windows) `Get-Content server.log | more`로 열어서 `Space`로 몇 쪽 넘겨 보고 `q`로 나온다. 마지막 `ERROR`는 `Get-Content server.log -Tail 50`의 출력에서 눈으로 찾아 적는다. 3장에서 같은 일을 명령 한 줄로 하는 방법을 배운다.
4. 로그 쓰는 프로그램을 만든다. `practice` 폴더에 `make_log.py`를 만든다.
   ```python
   # make_log.py — 1초마다 로그를 한 줄씩 쓴다
   import time
   from datetime import datetime

   with open("app.log", "a", encoding="utf-8") as f:
       for i in range(1, 61):
           f.write(f"{datetime.now():%H:%M:%S} INFO 요청 {i} 처리\n")
           f.flush()
           time.sleep(1)
   ```
5. 터미널을 하나 더 연다(터미널 앱의 새 탭이나 새 창, 또는 VS Code 터미널 패널의 `+`). 두 터미널 모두 `~/devtools-lab/ch02/practice`로 이동한다.
6. 첫째 터미널에서 `make_log.py`를 실행한다. 프롬프트가 돌아오지 않는 것을 확인한다(60초 동안 실행된다).
7. 둘째 터미널에서 `app.log`를 지켜본다(`tail -f`, Windows `Get-Content -Wait -Tail 10`). 1초마다 줄이 늘어나는지 확인한다. 몇 줄 본 뒤 둘째 터미널에서 `Ctrl+C`를 누르고, 첫째 터미널의 프로그램은 계속 돌고 있는지 확인한다.
8. (선택) `make_log.py`에서 `f.flush()` 줄을 지우고 같은 실험을 다시 해서, 줄이 언제 나타나는지 적는다. 끝나면 `f.flush()`를 되돌린다.
9. 실험이 끝나면 `app.log`를 지운다.

## 2.6 경로와 이름의 함정

이 절은 "분명히 있는데 없다고 하는" 문제들을 다룬다. 기초 과정 7.2에서 상대 경로가 실행 위치에 따라 달라지는 문제를 보았다. 이번에는 셸이 경로를 **해석하는 방식** 때문에 생기는 문제다.

### 2.6.1 특별한 이름 — `~`, `.`, `..`, `-`

| 이름 | 뜻 | 예 |
|---|---|---|
| `~` | 홈 폴더 | `cd ~/devtools-lab` |
| `.` | 지금 폴더 | `code .`, `open .` |
| `..` | 부모 폴더 | `cd ..`, `cd ../..` |
| `-`(`cd`에서만) | 바로 전에 있던 폴더 | `cd -` |

`.`과 `..`은 2.4.5의 `ls -a`에서 보았듯이 모든 폴더 안에 실제로 들어 있는 특별한 항목이다. 그래서 `../data/memo.txt`처럼 경로 중간에도 쓸 수 있다.

`cd -`는 두 폴더를 오갈 때 편하다. zsh와 PowerShell 7 모두 된다.

```
cd ~/python-lab/ch10/ledger_app
cd ~/devtools-lab/ch02
cd -                  # 다시 ledger_app으로
cd -                  # 다시 ch02로
```

### 2.6.2 공백과 따옴표

셸은 줄을 **공백**으로 나누어 조각을 만든다(2.2.1). 그래서 이름에 공백이 있으면 셸은 한 이름을 두 조각으로 본다.

```
cd 내 문서
```

```
# macOS
cd: string not in pwd: 내

# Windows
Set-Location: A positional parameter cannot be found that accepts argument '문서'.
```

zsh는 `cd`에 조각 두 개(`내`, `문서`)를 받았다. zsh의 `cd`는 조각 두 개를 받으면 "지금 경로에서 앞 글자를 뒤 글자로 바꾼 경로로 가라"는 특별한 뜻으로 해석하기 때문에 이상한 오류가 났다. PowerShell은 `Set-Location`에 넘길 인자가 하나 더 남았다고 했다. 둘 다 "공백 때문에 조각이 나뉘었다"는 같은 문제다.

해결 방법은 공백을 이름의 일부라고 알려 주는 것이다. 다음 세 줄은 **같은 일을 하는 서로 다른 방법**이다. 차례로 시험해 보려면 하나를 실행할 때마다 `cd ..`로 `practice` 폴더에 돌아온 뒤 다음 줄을 실행한다.

```
cd "내 문서"          # 큰따옴표 — 두 셸 모두
cd '내 문서'          # 작은따옴표 — 두 셸 모두
cd 내\ 문서           # 공백 앞에 \ — zsh만
```

가장 쉬운 방법은 2.3.1의 Tab이다. 알아서 따옴표나 `\`를 넣어 준다.

**큰따옴표와 작은따옴표의 차이**

두 셸 모두 큰따옴표 안에서는 **변수를 값으로 바꾸고**, 작은따옴표 안에서는 **적은 그대로** 둔다.

```
echo "홈: $HOME"
echo '홈: $HOME'
```

```
# macOS
홈: /Users/jinyoung
홈: $HOME

# Windows
홈: C:\Users\jinyoung
홈: $HOME
```

`$HOME`은 홈 폴더 경로를 담은 변수다. zsh에서는 환경 변수, PowerShell에서는 PowerShell의 자동 변수지만 두 셸에서 같은 이름으로 쓸 수 있다. 변수는 3장에서 자세히 다룬다. 지금은 "**글자 그대로**를 원하면 작은따옴표, **변수를 넣고 싶으면** 큰따옴표"라고 기억해 둔다.

**따옴표 안의 `~`**

zsh는 따옴표 **안의** `~`를 홈 폴더로 바꾸지 않는다.

```
# macOS
cd "~/devtools-lab/ch02/practice/내 문서"
```

```
cd: no such file or directory: ~/devtools-lab/ch02/practice/내 문서
```

`~`라는 이름의 폴더를 찾다가 실패한 것이다. PowerShell의 `cd`는 이 경우에도 알아서 바꿔 주지만, 파이썬 같은 외부 프로그램에 넘기는 인자에서는 PowerShell도 `~`를 바꾸지 않을 수 있다. 두 셸에서 똑같이 동작하는 쓰는 법은 다음 둘 중 하나다. 둘 다 홈 폴더부터 적은 경로라서 지금 어느 폴더에 있든 같은 곳으로 간다.

```
cd ~/"devtools-lab/ch02/practice/내 문서"        # ~는 따옴표 밖에
cd "$HOME/devtools-lab/ch02/practice/내 문서"    # ~ 대신 $HOME (큰따옴표)
```

`README.md`에 명령을 적거나 프로그램에 경로를 넘길 때는 둘째 방법인 `"$HOME/..."`가 가장 확실하다.

**한글 이름**

한글 파일·폴더 이름은 터미널에서도 잘 다뤄진다. 이 장의 실습처럼 `내 문서`, `계획.txt`도 Tab으로 완성되고 따옴표로 감싸면 된다. 다만 프로젝트 안의 파일 이름, 특히 **코드가 읽는 파일과 코드 파일**의 이름은 영문 소문자, 숫자, `-`, `_`로 짓는 것을 권한다. 이유는 셋이다.

- 공백이 없으면 따옴표를 신경 쓸 일이 없다.
- 명령을 입력할 때 한/영 전환을 하지 않아도 된다. 이것만으로도 오타가 크게 준다.
- macOS에서 만든 한글 파일 이름을 압축하거나 다른 운영체제로 옮기면 `ㄱㅖㅎㅚㄱ`처럼 자모가 풀려 보이는 경우가 있다. macOS가 한글 이름을 자모로 나누어 저장하는 방식(NFD)을 쓰는 경우가 있어서 생기는 일이다. Git은 macOS에서 이 차이를 알아서 맞춰 주도록 설정되어 있지만, 다른 경로로 파일을 주고받을 때는 문제가 될 수 있다.

### 2.6.3 와일드카드

**와일드카드**(wildcard)는 여러 파일 이름을 한 번에 가리키는 패턴이다. 카드 게임에서 무엇으로든 쓸 수 있는 카드에서 온 이름이다.

| 기호 | 뜻 | 예 | 일치하는 것 |
|---|---|---|---|
| `*` | 아무 글자나 0개 이상 | `*.csv` | `.csv`로 끝나는 모든 파일(zsh에서는 숨김 파일 제외) |
| `?` | 아무 글자나 정확히 1개 | `2026-1?.csv` | `2026-10.csv`, `2026-11.csv` |
| `[ ]` | 괄호 안의 글자 중 하나 | `2026-0[89].csv` | `2026-08.csv`, `2026-09.csv` |

```
ls data/*.csv
ls data/2026-1?.csv
```

```
data/2026-09.csv  data/2026-10.csv  data/2026-11.csv
data/2026-10.csv  data/2026-11.csv
```

(Windows의 `ls`는 표로 보여 준다. 일치하는 파일은 같다.)

zsh의 `*`는 숨김 파일과 일치하지 않는다. `ls *`를 해도 `.settings`는 나오지 않는다.

파이썬의 `Path.glob()`(기초 과정 7.2)도 `*`, `?`, `[ ]`의 뜻은 같지만 **숨김 파일을 다루는 방식이 다르다.** `Path.glob()`의 `*`는 `.`으로 시작하는 이름과도 일치한다. `practice` 폴더에서 확인해 보면 차이가 보인다.

```
# macOS
python3 -c "from pathlib import Path; print(sorted(p.name for p in Path().glob('*')))"

# Windows
python -c "from pathlib import Path; print(sorted(p.name for p in Path().glob('*')))"
```

```
['.settings', 'data', 'server.log', '내 문서', ...]
```

(실습을 진행하며 만든 파일이 함께 나온다.) 셸의 와일드카드와 파이썬의 와일드카드가 세부까지 같다고 기대하지 않는다. 숨김 파일을 빼야 한다면 파이썬 코드에서 `.`으로 시작하는 이름을 직접 걸러 낸다.

### 2.6.4 누가 와일드카드를 펼치나

위의 두 명령은 두 셸에서 같은 결과를 낸다. 하지만 **결과를 만드는 주체가 다르다.** 이 차이는 파이썬 프로그램에 와일드카드를 넘길 때 드러난다.

**zsh(그리고 bash)는 셸이 먼저 펼친다.** 명령을 실행하기 **전에** 셸이 `data/*.csv`를 실제 파일 이름 목록으로 바꾸고, 바뀐 목록을 명령에 넘긴다. `ls`는 `*`를 본 적도 없다. `ls data/2026-09.csv data/2026-10.csv data/2026-11.csv`를 받았을 뿐이다. `echo`로 셸이 무엇으로 펼치는지 미리 볼 수 있다.

```
# macOS
echo data/*.csv
```

```
data/2026-09.csv data/2026-10.csv data/2026-11.csv
```

일치하는 파일이 하나도 없으면 zsh는 명령을 **실행하지 않고** 오류를 낸다.

```
# macOS
ls data/*.json
```

```
zsh: no matches found: data/*.json
```

(리눅스의 bash는 이때 오류를 내지 않고 `data/*.json`이라는 글자를 그대로 명령에 넘긴다. 같은 계열이지만 다른 점이다.)

**PowerShell은 cmdlet이 직접 해석한다.** PowerShell은 명령에 `data/*.csv`라는 글자를 **그대로** 넘긴다. `Get-ChildItem`(`ls`)이나 `Remove-Item`의 경로 매개변수가 와일드카드를 이해하도록 만들어져 있어서 스스로 파일을 찾는 것이다. 그래서 cmdlet이 아닌 **외부 프로그램**에는 와일드카드가 펼쳐지지 않은 채 글자 그대로 전달된다.

```
# Windows
echo data/*.csv
```

```
data/*.csv
```

PowerShell의 `echo`(`Write-Output`)는 경로를 다루는 명령이 아니므로 받은 글자를 그대로 출력했다.

**파이썬 프로그램으로 확인하기**

`practice` 폴더에 `show_args.py`를 만든다. 기초 과정 8.2.2에서 쓴 `sys.argv`를 출력하는 것이 전부다.

```python
# show_args.py — 받은 명령행 인자를 그대로 보여 준다
import sys

print(sys.argv[1:])
```

```
# macOS
python3 show_args.py data/*.csv

# Windows
python show_args.py data/*.csv
```

```
# macOS
['data/2026-09.csv', 'data/2026-10.csv', 'data/2026-11.csv']

# Windows
['data/*.csv']
```

**같은 명령, 같은 프로그램인데 받은 인자가 다르다.** macOS에서는 셸이 펼친 파일 이름 세 개를, Windows에서는 `data/*.csv`라는 글자 하나를 받았다. 이 프로그램이 받은 인자를 파일 이름으로 열려고 했다면 macOS에서는 잘 되고, Windows에서는 `data/*.csv`라는 파일이 없다는 `FileNotFoundError`가 났을 것이다.

macOS에서도 와일드카드를 **따옴표로 감싸면** 셸이 펼치지 않는다. 2.6.2의 규칙 그대로 따옴표 안은 "글자 그대로"이기 때문이다.

```
# macOS
python3 show_args.py 'data/*.csv'
```

```
['data/*.csv']
```

### 2.6.5 운영체제에 상관없이 처리하기

프로그램이 여러 파일을 와일드카드로 받아야 한다면, **셸이 펼쳐 주기를 기대하지 말고 프로그램이 직접 펼치면** 된다. 기초 과정 7.2에서 쓴 `pathlib`의 `glob()`을 쓴다.

`practice` 폴더에 `show_paths.py`를 만든다.

```python
# show_paths.py — 와일드카드가 든 인자를 프로그램이 직접 펼친다
import sys
from pathlib import Path

WILDCARDS = "*?["


def expand(args):
    """명령행 인자를 경로 목록으로 바꾼다. 와일드카드가 있으면 직접 펼친다."""
    paths = []
    for arg in args:
        if any(ch in arg for ch in WILDCARDS):
            pattern = Path(arg)
            matches = sorted(pattern.parent.glob(pattern.name))
            if not matches:
                print(f"일치하는 파일이 없습니다: {arg}", file=sys.stderr)
            paths.extend(matches)
        else:
            paths.append(Path(arg))
    return paths


def main():
    for path in expand(sys.argv[1:]):
        print(path)


if __name__ == "__main__":
    main()
```

- 인자에 와일드카드 글자가 없으면 그대로 `Path`로 만든다. macOS에서 셸이 이미 펼쳐 준 이름이 이쪽으로 온다.
- 와일드카드가 있으면 경로를 **폴더 부분**(`pattern.parent`, 예: `data`)과 **이름 부분**(`pattern.name`, 예: `*.csv`)으로 나누고, 폴더에서 이름 패턴으로 찾는다. Windows에서 받은 `data/*.csv`나 macOS에서 따옴표로 감싸 넘긴 `'data/*.csv'`가 이쪽으로 온다.
- 일치하는 파일이 없으면 표준 오류로 알린다(기초 과정 8.2.2).

```
# macOS
python3 show_paths.py data/*.csv
python3 show_paths.py 'data/*.csv'

# Windows
python show_paths.py data/*.csv
```

```
# macOS — 두 명령 모두
data/2026-09.csv
data/2026-10.csv
data/2026-11.csv

# Windows
data\2026-09.csv
data\2026-10.csv
data\2026-11.csv
```

이제 세 경우 모두 같은 파일 세 개를 얻는다. Windows에서 `\`로 출력되는 것은 `Path`가 운영체제의 경로 구분자로 보여 주기 때문이다(기초 과정 7.2). 파일을 여는 데는 아무 차이가 없다.

이 함수는 와일드카드가 **마지막 이름 부분에만** 있는 경우를 처리한다(`data/*.csv`는 되고 `*/2026-09.csv`는 안 된다). 대부분의 명령행 프로그램에는 이것으로 충분하다.

> **명령행 프로그램을 만들 때의 원칙**
> 운영체제마다 셸이 다르게 행동하는 것은 바꿀 수 없다. 그래서 여러 운영체제에서 쓸 프로그램은 **셸이 무엇을 해 줄지 기대하지 않도록** 만든다. 와일드카드는 프로그램이 직접 펼치고, 경로는 `pathlib`으로 다루고, 파일은 인코딩을 지정해서 연다(기초 과정 7장). 1.1.3에서 말한 "두 운영체제에서 똑같이 돌아야 하면 파이썬으로 쓴다"는 선택(3장)도 같은 이유에서 나온다.

### 2.6.6 대소문자

`README.md`와 `readme.md`는 같은 파일인가? 운영체제마다 답이 다르다.

| 운영체제 | 대소문자 | 예 |
|---|---|---|
| macOS(기본 설정) | 구분하지 않는다. 다만 만들 때의 대소문자는 기억한다 | `cat README.MD`로 `README.md`를 읽을 수 있다 |
| Windows | 구분하지 않는다. 만들 때의 대소문자는 기억한다 | 위와 같다 |
| 리눅스 | **구분한다** | `README.md`와 `readme.md`가 서로 다른 파일로 함께 있을 수 있다 |

내 컴퓨터(macOS·Windows)에서는 대소문자를 틀려도 파일이 열리기 때문에 문제가 숨어 있다가, **리눅스에서 처음 드러난다.** 예를 들어 코드에 `open("Data/2026-10.csv")`라고 적었는데 실제 폴더 이름이 `data`라면, 내 맥에서는 잘 돌고 리눅스 서버나 Docker 컨테이너, GitHub Actions에서는 `FileNotFoundError`가 난다. 2단계 후반의 배포 과정에서 자주 만나는 오류다. 그래서 다음 규칙을 지킨다.

- 파일과 폴더 이름은 **소문자**로 짓는다(관례상 `README.md`, `LICENSE` 같은 몇몇 파일은 예외).
- 코드와 명령에서는 저장된 이름과 **대소문자까지 똑같이** 적는다. Tab 자동 완성을 쓰면 저절로 지켜진다.

와일드카드도 셸마다 다르다. zsh의 와일드카드는 macOS에서도 대소문자를 구분해서, `ls data/*.CSV`는 `2026-09.csv`와 일치하지 않는다. PowerShell의 와일드카드는 대소문자를 구분하지 않는다.

> **대소문자만 바꾸는 이름 변경**
> macOS와 Windows에서 `readme.md`를 `README.md`로 바꾸는 것은 `mv readme.md README.md`로 할 수 있다. 하지만 이렇게 대소문자만 바꾼 변경을 Git이 알아채지 못하는 경우가 있다. Git에서 파일 이름을 바꾸는 방법은 5장의 `git mv`에서 다룬다.

## 2.7 터미널에서 쓰는 편집기

### 2.7.1 왜 터미널에서 편집기가 열리나

어떤 명령은 실행 도중 **글을 입력받아야** 한다. 대표적인 것이 `git commit`이다. 커밋 메시지를 `-m "메시지"`로 주지 않으면, Git은 메시지를 쓸 수 있도록 **편집기를 연다.** 메시지를 쓰고 저장하고 편집기를 닫으면, Git은 그 내용을 커밋 메시지로 쓴다.

이때 열리는 편집기는 설정에 따라 다른데, 아무것도 설정하지 않았으면 대개 **Vim**이다. Windows용 Git도 설치할 때 기본 편집기로 Vim을 고른다. 5장에서 이것을 VS Code로 바꾸지만, 그 전에 한 번쯤은 Vim이 열린다. 리눅스 서버에서 설정 파일을 고칠 때도 Vim이나 nano를 만난다. 그러니 **빠져나오는 방법**만큼은 알아 둔다.

### 2.7.2 Vim에서 빠져나오기

Vim이 열리면 이런 화면이 된다.

```

# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored, and an empty message aborts the commit.
#
# On branch main
# Changes to be committed:
#       new file:   README.md
#
~
~
~
".git/COMMIT_EDITMSG" 9L, 241B
```

글자를 쳐도 입력이 안 되거나, 엉뚱한 일이 일어난다. 마우스로 닫을 수도 없다. Vim에는 **모드**가 있기 때문이다.

| 모드 | 들어가는 법 | 이 모드에서 키를 누르면 | 화면 맨 아래 |
|---|---|---|---|
| 일반 모드 | 처음 열렸을 때, 또는 `Esc` | 키가 **명령**으로 해석된다(`x`는 한 글자 지우기, `dd`는 한 줄 지우기) | 파일 정보나 빈칸 |
| 입력 모드 | 일반 모드에서 `i` | 일반 편집기처럼 글자가 입력된다 | `-- INSERT --` |
| 명령줄 모드 | 일반 모드에서 `:` | 맨 아래 줄에 명령을 입력한다 | `:` |

빠져나오기에 필요한 것은 다음뿐이다.

| 하고 싶은 일 | 누르는 키 |
|---|---|
| 글 쓰기 | `i`를 누르고 입력 |
| 저장하고 나가기 | `Esc` → `:wq` → Enter |
| 저장하지 않고 나가기 | `Esc` → `:q!` → Enter |
| 커밋을 취소하고 나가기 | `Esc` → `:cq` → Enter |
| 실수로 무언가 지웠을 때 되돌리기 | `Esc` → `u` |

- `:w`는 저장(write), `:q`는 나가기(quit)다. `!`는 "저장하지 않은 변경이 있어도 무시하고"라는 뜻이다.
- `:cq`는 Vim을 **실패 종료 코드**로 끝낸다. 1.3.4에서 본 종료 코드다. Git은 편집기가 실패로 끝나면 커밋을 하지 않는다. 메시지를 지우지 않은 채로 커밋을 취소하고 싶을 때 쓴다. (메시지를 모두 지우고 `:wq`해도 "빈 메시지"라서 커밋이 취소된다.)
- 어떤 상태인지 모르겠으면 **`Esc`를 두어 번** 누른다. 언제나 일반 모드로 돌아온다.

> **한글 입력 상태에서는 명령이 듣지 않는다**
> 일반 모드의 명령은 영문 키다. 입력기가 한글 상태이면 `:`는 입력되지만 `wq`가 `ㅈㅂ`으로 들어가서 "Not an editor command" 같은 오류가 난다. Vim에서 명령이 듣지 않으면 먼저 **한/영 상태**를 확인한다. 한국어 사용자가 Vim에서 가장 자주 막히는 지점이다.

Vim은 익숙해지면 매우 빠른 편집기라서 일부러 배워 쓰는 개발자도 많다. 관심이 생기면 macOS에서 `vimtutor`를 실행하면 30분짜리 연습 과정이 열린다. 이 과정에서는 빠져나오는 법까지만 다룬다.

### 2.7.3 nano

nano는 Vim보다 단순한 터미널 편집기다. 리눅스 서버에서 자주 만난다. 모드가 없어서 열자마자 글자를 입력할 수 있고, 화면 맨 아래에 단축키가 적혀 있다. `^`는 `Ctrl`이라는 뜻이다.

| 하고 싶은 일 | 키 |
|---|---|
| 저장 | `Ctrl+O` → 파일 이름 확인 → Enter |
| 나가기 | `Ctrl+X`(저장하지 않은 변경이 있으면 저장할지 묻는다. `Y` 또는 `N`) |
| 찾기 | `Ctrl+W` |

macOS에서 `nano`를 실행하면 비슷한 편집기인 pico가 열린다. 저장(`Ctrl+O`)과 나가기(`Ctrl+X`)는 같다. Windows에는 기본으로 들어 있지 않다.

터미널 편집기에서 긴 글을 쓸 일은 없다. **Git이 여는 편집기를 VS Code로 바꾸는 방법**은 5장에서 배운다. 그 뒤로는 `git commit`을 하면 VS Code 탭이 열리고, 메시지를 쓰고 탭을 닫으면 커밋이 된다.

### 실습 2-7. Vim 탈출 연습

`~/devtools-lab/ch02`에서 한다.

1. Vim으로 새 파일을 연다.
   ```
   # macOS
   vim vim_test.txt

   # Windows — Windows용 Git에 들어 있는 Vim
   & "$env:ProgramFiles\Git\usr\bin\vim.exe" vim_test.txt
   ```

   (Windows의 `&`는 "따옴표로 감싼 이 경로의 프로그램을 실행하라"는 뜻이다. 경로에 공백이 있어서 따옴표가 필요하고, 따옴표로 감싼 글자를 실행하려면 앞에 `&`가 필요하다.)
2. 아무 글자나 쳐 본다. 무슨 일이 일어나는지 관찰한다. 놀라지 말고 `Esc`를 두어 번 누른 뒤 `u`를 몇 번 눌러 되돌린다.
3. `i`를 누르고 `첫 줄`을 입력한다. 화면 아래의 `-- INSERT --`를 확인한다.

6. 다시 열어서, 입력기를 **한글**로 바꾼 상태에서 `Esc` → `:wq` → Enter를 해 본다. 어떤 메시지가 나오는지 적는다. 영문으로 바꿔 다시 나온다.

## 정리

| 항목 | 핵심 |
|---|---|
| 터미널과 셸 | 터미널은 창(글꼴·탭·복사), 셸은 명령을 해석하고 실행하는 프로그램(zsh, bash, PowerShell) |
| 프롬프트 | 현재 폴더, `(.venv)`, 덜 끝난 입력(`dquote>`, `>>`), 프롬프트가 없으면 실행 중 |
| 명령의 정체 | 셸 내장 명령, cmdlet, 함수, 별칭, 외부 프로그램. zsh `type`, PowerShell `Get-Command`(`CommandType` 열). PowerShell의 `ls`·`cp`·`rm`은 cmdlet의 별칭, `mkdir`는 `New-Item`을 부르는 함수라 유닉스 옵션이 통하지 않는다 |
| 명령의 구조 | 명령·(하위 명령)·옵션·인자. 짧은 옵션(`-a`, 합쳐 쓰기 `-la`)과 긴 옵션(`--all`), `--`는 옵션의 끝. PowerShell 매개변수는 `-Name 값`, 스위치, 위치 매개변수 |
| 도움말 | 외부 프로그램 `--help`/`-h`, Git `-h`/`--help`, macOS 기본 명령 `man`, PowerShell `Get-Help`(`-Examples`, `-Online`, `Update-Help -UICulture en-US`) |
| 사용법 찾는 순서 | 도움말 → 공식 문서 → AI(운영체제와 셸을 밝히고, 답을 도움말로 확인) |
| 빠르게 입력하기 | Tab, `↑`, `Ctrl+R`, `Ctrl+C`(멈추기), `Ctrl+L`(화면), 줄 맨 앞·줄 지우기. zsh의 `Ctrl+Z`는 일시 정지(`fg`) |
| 만들기 | `mkdir -p` / `New-Item -ItemType Directory`(중간 폴더 자동, 이미 있으면 오류), `touch` / `New-Item`(`-Force`는 덮어쓰기) |
| 복사·이동 | `cp -r` / `Copy-Item -Recurse`(빠뜨리면 macOS는 오류, Windows는 빈 폴더), 대상 폴더가 있으면 그 안으로. `mv`는 옮기기와 이름 바꾸기가 같다. 대상 파일이 있으면 `cp`·`mv`·`Copy-Item`은 묻지 않고 덮어쓰고(macOS는 `-i`로 묻게 한다), `Move-Item`은 오류를 낸다(`-Force`로 덮어쓰기) |
| 지우기 | 휴지통을 거치지 않는다. `rm -r` / `Remove-Item -Recurse`. 먼저 `ls 패턴`, PowerShell은 `-WhatIf`. `rm -rf`는 묻지 않고 모두 지운다 |
| 숨김 파일 | macOS·리눅스는 `.`으로 시작하는 이름(`ls -a`), Windows는 숨김 속성(`-Force`). 대부분 설정 파일이다 |
| 파일 내용 | `cat`(짧은 파일), `less`(쪽 단위, `/` 찾기, `q` 나가기 — `man`, `git log`도 같은 화면), `head`/`tail`(`-TotalCount`/`-Tail`), `tail -f`(`-Wait`)로 로그 지켜보기 |
| 경로 | `~`, `.`, `..`, `cd -`. 공백은 따옴표나 Tab. 작은따옴표는 글자 그대로, 큰따옴표는 변수를 바꾼다. zsh는 따옴표 안의 `~`를 바꾸지 않는다 → `"$HOME/..."` |
| 와일드카드 | `*`, `?`, `[ ]`. zsh는 셸이 먼저 펼쳐서 넘긴다(없으면 오류). PowerShell은 cmdlet이 해석하고 외부 프로그램에는 글자 그대로. 프로그램은 `pathlib`의 `glob()`으로 직접 펼친다 |
| 대소문자 | macOS·Windows는 구분하지 않고 리눅스는 구분한다. 이름은 소문자로, 코드에는 저장된 그대로 |
| 터미널 편집기 | Vim: `Esc` → `:wq`(저장하고 나가기), `:q!`(버리고 나가기), `:cq`(커밋 취소). 한/영 확인. nano: `Ctrl+O` 저장, `Ctrl+X` 나가기 |

## 확인 문제

1. 터미널과 셸은 각각 무엇인가? "Windows 터미널의 기본 프로필을 PowerShell 7로 바꾸었다"는 것은 둘 중 무엇을 바꾼 것인가?
2. 프롬프트가 `dquote>`로 바뀌었다(Windows는 `>>`). 무슨 상태이고 어떻게 빠져나오는가? 프롬프트가 아예 나타나지 않는 것과는 어떻게 다른가?
3. Windows PowerShell 7에서 `ls -la`를 실행했더니 `Get-ChildItem: A parameter cannot be found that matches parameter name 'la'.`라는 오류가 났다. 왜 그런가? 오류 메시지에 `ls`가 아니라 `Get-ChildItem`이 나온 이유는? 이 명령의 정체를 확인하는 명령은?
4. `git log --oneline -n 5 -- README.md`를 명령·하위 명령·옵션·옵션의 값·인자로 나누어라. `--`는 무슨 뜻인가?
5. macOS에서 `cp --help`를 실행했더니 오류가 났다. 왜 그런가? `cp`의 설명서는 어떻게 보는가? AI가 알려 준 `ls` 옵션이 macOS에서 "없는 옵션"이라고 나오는 경우가 생기는 이유는?
6. 처음 보는 명령의 사용법을 찾는 세 단계를 말하라. AI에게 물을 때 꼭 함께 알려 줄 것은 무엇이고, 받은 답으로 무엇을 하는가?
7. Windows에서 `Copy-Item data data_backup`을 실행했다. 오류가 나지 않았는데 `data_backup` 안이 비어 있었다. 왜 그런가? 같은 명령을 macOS의 `cp`로 하면 어떻게 되는가?
8. `mv report.txt archive`를 실행했는데 `archive` 폴더 안에 `report.txt`가 없다. 어떤 일이 일어났을 수 있는가? 이런 실수를 막는 방법은?
9. 터미널에서 `rm -r` 또는 `Remove-Item -Recurse`로 지운 폴더를 되살릴 수 있는가? `rm data/*.csv`처럼 와일드카드로 여러 파일을 지우기 전에 macOS와 Windows에서 각각 무엇을 하는가? `rm -rf`의 `-f`는 무엇을 더하는가?
10. `git log`를 실행했더니 출력이 끝나지 않고 터미널이 멈춘 것처럼 보인다. 무슨 상태이며 어떻게 나오는가? Windows에서도 같은 일이 생기는 이유는? 이 화면에서 `ERROR`라는 단어를 찾으려면?
11. 로그를 쓰는 파이썬 프로그램을 실행하고 다른 터미널에서 `tail -f`로 지켜보는데, 한참 동안 아무것도 나오지 않다가 한꺼번에 나왔다. 왜 그런가? 어떻게 고치는가?
12. macOS에서 `cd "~/devtools-lab/ch02"`가 실패했다. 왜 그런가? macOS와 Windows 모두에서 동작하도록 고쳐 써라.
13. `python main.py data/*.csv`를 macOS에서 실행하면 잘 되는데 Windows에서는 `FileNotFoundError: ... 'data/*.csv'`가 났다. 두 셸이 와일드카드를 다루는 방식의 차이로 설명하라. macOS에서 `data/*.json`처럼 일치하는 파일이 없을 때는 무슨 일이 일어나는가? 프로그램을 어떻게 고치면 운영체제에 상관없이 동작하는가?
14. 내 맥에서는 잘 돌던 프로그램이 리눅스 서버에서 `FileNotFoundError: 'Data/2026-10.csv'`를 냈다. 실제 폴더 이름은 `data`다. 왜 내 맥에서는 문제가 없었는가? 이런 문제를 막는 규칙 두 가지는?
15. `git commit`을 실행했더니 Vim이 열렸다. 메시지를 쓰고 커밋하려면 어떻게 하는가? 커밋하지 않고 나가려면? `:wq`를 입력했는데 "Not an editor command"라는 오류가 났다면 무엇을 확인하는가?
