# 파이썬 중급

[AI 엔지니어 학습 로드맵](../README.md) 2단계 "LLM 응용 서비스 개발"의 세 번째 항목인 **파이썬 중급**(컴프리헨션, 제너레이터, 데코레이터, 타입 힌트, 비동기(asyncio), 테스트(pytest), 패키지 배포)의 상세 학습 항목이다.

## 학습 목표

[파이썬 기초](../python-basic-lab/README.md)에서 "동작하는 코드를 직접 읽고 쓰고 고치는" 수준에 도달했다면, 이 과정에서는 **LLM 라이브러리와 웹 프레임워크의 코드를 막힘없이 읽고, 같은 방식으로 직접 쓸 수 있는** 수준에 도달한다. 기초 과정 10장에서 "아직 배우지 않은 문법"으로 적어 둔 것(컴프리헨션, `yield`, `async`/`await`, 직접 만드는 데코레이터, `match` 문)을 모두 다루고, 타입 검사·자동 테스트·패키지 배포로 **남이 믿고 쓸 수 있는 코드**를 만드는 방법을 익힌다.

이후 과정과의 연결은 다음과 같다.

- **데이터 처리 기초** — 컴프리헨션과 제너레이터로 JSON/CSV 데이터를 거르고 변환한다.
- **웹·API 기초, LLM API 활용** — 스트리밍 응답(이터레이터), 동시 요청(asyncio), 재시도(데코레이터), 구조화 출력·도구 정의(타입 힌트와 Pydantic)가 그대로 쓰인다.
- **RAG, 에이전트 개발** — 문서 청킹(제너레이터), `@tool`·`@mcp.tool()` 같은 도구 정의 데코레이터, 비동기 도구 호출을 읽고 쓴다.
- **LLM 평가(Evals) 심화, LLM 서비스 배포** — pytest 기반 회귀 테스트, FastAPI의 `async def`와 타입 힌트 기반 요청 검증, `pyproject.toml` 기반 프로젝트 구성으로 이어진다.

## 선행 조건

- [파이썬 기초](../python-basic-lab/README.md)를 마쳤거나, 함수·클래스·예외·파일 입출력·모듈/패키지·가상환경을 써서 작은 프로그램을 만들 수 있다.
- 로드맵의 "개발 도구"를 마쳐서 터미널, Git/GitHub, VS Code를 사용할 수 있다. 이 과정의 실습은 장마다 Git으로 커밋하며 진행한다.
- 파이썬 3.12 이상. 제네릭 문법(`def first[T](...)`), `itertools.batched()` 등 3.12에서 추가된 기능을 사용한다.

## 학습 항목

장의 순서는 로드맵의 나열 순서와 조금 다르다. 테스트(6장)를 비동기(7장)보다 먼저 배워서, 비동기 코드와 그 이후의 실습을 처음부터 테스트와 함께 작성한다.

### 1장. 시작하기

- **중급 과정의 지도** — 기초 과정 10장 선택 활동에서 적어 둔 "아직 배우지 않은 문법"과 이 과정의 장 연결, LLM SDK·FastAPI·LangChain 예제 코드에서 이 과정의 문법이 등장하는 모습 미리 보기
- **실습 환경** — 파이썬 버전 확인(3.12 이상), 실습 폴더·가상환경·Git 저장소 준비, VS Code의 Pylance로 정의로 이동·타입 정보 보기
- **기초 과정 점검** — 이 과정이 기대는 개념 다시 확인: 변수는 객체를 가리키는 이름(3.2), 함수도 값(4.4), `*args`/`**kwargs`(4.2), 클래스와 `self`(5장), 예외의 전파(6장), `with` 문(7.1.4)

### 2장. 컴프리헨션과 표현력 있는 문법

- **리스트 컴프리헨션** — `for`+`append()`와 `map()`/`filter()`를 컴프리헨션으로 바꾸기, 조건으로 거르기, 조건 표현식과 함께 쓰기, 중첩 컴프리헨션을 읽는 순서
- **딕셔너리·집합 컴프리헨션** — 키와 값 뒤집기, JSON 형태 데이터에서 필요한 필드만 뽑기, 중복 없는 값 모으기
- **컴프리헨션을 쓰지 않을 때** — 부수 효과(출력·파일 쓰기)가 목적인 반복, 두 겹 이상의 중첩, 디버깅하기 어려운 긴 식, 반복문으로 되돌리는 판단 기준
- **더 표현력 있는 문법** — 확장 언패킹(`first, *rest = items`), 딕셔너리 병합(`|`, `{**a, **b}`)과 `|`가 부르는 `__or__`, `any()`/`all()`, 할당 표현식(`:=`)과 남용을 피하는 기준
- **`match` 문** — 값 패턴, 시퀀스 패턴, 매핑 패턴, 클래스 패턴, 가드(`if`), `case _`, `if`/`elif` 사슬과의 선택 기준, LLM 응답 메시지의 종류(텍스트/도구 호출/오류)에 따라 딕셔너리를 분기하는 예

### 3장. 이터레이터와 제너레이터

- **이터러블과 이터레이터** — `for` 문이 실제로 하는 일(`iter()`, `next()`, `StopIteration`), 한 번 순회하면 소진되는 이터레이터, 이미 써 온 이터레이터(파일 객체, `zip`, `map`, `enumerate`)와 이터레이터가 아닌 이터러블(`range`, `dict.items()` 같은 뷰), `__iter__`/`__next__`로 이터레이터 클래스 만들기
- **제너레이터 함수** — `yield`, 실행이 멈췄다가 이어지는 모습을 디버거로 확인, 리스트를 돌려주는 함수와의 비교, 지연 평가와 메모리 사용량
- **제너레이터 표현식** — 괄호로 쓰는 컴프리헨션, `sum(x for x in ...)`, 리스트 컴프리헨션과의 선택 기준
- **제너레이터 파이프라인** — 큰 파일을 줄 단위로 읽고 거르고 변환하는 제너레이터 연결, `yield from`, 일정한 크기로 묶어 처리하기(배치), RAG의 문서 청킹·API 일괄 호출로의 연결
- **`itertools`** — `islice`, `chain`, `batched`, `groupby`(정렬이 먼저 필요한 이유), `count`, 무한 이터레이터를 안전하게 다루기
- **스트리밍 응답 읽기** — LLM SDK의 스트리밍 응답이 이터레이터라는 것, 가짜 스트림 제너레이터로 조각을 받는 즉시 출력하면서 전체 답을 모으는 실습

### 4장. 클로저와 데코레이터

- **중첩 함수와 클로저** — 함수 안의 함수, 함수를 돌려주는 함수, 바깥 변수를 기억하는 클로저, `nonlocal`, 반복문 안에서 만든 람다가 모두 같은 값을 보는 늦은 바인딩 함정
- **데코레이터 만들기** — `@deco`는 `f = deco(f)`의 줄임이라는 것, 래퍼 함수, `*args`/`**kwargs`로 어떤 함수든 감싸기, `functools.wraps`로 이름·독스트링 보존, 데코레이터 여러 개를 겹쳐 붙일 때의 순서
- **인자를 받는 데코레이터** — 세 겹 구조 읽기, 재시도 데코레이터(횟수·대기 시간·지수 백오프·다시 시도할 예외 지정) — LLM API의 시간 초과·요청 한도 초과(429) 대응으로 연결
- **표준 라이브러리의 데코레이터** — `functools.cache`/`lru_cache`(같은 입력의 결과 재사용, 같은 프롬프트 응답 캐시의 아이디어), `@classmethod`(대체 생성자 `from_dict()`), `@staticmethod`, 기초 과정에서 붙여 쓰기만 한 `@property`·`@dataclass` 다시 보기(`__eq__`와 `__hash__`의 약속, `NotImplemented`)
- **등록 데코레이터** — 함수를 딕셔너리에 등록하는 데코레이터를 직접 만들어, 웹 프레임워크의 `@app.get("/...")`, MCP 서버의 `@mcp.tool()`이 하는 일 이해하기, 등록 대신 함수를 도구 객체로 바꿔 돌려주는 LangChain의 `@tool`과 비교하기
- **컨텍스트 관리자 만들기** — `with` 문이 실제로 하는 일, `__enter__`/`__exit__`로 만들기, `contextlib.contextmanager`로 제너레이터 하나로 만들기(3장의 `yield`와 이 장의 데코레이터가 만나는 곳), 실행 시간 측정·임시 설정 변경 예

### 5장. 타입 힌트

- **정적 타입 검사** — 기초 과정의 타입 힌트(5.4.2, 8.2.5)를 "읽기"에서 "검사받기"로, mypy 설치와 실행, VS Code(Pylance)의 타입 검사 모드, 검사 오류 읽기, `reveal_type()`, 기존 코드에 점진적으로 도입하기
- **타입 좁히기** — `int | None`을 받았을 때 `None`을 먼저 처리하기, `isinstance()`로 좁히기, `assert`, `cast()`를 최후의 수단으로 두는 이유
- **컬렉션과 함수의 타입** — 매개변수는 넓게(`Iterable`, `Sequence`, `Mapping`), 반환값은 구체적으로(`list`, `dict`), `Callable`, 제너레이터의 반환 타입(`Iterator`, `Generator`), 데코레이터의 타입(`ParamSpec`) 읽기
- **제네릭** — 타입 매개변수(`def first[T](items: list[T]) -> T`), 제네릭 클래스, `type` 별칭 문, 옛 표기(`TypeVar`, `Generic`) 읽기
- **설계에 쓰는 타입** — `Literal`, `TypedDict`, `Enum`, 구조적 타이핑을 위한 `Protocol`(예: LLM 클라이언트를 `Protocol`로 정의하고 실제 클라이언트와 가짜 클라이언트를 바꿔 끼우기 — 6장 테스트로 연결), 특별한 메서드 한눈에 보기(문법과 메서드의 대응표인 파이썬 데이터 모델, `__len__`·`__getitem__`·`__contains__`·`__bool__`로 리스트처럼 쓰는 클래스, `__or__`로 읽는 LangChain의 `prompt | model | parser`)
- **실행 중 검증과 Pydantic** — `BaseModel`, 필드 타입·기본값·검증 규칙(`Field`), 딕셔너리·JSON에서 모델 만들기(`model_validate`, `model_validate_json`), 검증 오류 읽기, JSON 스키마 생성(`model_json_schema`), LLM 구조화 출력·도구 정의·FastAPI 요청 본문과의 연결, 데이터 클래스와 Pydantic의 선택 기준

### 6장. 테스트

- **자동 테스트가 필요한 이유** — 기초 과정 10장의 `check_samples.py`를 돌아보기, 고친 곳 때문에 멀쩡하던 곳이 망가지는 회귀, AI가 고친 코드를 테스트로 검토하기
- **pytest 시작** — 설치, 테스트 파일·함수 이름 규칙, `assert`와 실패 메시지 읽기, 실행 옵션(`-v`, `-x`, `-k`, 파일·함수 하나만 실행), VS Code 테스트 탐색기
- **테스트 작성 기술** — 준비·실행·확인(Arrange-Act-Assert), 정상·경계·실패 경우 나누기, `pytest.raises()`, `pytest.approx()`, `@pytest.mark.parametrize`로 여러 입력 한 번에 검사하기
- **픽스처** — `@pytest.fixture`, `yield` 픽스처로 준비와 정리(3·4장 연결), `conftest.py`, 내장 픽스처 `tmp_path`(임시 파일), `monkeypatch`(환경 변수·함수 바꿔 끼우기), `capsys`(출력 확인)
- **외부 의존을 떼어 내고 테스트하기** — 네트워크·LLM API를 직접 부르지 않는 테스트, 의존성 주입, `Protocol`로 만든 가짜 객체, `unittest.mock` 기초, 실제 API를 부르는 테스트를 마커로 표시해 따로 실행하기
- **코드 품질 도구** — `pytest-cov`로 커버리지 보기와 숫자의 함정, `ruff`로 린트·포맷, mypy·ruff·pytest를 한 번에 돌리는 습관, LLM 출력처럼 매번 달라지는 결과에서 무엇을 테스트로 단정하고 무엇을 평가(Evals)로 넘길지

### 7장. 비동기(asyncio)

- **왜 비동기인가** — 입출력 대기 시간, 몇 초씩 걸리는 LLM API 호출 20개를 차례로 할 때와 동시에 할 때, 동시성과 병렬성의 차이, CPU를 쓰는 작업은 asyncio로 빨라지지 않는다는 점(스레드·프로세스와의 간단한 비교)
- **코루틴과 이벤트 루프** — `async def`, `await`, `asyncio.run()`, `await`를 빠뜨렸을 때의 증상, `asyncio.sleep()`과 `time.sleep()`(블로킹)의 차이, Jupyter에서 `await`를 바로 쓸 수 있는 이유
- **동시에 실행하기** — 태스크, `asyncio.gather()`, `asyncio.TaskGroup`, 하나가 실패했을 때의 동작(`return_exceptions`, `ExceptionGroup`과 `except*` 읽기)
- **시간 제한과 동시 실행 수 제한** — `asyncio.timeout()`, `asyncio.Semaphore`로 API 요청 한도 지키기, 취소, 4장의 재시도 데코레이터를 비동기 함수용으로 바꾸기
- **비동기 반복과 컨텍스트 관리자** — `async for`와 비동기 제너레이터(비동기 스트리밍 응답), `async with`
- **비동기 HTTP 요청** — `httpx.AsyncClient`로 여러 URL에 동시에 요청하기, 동기 방식(`requests`)과 소요 시간 비교, 블로킹 코드를 섞었을 때의 문제와 `asyncio.to_thread()`
- **비동기 코드 테스트와 읽기** — `pytest-asyncio`로 비동기 함수 테스트, FastAPI의 `async def` 엔드포인트, LLM SDK의 비동기 클라이언트(`AsyncOpenAI`, `AsyncAnthropic`) 코드 모양 읽기(실제 호출은 "LLM API 활용"에서 한다)

### 8장. 패키지 배포

- **`pyproject.toml`** — 프로젝트 정보(이름, 버전, 설명, 지원하는 파이썬 버전), 의존성 선언, 빌드 백엔드, 도구 설정(pytest·ruff·mypy) 한곳에 모으기, `requirements.txt`와의 관계(라이브러리와 애플리케이션)
- **프로젝트 구조** — `src` 레이아웃, 편집 가능 설치(`pip install -e .`), 테스트가 설치된 패키지를 import하도록 하는 이유, 패키지 안의 데이터 파일(프롬프트 템플릿 등)을 `importlib.resources`로 읽기
- **명령행 도구 만들기** — `argparse`로 옵션과 도움말 만들기(기초 과정의 `sys.argv`에서 한 걸음 더), `[project.scripts]`로 설치하면 바로 실행되는 명령 만들기
- **빌드** — `python -m build`, 소스 배포판(sdist)과 휠(wheel), 휠 안을 열어 무엇이 들어갔는지 확인하기
- **버전과 의존성 범위** — 시맨틱 버저닝, 의존성 범위 지정(`>=`, `~=`, `<`)과 너무 좁거나 넓을 때의 문제, 잠금 파일의 역할, Git 태그로 버전 표시
- **배포와 설치 확인** — TestPyPI 계정과 API 토큰, `twine`으로 올리기, 새 가상환경에서 설치해 확인하기, 실제 PyPI에 공개하기 전에 확인할 것(이름, 라이선스, README)
- **uv로 같은 일 하기** — `uv init`, `uv add`, `uv run`, `uv.lock`, `uv build`, `uv publish`와 표준 도구(`venv`, `pip`, `build`, `twine`)의 대응 관계
- **(선택) 지속적 통합 맛보기** — GitHub Actions로 푸시할 때마다 ruff·mypy·pytest 자동 실행

### 9장. 마무리

- **종합 실습** — 여러 개의 입력(텍스트 문서, 질문 목록, URL 목록 등)을 읽어 외부 서비스에 동시에 요청하고, 응답을 검증해 저장하는 명령행 도구를 패키지로 만든다. 예제는 "문서 일괄 요약기"(폴더의 문서를 청크로 나눠 가짜 LLM 클라이언트에 동시에 요약을 요청하고 결과를 JSONL로 저장)이며, 가짜 클라이언트는 무작위로 지연되고 가끔 시간 초과·요청 한도 초과를 일으킨다. API 키가 있다면 같은 `Protocol`을 따르는 실제 LLM 클라이언트로 바꿔 끼워 본다.
   - 완료 기준
     - 컴프리헨션·제너레이터·데코레이터·`Protocol`·Pydantic을 각각 어디에 썼는지, 왜 그 자리에 썼는지 설명할 수 있다
     - 차례로 실행할 때와 비동기로 실행할 때의 소요 시간을 측정해 비교하고, 동시 실행 수 제한·시간 제한·재시도가 의도대로 동작함을 테스트로 보인다
     - 정상 응답, 형식이 맞지 않는 응답, 시간 초과, 요청 한도 초과를 각각 테스트하고, 네트워크 없이 모든 테스트가 통과한다
     - `ruff`와 `mypy` 검사를 경고 없이 통과한다
     - 새 가상환경에서 휠(또는 TestPyPI)로 설치하고, 설치된 명령으로 실행할 수 있다
   - 선택 활동: 기초 과정 10장에서 만든 프로그램에 먼저 pytest 테스트를 붙인 뒤, 이 과정에서 배운 문법으로 다시 작성하고 테스트가 그대로 통과하는지 확인한다
