# 1장. 데이터를 오래 보관하기: SQLite

> 이 장에서는 파일 대신 **데이터베이스**에 데이터를 저장하는 방법을 배운다. 테이블과 SQL의 기본을 익히고, 지출을 기록·조회·수정·삭제하는 가계부 프로그램을 SQLite로 만든다. AI가 "저장했다"고 말한 결과를 SQL과 DB Browser로 직접 검증하는 습관도 들인다.

## 이 장에서 배울 것

- 파일 저장과 데이터베이스 저장의 차이를 설명한다.
- 테이블·행·열의 의미를 알고, 기본 SQL 문장(`CREATE TABLE`, `INSERT`, `SELECT`, `UPDATE`, `DELETE`)을 읽는다.
- 파이썬의 `sqlite3` 모듈로 데이터를 저장·조회·수정·삭제하는 프로그램을 만든다.
- **DB Browser for SQLite**로 데이터베이스 파일을 직접 열어 AI가 만든 결과를 검증한다.
- `claude -c`와 `/resume`으로 여러 날에 걸친 작업을 이어서 한다.

## 1. 고급 과정 시작하기

### 1-1. 기본 과정과 무엇이 다른가

기본 과정에서는 "말로 설명하면 동작하는 프로그램이 나온다"는 경험을 했다. 고급 과정에서는 프로그램이 **커지고, 여러 사람이 쓰고, 돈(API 비용)이 드는** 상황을 다룬다.

| 구분 | 기본 과정 | 고급 과정 |
|---|---|---|
| 데이터 저장 | 텍스트·JSON·엑셀 파일 | 데이터베이스(SQLite) |
| 화면 | Streamlit | Django + HTMX |
| 사용자와 만나는 곳 | 웹 브라우저 | 웹 브라우저 + 메신저(텔레그램) |
| AI 활용 | Claude Code가 코드를 만들어 줌 | 내 서비스 안에 Claude를 넣어 기능으로 제공 |
| 검증 방법 | 직접 실행해서 눈으로 확인 | 눈으로 확인 + 자동 테스트 |

내 역할도 **"무엇을 만들지 정하는 사람"에서 "구조를 정하고 품질·비용·보안을 책임지는 사람"** 으로 넓어진다. 그 첫걸음이 이 장의 주제인 **데이터를 어떻게 저장할지 정하는 일**이다.

## 2. 왜 데이터베이스인가

### 2-1. 파일 저장의 한계

기본 과정 4장의 할 일 관리 프로그램은 할 일 목록을 `todos.json` 파일에 저장했다. 할 일이 수십 개일 때는 문제가 없지만, 데이터가 많아지고 프로그램이 커지면 한계가 드러난다.

| 상황 | JSON·CSV 파일 | 데이터베이스 |
|---|---|---|
| **검색** "11월 식비만 보여 줘" | 파일 전체를 읽어 하나씩 비교하는 코드를 직접 짜야 한다 | `SELECT ... WHERE ...` 한 문장으로 찾는다 |
| **저장** 한 건 추가 | 파일 전체를 다시 쓴다 | 한 건만 추가한다 |
| **데이터 양** 몇만 건 | 읽고 쓸 때마다 느려진다 | 많아도 필요한 부분만 빠르게 찾는다 |
| **동시 수정** 두 프로그램이 동시에 저장 | 한쪽 내용이 사라질 수 있다 | 순서를 정해 하나씩 처리한다 |
| **저장 중 오류** 저장하다 프로그램이 멈춤 | 파일이 반쯤 쓰여 깨질 수 있다(`JSONDecodeError`) | 끝까지 저장되거나, 아예 저장되지 않거나 둘 중 하나다 |

> 💡 파일 저장이 틀린 방법은 아니다. 설정 값이나 작은 목록은 지금도 파일로 저장한다. **데이터가 계속 쌓이고, 찾아보고, 여러 사람이 쓰기 시작하면** 데이터베이스로 옮긴다.

### 2-2. 테이블·행·열

데이터베이스는 데이터를 **테이블(table)** 이라는 표에 저장한다. 엑셀 시트를 떠올리면 된다.

**`expenses` 테이블 (지출 기록)**

| id | date | item | amount | category |
|---|---|---|---|---|
| 1 | 2026-11-01 | 지하철 | 1550 | 교통 |
| 2 | 2026-11-01 | 점심 김밥 | 4500 | 식비 |
| 3 | 2026-11-02 | 커피 | 4800 | 식비 |

| 용어 | 엑셀로 비유하면 | 위 표에서 |
|---|---|---|
| 테이블 | 시트 하나 | `expenses` 표 전체 |
| 열(column) | 머리글이 붙은 세로 칸 | `date`, `item`, `amount` 같은 항목 |
| 행(row) | 가로 한 줄 | 지출 한 건 |

엑셀과 다른 점은 **열마다 넣을 수 있는 값의 종류가 정해져 있다**는 것이다. `amount` 열에 "사천오백원"이라는 글자를 넣으려 하면 데이터베이스가 막을 수 있다. 처음에 규칙을 정해 두기 때문에 데이터가 깔끔하게 유지된다.

### 2-3. SQLite = 파일 하나로 된 데이터베이스

데이터베이스 프로그램에는 여러 종류가 있다.

| 종류 | 예시 | 특징 |
|---|---|---|
| 서버형 | PostgreSQL, MySQL | 별도의 데이터베이스 서버를 설치·운영한다. 큰 서비스에서 쓴다. |
| 파일형 | **SQLite** | 데이터베이스 전체가 **파일 하나**(`ledger.db`)에 들어 있다. 설치할 서버가 없다. |

SQLite는 스마트폰 앱, 웹 브라우저 등 우리가 매일 쓰는 프로그램 안에도 들어 있을 만큼 널리 쓰인다. 파이썬에 기본으로 들어 있는 **`sqlite3` 모듈**로 바로 쓸 수 있어서 **따로 설치할 패키지가 없다.**

> 💡 3장부터 배우는 Django도 기본 데이터베이스로 SQLite를 쓴다. 이 장에서 익힌 개념이 그대로 이어진다.

## 3. SQL 읽기

### 3-1. SQL이란?

**SQL**(에스큐엘 또는 시퀄)은 데이터베이스에게 일을 시키는 언어다. 파이썬이 컴퓨터에게 일을 시키는 언어라면, SQL은 **데이터베이스 전용 언어**다. 영어 문장과 비슷해서 읽기 쉽다.

데이터를 다루는 일은 크게 네 가지이고, 앞 글자를 따서 **CRUD**라고 부른다.

| 작업 | 영어 | SQL 명령 | 가계부에서 |
|---|---|---|---|
| 만들기 | **C**reate | `INSERT` | 지출 기록하기 |
| 읽기 | **R**ead | `SELECT` | 지출 목록 보기 |
| 고치기 | **U**pdate | `UPDATE` | 금액 수정하기 |
| 지우기 | **D**elete | `DELETE` | 잘못 쓴 기록 지우기 |

**SQL 읽기 규칙**
- `SELECT`, `FROM` 같은 명령어는 대문자로 쓰는 것이 관례다. 소문자로 써도 동작한다.
- 글자 값은 작은따옴표로 감싼다: `'식비'`. 숫자는 그대로 쓴다: `4500`.
- 문장 끝에는 세미콜론(`;`)을 붙인다. 파이썬 코드 안에서 쓸 때는 생략하기도 한다.

### 3-2. 테이블 만들기: `CREATE TABLE`

```sql
CREATE TABLE IF NOT EXISTS expenses (
    id       INTEGER PRIMARY KEY,
    date     TEXT    NOT NULL,
    item     TEXT    NOT NULL,
    amount   INTEGER NOT NULL,
    category TEXT    NOT NULL
);
```

| 부분 | 의미 |
|---|---|
| `CREATE TABLE expenses` | `expenses`라는 테이블을 만든다. |
| `IF NOT EXISTS` | 이미 있으면 만들지 않는다. 프로그램을 여러 번 실행해도 오류가 나지 않는다. |
| `id INTEGER PRIMARY KEY` | 행마다 붙는 **고유 번호**. 값을 넣지 않으면 1, 2, 3… 자동으로 붙는다. (2장에서 자세히 배운다) |
| `date TEXT` | 날짜를 글자로 저장한다. |
| `amount INTEGER` | 금액을 정수로 저장한다. |
| `NOT NULL` | 이 칸은 **비워 둘 수 없다**. |

SQLite에서 주로 쓰는 값의 종류(자료형)는 다음과 같다.

| 자료형 | 저장하는 값 | 예 |
|---|---|---|
| `INTEGER` | 정수 | `4500`, `1` |
| `REAL` | 소수 | `3.5`, `36.7` |
| `TEXT` | 글자 | `'점심 김밥'`, `'2026-11-03'` |

> 💡 **날짜는 왜 `TEXT`인가?** SQLite에는 날짜 전용 자료형이 없다. 대신 날짜를 **`'2026-11-03'` 형식(연-월-일, 두 자리 맞춤)** 의 글자로 저장하면, 글자 순서와 날짜 순서가 같아져서 정렬과 기간 검색이 제대로 된다. `'2026-11-3'`처럼 자릿수가 섞이면 순서가 틀어진다.

> 💡 **금액은 왜 `INTEGER`인가?** 원화는 소수점이 없다. 소수(`REAL`)로 저장하면 컴퓨터 계산 방식 때문에 `0.1 + 0.2`가 `0.30000000000000004`가 되는 것처럼 아주 작은 오차가 생길 수 있다. 돈은 정수로 저장하는 것이 안전하다.

### 3-3. 데이터 넣기: `INSERT`

```sql
INSERT INTO expenses (date, item, amount, category)
VALUES ('2026-11-03', '점심 김밥', 4500, '식비');
```

"`expenses` 테이블의 `date`, `item`, `amount`, `category` 열에 각각 이 값들을 넣어라"라는 뜻이다. `id`는 쓰지 않았으므로 자동으로 다음 번호가 붙는다.

### 3-4. 데이터 꺼내기: `SELECT`

```sql
SELECT * FROM expenses;
```

`expenses` 테이블의 **모든 열(`*`)**, 모든 행을 꺼낸다.

```sql
SELECT date, item, amount
FROM expenses
WHERE category = '식비'
ORDER BY date DESC;
```

| 부분 | 의미 |
|---|---|
| `SELECT date, item, amount` | 이 세 열만 꺼낸다. |
| `FROM expenses` | `expenses` 테이블에서 |
| `WHERE category = '식비'` | 카테고리가 식비인 행만 |
| `ORDER BY date DESC` | 날짜 순으로 정렬한다. `DESC`는 최신순(내림차순), `ASC` 또는 생략하면 오래된 순(오름차순) |

`WHERE` 뒤에는 다양한 조건을 쓸 수 있다.

| 조건 | 의미 | 예 |
|---|---|---|
| `=` | 같다 | `category = '식비'` |
| `<>` 또는 `!=` | 다르다 | `category <> '식비'` |
| `>`, `>=`, `<`, `<=` | 크다, 크거나 같다, 작다, 작거나 같다 | `amount >= 10000` |
| `BETWEEN A AND B` | A 이상 B 이하 (**양 끝 포함**) | `date BETWEEN '2026-11-01' AND '2026-11-30'` |
| `LIKE` | 글자 패턴. `%`는 "아무 글자나 몇 개든" | `date LIKE '2026-11-%'` (11월 전체) |
| `AND`, `OR` | 그리고, 또는 | `category = '식비' AND amount >= 10000` |

### 3-5. 데이터 고치기와 지우기: `UPDATE`, `DELETE`

```sql
UPDATE expenses SET amount = 5000 WHERE id = 3;
DELETE FROM expenses WHERE id = 3;
```

| 문장 | 의미 |
|---|---|
| `UPDATE expenses SET amount = 5000 WHERE id = 3` | 번호가 3인 행의 금액을 5000으로 바꾼다. |
| `DELETE FROM expenses WHERE id = 3` | 번호가 3인 행을 지운다. |

> ⚠️ **`UPDATE`와 `DELETE`에는 반드시 `WHERE`가 있어야 한다.** `DELETE FROM expenses`처럼 `WHERE`를 빼면 **모든 행이 지워진다.** 되돌리기 버튼도, 휴지통도 없다. AI가 만든 `UPDATE`·`DELETE` 문장을 볼 때 `WHERE`가 있는지 가장 먼저 확인한다.

### 3-6. 파이썬 코드 읽기: `sqlite3` 모듈

파이썬에서는 SQL 문장을 문자열로 만들어 데이터베이스에 보낸다.

```python
import sqlite3

conn = sqlite3.connect("ledger.db")       # ① 데이터베이스에 연결 (없으면 파일을 새로 만든다)

conn.execute(                              # ② SQL 실행
    "INSERT INTO expenses (date, item, amount, category) VALUES (?, ?, ?, ?)",
    ("2026-11-03", "점심 김밥", 4500, "식비"),
)
conn.commit()                              # ③ 변경 내용을 파일에 확정 저장

rows = conn.execute(                       # ④ 조회하고 결과를 모두 가져오기
    "SELECT id, date, item, amount FROM expenses WHERE category = ?",
    ("식비",),
).fetchall()

for row in rows:
    print(row)                             # (2, '2026-11-01', '점심 김밥', 4500) 처럼 출력

conn.close()                               # ⑤ 연결 닫기
```

| 코드 | 의미 |
|---|---|
| `sqlite3.connect("ledger.db")` | 데이터베이스 파일에 연결한다. 파일이 없으면 **빈 파일을 새로 만든다.** |
| `conn.execute(SQL, 값)` | SQL 문장을 실행한다. |
| `?` | **자리 표시자.** SQL 문장에는 `?`만 써 두고, 실제 값은 뒤에 튜플로 따로 넘긴다. |
| `conn.commit()` | `INSERT`·`UPDATE`·`DELETE`로 바꾼 내용을 **확정 저장**한다. 빠뜨리면 바꾼 내용이 사라진다. |
| `.fetchall()` | `SELECT` 결과를 리스트로 모두 가져온다. 행 하나는 튜플이다. |
| `conn.close()` | 연결을 닫는다. |

> 💡 **`?` 자리 표시자를 쓰는 이유**: 사용자가 입력한 값을 SQL 문자열에 직접 이어 붙이면, 나쁜 의도의 입력으로 데이터베이스가 공격당할 수 있다(**SQL 인젝션**). 2장에서 직접 공격해 보고 자세히 배운다. 지금은 **"값은 항상 `?`로 넘긴다"** 만 기억한다.

> ⚠️ **두 가지 "커밋"을 헷갈리지 않는다.** 데이터베이스의 `commit()`은 바꾼 데이터를 `ledger.db` 파일에 확정하는 것이고, Git 커밋은 코드 파일의 변경 기록을 남기는 것이다. 이름만 같고 전혀 다른 일이다.

## 4. 도구 준비: 데이터베이스 파일 들여다보기

`ledger.db`는 VS Code에서 그냥 열면 알아볼 수 없는 글자로 보인다. 표 형태로 보려면 전용 도구가 필요하다. 이 도구는 **AI가 만든 결과를 내 눈으로 검증**하는 데 쓴다.

### 4-1. DB Browser for SQLite (추천)

데이터베이스 파일을 엑셀처럼 표로 보여 주는 무료 프로그램이다.

- 내려받기: https://sqlitebrowser.org → **Download**
- macOS는 Homebrew로도 설치할 수 있다: `brew install --cask db-browser-for-sqlite`

**사용법**
1. **데이터베이스 열기**로 `ledger.db` 파일을 연다.
2. **데이터 보기(Browse Data)** 탭에서 테이블을 고르면 행이 표로 보인다.
3. **데이터베이스 구조(Database Structure)** 탭에서 테이블과 열 구성을 볼 수 있다.
4. **SQL 실행(Execute SQL)** 탭에서 `SELECT` 문장을 직접 실행해 볼 수 있다.

> ⚠️ DB Browser에서 데이터를 직접 고친 뒤 **변경사항 쓰기(Write Changes)** 를 누르지 않으면, 내 프로그램이 데이터베이스를 쓰지 못하고 `database is locked` 오류가 날 수 있다. 이 장에서는 DB Browser를 **보기 용도로만** 쓴다. 고치는 일은 프로그램으로 한다.

> 💡 프로그램으로 데이터를 바꾼 뒤에는 DB Browser 화면이 자동으로 바뀌지 않는다. **새로고침**(데이터 보기 탭의 새로고침 버튼 또는 `F5`)을 눌러야 최신 내용이 보인다.

### 4-2. VS Code 확장 (간편한 방법)

프로그램을 따로 설치하기 어렵다면 VS Code 확장을 써도 된다. **확장(Extensions)** 화면에서 `SQLite Viewer`를 검색해 설치하면, VS Code 탐색기에서 `ledger.db`를 클릭하는 것만으로 표가 보인다.

| 도구 | 장점 | 단점 |
|---|---|---|
| DB Browser for SQLite | 기능이 많다. SQL을 직접 실행해 볼 수 있다. | 프로그램을 따로 설치해야 한다. |
| VS Code 확장 | VS Code 안에서 바로 본다. | 확장에 따라 보기만 되고 SQL 실행은 안 될 수 있다. |

## 5. Claude Code 기능 익히기: 이어 하기와 SQL 검증

### 5-1. 여러 날에 걸친 작업 이어 하기

기본 과정 9장에서 지난 대화를 이어 하는 방법을 배웠다. 고급 과정의 프로젝트는 한 번에 끝나지 않으므로 이 기능을 자주 쓴다.

| 명령 | 어디서 | 하는 일 |
|---|---|---|
| `claude -c` | 터미널 | 이 폴더에서 **가장 최근에** 나눈 대화를 이어서 시작한다. `claude --continue`의 줄임말이다. |
| `claude -r` | 터미널 | 지난 대화 목록을 보여 주고 **골라서** 이어서 시작한다. `claude --resume`의 줄임말이다. |
| `/resume` | Claude Code 입력창 | 이미 Claude Code를 실행한 상태에서 지난 대화 목록을 열어 고른다. |

> 💡 지난 대화는 **폴더별로** 기억된다. `claude -c`는 반드시 프로젝트 폴더(`ledger`)에서 실행한다. 다른 폴더에서 실행하면 엉뚱한 대화가 열리거나 "이어 할 대화가 없다"고 나온다.

> 💡 이어 하기는 편리하지만, 대화가 너무 길어지면 Claude Code가 앞의 내용을 헷갈린다. 기능 하나를 끝내고 커밋했다면 새 대화로 시작하는 편이 낫다(기본 과정 9장의 **기능 하나 = 대화 하나**).

### 5-2. "저장했습니다"를 믿지 말고 SQL로 확인한다

AI가 "삭제했습니다", "저장 기능을 추가했습니다"라고 말해도 **실제로 데이터베이스가 그렇게 되었는지는 별개의 문제**다. 이 장에서는 세 가지 방법으로 교차 확인한다.

| 확인 방법 | 무엇을 보나 | 요청 예 |
|---|---|---|
| ① 프로그램 화면 | 내 프로그램이 보여 주는 결과 | (직접 실행해서 메뉴로 확인) |
| ② SQL 조회 | Claude Code가 `SELECT`로 직접 꺼낸 데이터 | `지금 데이터베이스에 들어 있는 내용을 SELECT 문으로 보여 줘.` |
| ③ DB Browser | 내 눈으로 직접 연 데이터베이스 파일 | (DB Browser에서 새로고침 후 확인) |

세 결과가 모두 같으면 믿을 수 있다. 하나라도 다르면 어딘가에 문제가 있다는 신호다. 예를 들어 프로그램 화면에는 보이는데 DB Browser에는 없다면 `commit()`을 빠뜨렸거나 다른 폴더의 `ledger.db`를 보고 있을 가능성이 크다.

> 💡 SQL을 직접 쓸 줄 몰라도 된다. "식비만 골라서 보여 줘", "번호가 3인 기록이 남아 있는지 확인해 줘"처럼 **말로 요청하고, Claude Code가 실행한 SQL 문장을 읽어 보는 것**으로 충분하다. 3장에서 배운 SQL 읽기가 여기서 쓰인다.

### 5-3. 터미널(CLI)과 VS Code 확장의 사용법 비교

| 기능 | 터미널(CLI) | VS Code 확장 |
|---|---|---|
| 가장 최근 대화 이어 하기 | `claude -c` | 패널의 이전 대화 기록에서 맨 위 대화 선택 |
| 대화 골라서 이어 하기 | `claude -r` 또는 입력창에 `/resume` | 패널의 이전 대화 기록에서 선택 |
| SQL로 데이터 확인 | 입력창에 요청 | 입력창에 요청 |
| 데이터베이스 파일 보기 | DB Browser 또는 VS Code 확장 | DB Browser 또는 VS Code 확장 |

### 6-1. 프로젝트 준비

고급 과정 실습을 모아 둘 `vibe-advanced` 폴더를 만들고, 그 안에 `ledger` 프로젝트 폴더를 만든다.

**macOS**
```bash
mkdir -p ~/vibe-advanced/ledger
cd ~/vibe-advanced/ledger
code .
```

**Windows (PowerShell)**
```powershell
mkdir ~\vibe-advanced\ledger
cd ~\vibe-advanced\ledger
code .
```

VS Code에서 Claude Code를 시작하고, 기본 과정 4~5장에서 하던 프로젝트 준비를 한 번에 요청한다.

```
이 폴더를 uv init --no-package --python 3.15로 uv 프로젝트로 만들어 줘. 그다음 /init으로 CLAUDE.md를 만들고 아래 규칙을 추가해 줘.
- 나는 코딩 초보자야. 설명은 쉬운 한국어로 해 줘.
- 파이썬 실행은 uv run을, 패키지 설치는 uv add를 사용해.
- 사용자 입력을 받는 프로그램은 네가 실행하지 말고, 내가 실행할 명령만 알려 줘.
- 데이터는 SQLite(파이썬 sqlite3 모듈)로 ledger.db 파일에 저장해.
- SQL에 값을 넣을 때는 문자열을 이어 붙이지 말고 반드시 ? 자리 표시자를 사용해.
- UPDATE와 DELETE 문에는 반드시 WHERE 조건을 넣어.
```

> 💡 `/init`이 VS Code 확장에서 동작하지 않으면 "이 프로젝트의 CLAUDE.md를 만들어 줘"라고 요청한다.

이어서 `.gitignore`를 점검하고 첫 커밋을 만든다.

```
.gitignore에 *.db와 *.db-journal을 추가해 줘. 가계부 데이터에는 내 개인적인 지출 내역이 들어가니까 Git에 올리면 안 돼. 그다음 지금 상태를 "프로젝트 준비"로 커밋해 줘.
```

> ⚠️ 데이터베이스 파일(`.db`)에 개인 데이터가 쌓이면 **GitHub에 올리지 않는다.** 기본 과정 5장에서 `todos.json`을 `.gitignore`에 넣은 것과 같은 이유다. 다른 사람과 나눌 샘플 데이터는 6-9에서 **생성 스크립트**로 만든다.

### 6-2. 1단계: 테이블 설계부터 보기

코드를 바로 만들게 하지 않고, **어떤 표에 무엇을 저장할지**부터 확인한다. 고급 과정의 원칙 "데이터부터 설계한다"의 첫 연습이다.

```
날짜, 항목, 금액, 카테고리를 저장하는 가계부 프로그램을 SQLite로 만들어 줘.
코드를 쓰기 전에 테이블 구조를 먼저 보여 주고, 각 열이 왜 필요한지 설명해 줘.
```

Claude Code가 보여 주는 테이블 구조를 3-2와 비교하며 다음을 확인한다.

- [ ] 행마다 고유 번호(`id`) 열이 있는가? (수정·삭제할 때 어느 행인지 가리키는 데 필요하다)
- [ ] 날짜는 `TEXT`로, `'YYYY-MM-DD'` 형식으로 저장하는가?
- [ ] 금액은 `INTEGER`인가?
- [ ] 꼭 있어야 하는 칸에 `NOT NULL`이 붙어 있는가?

마음에 들지 않는 부분이 있으면 승인하기 전에 고쳐 달라고 한다. 예를 들어 Claude Code가 메모 열을 추가로 제안했다면, 필요한지 스스로 판단해서 "메모 열은 빼 줘"라고 말해도 된다.

> 💡 테이블 구조는 나중에 바꾸기가 번거롭다. 데이터가 쌓인 뒤에 열을 바꾸면 기존 데이터를 옮기는 작업이 필요하다. 그래서 **설계는 코드보다 먼저, 천천히** 한다.

### 6-3. 2단계: 지출 기록하기

설계를 승인했으면 첫 기능을 만든다. 이번에도 한 번에 다 만들지 않고 **기록 기능부터** 만든다.

```
설계한 테이블로 main.py를 만들어 줘.
- 프로그램을 시작하면 테이블이 없을 때만 만들어.
- 메뉴: 1. 지출 기록  2. 전체 보기  3. 종료
- 지출 기록은 날짜, 항목, 금액, 카테고리를 차례로 입력받아 저장해.
- 전체 보기는 날짜순으로 보여 줘.
```

두 번째 터미널에서 직접 실행한다.

```bash
uv run main.py
```

지출을 3건 정도 기록하고 전체 보기로 확인한다. 이제 VS Code 탐색기에 `ledger.db` 파일이 생겼을 것이다.

**검증하기**
1. DB Browser(또는 VS Code 확장)로 `ledger.db`를 연다.
2. `expenses` 테이블에 방금 입력한 3건이 들어 있는지 확인한다.
3. 프로그램을 종료하고 다시 실행한 뒤 전체 보기를 고른다. 기록이 그대로 남아 있어야 한다.

> 💡 기본 과정 4장의 할 일 관리 프로그램과 비교해 보자. 그때는 저장할 때마다 **목록 전체를** `todos.json`에 다시 썼다. 지금은 `INSERT` 한 문장으로 **한 건만** 추가한다. 데이터가 1만 건이 되어도 저장하는 일의 양은 같다.

### 6-4. 3단계: SQL 읽어 보기

Claude Code가 만든 코드에서 SQL이 어떻게 쓰였는지 확인한다.

```
방금 만든 코드에서 실행되는 SQL 문장을 모두 찾아서 한 줄씩 쉬운 말로 설명해 줘.
```

설명을 들은 뒤, Claude Code에게 데이터를 직접 꺼내 보게 한다.

```
지금 데이터베이스에 들어 있는 내용을 SELECT 문으로 보여 줘. 내가 DB Browser에서 본 것과 같은지 비교해 볼게.
```

Claude Code가 실행한 `SELECT` 결과와 DB Browser 화면, 프로그램의 전체 보기 화면이 모두 같은지 비교한다(5-2의 세 가지 확인).

> 💡 Claude Code는 `sqlite3` 명령이나 짧은 파이썬 코드로 조회한다. Windows에는 `sqlite3` 명령이 기본으로 없어서 파이썬으로 조회할 수 있다. 어느 쪽이든 **실행한 SQL 문장**을 읽어 보는 것이 중요하다.

### 6-5. 4단계: 수정과 삭제

```
메뉴에 "금액 수정"과 "삭제"를 추가해 줘.
- 전체 보기에서 보이는 번호(id)를 입력받아서 수정하거나 삭제해.
- 없는 번호를 입력하면 "그런 번호가 없습니다"라고 알려 줘.
- 삭제하기 전에 "정말 삭제할까요? (y/n)"라고 한 번 물어봐 줘.
코드를 만든 뒤, 새로 추가된 UPDATE와 DELETE 문장을 보여 줘.
```

Claude Code가 보여 준 문장에 **`WHERE id = ?`가 있는지** 꼭 확인한다(3-5).

**검증하기**
1. 기록 하나의 금액을 수정하고, 다른 기록 하나를 삭제한다.
2. 없는 번호(예: `999`)로 수정·삭제를 시도해 안내 메시지가 나오는지 본다.
3. DB Browser에서 **새로고침**하고, 수정한 행은 금액이 바뀌었는지, 삭제한 행은 사라졌는지, **나머지 행은 그대로인지** 확인한다.

> 💡 삭제한 뒤 새 기록을 추가하면 번호가 이어서 붙는다. 예를 들어 3번을 지운 뒤 추가하면 3번이 아니라 4번(또는 그다음 번호)이 된다. 고유 번호는 "몇 번째 줄"이 아니라 그 행의 **이름표**라서 다시 쓰지 않는다.

### 6-6. 5단계: 대화를 끊었다가 이어 하기

실제 프로젝트에서는 오늘 하다가 내일 이어서 하는 일이 많다. 여기서 한번 연습해 본다.

1. 지금까지 만든 내용을 커밋한다.
   ```
   지금까지 만든 기능을 "지출 기록, 조회, 수정, 삭제"로 커밋해 줘.
   ```
2. Claude Code를 종료한다. 터미널(CLI)이라면 `/exit`을 입력하거나 `Ctrl+C`를 두 번 누른다. VS Code 확장이라면 패널을 닫는다.
3. 다시 시작하면서 지난 대화를 이어 간다.
   ```bash
   claude -c
   ```
   VS Code 확장이라면 패널의 이전 대화 기록에서 방금 대화를 고른다.
4. Claude Code가 앞의 내용을 기억하는지 확인한다.
   ```
   우리가 지금까지 무엇을 만들었고, 테이블 구조는 어떻게 되어 있지?
   ```
5. 이번에는 `/resume`을 입력해 지난 대화 목록이 어떻게 보이는지 확인하고, 방금 대화를 다시 고른다.

### 6-7. 6단계: 기간별 조회

이어 간 대화에서 다음 기능을 요청한다.

```
메뉴에 "기간별 보기"를 추가해 줘. 시작 날짜와 끝 날짜를 입력받아서 그 기간의 지출을 날짜순으로 보여 주고, 맨 아래에 합계를 보여 줘. 끝 날짜에 쓴 지출도 포함해야 해.
```

**검증하기**
- 11월 1일~7일처럼 기간을 정해 조회하고, 결과에 나온 기록을 DB Browser와 비교한다.
- **경계값**을 확인한다: 시작 날짜와 끝 날짜 **당일**의 기록이 빠지지 않았는가?
- 합계를 계산기로 직접 더해 맞는지 확인한다.

이 단계까지 만들면 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import sqlite3

DB_FILE = "ledger.db"   # 데이터베이스 파일 이름


def get_connection():
    """데이터베이스에 연결한다. 파일이 없으면 새로 만든다."""
    return sqlite3.connect(DB_FILE)


def create_table():
    """expenses 테이블이 없을 때만 만든다."""
    conn = get_connection()
    conn.execute("""
        CREATE TABLE IF NOT EXISTS expenses (
            id       INTEGER PRIMARY KEY,
            date     TEXT    NOT NULL,
            item     TEXT    NOT NULL,
            amount   INTEGER NOT NULL,
            category TEXT    NOT NULL
        )
    """)
    conn.commit()
    conn.close()


def add_expense(date, item, amount, category):
    """지출 한 건을 저장한다."""
    conn = get_connection()
    conn.execute(
        "INSERT INTO expenses (date, item, amount, category) VALUES (?, ?, ?, ?)",
        (date, item, amount, category),
    )
    conn.commit()
    conn.close()


def get_expenses(start=None, end=None):
    """지출 목록을 날짜순으로 가져온다. 기간을 주면 그 기간만 가져온다."""
    conn = get_connection()
    if start and end:
        rows = conn.execute(
            "SELECT id, date, item, amount, category FROM expenses "
            "WHERE date BETWEEN ? AND ? ORDER BY date, id",
            (start, end),
        ).fetchall()
    else:
        rows = conn.execute(
            "SELECT id, date, item, amount, category FROM expenses ORDER BY date, id"
        ).fetchall()
    conn.close()
    return rows


def update_amount(expense_id, amount):
    """번호가 expense_id인 지출의 금액을 바꾼다. 바뀐 행의 수를 돌려준다."""
    conn = get_connection()
    cursor = conn.execute(
        "UPDATE expenses SET amount = ? WHERE id = ?", (amount, expense_id)
    )
    conn.commit()
    count = cursor.rowcount   # 0이면 그런 번호가 없다는 뜻
    conn.close()
    return count


def delete_expense(expense_id):
    """번호가 expense_id인 지출을 지운다. 지운 행의 수를 돌려준다."""
    conn = get_connection()
    cursor = conn.execute("DELETE FROM expenses WHERE id = ?", (expense_id,))
    conn.commit()
    count = cursor.rowcount
    conn.close()
    return count


def show_expenses(rows):
    """지출 목록과 합계를 보여 준다."""
    if not rows:
        print("기록이 없습니다.")
        return
    print("번호  날짜            금액  내용")
    print("-" * 40)
    for expense_id, date, item, amount, category in rows:
        print(f"{expense_id:>4}  {date}  {amount:>8,}  [{category}] {item}")
    print("-" * 40)
    total = sum(row[3] for row in rows)   # 네 번째 값(금액)을 모두 더한다
    print(f"합계: {total:,}원")


def main():
    create_table()   # 시작할 때 테이블을 준비한다

    while True:
        print("\n=== 가계부 ===")
        print("1. 지출 기록  2. 전체 보기  3. 기간별 보기  4. 금액 수정  5. 삭제  6. 종료")
        choice = input("선택: ")

        if choice == "1":
            date = input("날짜 (예: 2026-11-15): ")
            item = input("항목: ")
            amount = int(input("금액: "))
            category = input("카테고리 (예: 식비, 교통, 생활, 문화): ")
            add_expense(date, item, amount, category)
            print("기록했습니다.")
        elif choice == "2":
            show_expenses(get_expenses())
        elif choice == "3":
            start = input("시작 날짜 (예: 2026-11-01): ")
            end = input("끝 날짜 (예: 2026-11-30): ")
            print()
            show_expenses(get_expenses(start, end))
        elif choice == "4":
            expense_id = int(input("수정할 번호: "))
            amount = int(input("새 금액: "))
            if update_amount(expense_id, amount):
                print("수정했습니다.")
            else:
                print("그런 번호가 없습니다.")
        elif choice == "5":
            expense_id = int(input("삭제할 번호: "))
            if input("정말 삭제할까요? (y/n): ") != "y":
                print("취소했습니다.")
            elif delete_expense(expense_id):
                print("삭제했습니다.")
            else:
                print("그런 번호가 없습니다.")
        elif choice == "6":
            print("종료합니다.")
            break
        else:
            print("1~6 중에서 선택하세요.")


if __name__ == "__main__":
    main()
```

#### 코드에서 개념 찾기

| 개념 | 코드 | 하는 일 |
|---|---|---|
| 연결 | `sqlite3.connect(DB_FILE)` | `ledger.db`에 연결한다. 없으면 새로 만든다. |
| 테이블 만들기 | `CREATE TABLE IF NOT EXISTS` | 처음 실행할 때만 테이블을 만든다. |
| Create | `INSERT INTO expenses ... VALUES (?, ?, ?, ?)` | 지출 한 건을 추가한다. |
| Read | `SELECT ... ORDER BY date, id` | 날짜순(같은 날짜면 번호순)으로 꺼낸다. |
| 기간 조건 | `WHERE date BETWEEN ? AND ?` | 시작 날짜부터 끝 날짜까지(양 끝 포함) 고른다. |
| Update | `UPDATE expenses SET amount = ? WHERE id = ?` | 지정한 번호의 금액만 바꾼다. |
| Delete | `DELETE FROM expenses WHERE id = ?` | 지정한 번호의 행만 지운다. |
| 자리 표시자 | `?`와 뒤의 튜플 | 값을 SQL 문자열에 이어 붙이지 않고 따로 넘긴다. |
| 확정 저장 | `conn.commit()` | 바꾼 내용을 파일에 확정한다. |
| 결과 가져오기 | `.fetchall()` | `SELECT` 결과를 튜플의 리스트로 받는다. |
| 바뀐 행의 수 | `cursor.rowcount` | 0이면 조건에 맞는 행이 없었다는 뜻이다. |
| 천 단위 쉼표 | `f"{amount:,}"` | `38000`을 `38,000`으로 보여 준다. |

> 💡 `("식비",)`처럼 값이 하나뿐일 때도 끝에 쉼표를 붙인다. 쉼표가 없으면 파이썬은 튜플이 아니라 그냥 괄호로 감싼 글자로 알아듣는다.

### 6-8. 7단계: 잘못된 입력 막기

일부러 잘못된 값을 넣어 본다.

- 금액에 `abc`를 입력한다 → `ValueError`로 프로그램이 멈춘다.
- 날짜에 `2026-11-5`(한 자리 일)나 `11월 5일`을 입력한다 → 저장은 되지만 기간별 보기에서 빠지거나 순서가 엉킨다.

두 번째가 더 위험하다. 프로그램은 멈추지 않는데 **데이터가 조용히 망가지기** 때문이다. 3-2에서 본 것처럼 날짜는 `'YYYY-MM-DD'` 형식이어야 글자 비교로 기간 검색이 된다.

```
잘못된 입력을 막아 줘.
- 금액이 숫자가 아니거나 0 이하이면 다시 입력받아.
- 날짜는 2026-11-05처럼 YYYY-MM-DD 형식의 실제 있는 날짜만 받아. 그냥 엔터를 치면 오늘 날짜로 해 줘.
- 수정·삭제할 번호가 숫자가 아니면 "올바른 번호를 입력하세요"라고 알려 줘.
그리고 지금 데이터베이스에 형식이 잘못된 날짜가 들어 있는지 SELECT로 찾아서 보여 줘.
```

잘못된 날짜가 이미 들어 있다면, 어떤 `UPDATE` 문장으로 고칠지 먼저 보여 달라고 하고 **`WHERE`를 확인한 뒤** 승인한다.

> 💡 데이터베이스는 **들어온 값만 지킬 수 있다.** `NOT NULL`이나 자료형처럼 테이블 설계로 막을 수 있는 것도 있지만, "날짜 형식"처럼 세세한 규칙은 프로그램이 입력을 받을 때 검사해야 한다.

### 6-9. 8단계: 샘플 데이터와 GitHub 올리기

`ledger.db`는 `.gitignore`에 들어 있어서 GitHub에 올라가지 않는다. 그러면 다른 사람이 내 저장소를 내려받았을 때(또는 내가 다른 컴퓨터에서 작업할 때) 테스트할 데이터가 없다. 이럴 때 **샘플 데이터를 만드는 스크립트**를 올린다.

```
샘플 데이터를 만드는 seed.py를 만들어 줘.
- 2026년 10월~11월의 가짜 지출 30건을 식비, 교통, 생활, 문화 카테고리로 골고루 만들어 줘.
- ledger.db에 이미 데이터가 있으면 아무것도 지우지 말고 "이미 데이터가 있습니다"라고 알리고 멈춰.
실행 명령은 내가 직접 입력할게.
```

> ⚠️ "이미 데이터가 있으면 멈춰"라는 조건이 중요하다. 이 조건이 없으면 AI가 "깨끗하게 시작하려고" 기존 데이터를 지우는 코드를 만들 수도 있다. 데이터를 지우거나 덮어쓰는 코드는 항상 의심하고 확인한다.

테스트할 때는 진짜 가계부를 잠시 다른 이름으로 옮겨 둔다.

```bash
mv ledger.db ledger-backup.db     # Windows: Rename-Item ledger.db ledger-backup.db
uv run seed.py
uv run main.py
```

기간별 보기로 10월과 11월을 각각 조회해 보고, 확인이 끝나면 원래 파일로 되돌린다.

```bash
mv ledger-backup.db ledger.db     # Windows: Move-Item -Force ledger-backup.db ledger.db
```

> 💡 `mv`는 같은 이름의 파일이 있으면 덮어쓴다. 샘플 데이터가 담긴 `ledger.db`가 진짜 데이터로 교체된다.

마지막으로 커밋하고 GitHub에 올린다.

```
ledger.db가 Git에서 무시되는지 확인해 줘. 그다음 지금까지의 변경을 커밋하고, GitHub에 비공개 저장소 ledger를 만들어서 올려 줘.
```

GitHub 저장소 페이지에서 `main.py`, `seed.py`, `CLAUDE.md`는 보이고 **`ledger.db`는 보이지 않는지** 확인한다.

> 💡 이 가계부 데이터베이스는 9장에서 다시 쓴다. 텔레그램 봇에게 "이번 달 식비 얼마야?"라고 물으면, Claude가 이 데이터베이스를 조회해서 답하게 만든다. 지금 만든 테이블 구조와 코드를 잘 보관해 둔다.

## 7. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| `sqlite3.OperationalError: database is locked` | DB Browser에서 데이터를 고치고 **변경사항 쓰기**를 누르지 않은 상태일 수 있다. DB Browser에서 변경사항을 저장하거나 되돌린 뒤 닫고 다시 실행한다. |
| `sqlite3.OperationalError: no such table: expenses` | 테이블을 만들기 전에 조회했거나, 다른 폴더의 빈 `ledger.db`에 연결한 것이다. 프로젝트 폴더에서 실행했는지(`pwd`) 확인한다. |
| 엉뚱한 폴더에 빈 `ledger.db`가 생겼다 | `sqlite3.connect()`는 파일이 없으면 새로 만든다. 다른 폴더에서 실행한 것이므로 빈 파일은 지우고 `ledger` 폴더에서 실행한다. |
| 프로그램에서는 저장했다는데 DB Browser에 안 보인다 | DB Browser에서 **새로고침**한다. 그래도 없으면 `commit()`을 빠뜨렸는지 Claude Code에게 확인을 요청한다. |
| 껐다 켰더니 방금 기록이 사라졌다 | `INSERT`·`UPDATE`·`DELETE` 뒤에 `conn.commit()`이 있는지 확인해 달라고 요청한다. |
| 기간별 보기에서 일부 기록이 빠진다 | 날짜 형식이 섞여 있을 가능성이 크다(`2026-11-5`, `2026/11/05`). 6-8처럼 잘못된 날짜를 찾아 고치고, 입력 검사를 추가한다. |
| 수정·삭제했더니 **모든 행**이 바뀌거나 사라졌다 | `WHERE`가 빠진 것이다. 백업이 없으면 되돌릴 수 없다. 코드를 고치고, 앞으로는 큰 작업 전에 `ledger.db`를 복사해 둔다. |
| `sqlite3.OperationalError: near "...": syntax error` | SQL 문장의 문법 오류다. 오류 메시지 전체를 Claude Code에게 붙여 넣는다. |
| `claude -c`를 했더니 다른 대화가 열린다 | 다른 폴더에서 실행했다. `ledger` 폴더로 이동해 다시 실행하거나 `/resume`으로 목록에서 고른다. |
| Windows에서 `sqlite3` 명령을 찾을 수 없다 | Windows에는 기본으로 없다. 설치하지 않아도 된다. Claude Code에게 "파이썬으로 조회해 줘"라고 요청하거나 DB Browser를 쓴다. |

## 8. 정리

### 핵심 요약

1. 데이터가 계속 쌓이고, 찾아보고, 여러 사람이 쓰기 시작하면 파일 대신 **데이터베이스**에 저장한다.
2. 데이터베이스는 **테이블**(표)에 데이터를 저장한다. 열마다 넣을 수 있는 **자료형**이 정해져 있다.
3. **SQLite**는 파일 하나로 된 데이터베이스이고, 파이썬의 `sqlite3` 모듈로 바로 쓸 수 있다.
4. 데이터를 다루는 네 가지 일 **CRUD**는 SQL의 `INSERT`, `SELECT`, `UPDATE`, `DELETE`에 해당한다. `UPDATE`·`DELETE`에는 반드시 `WHERE`가 있어야 한다.
5. 파이썬에서는 값을 **`?` 자리 표시자**로 넘기고, 바꾼 내용은 **`commit()`** 으로 확정한다.
6. 코드보다 **테이블 설계를 먼저** 확인하고, AI의 결과는 **프로그램 화면·SQL 조회·DB Browser**로 교차 검증한다.
7. 여러 날에 걸친 작업은 `claude -c`(가장 최근 대화)와 `/resume`(골라서)으로 이어 간다.

### 요청문 템플릿

**테이블 설계 먼저 보기**
```
[무엇을] 저장하는 프로그램을 SQLite로 만들려고 해. 저장할 정보는 [목록]이야.
코드를 쓰기 전에 테이블 구조를 먼저 보여 주고, 각 열의 자료형과 필요한 이유를 설명해 줘.
```

**SQL 설명 요청**
```
방금 실행한 SQL 문장을 한 줄씩 쉬운 말로 설명해 줘.
```

**결과를 SQL로 검증**
```
[확인하고 싶은 내용]을 SELECT 문으로 보여 줘. 실행한 SQL 문장도 같이 보여 줘.
```

**위험한 변경 전 확인**
```
[무엇을] 고치거나 지우는 UPDATE/DELETE 문장을 실행하기 전에 먼저 보여 줘. 몇 개의 행이 바뀔지도 SELECT로 미리 확인해 줘.
```

### 용어 사전

| 용어 | 뜻 |
|---|---|
| 데이터베이스 | 데이터를 체계적으로 저장하고 빠르게 찾을 수 있게 관리하는 저장소 |
| SQLite | 데이터베이스 전체가 파일 하나에 들어 있는 가벼운 데이터베이스 |
| 테이블 | 데이터베이스 안의 표. 행과 열로 이루어진다. |
| 행(row) | 테이블의 가로 한 줄. 데이터 한 건 |
| 열(column) | 테이블의 세로 칸. 데이터의 항목 |
| 자료형 | 열에 넣을 수 있는 값의 종류(`INTEGER`, `REAL`, `TEXT`) |
| SQL | 데이터베이스에게 일을 시키는 언어 |
| CRUD | 만들기(Create)·읽기(Read)·고치기(Update)·지우기(Delete)의 앞 글자 |
| 쿼리(query) | 데이터베이스에 보내는 SQL 요청, 특히 `SELECT` 문 |
| 고유 번호(`id`) | 행마다 붙는 겹치지 않는 번호. 어느 행인지 가리킬 때 쓴다. |
| 자리 표시자(`?`) | SQL 문장에 값 대신 써 두는 표시. 실제 값은 따로 넘긴다. |
| `commit()` | 데이터베이스에서 바꾼 내용을 파일에 확정 저장하는 것. Git 커밋과는 다르다. |
| DB Browser for SQLite | SQLite 데이터베이스 파일을 표 형태로 보여 주는 프로그램 |
| 샘플 데이터 | 테스트와 시연을 위해 만든 가짜 데이터 |

## 9. 과제

가계부 프로그램에 다음 두 기능을 추가한다.

1. **카테고리별 검색**: 카테고리를 입력하면 그 카테고리의 지출만 날짜순으로 보여 주고, 합계를 표시한다.
2. **이번 달 지출만 보기**: 날짜를 입력하지 않아도 **오늘이 속한 달**의 지출만 보여 준다.

### 진행 방법

- 두 기능을 한 번에 요청하지 말고, **카테고리별 검색 → 이번 달 지출 보기** 순서로 하나씩 요청한다.
- 요청하기 전에 Plan 모드(`Shift+Tab`)로 어떤 SQL 문장을 쓸지 먼저 확인한다. `WHERE` 조건이 어떻게 바뀌는지 읽어 본다.
- 카테고리 검색은 `'식비'`처럼 **정확히 같은** 값을 찾는 방법과, `'식'`만 입력해도 찾는 방법(`LIKE`)이 있다. 어느 쪽이 내 가계부에 맞는지 정해서 요청한다.
- "이번 달"은 오늘 날짜에서 계산해야 한다. 달이 바뀌어도 코드를 고치지 않고 동작하는지 Claude Code에게 확인을 요청한다.
- 기능마다 결과를 **SQL 조회와 DB Browser로 검증**하고, 확인이 끝나면 커밋한다.
- 다음 수업 날에는 `claude -c`로 과제 대화를 이어서 시작해 본다.
