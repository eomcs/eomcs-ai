# 비전공자를 위한 파이썬 기반 바이브 코딩 (고급)

> 데이터베이스와 AI를 갖춘 웹 서비스·메신저 봇을 Claude Code와 함께 만들고, Claude Code 자체를 내 작업 방식에 맞게 확장하는 과정

---

## 1. 과정 개요

| 항목 | 내용 |
|---|---|
| 학습 대상 | 바이브 코딩 기본 과정 수료자, 또는 Claude Code로 파이썬 프로그램을 만들고 Git·GitHub를 써 본 사람 |
| 과정 구성 | 12장 × 3시간 (총 36시간) |
| 진행 방식 | 짧은 개념 설명(30%) + 실습(60%) + 공유·회고(10%) |
| 사용 도구 | Claude Code, Python, uv, VS Code, Git·GitHub, SQLite, Django, HTMX, 텔레그램 봇, Claude API |
| 사전 준비 | 기본 과정 준비물(노트북, Claude 유료 구독, GitHub 계정) + Anthropic Console 계정(API 사용료 별도), 텔레그램 계정 |
| 최종 결과물 | 데이터베이스와 AI 기능을 갖춘 웹 서비스(필요하면 메신저 봇 포함) 1개를 만들어 인터넷에 배포하고 발표 |

### 기본 과정과 무엇이 다른가?

기본 과정에서는 "말로 설명하면 동작하는 프로그램이 나온다"는 경험을 했다. 고급 과정에서는 프로그램이 커지고, 여러 사람이 쓰고, 돈(API 비용)이 드는 상황을 다룬다. 학습자의 역할은 **"무엇을 만들지 정하는 사람"에서 "구조를 정하고 품질·비용·보안을 책임지는 사람"** 으로 넓어진다.

| 구분 | 기본 과정 | 고급 과정 |
|---|---|---|
| 데이터 저장 | 텍스트·JSON·엑셀 파일 | 데이터베이스(SQLite) |
| 화면 | Streamlit (한 사람이 쓰는 도구) | Django + HTMX (여러 사람이 가입해 쓰는 서비스) |
| 사용자와 만나는 곳 | 웹 브라우저 | 웹 브라우저 + 메신저(텔레그램) |
| AI 활용 | Claude Code가 코드를 만들어 줌 | 내 서비스 안에 Claude를 넣어 기능으로 제공 |
| 검증 방법 | 직접 실행해서 눈으로 확인 | 눈으로 확인 + 자동 테스트 |
| Claude Code 사용 | 기본 기능 사용 | Skills·MCP로 확장해서 사용 |

### 교육 원칙

1. **구조를 알고 지시한다.** 코드를 한 줄씩 외우지 않되, 화면·서버·데이터베이스가 어떻게 연결되는지는 그림으로 설명할 수 있어야 한다.
2. **데이터부터 설계한다.** 화면보다 "무엇을 어떤 표에 저장할지"를 먼저 정하면 AI도 덜 헤맨다.
3. **테스트로 검증한다.** 기능이 늘어날수록 손으로 다 확인할 수 없다. "잘 된다"는 테스트가 통과했다는 뜻이어야 한다.
4. **비용과 보안을 설계에 넣는다.** API 키·봇 토큰·개인정보와 API 사용료는 다 만든 뒤가 아니라 처음부터 고려한다.
5. **작게 만들고 자주 저장한다.** 기본 과정의 원칙은 그대로다. 기능마다 커밋하고, 실험은 브랜치에서 한다.
6. **내 문제에서 출발한다.** 예제는 출발점일 뿐, 최종 프로젝트는 학습자 본인의 업무·생활 문제를 소재로 삼는다.

## 2. 수료 시 학습 목표

과정을 마친 학습자는 다음을 할 수 있다.

- 데이터를 테이블로 설계하고, SQL로 저장·조회·집계하는 프로그램을 Claude Code와 함께 만들 수 있다.
- 웹 서비스의 구조(요청·응답, URL·뷰·템플릿, 모델·데이터베이스)를 그림으로 설명할 수 있다.
- Django와 HTMX로 회원가입·로그인, 글쓰기, 즉시 반응하는 화면을 갖춘 웹 서비스를 만들 수 있다.
- Claude Code에게 자동 테스트를 작성·실행하도록 요청하고, 결과를 해석할 수 있다.
- 메신저 봇을 만들어 명령에 응답하고 정해진 시간에 알림을 보낼 수 있다.
- Claude API로 내 서비스와 봇에 AI 기능(대화, 요약, 분류, 도구 사용)을 넣고, 사용량과 비용을 관리할 수 있다.
- Skills와 MCP로 Claude Code를 내 프로젝트에 맞게 확장할 수 있다.
- 웹 서비스를 인터넷에 배포하고, 운영 설정과 비밀 정보를 안전하게 관리할 수 있다.
- SQL 인젝션, 프롬프트 인젝션, 키 노출 같은 위험을 이해하고 예방할 수 있다.

### 1장. 데이터를 오래 보관하기: SQLite

📘 학습 교재: [ch01.md](ch01.md)

**학습 목표**
- 파일 저장과 데이터베이스 저장의 차이를 설명할 수 있다.
- 테이블·행·열의 의미를 알고, 기본 SQL 문장을 읽을 수 있다.
- SQLite에 데이터를 저장·조회·수정·삭제하는 프로그램을 만들 수 있다.

**진행 (180분)**

| 시간 | 내용 |
|---|---|
| 20분 | 오리엔테이션: 기본 과정 결과물 공유, 개발 환경 점검(Claude Code 업데이트, uv, Git) |
| 30분 | 개념: 왜 데이터베이스인가 — JSON·CSV 파일의 한계(검색, 동시 수정, 데이터 양), 테이블·행·열, SQLite = 파일 하나로 된 데이터베이스 |

| 80분 | 실습: 가계부 프로그램 (지출 기록 → 조회 → 수정·삭제 → 기간별 조회) |
| 20분 | 공유 및 회고 |

**도구 준비**
- **DB Browser for SQLite** 또는 VS Code의 SQLite 확장: 데이터베이스 파일을 표 형태로 직접 열어 보는 도구 (AI가 만든 결과를 눈으로 검증)
- 파이썬에 기본으로 들어 있는 `sqlite3` 모듈을 사용하므로 별도 패키지 설치는 필요 없다.

**실습 프롬프트 예시**
```
날짜, 항목, 금액, 카테고리를 저장하는 가계부 프로그램을 SQLite로 만들어 줘.
코드를 쓰기 전에 테이블 구조를 먼저 보여 주고, 각 열이 왜 필요한지 설명해 줘.
```
```
방금 실행한 SQL 문장을 한 줄씩 쉬운 말로 설명해 줘.
```
```
지금 데이터베이스에 들어 있는 내용을 SELECT 문으로 보여 줘. 내가 DB Browser에서 본 것과 같은지 비교해 볼게.
```

**Claude Code 기능**
- `claude -c`: 가장 최근 대화를 이어서 시작하기
- `/resume`: 지난 대화 목록에서 골라 이어 하기 — 여러 날에 걸친 프로젝트에서 유용

**핵심 포인트**
- 기본 과정 4장의 할 일 관리 프로그램(파일 저장)과 비교해 보며 데이터베이스의 장점을 체감한다.
- 데이터베이스 파일(`.db`)에 개인 데이터가 쌓이면 GitHub에 올리지 않는다. 샘플 데이터는 생성 스크립트로 만든다.

**과제**: 가계부에 카테고리별 검색과 "이번 달 지출만 보기" 기능 추가

### 2장. 데이터 설계와 활용

📘 학습 교재: [ch02.md](ch02.md)

**학습 목표**
- 데이터를 여러 테이블로 나누는 이유와 테이블 사이의 관계를 설명할 수 있다.
- `JOIN`과 `GROUP BY`로 여러 테이블의 데이터를 합치고 집계할 수 있다.
- SQL 인젝션이 무엇인지 알고 예방할 수 있다.

**진행 (180분)**

| 시간 | 내용 |
|---|---|
| 20분 | 과제 공유 |
| 30분 | 개념: 중복을 없애는 테이블 나누기, 기본키·외래키, 1:N 관계, ERD(테이블 관계 그림) |
| 30분 | SQL 읽기: `JOIN`, `GROUP BY`와 집계 함수(`COUNT`, `SUM`, `AVG`) / **보안 수업**: SQL 인젝션과 파라미터 바인딩 |
| 80분 | 실습: 독서 기록 웹 앱 — 테이블 설계 → SQLite 저장 → Streamlit 화면 연결(기본 과정 8장 복습) |
| 20분 | 회고 |

**실습 프롬프트 예시**
```
독서 기록 앱을 만들려고 해. 책 정보, 읽은 기록, 메모를 저장하고 싶어.
아직 코드는 쓰지 말고, 테이블 구조와 관계를 표와 mermaid ERD로 보여 줘.
```
```
장르별로 읽은 책 수와 평균 별점을 구하는 SQL을 만들어 주고, 결과가 맞는지 확인할 수 있게 원본 데이터도 같이 보여 줘.
```
```
이 코드에 SQL 인젝션 위험이 있는지 검사해 줘. 있다면 어떤 입력으로 공격할 수 있는지 보여 주고 고쳐 줘.
```

**Claude Code 기능**
- **Plan 모드**로 테이블 설계를 먼저 검토 → 설계가 마음에 들 때만 구현 승인
- mermaid 다이어그램 요청 → VS Code 미리보기나 GitHub에서 그림으로 확인

**핵심 포인트**
- 사용자 입력을 SQL 문자열에 **직접 이어 붙이지 않는다**. `?` 자리 표시자(파라미터 바인딩)를 쓰도록 CLAUDE.md에 규칙으로 적어 둔다.
- 테이블 구조를 바꾸기 전에는 반드시 커밋하고 데이터베이스 파일을 백업한다.

**과제**: 독서 기록 앱에 통계 화면(월별 읽은 권수, 장르별 비율 차트) 추가

### 3장. 웹 서비스의 구조와 Django

📘 학습 교재: [ch03.md](ch03.md)

**학습 목표**
- 브라우저·서버·데이터베이스가 요청과 응답으로 어떻게 대화하는지 설명할 수 있다.
- 모던 모놀리스가 무엇이고, 왜 1인 개발자에게 유리한지 설명할 수 있다.
- Django 프로젝트를 만들고 URL → 뷰 → 템플릿 흐름으로 페이지를 추가할 수 있다.

**진행 (180분)**

| 시간 | 내용 |
|---|---|
| 20분 | 과제 공유 |
| 30분 | 개념: 웹 서비스의 구조(요청·응답, URL, HTML), Streamlit과 Django의 차이, **모던 모놀리스** — 화면 렌더링·요청 처리·데이터 접근 코드를 하나의 Django 애플리케이션으로 관리하고 배포하는 방식(데이터베이스는 이 과정에서 고른 SQLite) |
| 20분 | Django 구조 읽기: 프로젝트와 앱, `urls.py` → `views.py` → `templates/` 흐름 |
| 90분 | 실습: 스터디 모임 사이트 시작 — 홈·소개·모임 목록 페이지(파이썬 리스트의 임시 데이터를 서버에서 렌더링), 공통 레이아웃(`base.html`), CSS 프레임워크 적용 **(여기까지 기본 완료)** → 브랜치에서 색 테마 실험 → GitHub 업로드 |
| 20분 | 회고 |

**Streamlit vs Django**

| 구분 | Streamlit | Django |
|---|---|---|
| 잘하는 일 | 데이터 대시보드, 혼자 쓰는 도구 | 회원이 있는 서비스, 여러 화면과 데이터 |
| 화면 만들기 | 파이썬 코드만으로 | HTML 템플릿 + 파이썬 |
| 페이지와 주소 | 여러 페이지와 페이지별 주소 지원(`st.navigation`) | 주소 규칙을 자유롭게 설계(`/studies/3/`처럼 번호가 든 주소) |

| 관리자 화면 | 없음 | 기본 제공 |

**실습 프롬프트 예시**

|---|---|
| 20분 | 과제 공유 |
| 30분 | 개념: 전체 새로고침 vs 부분 갱신, HTMX = HTML 속성만으로 서버와 대화하기(`hx-get`, `hx-post`, `hx-target`, `hx-swap`, `hx-trigger`), 조각(partial) 템플릿 |
| 30분 | 사용자 기능: Django 인증 — 회원가입·로그인·로그아웃, 로그인한 사람만 글쓰기, 작성자만 수정·삭제 |

**일반 방식 vs HTMX 방식**

| 기능 | 일반 방식 | HTMX 방식 |
|---|---|---|
| 댓글 등록 | 페이지 전체가 다시 그려짐 | 새 댓글만 목록 아래에 붙음 |
| 좋아요 | 페이지 이동 후 돌아옴 | 숫자만 바뀜 |
| 검색 | 검색 버튼 → 결과 페이지 | 글자를 입력할 때마다 결과가 바뀜 |

**실습 프롬프트 예시**
```
게시글 상세 화면에서 댓글을 등록하면 페이지 새로고침 없이 댓글 목록에 바로 추가되게 HTMX로 바꿔 줘.
서버가 돌려주는 HTML 조각이 무엇인지도 설명해 줘.
```
```
다른 사람이 쓴 글의 수정 주소를 직접 입력하면 어떻게 돼? 막혀 있지 않다면 막아 줘.
```

**Claude Code 활용 포인트**
- 브라우저 **개발자 도구(F12)** 의 콘솔·네트워크 탭에 보이는 오류를 복사해서 전달하기
- 실행 화면의 **스크린샷**을 붙여 넣고 "이 버튼을 누르면 이 영역만 바뀌게 해 줘"처럼 위치를 지목하기

**핵심 포인트**
- 로그인하지 않은 사용자, 다른 사용자로 로그인한 상태에서 **직접** 눌러 보며 권한을 검증한다. 시크릿 창을 열어 두 사용자를 동시에 테스트한다.

```
```
이 프로젝트를 배포하려고 해. 운영 환경에서 바꿔야 할 설정을 체크리스트로 보여 주고, 비밀 정보는 환경 변수에서 읽도록 바꿔 줘.
```

**배포 전 체크리스트**

| 항목 | 확인 내용 |
|---|---|
| `DEBUG` | 운영에서는 `False` (오류 화면에 내부 정보가 노출되지 않게) |

| 정적 파일 | `collectstatic` 실행, CSS가 깨지지 않는지 확인 |
| 데이터베이스 | SQLite 파일이 재시작 후에도 남는 서비스인지 확인, 백업 방법 |
| 테스트 | 모두 통과한 상태에서 배포 |

**핵심 포인트**
- "테스트 통과 → 커밋 → 배포" 흐름을 이후 모든 장의 기본 작업 순서로 삼는다.
- 무료 배포 서비스는 조건(디스크 보존, 잠자기, 외부 접속 제한)이 자주 바뀌므로, 수업 전에 최신 조건을 확인한다.

**과제**: 배포된 사이트 주소 제출, 동료 3명에게 가입·글쓰기를 부탁하고 발견된 문제 고치기

| 80분 | 실습: 7장 봇에 Claude 연결 → AI 챗봇 (시스템 프롬프트로 역할 정하기 → 대화 기억하기 → 대화 초기화 명령) |
| 20분 | 회고 |

**Claude Code와 Claude API**

| 구분 | Claude Code | Claude API |
|---|---|---|
| 누가 쓰나 | 나 (개발할 때) | 내 서비스의 사용자 (서비스 안에서) |
| 비용 | 구독 요금에 포함 | 쓴 만큼 별도 결제 (토큰 단위) |
| 인증 | 로그인 | API 키 |
| 비유 | 내가 고용한 개발 도우미 | 내 가게에 들여놓은 AI 직원 |

**실습 프롬프트 예시**
```
Anthropic 공식 Python SDK로 Claude에게 질문하고 답을 출력하는 코드를 만들어 줘.
API 키는 .env의 ANTHROPIC_API_KEY에서 읽어 줘. 응답에 쓰인 입력·출력 토큰 수와 대략적인 비용도 함께 출력해 줘.
```
```
텔레그램 봇이 이전 대화를 기억하게 해 줘. 대화가 길어지면 비용이 어떻게 늘어나는지도 설명해 줘.
```

**핵심 포인트**
- API는 기억이 없다. "대화를 기억하는 챗봇"은 매번 이전 대화 전체를 함께 보내는 것이다 → 대화가 길수록 비용이 늘어난다.
- 수업 시작 전에 Console에서 **월 사용 한도**를 반드시 설정한다. 봇을 공개하면 모르는 사람도 내 돈으로 AI를 쓰게 된다.
- 모델 이름과 가격은 자주 바뀐다. 코드에 쓰기 전에 공식 문서의 최신 목록을 확인하게 한다.

**과제**: 시스템 프롬프트를 3가지 버전으로 바꿔 같은 질문 5개에 대한 답을 비교하고, 가장 좋은 버전과 그 이유를 정리해 오기

## 6. 부록

### A. 고급 과정에서 새로 쓰는 Claude Code 기능

기본 과정의 기능(`@파일`, `Esc`, `/rewind`, `Shift+Tab`, `/clear`, `/compact`, `/init`, `/memory`)은 그대로 쓴다.

| 기능 | 사용법 | 언제 쓰나 |
|---|---|---|
| 대화 이어 하기 | `claude -c`, `/resume` | 어제 하던 작업을 이어서 할 때 |
| 셸 명령 직접 실행 | `!명령` | 간단한 명령을 AI를 거치지 않고 실행할 때 |
| 컨텍스트 확인 | `/context` | 대화가 길어져 무엇이 기억되고 있는지 볼 때 |
| 모델 바꾸기 | `/model` | 어려운 설계는 성능 좋은 모델로, 단순 작업은 빠른 모델로 |
| 권한 설정 | `/permissions` | 자주 승인하는 안전한 명령(테스트 실행 등)을 미리 허용할 때 |
| Skills | `.claude/skills/이름/SKILL.md`, `/스킬이름` | 반복되는 작업 절차를 재사용할 때 |
| MCP | `claude mcp add`, `/mcp` | 외부 도구·서비스를 연결할 때 |
| 서브에이전트 | `/agents` | 리뷰·테스트 같은 역할을 따로 맡길 때 |
| Hooks | `/hooks` | 특정 시점에 명령을 자동 실행할 때 |

> Claude Code는 업데이트가 잦으므로, 수업 전에 공식 문서(https://docs.claude.com/en/docs/claude-code)에서 최신 사용법을 확인한다.

### B. 프롬프트 템플릿

```

**웹 기능 추가**

### D. 운영 시 유의 사항

- **API 비용**: Claude API는 구독과 별도로 과금된다. 학습자당 과정 전체 예상 비용을 미리 안내하고, 월 사용 한도를 반드시 설정하게 한다. 공개한 봇·서비스에는 사용자당 호출 횟수 제한을 둔다.
- **비밀 정보**: API 키, 봇 토큰, 운영용 `SECRET_KEY`는 `.env`와 배포 서비스의 환경 변수에만 둔다. 노출되면 커밋 삭제가 아니라 **즉시 폐기·재발급**이 정답이다. 단, Django가 만든 개발용 `SECRET_KEY`는 3장에서 `settings.py`에 둔 채 비공개 저장소에 커밋하며, 이 키는 노출된 것으로 보고 운영에 쓰지 않는다(6장에서 운영용 키를 새로 만든다).
- **개인정보·회사 데이터**: 봇 대화나 게시판에 실명·연락처·회사 기밀을 넣지 않는다. AI API로 보내는 데이터는 외부 서비스로 전송된다는 점을 안내한다.
- **공개 범위**: 회원가입을 누구에게나 열어 두면 스팸이나 악용이 생길 수 있다. 실습 기간에는 초대한 사람만 가입하거나 관리자 승인 후 활동하도록 설정한다.
- **권한 승인**: MCP 연결, 데이터베이스 삭제, 배포처럼 영향이 큰 작업은 Claude Code가 요청하는 내용을 읽고 이해한 뒤 승인하도록 지도한다.
- **AI 결과 검증**: 테스트가 통과하고, 직접 눌러 본 것만 믿는다. AI 기능의 답은 테스트 질문 목록으로 반복 확인한다.
- **진도 격차**: 고급 과정은 이전 장 결과물 위에 쌓아 가므로, 뒤처진 학습자를 위해 장마다 "시작용 저장소(이전 장 완성본)"를 준비해 둔다.

### E. 다음 과정

고급 과정을 마치면 로드맵의 **2단계: LLM 응용 서비스 개발**로 넘어간다. 2단계에서는 AI가 만든 코드를 읽는 수준을 넘어, 파이썬 기초부터 직접 코드를 작성하며 체계적으로 배운다.

| 고급 과정에서 맛본 것 | 2단계에서 깊이 배우는 것 |
|---|---|
| SQLite, SQL 기본 | 데이터 처리 기초(SQL, pandas) |
| Django, 요청·응답 | 웹·API 기초, LLM 서비스 배포(FastAPI, Docker) |
| Claude API, 시스템 프롬프트 | LLM 기본 이해, 프롬프트 엔지니어링, LLM API 활용 |
| 도구 사용(Tool Use), MCP | 에이전트 개발 |
| 테스트 질문 목록 | LLM 평가(Evals) 심화 |
| 프롬프트 인젝션, 비밀 정보 관리 | AI 안전·책임 |
