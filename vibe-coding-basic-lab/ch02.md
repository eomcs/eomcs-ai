# 2장. AI에게 일 잘 시키기

> 이 장에서는 AI가 내 의도대로 일하게 만드는 요청 방법을 익히고, 요청을 하나씩 쌓아 가며 숫자 맞추기 게임을 완성한다.

## 이 장에서 배울 것

- 좋은 요청과 나쁜 요청의 차이를 알고, **목적 · 입력 · 출력 · 조건** 4요소로 요청문을 쓴다.
- 큰 기능을 작게 쪼개서 한 번에 하나씩 요청하고, 결과를 보고 다시 요청한다.
- 파이썬의 입력(`input`), 조건문(`if`), 반복문(`for`, `while`)을 코드에서 알아본다.
- Claude Code의 `@`파일 참조, 작업 중단, 대화 초기화, 이미지 첨부 기능을 사용한다.

### 이 장의 결과물

```
난이도를 선택하세요 (1: 쉬움, 2: 보통, 3: 어려움): 2
1부터 100 사이의 숫자를 맞춰 보세요!
숫자 입력: 50
더 큰 숫자입니다.
숫자 입력: abc
숫자를 입력하세요.
숫자 입력: 75
더 작은 숫자입니다.
숫자 입력: 63
정답입니다! 3번 만에 맞췄습니다.
현재 최고 기록: 3번
다시 하시겠습니까? (y/n): n
```

난이도 선택, 잘못된 입력 처리, 최고 기록 기능을 갖춘 숫자 맞추기 게임 `game.py`

## 1. 좋은 요청의 조건

### 1-1. AI는 독심술사가 아니다

Claude Code는 매우 유능하지만 내 머릿속을 들여다볼 수는 없다. 처음 출근한 **신입 사원**에게 일을 맡기는 상황을 떠올려 보자.

| 상사의 지시 | 결과 |
|---|---|
| "보고서 좀 만들어 줘." | 무슨 보고서인지, 언제까지인지, 어떤 형식인지 몰라서 엉뚱한 결과가 나온다. |
| "이번 달 지역별 매출을 표로 정리해 줘. 엑셀 한 장으로, 금요일까지." | 원하는 결과에 가까운 보고서가 나온다. |

AI도 마찬가지다. 요청이 모호하면 AI는 빈칸을 **자기 마음대로 채운다**. 결과가 마음에 들지 않는다면 AI의 실력보다 요청이 모호했을 가능성이 크다.

### 1-2. 좋은 요청의 4요소

좋은 요청에는 다음 네 가지가 들어 있다.

| 요소 | 질문 | 예시 (숫자 맞추기 게임) |
|---|---|---|
| **목적** | 무엇을 만들고 싶은가? | 숫자 맞추기 게임을 만들고 싶다. |
| **입력** | 사용자가 무엇을 넣는가? | 사용자가 숫자를 입력한다. |
| **출력** | 무엇을 보여 줘야 하는가? | "더 큼/더 작음"을 알려 주고, 맞추면 몇 번 만에 맞췄는지 보여 준다. |
| **조건** | 지켜야 할 규칙이나 예외 상황은? | 정답은 1~100 사이에서 컴퓨터가 정한다. 맞출 때까지 반복한다. |

네 가지를 모두 담으면 다음과 같은 요청문이 된다.

```
1~100 사이 숫자를 컴퓨터가 정하고, 내가 맞출 때까지 "더 큼/더 작음"을 알려 주는 게임을 game.py로 만들어 줘. 몇 번 만에 맞췄는지도 마지막에 보여 줘.
```

> 💡 4요소를 매번 빠짐없이 쓸 필요는 없다. 결과가 기대와 다르게 나왔을 때 "4요소 중 무엇을 빠뜨렸나?"를 점검하는 도구로 쓰면 된다.

### 1-3. 나쁜 요청과 좋은 요청 비교

| 나쁜 예 | 좋은 예 | 무엇이 나아졌나 |
|---|---|---|
| 게임 만들어 줘 | 1~100 사이 숫자를 컴퓨터가 정하고, 내가 맞출 때까지 "더 큼/더 작음"을 알려 주는 게임을 game.py로 만들어 줘. | 목적·입력·출력·조건이 모두 드러난다. |
| 이상해. 고쳐 줘 | 숫자 대신 글자를 입력하면 프로그램이 멈춰. 이럴 땐 "숫자를 입력하세요"라고 안내하고 다시 입력받게 고쳐 줘. | 무엇이 문제인지, 어떻게 바뀌길 원하는지가 분명하다. |
| 더 예쁘게 해 줘 | 정답을 맞추면 축하 문구 위아래에 ★ 줄을 넣어서 눈에 띄게 해 줘. | "예쁘게"가 구체적인 모습으로 바뀌었다. |
| 기능 좀 추가해 줘 | 게임이 끝나면 "다시 하시겠습니까? (y/n)"를 물어보고, y를 누르면 새 게임을 시작하게 해 줘. | 어떤 기능인지, 어떻게 동작해야 하는지 알 수 있다. |

### 1-4. 한 번에 하나씩 요청한다

처음부터 모든 기능을 한꺼번에 요청하면 다음과 같은 문제가 생긴다.

- 결과가 이상할 때 **어느 부분이 문제인지** 찾기 어렵다.
- AI가 여러 기능을 동시에 만들다가 일부를 빠뜨리거나 잘못 이해한다.
- 내가 코드를 읽고 확인해야 할 양이 너무 많아진다.

그래서 바이브 코딩은 **작게 요청 → 실행해서 확인 → 다음 요청**을 반복한다. 계단을 한 칸씩 오르는 것과 같다.

```
1단계: 기본 게임        → 실행해서 확인
2단계: 잘못된 입력 처리  → 실행해서 확인
3단계: 난이도 선택       → 실행해서 확인
4단계: 최고 기록 표시    → 실행해서 확인
```

### 1-5. 결과를 보고 다시 요청한다

첫 요청으로 완벽한 결과가 나오는 경우는 드물다. 결과가 기대와 다르면 다음 세 가지를 담아 다시 요청한다.

1. **지금 어떤 상태인가**: "글자를 입력하면 오류가 나면서 프로그램이 꺼져."
2. **어떻게 되길 원하는가**: "다시 입력받게 해 줘."
3. **바꾸지 말아야 할 것은 무엇인가**: "나머지 기능은 그대로 둬."

> ⚠️ "다시 해 줘", "제대로 해 줘"만으로는 AI가 무엇을 고쳐야 할지 모른다. 무엇이 마음에 들지 않는지 구체적으로 말한다.

## 2. 파이썬 개념 읽기: 입력, 조건, 반복

이 절의 목표는 문법을 외우는 것이 아니다. AI가 만든 코드를 보고 **"아, 여기서 입력을 받는구나", "여기서 반복하는구나"를 알아보는 것**이 목표다.

### 2-1. 입력: `input()`

```python
name = input("이름을 입력하세요: ")
print(f"반갑습니다, {name}님!")
```

- `input()`은 프로그램을 잠시 멈추고 사용자가 키보드로 입력할 때까지 기다린다.
- 사용자가 입력한 내용은 변수(`name`)에 담긴다.

`input()`으로 받은 값은 숫자를 입력해도 항상 **글자(문자열)** 다. 계산하려면 숫자로 바꿔야 한다.

```python
age = int(input("나이를 입력하세요: "))   # int()는 글자를 정수로 바꾼다
print(f"10년 뒤에는 {age + 10}살입니다.")
```

> 💡 `int("abc")`처럼 숫자가 아닌 글자를 정수로 바꾸려 하면 `ValueError` 오류가 난다. 실습 2단계에서 이 문제를 직접 해결한다.

### 2-2. 조건문: `if` / `elif` / `else`

조건에 따라 **다른 일**을 하게 만든다.

```python
score = 85

if score >= 90:
    print("A 학점")
elif score >= 80:
    print("B 학점")
else:
    print("C 학점")
```

| 코드 | 읽는 법 |
|---|---|
| `if score >= 90:` | 만약 점수가 90 이상이면 |
| `elif score >= 80:` | 그렇지 않고 점수가 80 이상이면 |
| `else:` | 둘 다 아니면 |

- 조건 줄 끝에는 콜론(`:`)이 붙는다.
- 조건이 맞을 때 실행할 코드는 **한 단계 들여쓴다**(보통 스페이스 4칸). 파이썬은 들여쓰기로 "여기까지가 이 조건에 속한 코드"임을 구분한다.

자주 쓰는 비교 기호는 다음과 같다.

| 기호 | 뜻 | 기호 | 뜻 |
|---|---|---|---|
| `==` | 같다 | `!=` | 같지 않다 |
| `>` | 크다 | `<` | 작다 |
| `>=` | 크거나 같다 | `<=` | 작거나 같다 |

> ⚠️ `=`는 "변수에 값을 넣는다", `==`는 "두 값이 같은가?"를 묻는다. 서로 다른 기호다.

### 2-3. 반복문: `for`

**정해진 횟수만큼** 반복한다.

```python
for i in range(3):
    print(f"{i + 1}번째 인사: 안녕하세요!")
```

```
1번째 인사: 안녕하세요!
2번째 인사: 안녕하세요!
3번째 인사: 안녕하세요!
```

- `range(3)`은 0, 1, 2 세 개의 숫자를 차례로 만든다. 컴퓨터는 숫자를 0부터 센다.
- 반복할 코드는 `if`와 마찬가지로 들여쓴다.

### 2-4. 반복문: `while`

**조건이 맞는 동안** 계속 반복한다. 몇 번 반복할지 미리 알 수 없을 때 쓴다.

```python
password = ""

while password != "1234":
    password = input("비밀번호를 입력하세요: ")

print("로그인 성공!")
```

- 비밀번호가 `"1234"`가 아닌 동안 계속 다시 묻는다.
- `while True:`는 "무조건 계속 반복하라"는 뜻이다. 이때는 반복 안에서 `break`를 만나야 반복이 끝난다.

```python
while True:
    answer = input("종료하려면 q를 입력하세요: ")
    if answer == "q":
        break          # 반복을 빠져나간다
```

> ⚠️ 끝나는 조건이 없는 반복을 **무한 반복**이라고 한다. 프로그램이 멈추지 않으면 터미널에서 `Ctrl+C`를 눌러 강제로 끝낸다.

## 3. Claude Code 기능 익히기

### 3-1. `@`로 파일 지목하기

입력창에 `@`를 입력하면 파일 목록이 나타난다. 원하는 파일을 고르면 그 파일을 대상으로 대화할 수 있다.

```
@game.py 에서 정답을 맞췄을 때 나오는 문구를 바꿔 줘.
```

파일이 여러 개일 때 AI가 엉뚱한 파일을 고치는 일을 막을 수 있다.

### 3-2. 작업 중단하기

AI가 내 의도와 다른 방향으로 작업하고 있다면 끝날 때까지 기다리지 말고 **바로 멈춘다**. 멈춘 뒤 원하는 것을 다시 설명하면 된다.

### 3-3. 대화 초기화하기

Claude Code는 같은 대화 안에서 앞서 나눈 이야기를 모두 기억한다. 전혀 다른 주제를 시작할 때는 대화를 비우는 것이 좋다. 이전 대화가 새 작업에 영향을 주지 않고, 응답도 빨라진다.

> 💡 대화를 비워도 **파일은 그대로 남는다.** 지워지는 것은 대화 기록뿐이다.

### 3-4. 이미지 붙여 넣기

오류 화면이나 결과 화면을 말로 설명하기 어려우면 **스크린샷**을 붙여 넣는다. "이 화면처럼 나오는데 왜 그런지 알려 줘"처럼 이미지와 함께 요청할 수 있다.

### 3-5. 여러 줄로 요청 쓰기

요청이 길어지면 여러 줄로 나눠 쓰는 것이 읽기 좋다. 그냥 `Enter`를 누르면 요청이 바로 전송되므로, 줄을 바꿀 때는 다른 키를 쓴다.

### 3-6. 터미널(CLI)과 VS Code 확장의 사용법 비교

| 기능 | 터미널(CLI) | VS Code 확장 |
|---|---|---|
| 파일 지목 | `@` 입력 후 파일 선택 | `@` 입력 후 파일 선택 |
| 작업 중단 | `Esc` | 입력창의 중지 버튼 |
| 대화 초기화 | `/clear` 입력 | 패널의 **새 대화** 버튼 |
| 이미지 붙여 넣기 | 이미지 파일을 터미널로 끌어다 놓기, 또는 복사 후 `Ctrl+V` (macOS도 `Cmd+V`가 아닌 `Ctrl+V`) | 입력창에 끌어다 놓거나 붙여 넣기 |
| 줄 바꿈 | `\` 입력 후 `Enter`, 또는 `Shift+Enter` | `Shift+Enter` |

> 💡 터미널에서 `Shift+Enter`로 줄이 바뀌지 않으면 Claude Code 입력창에 `/terminal-setup`을 입력해 설정한다. 버튼 이름이나 단축키는 버전에 따라 다를 수 있다.

## 4. 실습: 숫자 맞추기 게임

### 4-1. 시작 준비

1장에서 익힌 방법으로 Claude Code를 시작한다.

```bash
cd ~/vibe-coding
code .
```

VS Code에서 **터미널 → 새 터미널**을 열고 `claude`를 입력한다(VS Code 확장을 쓴다면 Claude Code 패널을 연다).

> ⚠️ **게임은 내가 직접 실행한다.** 숫자 맞추기 게임은 사용자의 입력을 기다리는 프로그램이다. Claude Code는 키보드 입력을 직접 해 줄 수 없으므로, 게임 실행은 **별도의 터미널을 하나 더 열어** 내가 직접 한다. VS Code에서 **터미널 → 새 터미널**을 한 번 더 누르면 된다.

| 터미널 | 용도 |
|---|---|
| 첫 번째 터미널 | Claude Code와 대화 |
| 두 번째 터미널 | `python3 game.py`(Windows는 `python game.py`)로 게임 실행 |

### 4-2. 1단계: 기본 게임 만들기

4요소를 담아 요청한다.

```
1~100 사이 숫자를 컴퓨터가 정하고, 내가 맞출 때까지 "더 큼/더 작음"을 알려 주는 게임을 game.py로 만들어 줘. 몇 번 만에 맞췄는지도 마지막에 보여 줘. 실행은 내가 직접 해 볼게.
```

만들어진 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import random

answer = random.randint(1, 100)   # 1~100 사이 숫자를 무작위로 정한다
count = 0                         # 시도 횟수

print("1부터 100 사이의 숫자를 맞춰 보세요!")

while True:
    guess = int(input("숫자 입력: "))
    count = count + 1

    if guess > answer:
        print("더 작은 숫자입니다.")
    elif guess < answer:
        print("더 큰 숫자입니다.")
    else:
        print(f"정답입니다! {count}번 만에 맞췄습니다.")
        break
```

두 번째 터미널에서 게임을 실행해 본다.

```bash
python3 game.py   # macOS
python game.py    # Windows
```

#### 코드에서 개념 찾기

2절에서 배운 개념이 코드의 어디에 있는지 찾아본다.

| 개념 | 코드 | 하는 일 |
|---|---|---|
| 입력 | `input("숫자 입력: ")` | 사용자에게 숫자를 받는다. |
| 형 변환 | `int(...)` | 입력받은 글자를 정수로 바꾼다. |
| 반복 | `while True:` | 맞출 때까지 계속 묻는다. |
| 조건 | `if` / `elif` / `else` | 입력한 숫자와 정답을 비교한다. |
| 반복 종료 | `break` | 정답을 맞추면 반복을 끝낸다. |
| 모듈 | `import random` | 무작위 숫자를 만드는 도구를 불러온다. |

잘 모르는 부분이 있으면 질문한다.

```
@game.py 에서 import random과 random.randint가 무슨 뜻인지 쉽게 설명해 줘.
```

### 4-3. 2단계: 잘못된 입력 처리하기

먼저 게임을 실행하고 숫자 대신 `abc`를 입력해 본다. 다음과 같은 오류가 나면서 프로그램이 꺼진다.

```
ValueError: invalid literal for int() with base 10: 'abc'
```

이 문제를 1-5에서 배운 방법(지금 상태 → 원하는 결과)으로 요청한다.

```
숫자 대신 글자를 입력하면 ValueError가 나면서 프로그램이 멈춰. 이럴 땐 "숫자를 입력하세요"라고 안내하고 다시 입력받게 고쳐 줘. 잘못 입력한 것은 시도 횟수에 넣지 마.
```

수정이 끝나면 다시 실행해서 `abc`, 빈칸, `3.5` 등을 입력해 본다. 모두 안내 문구가 나오고 게임이 계속되는지 **직접 확인**한다.

> 💡 마지막 문장 "잘못 입력한 것은 시도 횟수에 넣지 마"가 **조건**이다. 이 문장이 없으면 AI가 잘못 입력한 것도 횟수에 넣을 수 있다. 내가 원하는 규칙은 말로 분명히 해 둔다.

### 4-4. 3단계: 난이도 선택 기능 추가하기

```
게임을 시작할 때 난이도를 고르게 해 줘.
- 1: 쉬움 (1~10)
- 2: 보통 (1~100)
- 3: 어려움 (1~1000)
안내 문구도 고른 난이도에 맞는 범위로 바꿔 줘. 1, 2, 3 말고 다른 값을 입력하면 다시 고르게 해 줘.
```

> 💡 이렇게 목록 형태로 쓰면 AI가 요구 사항을 빠뜨리지 않는다. 줄을 바꾸는 방법은 3-5, 3-6을 참고한다.

실행해서 세 가지 난이도를 모두 확인한다. 특히 **쉬움**을 골랐을 때 정말 1~10 사이 숫자만 나오는지 확인한다.

### 4-5. 4단계: 최고 기록 표시하기

```
게임이 끝나면 "다시 하시겠습니까? (y/n)"를 물어봐 줘. y를 입력하면 난이도 선택부터 다시 시작하고, n을 입력하면 종료해 줘. 게임을 여러 판 하는 동안 가장 적은 시도 횟수를 "현재 최고 기록"으로 보여 줘.
```

실행해서 세 판 이상 해 보고, 최고 기록이 제대로 바뀌는지 확인한다.

> 💡 프로그램을 종료했다가 다시 실행하면 최고 기록이 사라진다. 프로그램이 꺼져도 기록이 남게 하려면 파일에 저장해야 하는데, 이 방법은 4장에서 배운다.

### 4-6. 원하는 대로 다듬기

이제 자유롭게 요청해서 나만의 게임으로 다듬는다. 예를 들면 다음과 같다.

```
정답과의 차이가 10 이하이면 "아주 가까워요!"라는 힌트를 추가로 보여 줘.
```

```
시도 횟수가 10번을 넘으면 정답을 알려 주고 게임을 끝내 줘.
```

```
@game.py 의 안내 문구를 모두 반말로 바꿔 줘. 나머지 기능은 그대로 둬.
```

> 💡 옆 사람과 같은 요청을 했는데 코드가 다를 수 있다. AI는 같은 요청에도 매번 조금씩 다른 코드를 만든다. 정답 코드가 하나만 있는 것이 아니다. **원하는 대로 동작하는지**가 중요하다.

### 4-7. 새 주제 시작하기

게임을 완성했으면 대화를 비우고 새 주제를 시작하는 연습을 한다. 터미널(CLI)에서는 `/clear`를 입력하고, VS Code 확장에서는 **새 대화** 버튼을 누른다.

대화를 비운 뒤 다음과 같이 요청해 본다.

```
@game.py 가 어떤 프로그램인지 세 줄로 요약해 줘.
```

대화 기록이 지워져도 `@`로 파일을 지목하면 Claude Code가 파일 내용을 읽고 답한다.

## 5. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| Claude Code가 `game.py`를 실행하다 멈춘 것처럼 보인다 | 게임이 입력을 기다리고 있는 것이다. 작업을 중단하고(CLI는 `Esc`), 두 번째 터미널에서 직접 실행한다. |
| 게임이 끝나지 않는다 | 무한 반복에 빠진 것이다. 게임을 실행한 터미널에서 `Ctrl+C`를 눌러 끝내고, 증상을 Claude Code에게 설명한다. |
| `ValueError` 오류가 난다 | 숫자가 아닌 값을 정수로 바꾸려 한 것이다. 4-3처럼 잘못된 입력을 처리해 달라고 요청한다. |
| `IndentationError` 오류가 난다 | 들여쓰기가 잘못된 것이다. 오류 메시지를 그대로 붙여 넣고 고쳐 달라고 요청한다. |
| 요청하지 않은 부분까지 바뀌었다 | "방금 바꾼 것 중 ○○는 원래대로 돌려 줘. 앞으로는 요청한 부분만 바꿔 줘."라고 요청한다. 3장에서 변경을 되돌리는 기능도 배운다. |
| AI가 다른 파일을 고쳤다 | `@파일이름`으로 고칠 파일을 지목해서 다시 요청한다. |
| 요청을 쓰다가 `Enter`를 눌러 전송돼 버렸다 | 작업을 중단하고 나머지 내용을 이어서 쓴다. 줄 바꿈 방법은 3-6을 참고한다. |

## 6. 정리

### 핵심 요약

1. AI는 요청이 모호하면 빈칸을 마음대로 채운다. **목적 · 입력 · 출력 · 조건**을 담아 요청한다.
2. 큰 기능은 작게 쪼개서 **한 번에 하나씩** 요청하고, 매번 실행해서 확인한다.
3. 결과가 마음에 들지 않으면 **지금 상태, 원하는 결과, 바꾸지 말아야 할 것**을 담아 다시 요청한다.
4. `input()`은 입력, `if`는 조건, `for`와 `while`은 반복이다. 코드를 외우지 말고 알아볼 수 있으면 된다.
5. 사용자 입력을 기다리는 프로그램은 별도의 터미널에서 **내가 직접 실행**한다.

### 요청문 템플릿

**새 기능 요청**
```
[무엇을] 하는 기능을 만들어 줘.
- 입력: [사용자가 넣는 것]
- 출력: [보여 줘야 하는 것]
- 조건: [지켜야 할 규칙, 예외 상황]
```

**수정 요청**
```
지금은 [현재 상태]야.
[원하는 결과]가 되게 고쳐 줘.
[바꾸지 말아야 할 것]은 그대로 둬.
```

### 용어 사전

| 용어 | 뜻 |
|---|---|
| 프롬프트(요청문) | AI에게 보내는 지시나 질문 |
| 입력 | 사용자가 프로그램에 넣는 값. 파이썬에서는 `input()`으로 받는다. |
| 형 변환 | 값의 종류를 바꾸는 것. 예) `int()`로 글자를 정수로 바꾼다. |
| 조건문 | 조건에 따라 다른 코드를 실행하는 문장(`if`, `elif`, `else`) |
| 반복문 | 같은 코드를 여러 번 실행하는 문장(`for`, `while`) |
| 들여쓰기 | 줄 앞의 빈칸. 파이썬은 들여쓰기로 코드의 묶음을 구분한다. |
| 무한 반복 | 끝나는 조건이 없어 멈추지 않는 반복 |
| `break` | 반복을 즉시 빠져나가게 하는 명령 |
| 모듈 | 다른 사람이 만들어 둔 기능 묶음. `import`로 불러온다. |

### 스스로 점검하기

- [ ] 좋은 요청의 4요소를 말할 수 있다.
- [ ] 모호한 요청을 4요소가 담긴 요청으로 바꿔 쓸 수 있다.
- [ ] 큰 기능을 여러 단계로 쪼개서 하나씩 요청했다.
- [ ] `game.py`에서 `input`, `if`, `while`, `break`를 찾아 역할을 설명할 수 있다.
- [ ] `@`로 파일을 지목해서 요청했다.
- [ ] 작업 중단과 대화 초기화를 직접 해 봤다.
- [ ] 게임을 별도의 터미널에서 직접 실행하고, 각 단계의 기능을 확인했다.

## 7. 과제

**가위바위보 게임** 또는 **용돈 계산기** 중 하나를 골라 직접 기획하고, Claude Code에게 보낼 **요청문**을 작성한다.

### 작성 방법

1. 만들 프로그램을 **목적 · 입력 · 출력 · 조건** 4요소로 정리한다.
2. 기능을 **3단계 이상**으로 쪼갠다.
3. 단계마다 Claude Code에게 보낼 요청문을 쓴다.

### 작성 예시 (가위바위보의 1단계)

```markdown
## 기획
- 목적: 컴퓨터와 가위바위보를 하는 게임
- 입력: 사용자가 가위, 바위, 보 중 하나를 입력
- 출력: 컴퓨터가 낸 것과 승패 결과
- 조건: 컴퓨터는 무작위로 낸다. 잘못 입력하면 다시 입력받는다.

## 1단계 요청문
컴퓨터와 가위바위보를 하는 게임을 rps.py로 만들어 줘. 내가 "가위", "바위", "보" 중 하나를 입력하면 컴퓨터도 무작위로 하나를 내고, 컴퓨터가 낸 것과 승패를 보여 줘. 셋 중 하나가 아닌 값을 입력하면 다시 입력받아 줘.
```

**용돈 계산기** 아이디어: 한 달 용돈을 입력하고 지출 항목과 금액을 계속 입력하면 남은 금액을 보여 주고, 남은 금액이 0원 아래로 내려가면 경고하는 프로그램

### 제출할 것

1. 4요소로 정리한 기획
2. 단계별 요청문 (3단계 이상)
3. (선택) 요청문으로 실제로 만들어 본 결과 파일과, 다시 요청한 내용

> 💡 요청문을 쓰는 것 자체가 과제다. 실제로 만들어 보지 않아도 된다. 다음 장 시작 때 서로의 요청문을 비교하며 피드백을 주고받는다.
