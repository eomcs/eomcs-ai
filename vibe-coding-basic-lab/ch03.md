## 1. 파이썬 코드 읽기: 함수, 리스트, 딕셔너리

2장에서 입력·조건·반복을 배웠다. 이 장에서는 데이터를 담는 그릇인 **리스트**와 **딕셔너리**, 그리고 코드를 묶어 이름을 붙이는 **함수**를 배운다. 이번에도 목표는 외우는 것이 아니라 **알아보는 것**이다.

### 1-1. 함수: `def`

**함수**는 여러 줄의 코드를 하나로 묶고 이름을 붙인 것이다. **자판기**를 떠올려 보자. 돈과 버튼(입력)을 넣으면 음료(결과)가 나온다. 자판기 안에서 무슨 일이 일어나는지 몰라도 쓸 수 있다.

```python
def greet(name):              # greet라는 함수를 만든다. name을 받는다.
    message = f"안녕하세요, {name}님!"
    return message            # 결과를 돌려준다

text = greet("홍길동")         # 함수를 사용(호출)한다
print(text)                   # 안녕하세요, 홍길동님!
```

| 코드 | 이름 | 의미 |
|---|---|---|
| `def greet(name):` | **함수 정의** | `greet`라는 이름의 함수를 만든다. |
| `name` | **매개변수** | 함수가 받는 입력값이다. |
| `return message` | **반환** | 함수의 결과를 돌려준다. |
| `greet("홍길동")` | **함수 호출** | 만들어 둔 함수를 실제로 사용한다. |

- `def`로 함수를 **만들기만** 하면 아무 일도 일어나지 않는다. 함수 이름을 불러서 **호출**해야 실행된다.
- 사실 1장부터 써 온 `print()`, `input()`, `int()`도 파이썬이 미리 만들어 둔 함수다.

> 💡 함수를 쓰는 이유: 같은 코드를 여러 번 쓰지 않아도 되고, 이름만 보고도 무슨 일을 하는지 알 수 있다. 코드를 읽을 때 함수 이름부터 훑어보면 프로그램의 큰 구조가 보인다.

### 1-2. 리스트: `[ ]`

**리스트**는 여러 값을 **순서대로** 담는 그릇이다. 번호가 붙은 사물함을 떠올리면 된다.

```python
fruits = ["사과", "바나나", "포도"]

print(fruits[0])        # 사과   ← 첫 번째 값
print(fruits[2])        # 포도   ← 세 번째 값
print(len(fruits))      # 3     ← 값의 개수

fruits.append("딸기")    # 맨 뒤에 값을 추가한다
print(fruits)           # ['사과', '바나나', '포도', '딸기']
```

- 대괄호 `[ ]` 안에 값을 쉼표로 구분해 넣는다.
- 순서 번호(**인덱스**)는 **0부터** 시작한다. 첫 번째 값은 `fruits[0]`이다.
- `for`와 함께 쓰면 리스트의 값을 하나씩 꺼낼 수 있다.

```python
for fruit in fruits:
    print(f"{fruit}를 좋아합니다.")
```

### 1-3. 딕셔너리: `{ }`

**딕셔너리**는 **키(key)** 와 **값(value)** 을 짝지어 담는 그릇이다. 이름 그대로 **사전**과 같다. 사전에서 단어(키)를 찾으면 뜻(값)이 나온다.

```python
words = {
    "apple": "사과",
    "book": "책",
    "water": "물",
}

print(words["apple"])       # 사과  ← 키로 값을 찾는다
words["school"] = "학교"     # 새 짝을 추가한다
print(len(words))           # 4
```

- 중괄호 `{ }` 안에 `키: 값` 형태로 넣는다.
- 리스트는 **번호**로 값을 찾고, 딕셔너리는 **키**로 값을 찾는다.

| 구분 | 리스트 | 딕셔너리 |
|---|---|---|
| 기호 | `[ ]` | `{ }` |
| 값을 찾는 방법 | 번호(0, 1, 2…) | 키("apple", "book"…) |
| 비유 | 번호 붙은 사물함 | 사전 |
| 쓰임 예 | 틀린 단어 목록, 점수 기록 | 단어와 뜻, 이름과 전화번호 |

### 1-4. 함께 쓰이는 모습

실제 프로그램에서는 세 가지가 함께 쓰인다. 다음 코드에서 함수·리스트·딕셔너리를 찾아보자.

```python
scores = {"철수": 85, "영희": 92, "민수": 78}

def find_passed(score_book):
    passed = []
    for name in score_book:
        if score_book[name] >= 80:
            passed.append(name)
    return passed

print(find_passed(scores))   # ['철수', '영희']
```

- `scores`는 이름과 점수를 짝지은 **딕셔너리**다.
- `find_passed`는 80점 이상인 사람을 찾는 **함수**다.
- `passed`는 합격자 이름을 모으는 **리스트**다.

## 2. 오류 메시지 읽기

### 2-1. 오류는 컴퓨터가 주는 힌트다

오류가 나면 당황하기 쉽지만, 오류 메시지는 컴퓨터가 **"여기에서, 이런 이유로 멈췄다"** 고 알려 주는 친절한 안내문이다. 개발자도 매일 오류를 만난다. 중요한 것은 오류를 피하는 것이 아니라 **오류를 읽고 해결하는 것**이다.

### 2-2. 마지막 줄부터 읽는다

파이썬의 오류 메시지(**Traceback**)는 길고 복잡해 보인다. 하지만 읽는 순서만 알면 어렵지 않다.

```
Traceback (most recent call last):
  File "/Users/gildong/vibe-coding/quiz.py", line 43, in <module>
    run_quiz()
    ~~~~~~~~^^
  File "/Users/gildong/vibe-coding/quiz.py", line 34, in run_quiz
    score = scor + 1
            ^^^^
NameError: name 'scor' is not defined. Did you mean: 'score'?
```

| 순서 | 읽을 곳 | 알 수 있는 것 |
|---|---|---|
| ① | 마지막 줄의 앞부분 `NameError` | **오류의 종류**: 이름(변수)과 관련된 오류다. |
| ② | 마지막 줄의 뒷부분 | **오류의 이유**: `scor`라는 이름이 정의되지 않았다. 혹시 `score`를 말한 것인가? |
| ③ | 바로 위의 `File ... line 34` | **오류가 난 위치**: `quiz.py`의 34번째 줄이다. |
| ④ | 그 아래 코드와 `^^^^` | **문제의 코드**: `scor` 부분이 문제다. |

> 💡 `^`나 `~` 표시는 파이썬 버전에 따라 보이지 않을 수 있다. 표시가 없어도 읽는 방법은 같다.

> 💡 위쪽의 나머지 줄은 "어떤 경로를 거쳐 오류가 난 줄까지 왔는지"를 보여 준다. 처음에는 **마지막 줄과 그 바로 위의 위치**만 보면 충분하다.

### 2-3. 자주 보는 오류

| 오류 | 뜻 | 흔한 원인 | 예시 |
|---|---|---|---|
| `NameError` | 그런 이름은 없다 | 변수·함수 이름 오타, 만들기 전에 사용 | `print(scor)` |
| `TypeError` | 값의 종류가 맞지 않다 | 글자와 숫자를 `+`로 이어 붙이기 | `"점수: " + 5` |
| `IndentationError` | 들여쓰기가 잘못됐다 | `if`, `for`, `def` 아래 줄을 들여쓰지 않음 | 아래 예시 참고 |
| `FileNotFoundError` | 파일을 찾을 수 없다 | 파일 이름 오타, 다른 폴더에서 실행 | `open("wrods.txt")` |
| `ValueError` | 값이 올바르지 않다 | 숫자가 아닌 글자를 `int()`로 변환 (2장) | `int("abc")` |
| `SyntaxError` | 문법이 틀렸다 | 괄호·따옴표·콜론(`:`) 빠뜨림 | `print("안녕)` |

**`IndentationError` 예시**

```python
if score >= 80:
print("합격")       # ← if 아래인데 들여쓰지 않았다
```

```
IndentationError: expected an indented block after 'if' statement on line 1
```

**`TypeError` 예시**

```python
score = 5
print("점수: " + score)
```

```
TypeError: can only concatenate str (not "int") to str
```

글자(`str`)에는 글자만 이어 붙일 수 있는데 숫자(`int`)를 붙이려 했다는 뜻이다. `f"점수: {score}"`처럼 f-문자열을 쓰면 해결된다.

### 2-4. AI와 함께 오류 해결하기

오류가 나면 다음 순서로 해결한다.

1. 오류 메시지의 **마지막 줄**을 읽고 종류와 이유를 짐작해 본다.
2. 오류 메시지 **전체**를 복사해서 Claude Code에게 붙여 넣는다.
3. 바로 고쳐 달라고 하기보다 **먼저 설명을 듣고** 고쳐 달라고 한다.

```
quiz.py를 실행했더니 아래 오류가 났어.
(오류 메시지 전체 붙여 넣기)
이 오류가 무슨 뜻인지 먼저 설명해 주고, 그다음에 고쳐 줘.
```

> 💡 설명을 먼저 듣는 이유: 같은 오류를 다시 만났을 때 스스로 알아볼 수 있게 된다. 오타처럼 간단한 오류는 설명을 듣고 직접 고쳐 보는 것도 좋은 연습이다.

> ⚠️ Claude Code는 내 화면을 볼 수 없다. "오류가 났어"만 말하지 말고 **오류 메시지 전체**와 **무엇을 하다가 오류가 났는지**를 함께 알려 준다.

## 3. Claude Code 기능 익히기

### 3-1. 코드 설명 요청하기

AI가 만든 코드를 그냥 넘기지 말고 질문한다. 질문하는 방법에 따라 얻는 설명이 달라진다.

| 알고 싶은 것 | 요청 예시 |
|---|---|
| 전체 구조 | `@quiz.py 가 어떤 순서로 동작하는지 큰 흐름만 설명해 줘.` |
| 특정 부분 | `@quiz.py 의 ask_question 함수가 하는 일을 설명해 줘.` |
| 한 줄의 의미 | `random.shuffle(questions)는 무슨 뜻이야?` |
| 바꾸면 생기는 일 | `return True 줄을 지우면 어떻게 돼? 파일은 고치지 말고 설명만 해 줘.` |
| 쉬운 비유 | `딕셔너리를 일상생활에 비유해서 설명해 줘.` |
| 실행 흐름 | `내가 'apple' 문제에서 '사과'를 입력하면 코드가 어떤 순서로 실행되는지 따라가 줘.` |

> 💡 설명만 듣고 싶을 때는 **"파일은 고치지 말고 설명만 해 줘"** 라고 덧붙인다. 그렇지 않으면 AI가 질문을 수정 요청으로 이해하고 코드를 바꿀 수 있다.

### 3-2. Plan 모드: 계획부터 세우기

**Plan 모드**는 Claude Code가 파일을 고치지 않고 **계획만 세우는** 모드다. 집을 짓기 전에 설계도부터 확인하는 것과 같다.

- 큰 작업을 시작할 때 AI가 무엇을 어떻게 만들지 **미리 확인**할 수 있다.
- 계획이 마음에 들지 않으면 코드가 만들어지기 전에 **방향을 바꿀 수** 있다.
- 계획을 읽는 것만으로도 프로그램의 구조를 이해하는 데 도움이 된다.

**Plan 모드 사용 흐름**

1. Plan 모드로 전환한다.
2. 만들고 싶은 것을 요청한다.
3. Claude Code가 계획을 보여 준다.
4. 계획을 읽고, 바꾸고 싶은 점이 있으면 말한다.
5. 계획이 마음에 들면 승인한다. 이때부터 실제로 파일을 만든다.

터미널(CLI)에서는 `Shift+Tab`을 누를 때마다 모드가 바뀐다. 입력창 아래에 **plan mode on**이 표시될 때까지 누른다.

| 표시 | 모드 | 의미 |
|---|---|---|
| (표시 없음) | 기본 모드 | 파일 수정·명령 실행 전에 매번 허락을 구한다. |
| accept edits on | 수정 자동 승인 모드 | 파일 수정은 묻지 않고 바로 한다. |
| plan mode on | Plan 모드 | 파일을 고치지 않고 계획만 세운다. |

> ⚠️ 수정 자동 승인 모드는 편리하지만 AI가 무엇을 바꾸는지 놓치기 쉽다. 익숙해질 때까지는 기본 모드와 Plan 모드를 쓴다.

> 💡 Plan 모드를 쓰기 어려운 상황이라면 요청문에 **"아직 코드는 쓰지 말고 계획부터 보여 줘"** 라고 쓰면 비슷한 효과를 얻을 수 있다.

### 3-3. 되돌리기: `/rewind`

Claude Code가 파일을 고친 결과가 마음에 들지 않으면 **이전 시점으로 되돌릴 수** 있다. 게임에서 저장해 둔 지점으로 돌아가는 것과 같다.

터미널(CLI)에서는 `/rewind`를 입력하거나 `Esc`를 두 번 누른다.

1. 지금까지 보낸 요청 목록이 나타난다.
2. 되돌아갈 시점(요청)을 고른다.
3. 무엇을 되돌릴지 고른다.

| 선택 | 결과 |
|---|---|
| 코드와 대화 모두 되돌리기 | 파일과 대화가 모두 그 시점으로 돌아간다. |
| 대화만 되돌리기 | 파일은 그대로 두고 대화만 그 시점으로 돌아간다. |
| 코드만 되돌리기 | 대화는 그대로 두고 파일만 그 시점으로 돌아간다. |

> ⚠️ 되돌리기는 **Claude Code가 직접 고친 파일**만 되돌린다. 내가 VS Code에서 직접 고친 내용이나, 터미널 명령으로 지운 파일은 되돌리지 못한다. 또 이 기능은 대화 중에 쓰는 임시 저장 장치다. 작업을 영구적으로 안전하게 저장하는 방법(Git)은 5장에서 배운다.

### 3-4. 터미널(CLI)과 VS Code 확장의 사용법 비교

| 기능 | 터미널(CLI) | VS Code 확장 |
|---|---|---|
| Plan 모드 전환 | `Shift+Tab`을 눌러 **plan mode on** 표시 | 입력창의 모드 선택 메뉴에서 Plan 모드 선택 |
| 계획 승인 | 계획 아래에 나타나는 선택지에서 진행 선택 | 계획 아래에 나타나는 버튼에서 진행 선택 |
| 되돌리기 | `/rewind` 입력 또는 `Esc` 두 번 | 되돌아갈 메시지에 마우스를 올리면 나타나는 되돌리기 버튼 |

> 💡 VS Code 확장의 메뉴와 버튼 위치는 버전에 따라 다를 수 있다. 찾기 어려우면 Claude Code에게 "VS Code 확장에서 Plan 모드는 어떻게 켜?"라고 물어본다.

## 4. 실습: 단어장 퀴즈 프로그램

### 4-1. 시작 준비

1장에서 익힌 방법으로 Claude Code를 시작한다.

```bash
cd ~/vibe-coding
code .
```

VS Code에서 **터미널 → 새 터미널**을 열고 `claude`를 입력한다(VS Code 확장을 쓴다면 Claude Code 패널을 연다). 2장과 마찬가지로 퀴즈 프로그램은 사용자의 입력을 기다리므로, **두 번째 터미널**을 열어 내가 직접 실행한다.

### 4-2. 1단계: Plan 모드로 계획 세우기

Plan 모드로 전환한 뒤 요청한다.

```
영어 단어장 퀴즈 프로그램을 quiz.py로 만들고 싶어.
- 영어 단어와 한국어 뜻을 5개 정도 넣어 둬.
- 단어를 무작위 순서로 하나씩 보여 주고, 내가 뜻을 입력하면 정답인지 알려 줘.
- 마지막에 점수와 틀린 단어 목록을 보여 줘.
초보자가 읽기 쉽게 함수로 나눠서 만들어 줘. 실행은 내가 직접 해 볼게.
```

Claude Code가 보여 주는 계획은 대략 다음과 같다.

```
계획: 영어 단어장 퀴즈 (quiz.py)

1. 단어장 데이터
   - 딕셔너리 words에 영어 단어(키)와 한국어 뜻(값) 5개 저장

2. 함수 구성
   - ask_question(english, korean): 단어 하나를 묻고 정답이면 True, 오답이면 False 반환
   - run_quiz(): 단어 순서를 섞고, 모든 단어를 차례로 물은 뒤 점수와 틀린 단어 출력

3. 실행 흐름
   - 프로그램 시작 → run_quiz() 호출 → 문제 풀이 → 결과 출력
```

계획을 읽고 궁금한 점이나 바꾸고 싶은 점을 말한다. 예를 들면 다음과 같다.

```
단어를 10개로 늘려 줘. 그리고 퀴즈 시작할 때 "=== 영어 단어 퀴즈 ===" 제목을 보여 줘.
```

```
계획에 나온 True, False가 무슨 뜻이야?
```

계획이 마음에 들면 승인한다. Claude Code가 계획에 따라 `quiz.py`를 만든다.

> 💡 계획 단계에서 방향을 바꾸는 것이 코드를 다 만든 뒤에 바꾸는 것보다 훨씬 쉽고 빠르다.

### 4-3. 2단계: 실행하고 코드 읽기

두 번째 터미널에서 퀴즈를 실행해 본다.

```bash
python3 quiz.py   # macOS
python quiz.py    # Windows
```

만들어진 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import random

# 단어장: 영어 단어(키)와 한국어 뜻(값)
words = {
    "apple": "사과",
    "book": "책",
    "water": "물",
    "friend": "친구",
    "school": "학교",
}


def ask_question(english, korean):
    """단어 하나를 문제로 내고, 맞으면 True를 돌려준다."""
    answer = input(f"'{english}'의 뜻은? ")
    if answer == korean:
        print("정답입니다!")
        return True
    else:
        print(f"틀렸습니다. 정답은 '{korean}'입니다.")
        return False


def run_quiz():
    """단어장의 모든 단어를 무작위 순서로 묻고 점수를 보여 준다."""
    questions = list(words.keys())
    random.shuffle(questions)

    score = 0
    wrong_words = []

    for english in questions:
        if ask_question(english, words[english]):
            score = score + 1
        else:
            wrong_words.append(english)

    print(f"\n점수: {score} / {len(questions)}")
    if wrong_words:
        print("다시 볼 단어:", ", ".join(wrong_words))


run_quiz()
```

#### 코드에서 개념 찾기

| 개념 | 코드 | 하는 일 |
|---|---|---|
| 딕셔너리 | `words = { ... }` | 영어 단어와 뜻을 짝지어 저장한다. |
| 함수 정의 | `def ask_question(english, korean):` | 문제 하나를 내는 함수를 만든다. |
| 반환 | `return True` / `return False` | 정답 여부를 함수 밖으로 알려 준다. |
| 리스트 | `questions = list(words.keys())` | 영어 단어만 뽑아 리스트로 만든다. |
| 리스트 | `wrong_words = []` | 틀린 단어를 모을 빈 리스트를 만든다. |
| 리스트에 추가 | `wrong_words.append(english)` | 틀린 단어를 리스트에 넣는다. |
| 함수 호출 | `run_quiz()` | 맨 아래에서 퀴즈를 실제로 시작한다. |

3-1의 요청 예시를 활용해 잘 모르는 부분을 질문한다.

```
내가 'apple' 문제에서 '사과'를 입력하면 코드가 어떤 순서로 실행되는지 따라가 줘. 파일은 고치지 말고 설명만 해 줘.
```

### 4-4. 3단계: 일부러 망가뜨리고 고치기

이번에는 **내가 직접** VS Code에서 코드를 조금 망가뜨려 오류를 만들어 본다. 각 실험마다 다음 순서를 따른다.

1. 코드를 망가뜨리고 저장한다(`Cmd+S` / `Ctrl+S`).
2. 두 번째 터미널에서 실행한다.
3. 오류 메시지의 **마지막 줄**을 읽고, 무슨 오류인지 먼저 스스로 짐작해 본다.
4. 짐작한 내용을 Claude Code의 설명과 비교한다.
5. 직접 고치거나 Claude Code에게 고쳐 달라고 한다.

**실험 1. 오타 내기 (`NameError`)**

`score = score + 1`을 `score = scor + 1`로 바꾼다. 이 줄은 정답을 맞췄을 때만 실행되므로, 실행한 뒤 **정답을 하나 입력해야** 오류가 나타난다.

```
NameError: name 'scor' is not defined. Did you mean: 'score'?
```

파이썬이 `Did you mean: 'score'?`(혹시 `score`를 말한 것인가?)라고 답까지 알려 준다. 직접 고쳐 본다.

**실험 2. 들여쓰기 지우기 (`IndentationError`)**

`ask_question` 함수 안의 `print("정답입니다!")` 줄 앞의 빈칸을 모두 지운다.

```
IndentationError: expected an indented block after 'if' statement on line 16
```

16번째 줄의 `if` 아래에 들여쓴 코드가 있어야 한다는 뜻이다.

**실험 3. 글자와 숫자 이어 붙이기 (`TypeError`)**

`print(f"\n점수: {score} / {len(questions)}")`를 `print("점수: " + score)`로 바꾼다. 이 오류는 퀴즈를 끝까지 푼 뒤에 나타난다.

```
TypeError: can only concatenate str (not "int") to str
```

Claude Code에게 오류 메시지를 붙여 넣고 설명을 먼저 들은 뒤 고쳐 달라고 한다.

**실험 4. 없는 파일 열기 (`FileNotFoundError`)**

Claude Code에게 다음과 같이 요청해 오류를 일부러 만들어 본다.

```
없는 파일을 열려고 할 때 나는 오류를 보고 싶어. "wrods.txt" 파일을 여는 두 줄짜리 test.py를 만들어 줘. 실행은 내가 해 볼게.
```

```
FileNotFoundError: [Errno 2] No such file or directory: 'wrods.txt'
```

파일 이름에 오타가 있거나, 파일이 없는 폴더에서 실행하면 이 오류가 난다. 실험이 끝나면 `test.py`는 지워 달라고 한다.

> 💡 실험 1~3에서 내가 직접 고친 내용은 `/rewind`로 되돌릴 수 없다. 원래대로 돌리려면 VS Code에서 `Cmd+Z`(Windows는 `Ctrl+Z`)를 누르거나, 직접 고치거나, Claude Code에게 고쳐 달라고 한다.

### 4-5. 4단계: 되돌리기 연습하기

이번에는 Claude Code에게 변경을 요청한 뒤 되돌려 본다.

```
단어장을 영어-한국어 대신 일본어-한국어 단어로 모두 바꿔 줘.
```

바뀐 `quiz.py`를 확인한 뒤, 원래의 영어 단어장으로 되돌린다. 터미널(CLI)에서는 `/rewind`를 입력하고, 일본어로 바꿔 달라고 요청하기 **직전 시점**을 골라 **코드와 대화 모두 되돌리기**를 선택한다.

VS Code에서 `quiz.py`를 열어 영어 단어장으로 돌아왔는지 확인한다.

### 4-6. 5단계: 기능 추가하기

이제 2장에서 배운 요청 방법으로 기능을 하나씩 추가한다. 큰 기능은 Plan 모드로 계획부터 확인한다.

```
퀴즈가 끝나면 틀린 단어만 모아서 한 번 더 풀게 해 줘. 다시 풀 때도 틀린 단어가 있으면 그 단어만 또 풀게 해서, 모두 맞출 때까지 반복해 줘.
```

```
뜻을 입력할 때 앞뒤에 빈칸이 있어도 정답으로 처리해 줘.
```

```
뜻이 여러 개인 단어도 넣고 싶어. 예를 들어 "right"는 "오른쪽"과 "옳은" 중 하나만 입력해도 정답으로 처리해 줘.
```

> 💡 세 번째 요청을 하면 딕셔너리의 값이 리스트로 바뀔 가능성이 크다(`"right": ["오른쪽", "옳은"]`). 코드가 어떻게 바뀌었는지 설명을 요청해 본다.

## 5. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| `Shift+Tab`을 눌러도 Plan 모드가 안 된다 | 모드는 순서대로 바뀐다. 입력창 아래에 **plan mode on**이 보일 때까지 여러 번 누른다. |
| Plan 모드에서 파일이 만들어지지 않는다 | 정상이다. Plan 모드는 계획만 세운다. 계획을 승인해야 파일을 만든다. |
| 정답을 입력했는데 틀렸다고 한다 | 입력값 앞뒤의 빈칸이나 띄어쓰기 차이일 수 있다. 4-6의 두 번째 요청처럼 빈칸을 무시하도록 요청한다. |
| `/rewind`를 했는데 내가 고친 내용이 그대로다 | 되돌리기는 Claude Code가 고친 내용만 되돌린다. VS Code에서 `Cmd+Z`/`Ctrl+Z`로 되돌리거나 직접 고친다. |
| 오류 메시지가 너무 길어서 겁이 난다 | 마지막 줄과 그 바로 위의 `File ... line ...`만 먼저 읽는다. |
| AI가 같은 오류를 계속 못 고친다 | `/rewind`로 오류가 나기 전으로 돌아가 다른 방법으로 설명하거나, 대화를 비우고(`/clear`) 오류 메시지와 함께 처음부터 다시 요청한다. |
| 설명만 들으려 했는데 AI가 코드를 고쳤다 | `/rewind`로 되돌리고, 요청 끝에 "파일은 고치지 말고 설명만 해 줘"를 붙인다. |

## 6. 정리

### 핵심 요약

1. **함수**는 코드를 묶어 이름을 붙인 것이고, **리스트**는 순서대로, **딕셔너리**는 키와 값의 짝으로 데이터를 담는다.
2. 코드를 읽을 때는 함수 이름부터 훑어 큰 구조를 파악하고, 모르는 부분은 AI에게 질문한다.
3. 오류 메시지는 **마지막 줄**(종류와 이유)과 **그 바로 위**(위치)부터 읽는다.
4. 오류를 고칠 때는 메시지 전체를 붙여 넣고, **설명을 먼저 들은 뒤** 고쳐 달라고 한다.
5. 큰 작업은 **Plan 모드**로 계획부터 확인하고, 마음에 들지 않는 변경은 **`/rewind`** 로 되돌린다.

### 요청문 템플릿

**오류 해결**
```
[무엇을] 하다가 아래 오류가 났어.
(오류 메시지 전체 붙여 넣기)
이 오류가 무슨 뜻인지 먼저 설명해 주고, 그다음에 고쳐 줘.
```

**코드 설명**
```
@[파일 이름] 의 [함수/부분]이 하는 일을 쉽게 설명해 줘. 파일은 고치지 말고 설명만 해 줘.
```

**계획 먼저**
```
[만들고 싶은 것]을 만들고 싶어. 아직 코드는 쓰지 말고, 어떤 기능과 구조로 만들지 계획부터 보여 줘.
```

### 용어 사전

| 용어 | 뜻 |
|---|---|
| 함수 | 여러 줄의 코드를 묶어 이름을 붙인 것. `def`로 만든다. |
| 매개변수 | 함수가 받는 입력값 |
| 반환(`return`) | 함수가 결과를 돌려주는 것 |
| 호출 | 만들어 둔 함수를 실제로 사용하는 것 |
| 리스트 | 여러 값을 순서대로 담는 그릇. `[ ]`로 만든다. |
| 인덱스 | 리스트에서 값의 순서 번호. 0부터 시작한다. |
| 딕셔너리 | 키와 값을 짝지어 담는 그릇. `{ }`로 만든다. |
| Traceback | 오류가 났을 때 파이썬이 보여 주는 오류 메시지 전체 |
| Plan 모드 | Claude Code가 파일을 고치지 않고 계획만 세우는 모드 |
| 되돌리기(`/rewind`) | Claude Code가 고친 파일과 대화를 이전 시점으로 돌리는 기능 |

### 스스로 점검하기

- [ ] 코드에서 함수 정의와 함수 호출을 구분할 수 있다.
- [ ] 리스트와 딕셔너리의 차이를 설명할 수 있다.
- [ ] 오류 메시지에서 오류의 종류, 이유, 위치를 찾을 수 있다.
- [ ] `NameError`, `TypeError`, `IndentationError`, `FileNotFoundError`가 각각 언제 나는지 말할 수 있다.
- [ ] Plan 모드로 계획을 세우고, 수정을 요청한 뒤 승인했다.
- [ ] `/rewind`로 Claude Code의 변경을 되돌렸다.
- [ ] 일부러 만든 오류를 읽고 해결했다.

## 7. 과제

지금까지 만든 프로그램(`hello.py`, `game.py`, `quiz.py` 등) 중 하나를 골라, 코드에서 **함수 · 리스트 · 딕셔너리**를 찾아 표시하고 각각 무슨 역할인지 한 줄씩 적는다.

### 작성 방법

1. 프로그램 하나를 고른다.
2. 코드에서 함수, 리스트, 딕셔너리를 찾는다. 프로그램에 없는 것이 있다면 Claude Code에게 그것을 쓰도록 기능을 하나 추가해 달라고 요청한다.
3. 찾은 것마다 코드와 역할을 한 줄씩 적는다.
4. 다 적은 뒤 Claude Code에게 내가 적은 설명이 맞는지 확인을 요청한다.

### 작성 예시 (`quiz.py`)

```markdown
| 종류 | 코드 | 역할 |
|---|---|---|
| 딕셔너리 | `words = {...}` | 영어 단어와 한국어 뜻을 짝지어 저장한다. |
| 함수 | `def ask_question(english, korean):` | 단어 하나를 묻고 정답이면 True를 돌려준다. |
| 리스트 | `wrong_words = []` | 틀린 단어를 모아 둔다. |
```

### 제출할 것

1. 함수·리스트·딕셔너리와 각각의 역할을 정리한 표
2. 실습 중 만난 오류 하나와, 그 오류를 어떻게 해결했는지에 대한 짧은 기록

> 💡 확인을 요청할 때는 "내가 쓴 설명이 맞는지 확인하고, 틀린 부분만 알려 줘. 파일은 고치지 마."라고 요청한다.
