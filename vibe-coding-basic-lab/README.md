# 비전공자를 위한 파이썬 기반 바이브 코딩

> Claude Code와 대화하며 파이썬 프로그램을 만들고, 내 업무와 일상의 문제를 직접 해결하는 사람이 되는 과정

---

## 1. 과정 개요

| 항목 | 내용 |
|---|---|
| 학습 대상 | 비전공자, 코딩 초보자, 파이썬을 처음 접하는 사람 |
| 과정 구성 | 10장 × 3시간 (총 30시간) |
| 진행 방식 | 짧은 개념 설명(30%) + 실습(60%) + 공유·회고(10%) |
| 사용 도구 | Claude Code, Python, uv, VS Code, Git·GitHub, Streamlit |
| 사전 준비 | 노트북(macOS 또는 Windows), Claude 유료 구독(Pro 이상), GitHub 계정 |
| 최종 결과물 | 내 문제를 해결하는 파이썬 웹 앱 1개를 만들어 인터넷에 배포하고 발표 |

### 바이브 코딩이란?

코드를 한 줄씩 직접 타이핑하는 대신, **만들고 싶은 것을 말로 설명하고 AI가 작성한 코드를 실행·확인·수정 요청하며** 프로그램을 완성해 가는 방식이다. 이 과정에서 학습자는 "코드를 쓰는 사람"이 아니라 **"무엇을 만들지 정하고 결과를 검증하는 사람"** 역할을 맡는다.

### 교육 원칙

1. **외우지 말고 읽을 수 있게 된다.** 문법 암기 대신 AI가 만든 코드를 대략 읽고 설명할 수 있는 수준을 목표로 한다.
2. **말로 설계하고, 실행으로 검증한다.** "잘 된 것 같다"가 아니라 직접 실행해서 확인한 것만 믿는다.
3. **작게 만들고 자주 저장한다.** 한 번에 큰 기능을 요청하지 않고, 작동하는 단계마다 Git으로 저장한다.
4. **막히면 AI에게 묻는다.** 오류 메시지, 모르는 용어, 이해 안 되는 코드 모두 질문 대상이다.
5. **내 문제에서 출발한다.** 예제보다 학습자 본인의 업무·생활 문제를 소재로 삼을수록 끝까지 완성한다.

## 2. 수료 시 학습 목표

과정을 마친 학습자는 다음을 할 수 있다.

- Claude Code를 설치하고, 프로젝트 폴더에서 대화하며 파이썬 프로그램을 만들 수 있다.
- 원하는 기능을 **구체적인 요구사항**으로 설명하고, 결과를 보고 수정 요청을 할 수 있다.
- 변수·조건문·반복문·함수·리스트·딕셔너리 등 파이썬 기본 구조를 코드에서 **알아보고 설명**할 수 있다.
- 오류 메시지를 두려워하지 않고 AI와 함께 원인을 찾아 해결할 수 있다.
- 엑셀·CSV 파일 처리, 인터넷 데이터(API) 활용, 데이터 시각화 같은 실용 자동화를 만들 수 있다.
- Git으로 작업을 저장·되돌리고, GitHub에 올릴 수 있다.
- Streamlit으로 웹 앱을 만들어 인터넷에 배포할 수 있다.
- AI 코딩의 한계와 위험(잘못된 코드, 비밀번호·개인정보 노출)을 이해하고 조심할 수 있다.

- 터미널이 부담스러운 학습자는 **VS Code 확장(Claude Code)** 또는 **Claude 데스크톱 앱**으로 시작해도 된다.

**실습 프롬프트 예시**
```
이 컴퓨터에 파이썬이 설치되어 있는지 확인해 줘. 없으면 설치 방법을 알려 줘.
```
```
내 이름, 취미, 좋아하는 음식을 출력하는 파이썬 프로그램을 hello.py로 만들고 실행해 줘.
```
```
방금 만든 코드를 한 줄씩 초등학생도 이해할 수 있게 설명해 줘.
```

**핵심 포인트**

**과제**: 자기소개 프로그램에 기능 2개를 추가 요청해 보기 (예: 오늘 날짜 출력, 나이 계산)

### 3장. 코드 읽기와 오류 다루기

📘 학습 교재: [ch03.md](ch03.md)

**학습 목표**
- 함수·리스트·딕셔너리가 코드에서 어떤 역할을 하는지 알아볼 수 있다.
- 오류 메시지를 읽고 AI와 함께 해결할 수 있다.
- 큰 작업을 시작하기 전에 계획부터 세우도록 요청할 수 있다.

**진행 (180분)**

| 시간 | 내용 |
|---|---|
| 20분 | 과제 공유 — 요청문 비교하며 서로 피드백 |
| 30분 | 파이썬 개념 읽기: 함수(`def`), 리스트(`[]`), 딕셔너리(`{}`) |
| 30분 | 오류 읽는 법: 마지막 줄부터 읽기, 자주 보는 오류(`NameError`, `TypeError`, `IndentationError`, `FileNotFoundError`) |
| 80분 | 실습: 단어장 퀴즈 프로그램 (Plan 모드 → 구현 → 일부러 망가뜨리고 고치기) |
| 20분 | 회고 |

**Claude Code 기능**
- **Plan 모드** (`Shift+Tab`으로 전환): 코드를 바로 고치지 않고 계획만 세우게 하기 → 계획을 읽고 승인
- **`/rewind`** (또는 `Esc` 두 번): 마음에 안 드는 변경을 이전 시점으로 되돌리기
- 코드 설명 요청: "이 함수가 하는 일을 설명해 줘", "이 줄을 지우면 어떻게 돼?"

**실습 프롬프트 예시**
```
영어 단어장 퀴즈 프로그램을 만들고 싶어. 아직 코드는 쓰지 말고, 어떤 기능과 구조로 만들지 계획부터 보여 줘.
```
```
이 오류 메시지가 무슨 뜻인지 먼저 설명해 주고, 그다음에 고쳐 줘.
```

**핵심 포인트**: 일부러 코드 한 줄을 지우거나 들여쓰기를 망가뜨리게 해서 오류를 경험한다. "오류 = 실패"가 아니라 "오류 = 컴퓨터가 주는 힌트"이다.

**과제**: 지금까지 만든 프로그램 중 하나에서 함수·리스트·딕셔너리를 찾아 표시하고, 각각 무슨 역할인지 한 줄씩 적어 오기

### 4장. 프로젝트처럼 일하기

📘 학습 교재: [ch04.md](ch04.md)

**학습 목표**
- 파일에 데이터를 저장하고 다시 불러오는 프로그램을 만들 수 있다.
- 외부 패키지와 가상환경의 개념을 이해한다.
- CLAUDE.md로 AI에게 프로젝트 규칙을 알려 줄 수 있다.

**진행 (180분)**

| 시간 | 내용 |
|---|---|
| 20분 | 과제 공유 |
| 30분 | 개념: 파일 읽기·쓰기, 모듈과 패키지, 가상환경이 필요한 이유 |
| 30분 | uv로 프로젝트 만들기: `uv init` → `uv add`로 패키지 설치 → `uv run`으로 실행 (Claude Code에게 맡기고 과정 관찰) |
| 30분 | CLAUDE.md 작성: `/init` 실행 → 내용 읽고 나만의 규칙 추가 |
| 50분 | 실습: 할 일 관리 프로그램 (추가·완료·삭제, 파일에 저장) |
| 20분 | 회고 |

**uv 기본 명령** (macOS·Windows 동일)

| 작업 | 명령 |
|---|---|
| 새 프로젝트 만들기 | `uv init` |
| 패키지 설치 (목록 자동 기록) | `uv add 패키지이름` |
| 프로그램 실행 | `uv run 파일이름.py` |
| 다른 컴퓨터에서 같은 환경 만들기 | `uv sync` |
| 파이썬 설치 | `uv python install` |

- uv가 설치되어 있지 않으면 Claude Code에게 "uv를 설치해 줘"라고 요청한다.
- 명령을 외울 필요는 없다. Claude Code에게 "uv로 프로젝트 만들어 줘"라고 요청하고, 위 명령이 실행되는 과정을 관찰한다.
- `uv run`은 가상환경(`.venv`)을 알아서 만들고 사용하므로 직접 켜고 끌 필요가 없다. 비전공자가 자주 겪는 "가상환경을 안 켜서 생기는 오류"가 줄어든다.
- 설치한 패키지 목록은 `pyproject.toml`에, 정확한 버전은 `uv.lock`에 자동으로 기록된다.
- `.venv` 폴더는 GitHub에 올리지 않는다(5장 `.gitignore`와 연결).

**CLAUDE.md 규칙 예시 (학습자용)**
```markdown
# 프로젝트 규칙
- 나는 코딩 초보자야. 설명은 쉬운 한국어로 해 줘.
- 코드에는 한국어 주석을 달아 줘.
- 새 패키지를 설치하기 전에 왜 필요한지 먼저 알려 줘.
- 파이썬 실행은 `uv run`을, 패키지 설치는 `uv add`를 사용해.
```

**핵심 포인트**
- CLAUDE.md는 "매번 반복해서 말해야 하는 것을 적어 두는 메모"라는 점을 체감한다.
- 프로그램을 껐다 켜도 데이터가 남아 있는지 직접 확인한다(검증 습관).

**과제**: 할 일 관리 프로그램에 마감일과 "오늘 할 일만 보기" 기능 추가

| 시간 | 내용 |
|---|---|
| 20분 | 과제 공유 |
| 30분 | 개념: Git = 게임의 세이브 포인트, 커밋·저장소·원격 저장소 |
| 30분 | Git 설치·설정, GitHub 계정 연결 (`gh` CLI 로그인) |
| 70분 | 실습: 지금까지 만든 프로그램을 저장소로 만들기 → 기능 추가 → 커밋 → 망가뜨리기 → 되돌리기 → GitHub 업로드 |
| 30분 | 서로의 GitHub 저장소 구경하기, 회고 |

**실습 프롬프트 예시**
```
이 폴더를 Git 저장소로 만들고, 지금 상태를 첫 번째 커밋으로 저장해 줘.
```
```
지금까지의 커밋 기록을 보여 주고, 각 커밋에서 무엇이 바뀌었는지 쉽게 설명해 줘.
```
```
GitHub에 vibe-todo라는 공개 저장소를 만들어서 올려 줘.
```

**핵심 포인트**
- `/rewind`(대화 중 되돌리기)와 Git 커밋(영구 저장)의 차이를 구분한다.
- "작동하면 커밋" 습관: 이후 모든 장에서 기능 하나가 완성될 때마다 커밋을 요청한다.
- `.gitignore`의 역할 — 올리면 안 되는 파일이 있다는 것(7장 비밀정보 관리와 연결).

**과제**: 지난 과제 결과물을 GitHub에 올리고 저장소 주소 제출

**진행 (180분)**

| 시간 | 내용 |
|---|---|
| 20분 | 과제 공유 |
| 30분 | 개념: 인터넷 요청·응답, API, JSON |

**실습 흐름**
1. 키가 필요 없는 공개 API로 시작 (예: 환율, 공휴일 정보)

```
API 키는 .env 파일에 저장하고, .env가 GitHub에 올라가지 않도록 설정해 줘. 설정이 잘 됐는지 확인하는 방법도 알려 줘.
```

**주의 사항**
- 웹사이트 데이터 수집(크롤링)은 해당 사이트의 이용 약관과 robots.txt를 존중해야 한다는 점을 함께 다룬다.
- 실수로 키를 GitHub에 올렸다면: 즉시 키를 폐기·재발급하는 것이 정답(커밋 삭제만으로는 부족).

**과제**: 관심 있는 공개 API 하나를 찾아 간단한 프로그램 만들기

## 6. 부록

### A. Claude Code 자주 쓰는 기능 정리

| 기능 | 사용법 | 언제 쓰나 |
|---|---|---|
| 시작 | 프로젝트 폴더에서 `claude` | 작업 시작 |
| 파일 지목 | `@파일이름` | 특정 파일에 대해 이야기할 때 |
| 중단 | `Esc` | AI가 엉뚱한 작업을 할 때 |
| 되돌리기 | `/rewind` 또는 `Esc` 두 번 | 변경 사항을 이전 시점으로 돌릴 때 |
| 모드 전환 | `Shift+Tab` | Plan 모드(계획만 세우기) 등으로 바꿀 때 |
| 대화 초기화 | `/clear` | 새 주제를 시작할 때 |
| 대화 요약 | `/compact` | 대화가 길어져 느려질 때 |
| 프로젝트 메모 | `/init`, `/memory` | CLAUDE.md 만들기·수정 |
| 도움말 | `/help` | 명령이 기억나지 않을 때 |

> Claude Code는 업데이트가 잦으므로, 수업 전에 공식 문서(https://docs.claude.com/en/docs/claude-code)에서 최신 사용법을 확인한다.

### B. 프롬프트 템플릿

**새 기능 요청**
```
[무엇을] 하는 기능을 추가하고 싶어.
- 입력: [사용자가 넣는 것]
- 출력: [보여 줘야 하는 것]
- 조건: [지켜야 할 것, 예외 상황]
먼저 계획을 보여 주고, 내가 승인하면 만들어 줘.
```

**오류 해결**
```
[무엇을] 했더니 아래 오류가 났어.
(오류 메시지 전체 붙여넣기)
원인을 쉽게 설명해 주고 고쳐 줘. 고친 뒤 직접 실행해서 확인해 줘.
```

**코드 이해**
```
@파일이름 의 [함수/부분]이 무슨 일을 하는지, 비전공자가 이해할 수 있게 비유를 들어 설명해 줘.
```

### D. 운영 시 유의 사항

- **사용량 한도**: 구독 요금제마다 사용량 한도가 있다. 실습이 몰리는 장(8~10장)에는 한도에 걸릴 수 있으므로 미리 안내한다.
- **개인정보·회사 데이터**: 실제 고객 정보나 회사 기밀 파일은 실습에 사용하지 않는다. 항상 가짜 데이터로 대체한다.
- **권한 승인**: 초반에는 Claude Code가 요청하는 권한을 읽고 승인하는 습관을 들인다. 무엇을 하려는지 모르면 승인 전에 질문하도록 지도한다.
- **AI 결과 검증**: "AI가 그렇게 말했다"는 근거가 아니다. 실행 결과와 직접 확인한 값만 믿도록 반복 강조한다.
- **진도 격차**: 같은 요청이라도 AI가 매번 다른 코드를 만든다. 정답 코드 하나를 따라 치는 수업이 아니라는 점을 처음부터 안내한다.
