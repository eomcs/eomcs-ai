## 1. 인터넷 데이터와 API

### 1-1. 요청과 응답

웹 브라우저로 뉴스 사이트에 접속하는 과정은 식당에서 주문하는 것과 같다.

| 식당 | 인터넷 |
|---|---|
| 손님이 주문한다 | 내 컴퓨터가 **요청**(request)을 보낸다 |
| 주방에서 음식을 만든다 | 서버가 요청을 처리한다 |
| 음식이 나온다 | 서버가 **응답**(response)을 돌려준다 |

브라우저는 응답으로 사람이 보기 좋은 **웹 페이지**를 받는다. 프로그램은 응답으로 다루기 쉬운 **데이터**를 받는다. 프로그램이 데이터를 받아 가도록 만들어 둔 창구가 **API**다.

### 1-2. API란?

**API**(Application Programming Interface)는 프로그램끼리 정보를 주고받는 **약속된 창구**다. 식당의 **메뉴판**을 떠올리면 된다.

- 메뉴판에 있는 음식만 주문할 수 있듯이, API가 제공하는 정보만 요청할 수 있다.
- 메뉴판에 적힌 방식대로 주문해야 하듯이, API **문서**에 적힌 방식대로 요청해야 한다.

| API | 제공하는 정보 | API 키 |
|---|---|---|
| Nager.Date | 나라별 공휴일 | 필요 없음 |
| Frankfurter | 유럽중앙은행 기준 환율 | 필요 없음 |
| OpenWeatherMap | 도시별 날씨 | 필요함 (무료 가입) |

### 1-3. API 주소 읽기

API에 요청할 때는 **주소(URL)** 에 원하는 내용을 담는다.

```
https://api.frankfurter.dev/v1/latest?base=USD&symbols=KRW
└──────────┬──────────────┘└───┬────┘ └──────────┬──────────┘
         서버 주소             경로         쿼리 매개변수
```

| 부분 | 뜻 |
|---|---|
| 서버 주소 | 어느 서버에 요청하는가 (Frankfurter 환율 서버) |
| 경로 `/v1/latest` | 어떤 정보를 원하는가 (최신 환율) |
| 쿼리 매개변수 `?base=USD&symbols=KRW` | 세부 조건 (1달러가 원화로 얼마인지) |

쿼리 매개변수는 `?` 뒤에 `이름=값` 형태로 쓰고, 여러 개일 때는 `&`로 잇는다.

> 💡 이 주소를 웹 브라우저 주소창에 그대로 붙여 넣으면 API의 응답을 눈으로 볼 수 있다. 직접 해 보자.

### 1-4. JSON 응답 읽기

대부분의 API는 **JSON** 형식으로 응답한다. 4장에서 할 일 목록을 저장할 때 쓴 바로 그 형식이다.

```json
{
  "amount": 1.0,
  "base": "USD",
  "date": "2026-11-13",
  "rates": {
    "KRW": 1337.13
  }
}
```

- 바깥의 `{ }`는 딕셔너리다. `"date"`, `"rates"` 같은 **키**로 값을 꺼낸다.
- `"rates"`의 값은 또 하나의 딕셔너리다. 원화 환율은 `data["rates"]["KRW"]`처럼 **두 번** 꺼낸다.

> 💡 2026-11-13은 금요일이다. 환율은 은행 영업일에만 발표되므로 주말에는 가장 최근 영업일의 값이 나온다. 응답에 들어 있는 **날짜를 함께 확인**하는 습관을 들인다.

### 1-5. 상태 코드

서버는 응답과 함께 **상태 코드**(숫자 세 자리)를 보낸다. 요청이 성공했는지, 왜 실패했는지 알려 준다.

| 상태 코드 | 뜻 | 흔한 원인 |
|---|---|---|
| `200` | 성공 | - |
| `400` | 잘못된 요청 | 매개변수 이름이나 값이 틀렸다. |
| `401` | 인증 실패 | API 키가 없거나 틀렸다. 아직 활성화되지 않았다. |
| `404` | 찾을 수 없음 | 주소(경로)가 틀렸다. |
| `429` | 요청이 너무 많음 | 짧은 시간에 너무 자주 요청했다. |
| `500`번대 | 서버 오류 | 서버 쪽 문제다. 잠시 후 다시 시도한다. |

## 2. 파이썬 코드 읽기: requests

### 2-1. API에 요청하기

**requests**는 파이썬에서 인터넷 요청을 보내는 가장 유명한 패키지다.

```python
import requests

url = "https://date.nager.at/api/v3/PublicHolidays/2026/KR"
response = requests.get(url, timeout=10)   # 10초 안에 응답이 없으면 포기한다
response.raise_for_status()                # 오류 응답(4xx, 5xx)이면 멈춘다

holidays = response.json()                 # JSON 응답을 리스트·딕셔너리로 바꾼다
print(f"2026년 공휴일: {len(holidays)}일")
for day in holidays:
    print(day["date"], day["localName"])
```

| 코드 | 하는 일 |
|---|---|
| `requests.get(url)` | 주소로 요청을 보내고 응답을 받는다. |
| `timeout=10` | 10초 안에 응답이 없으면 기다리지 않고 오류를 낸다. |
| `response.raise_for_status()` | 상태 코드가 실패(400 이상)면 오류를 내고 멈춘다. |
| `response.json()` | JSON 응답을 파이썬의 리스트·딕셔너리로 바꾼다. |
| `day["localName"]` | 공휴일 하나(딕셔너리)에서 한국어 이름을 꺼낸다. |

### 2-2. 쿼리 매개변수 넘기기

쿼리 매개변수는 주소에 직접 이어 쓰는 대신 `params`에 딕셔너리로 넘기면 읽기 쉽다.

```python
params = {"base": "USD", "symbols": "KRW"}
response = requests.get("https://api.frankfurter.dev/v1/latest", params=params, timeout=10)
data = response.json()
print(data["rates"]["KRW"])   # 1337.13
```

`requests`가 `params`를 `?base=USD&symbols=KRW`로 바꿔 주소 뒤에 붙여 준다.

## 3. 보안: API 키와 `.env`

### 3-1. API 키란?

**API 키**는 API를 쓸 수 있는 사람인지 확인하는 **회원 카드 번호**다. 날씨처럼 서비스 제공자가 비용을 들여 제공하는 API는 가입한 사람에게만 키를 발급하고, 키마다 사용량을 기록한다.

> ⚠️ API 키는 **비밀번호와 같다.** 다른 사람이 내 키를 쓰면 내 사용량이 소진되고, 유료 서비스라면 **요금이 나에게 청구**된다.

### 3-2. 키를 코드에 쓰면 안 되는 이유

```python
API_KEY = "a1b2c3d4e5f6..."   # ← 이렇게 쓰면 안 된다!
```

- 코드를 GitHub에 올리는 순간 **키가 공개**된다. GitHub에서 키를 찾아 수집하는 자동 프로그램이 항상 돌아다니며, 올린 지 몇 분 만에 악용되기도 한다.
- 코드를 친구에게 보여 주거나 화면을 공유할 때도 키가 노출된다.
- 키를 바꿀 때마다 코드를 고쳐야 한다.

### 3-3. `.env` 파일로 분리하기

비밀 정보는 코드와 분리해 **`.env` 파일**에 저장한다.

**`.env` 파일**
```
OPENWEATHER_API_KEY=a1b2c3d4e5f6...
```

**코드**
```python
import os

from dotenv import load_dotenv

load_dotenv()                                  # .env 파일의 내용을 불러온다
API_KEY = os.getenv("OPENWEATHER_API_KEY")     # 이름으로 키를 꺼낸다
```

- `.env` 파일에는 `이름=값` 형태로 한 줄에 하나씩 쓴다. `=` 앞뒤에 빈칸을 넣지 않는다.
- 코드에는 키의 **이름**만 있고 **값**은 없다. 코드를 공개해도 키는 안전하다.
- `load_dotenv()`는 **python-dotenv** 패키지의 기능이다.

### 3-4. `.env`를 `.gitignore`에 넣는다

> ⚠️ 4장에서 `uv init`이 만든 `.gitignore`에는 **`.env`가 들어 있지 않다.** 직접 추가해야 한다.

`.gitignore`에 `.env`를 추가한 뒤, 정말 무시되는지 다음 명령으로 확인한다.

```bash
git check-ignore -v .env
```

```
.gitignore:11:.env	.env
```

이렇게 `.gitignore`의 몇 번째 줄 때문에 무시되는지 나오면 성공이다. 아무것도 나오지 않으면 `.env`가 GitHub에 올라갈 수 있는 상태다.

### 3-5. `.env.example`로 사용법 알려 주기

`.env`를 GitHub에 올리지 않으면, 내 코드를 내려받은 사람은 어떤 키가 필요한지 알 수 없다. 그래서 값을 비운 **`.env.example`** 파일을 함께 올린다.

```
OPENWEATHER_API_KEY=여기에_발급받은_키를_넣으세요
```

내려받은 사람은 이 파일을 `.env`로 복사하고 자기 키를 넣으면 된다.

### 3-6. Claude Code와 비밀 정보

> ⚠️ **API 키를 Claude Code 대화창에 붙여 넣지 않는다.** 대화 내용은 AI 서비스로 전송된다. 키는 VS Code에서 `.env` 파일을 열어 **내가 직접** 입력한다. Claude Code에게는 "키는 내가 .env에 넣을게"라고 말한다.

오류 메시지에도 키가 들어 있을 수 있다. 예를 들어 키가 틀리면 다음과 같은 오류가 나는데, 주소 안에 키(`appid=...`)가 그대로 보인다.

```
requests.exceptions.HTTPError: 401 Client Error: Unauthorized for url: https://api.openweathermap.org/data/2.5/weather?q=Seoul&appid=abc123&units=metric&lang=kr
```

오류 메시지를 다른 사람에게 보여 주거나 어딘가에 올릴 때는 키 부분을 `***`로 가린다.

### 3-7. 키가 노출되었다면

실수로 키를 GitHub에 올렸다면 **즉시 그 키를 폐기하고 새로 발급**받는다. 파일을 지우고 다시 커밋해도 **커밋 기록에는 키가 남아 있다.** 키를 폐기하는 것만이 확실한 방법이다. 폐기는 키를 발급한 서비스의 웹사이트(내 계정 → API 키 메뉴)에서 한다.

### 3-8. 웹사이트 데이터를 가져올 때의 예절

API가 없는 웹사이트에서 데이터를 자동으로 긁어 오는 것을 **크롤링**(스크래핑)이라고 한다. 기술적으로 가능해도 함부로 하면 안 된다.

- 사이트의 **이용 약관**에서 자동 수집을 금지하는지 확인한다.
- 사이트 주소 뒤에 `/robots.txt`를 붙여 열면 자동 수집 프로그램에 대한 규칙이 나온다. 이 규칙을 존중한다.
- 짧은 시간에 너무 많이 요청하면 사이트에 부담을 준다. 요청 사이에 간격을 둔다.
- **API가 있다면 API를 먼저 쓴다.** API는 데이터를 가져가도 된다고 공식적으로 허락한 창구다.

API에도 **사용 한도**가 있다. 무료 키는 하루 또는 1분에 요청할 수 있는 횟수가 정해져 있으므로, 테스트할 때 프로그램을 너무 자주 실행하지 않는다.

## 4. Claude Code 기능 익히기: 문서 읽히기

### 4-1. API 문서 주소를 알려 주기

API를 쓰려면 문서를 읽어야 하지만, 대부분 영어이고 용어가 어렵다. Claude Code에게 **문서 주소를 알려 주면** 직접 읽고 코드를 만든다.

```
이 API 문서 주소를 읽고, 서울의 현재 날씨를 가져오는 코드를 만들어 줘: https://openweathermap.org/current
```

Claude Code가 웹 페이지를 읽기 전에 허락을 구하면 주소를 확인하고 승인한다.

> 💡 AI가 기억하는 API 사용법은 오래되었을 수 있다. API는 주소나 매개변수가 바뀌기도 하므로, **최신 문서를 읽히는 것**이 정확한 코드를 얻는 방법이다.

### 4-2. 문서 내용을 설명해 달라고 하기

코드를 만들기 전에 문서 내용을 먼저 이해하는 것도 좋다.

```
https://openweathermap.org/current 문서를 읽고, 무료로 쓸 수 있는지, 어떤 매개변수가 필요한지, 응답에 어떤 정보가 들어 있는지 쉽게 정리해 줘. 코드는 아직 만들지 마.
```

### 4-3. 터미널(CLI)과 VS Code 확장의 사용법 비교

문서 읽히기와 API 작업은 요청으로 진행하므로 터미널(CLI)과 VS Code 확장의 사용법이 같다.

| 기능 | 터미널(CLI) | VS Code 확장 |
|---|---|---|
| 문서 주소 읽히기 | 요청에 주소 포함 → 웹 페이지 읽기 허락 | 같음 |
| `.env`에 키 입력 | VS Code에서 `.env`를 열어 직접 입력 | 같음 |

```
uv init --no-package로 이 폴더를 uv 프로젝트로 만들고, requests와 python-dotenv 패키지를 설치해 줘.
```

`/init`으로 CLAUDE.md를 만들고 규칙을 추가한다.

```
- 파이썬 실행은 uv run을, 패키지 설치는 uv add를 사용해.
```

첫 커밋을 만든다.

### 5-2. 1단계: 키 없는 API로 시작하기 (공휴일)

먼저 웹 브라우저 주소창에 다음 주소를 붙여 넣어 응답을 눈으로 본다.

```
https://date.nager.at/api/v3/PublicHolidays/2026/KR
```

JSON 형태의 공휴일 목록이 보인다. 이제 같은 일을 프로그램으로 한다.

```
https://date.nager.at/api/v3/PublicHolidays/2026/KR 에서 2026년 한국 공휴일을 받아 와서 날짜와 한국어 이름을 출력하는 holidays.py를 만들고 실행해 줘.
```

만들어진 코드는 2-1의 예시와 비슷하다. 실행 결과는 대략 다음과 같다.

```
2026년 공휴일: 18일
```

### 5-3. 2단계: 환율 가져오기

```
https://frankfurter.dev 문서를 읽고, 미국 달러(USD), 유로(EUR), 일본 엔(JPY)이 각각 몇 원인지 가져오는 exchange.py를 만들고 실행해 줘. 엔화는 우리나라에서 보통 쓰는 방식대로 100엔 기준으로 보여 주고, 몇 월 며칠 기준 환율인지도 함께 보여 줘.
```

만들어진 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import requests

API_URL = "https://api.frankfurter.dev/v1/latest"


def get_rate(currency):
    """1 외화가 몇 원인지 돌려준다."""
    params = {"base": currency, "symbols": "KRW"}
    response = requests.get(API_URL, params=params, timeout=10)
    response.raise_for_status()
    data = response.json()
    return data["rates"]["KRW"], data["date"]


for currency in ["USD", "EUR", "JPY"]:
    rate, date = get_rate(currency)
    if currency == "JPY":
        print(f"100 JPY = {rate * 100:,.2f}원 ({date} 기준)")
    else:
        print(f"1 {currency} = {rate:,.2f}원 ({date} 기준)")
```

```
1 USD = 1,337.13원 (2026-11-13 기준)
1 EUR = 1,477.80원 (2026-11-13 기준)
100 JPY = 835.72원 (2026-11-13 기준)
```

#### 코드에서 개념 찾기

| 코드 | 하는 일 |
|---|---|
| `params = {"base": currency, "symbols": "KRW"}` | "이 외화 1단위가 원화로 얼마인지"를 묻는 조건을 만든다. |
| `requests.get(API_URL, params=params, timeout=10)` | 환율 API에 요청한다. |
| `data["rates"]["KRW"]` | 응답 딕셔너리 안의 딕셔너리에서 원화 환율을 꺼낸다. |
| `return data["rates"]["KRW"], data["date"]` | 환율과 기준 날짜 두 값을 함께 돌려준다. |
| `{rate:,.2f}` | 천 단위 쉼표를 넣고 소수점 둘째 자리까지 보여 준다. |

> 💡 Frankfurter는 유럽중앙은행이 발표한 기준 환율을 제공한다. 은행 창구에서 실제로 환전할 때의 환율과는 조금 다르다. 포털 사이트의 환율과 비교해 보고, 차이가 나는 이유도 Claude Code에게 물어본다.

### 5-4. 3단계: API 키로 날씨 가져오기

**① `.env`를 `.gitignore`에 추가하기**

키를 넣기 **전에** 먼저 `.env`가 GitHub에 올라가지 않게 설정한다.

```
.env 파일을 만들고 .gitignore에 추가해 줘. .env가 Git에서 무시되는지 확인하는 방법도 알려 줘. .env에는 OPENWEATHER_API_KEY= 한 줄만 써 두고, 키는 내가 직접 넣을게.
```

두 번째 터미널에서 직접 확인한다.

```bash
git check-ignore -v .env
```

`.gitignore:...:.env` 형태로 나오면 안전하다.

**② 키 입력하기**

VS Code에서 `.env` 파일을 열고, `=` 뒤에 발급받은 키를 붙여 넣고 저장한다.

```
OPENWEATHER_API_KEY=발급받은키
```

**③ 날씨 코드 만들기**

```
https://openweathermap.org/current 문서를 읽고, 서울의 현재 날씨(날씨 설명, 기온, 체감 온도, 습도)를 가져오는 weather.py를 만들고 실행해 줘. API 키는 .env의 OPENWEATHER_API_KEY에서 읽고, 날씨 설명은 한국어로, 온도는 섭씨로 받아 줘. 키가 없으면 안내 문구를 보여 줘.
```

만들어진 코드는 대략 다음과 같다.

```python
import os

import requests
from dotenv import load_dotenv

load_dotenv()                                  # .env 파일의 내용을 불러온다
API_KEY = os.getenv("OPENWEATHER_API_KEY")     # 환경 변수에서 API 키를 꺼낸다

if not API_KEY:
    print(".env 파일에 OPENWEATHER_API_KEY가 없습니다.")
    raise SystemExit(1)

params = {
    "q": "Seoul",
    "appid": API_KEY,
    "units": "metric",   # 섭씨온도로 받기
    "lang": "kr",        # 날씨 설명을 한국어로 받기
}
response = requests.get(
    "https://api.openweathermap.org/data/2.5/weather", params=params, timeout=10
)
response.raise_for_status()
data = response.json()

print(f"서울 날씨: {data['weather'][0]['description']}")
print(f"기온: {data['main']['temp']:.1f}°C (체감 {data['main']['feels_like']:.1f}°C)")
print(f"습도: {data['main']['humidity']}%")
```

코드 어디에도 키의 **값**이 없다는 것을 확인한다. `401` 오류가 나면 키가 아직 활성화되지 않았을 수 있으니 잠시 후 다시 실행한다.

> 💡 `data['weather'][0]['description']`은 딕셔너리(`data`) → 키 `weather`의 리스트 → 첫 번째 값(`[0]`) → 키 `description` 순서로 꺼낸 것이다. 3장에서 배운 리스트와 딕셔너리가 겹겹이 들어 있다. 응답의 구조가 궁금하면 "날씨 API 응답의 구조를 보기 좋게 보여 줘"라고 요청한다.

**④ `.env.example` 만들고 커밋하기**

```
.env.example 파일을 만들어 줘. 키 값은 비워 두고 어떤 값을 넣어야 하는지만 알려 줘. 그다음 지금까지의 작업을 커밋해 줘. 커밋하기 전에 .env가 커밋 대상에 없는지 확인해 줘.
```

## 6. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| `401 Client Error: Unauthorized` | API 키가 틀렸거나 아직 활성화되지 않았다. `.env`의 키 앞뒤에 빈칸이나 따옴표가 없는지 확인하고, 발급 직후라면 잠시 후 다시 시도한다. |
| `.env 파일에 OPENWEATHER_API_KEY가 없습니다` | `.env` 파일이 프로젝트 폴더(`alert`) 바로 안에 있는지, 이름이 정확한지(`.env.txt`가 아닌지) 확인한다. 저장했는지도 확인한다. |
| `404 Client Error: Not Found` | 주소(경로)가 틀렸다. Claude Code에게 API 문서를 다시 읽고 주소를 확인해 달라고 요청한다. |
| `429 Client Error: Too Many Requests` | 짧은 시간에 너무 많이 요청했다. 몇 분 기다렸다가 다시 실행한다. |
| `ConnectionError` 또는 `Timeout` | 인터넷 연결을 확인한다. 회사·학교 네트워크에서는 일부 사이트가 막혀 있을 수 있다. |
| `KeyError: 'rates'` 같은 오류 | 응답에 예상한 키가 없다. 오류 응답을 받았거나 API 형식이 바뀐 것이다. "응답 전체를 출력해서 구조를 확인해 줘"라고 요청한다. |
| `git check-ignore -v .env`에 아무것도 나오지 않는다 | `.env`가 무시되지 않는 상태다. `.gitignore`에 `.env` 줄을 추가하고 저장한 뒤 다시 확인한다. |
| `.env`를 이미 커밋했다 | GitHub에 올리기 전이라면 Claude Code에게 "방금 커밋에서 .env를 빼 줘"라고 요청한다. 이미 올렸다면 3-7대로 **키를 즉시 폐기**하고 새로 발급받는다. |
| 오류 메시지에 키가 보인다 | 다른 사람에게 보여 줄 때는 키 부분을 `***`로 가린다. 이미 공개된 곳에 올렸다면 키를 폐기한다. |

## 7. 정리

### 핵심 요약

1. 프로그램은 서버에 **요청**을 보내고 **응답**을 받는다. 프로그램용으로 약속된 창구가 **API**다.
2. API 주소는 서버 주소, 경로, 쿼리 매개변수로 이루어지고, 응답은 주로 **JSON**이다. 성공 여부는 **상태 코드**로 알 수 있다.
3. `requests.get()`으로 요청하고, `raise_for_status()`로 실패를 확인하고, `.json()`으로 응답을 꺼낸다.
4. **API 키는 비밀번호다.** 코드에 쓰지 말고 `.env`에 저장하고, `.env`는 반드시 `.gitignore`에 넣는다. 대화창에도 붙여 넣지 않는다.
5. 키가 노출되면 커밋을 지우는 것으로는 부족하다. **즉시 폐기하고 새로 발급**받는다.

### 요청문 템플릿

**API 문서 읽히기**
```
[API 문서 주소]를 읽고, [원하는 정보]를 가져오는 [파일 이름]을 만들어 줘. 응답에서 [필요한 값]을 꺼내서 보여 줘.
```

**키가 필요한 API**
```
.env 파일을 만들고 .gitignore에 추가해 줘. .env에는 [키 이름]= 한 줄만 써 두고, 키는 내가 직접 넣을게. 코드는 .env에서 키를 읽어 오게 만들어 줘.
```

**올리기 전 점검**
```
GitHub에 올리기 전에 .env가 커밋 대상에 없는지, 코드 안에 키 값이 들어 있지 않은지 확인해 줘.
```

### 용어 사전

| 용어 | 뜻 |
|---|---|
| 요청 / 응답 | 내 프로그램이 서버에 보내는 부탁 / 서버가 돌려주는 결과 |
| 서버 | 요청을 받아 처리하고 응답을 돌려주는 컴퓨터 |
| API | 프로그램끼리 정보를 주고받도록 약속된 창구 |
| API 문서 | API를 쓰는 방법(주소, 매개변수, 응답 형식)을 설명한 안내서 |
| 쿼리 매개변수 | 주소의 `?` 뒤에 붙는 세부 조건 (`이름=값`) |
| 상태 코드 | 응답의 성공·실패를 알려 주는 세 자리 숫자 |
| requests | 파이썬에서 인터넷 요청을 보내는 패키지 |
| API 키 | API를 쓸 수 있는 사람인지 확인하는 비밀 문자열 |
| `.env` | 비밀 정보와 설정값을 코드와 분리해 저장하는 파일 |
| python-dotenv | `.env` 파일의 값을 불러오는 패키지 |
| 크롤링(스크래핑) | 웹사이트의 내용을 프로그램으로 자동 수집하는 것 |
| robots.txt | 자동 수집 프로그램에 대한 사이트의 규칙을 적은 파일 |

### 스스로 점검하기

- [ ] 요청, 응답, API의 뜻을 비유를 들어 설명할 수 있다.
- [ ] API 주소에서 경로와 쿼리 매개변수를 구분할 수 있다.
- [ ] 상태 코드 200, 401, 404의 뜻을 말할 수 있다.
- [ ] 코드에서 요청을 보내는 부분과 응답에서 값을 꺼내는 부분을 찾을 수 있다.
- [ ] API 키를 코드에 쓰면 안 되는 이유를 설명할 수 있다.
- [ ] `.env`에 키를 직접 입력하고, `git check-ignore`로 무시되는지 확인했다.
- [ ] GitHub에 올린 저장소에 `.env`와 키 값이 없는 것을 직접 확인했다.

## 8. 과제

관심 있는 **공개 API 하나**를 찾아 간단한 프로그램을 만든다.

### 진행 방법

1. 사용할 API를 고른다. Claude Code에게 "○○ 정보를 주는 무료 공개 API를 추천해 줘"라고 물어봐도 된다.
2. Claude Code에게 API 문서를 읽혀서 무료인지, 키가 필요한지, 어떤 정보를 주는지 정리하게 한다.
3. 브라우저 주소창에서 API 응답을 직접 확인한다.
4. 프로그램을 만들고, 기능이 동작할 때마다 커밋한다.
5. 키가 필요한 API라면 `.env`와 `.env.example`을 쓰고, GitHub에 올린 뒤 키가 없는지 확인한다.

### API 아이디어

| 분야 | 예 |
|---|---|
| 공공 데이터 | 공공데이터포털(data.go.kr)의 미세먼지, 버스 도착 정보, 공공 와이파이 위치 |

### 제출할 것

1. 사용한 API 이름과 문서 주소
2. 완성된 프로그램의 GitHub 저장소 주소
3. (키가 필요한 API라면) `.env`가 저장소에 없다는 것을 확인한 방법
