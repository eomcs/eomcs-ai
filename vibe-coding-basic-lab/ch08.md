- 웹 앱이 무엇인지 이해하고, **Streamlit**으로 웹 앱을 만들어 실행한다.
- Streamlit 코드에서 화면 요소(제목, 지표, 차트, 필터)를 알아본다.
- 실행 중인 앱의 **스크린샷**을 Claude Code에게 보여 주며 화면을 다듬는다.

## 1. 데이터 시각화 기초

### 1-1. 왜 차트로 그리는가

6장에서 만든 "지역별 월별 합계" 표에는 숫자 30개가 있다. 표를 보고 "어느 지역이 3월에 가장 잘 팔렸나?", "매출이 늘고 있나, 줄고 있나?"에 답하려면 숫자를 하나하나 비교해야 한다. 같은 데이터를 차트로 그리면 **한눈에** 보인다.

| 표 | 차트 |
|---|---|
| 정확한 값을 확인할 때 좋다 | 흐름, 비교, 차이를 빠르게 파악할 때 좋다 |
| 숫자를 하나씩 읽어야 한다 | 모양과 길이로 바로 비교된다 |

그래서 대시보드에는 보통 **핵심 숫자(지표)**, **차트**, **상세 표**가 함께 들어간다.

### 1-2. 어떤 차트를 언제 쓰나

| 알고 싶은 것 | 차트 | 예 |
|---|---|---|
| 시간에 따른 **변화** | 선 차트 | 월별 매출 추이 |
| 항목끼리 **크기 비교** | 막대 차트 | 지역별 매출 |
| 항목이 많거나 이름이 긴 **순위** | 가로 막대 차트 | 매출 상위 10개 상품 |
| 전체 중 **비율** (항목이 적을 때) | 원 차트 | 지역별 매출 비중 |
| 두 값의 **관계** | 산점도 | 단가와 판매 수량의 관계 |

> 💡 원 차트는 항목이 5개를 넘으면 조각을 비교하기 어렵다. 비율을 보여 주고 싶어도 항목이 많으면 막대 차트가 낫다.

### 1-3. 좋은 차트의 조건

- **제목**이 있다. 무엇을 보여 주는 차트인지 바로 알 수 있다.
- **단위**가 있다. 원인지, 천 원인지, 건인지 알 수 있다.
- **항목이 너무 많지 않다.** 상품 20개를 모두 그리기보다 상위 10개만 보여 준다.
- **순서가 의미 있다.** 순위 차트는 큰 것부터, 시간 차트는 시간 순서대로 놓는다.
- 꾸밈보다 **내용이 먼저**다. 색이 많을수록 좋은 것이 아니다.

## 2. 웹 앱과 Streamlit

### 2-1. 웹 앱이란?

지금까지 만든 프로그램은 모두 **터미널**에서 동작했다. 글자로 메뉴를 보여 주고, 키보드로 입력받았다. **웹 앱**은 **웹 브라우저**에서 동작하는 프로그램이다.

| 구분 | 터미널 프로그램 | 웹 앱 |
|---|---|---|
| 화면 | 글자만 | 버튼, 표, 차트, 이미지 |
| 조작 | 키보드로 입력 | 마우스로 클릭, 파일 끌어다 놓기 |
| 사용자 | 터미널을 쓸 줄 아는 사람 | 브라우저만 있으면 누구나 |
| 공유 | 코드를 받아 직접 실행해야 함 | 인터넷 주소만 알려 주면 됨 (10장) |

### 2-2. Streamlit이란?

웹 앱을 만들려면 보통 HTML, CSS, 자바스크립트 같은 여러 기술을 배워야 한다. **Streamlit**은 **파이썬 코드만으로** 웹 앱을 만들게 해 주는 패키지다. 데이터 분석 결과를 보여 주는 대시보드를 만들기에 특히 좋다.

```python
import streamlit as st

st.title("안녕하세요!")
name = st.text_input("이름을 입력하세요")
if name:
    st.write(f"반갑습니다, {name}님!")
```

이 몇 줄로 제목, 입력 칸, 인사 문구가 있는 웹 페이지가 만들어진다.

### 2-3. 파이썬 코드 읽기: Streamlit 화면 요소

Streamlit은 `st.○○()` 한 줄이 화면 요소 하나가 된다. 코드의 **위에서 아래 순서대로** 화면에 나타난다.

| 코드 | 화면에 나타나는 것 |
|---|---|
| `st.title("제목")` | 큰 제목 |
| `st.subheader("소제목")` | 작은 제목 |
| `st.write(...)` | 글자, 숫자, 표 등 무엇이든 |
| `st.metric("총 매출", "328,430,000원")` | 큰 숫자로 강조한 지표 카드 |
| `st.dataframe(df)` | 정렬·스크롤이 되는 표 |
| `st.line_chart(데이터)` | 선 차트 |
| `st.bar_chart(데이터)` | 막대 차트 |
| `st.file_uploader("안내 문구")` | 파일 올리기 버튼 |
| `st.multiselect("지역", 목록)` | 여러 개를 고르는 선택 상자 |
| `st.slider("기간", 1, 12, (1, 6))` | 범위를 고르는 슬라이더 |
| `st.sidebar.○○(...)` | 왼쪽 사이드바에 요소를 넣는다 |
| `col1, col2 = st.columns(2)` | 화면을 세로로 나눠 나란히 배치한다 |

### 2-4. Streamlit 앱 실행하기

Streamlit 앱은 `python`이 아니라 **`streamlit run`** 으로 실행한다. uv 프로젝트에서는 다음과 같이 입력한다.

```bash
uv run streamlit run app.py
```

```
  You can now view your Streamlit app in your browser.

  Local URL: http://localhost:8501
```

브라우저가 자동으로 열리고 앱이 나타난다. 열리지 않으면 `http://localhost:8501`을 브라우저 주소창에 입력한다.

- `localhost`는 "**내 컴퓨터**"라는 뜻이다. 지금은 내 컴퓨터에서만 볼 수 있다. 다른 사람도 볼 수 있게 인터넷에 올리는 방법(배포)은 10장에서 배운다.
- 앱을 끄려면 앱을 실행한 터미널에서 `Ctrl+C`를 누른다.

> 💡 처음 실행하면 터미널에 이메일을 입력하라는 안내가 나올 수 있다. 입력하지 않고 `Enter`를 누르면 된다.

### 2-5. Streamlit의 동작 방식

Streamlit 앱은 사용자가 필터를 바꾸거나 버튼을 누를 때마다 **코드 전체를 위에서부터 다시 실행**한다. 그래서 필터를 바꾸면 그 값에 맞게 지표와 차트가 모두 다시 계산된다.

코드를 고치고 저장하면 브라우저 오른쪽 위에 **Rerun**(다시 실행) 버튼이 나타난다. **Always rerun**을 누르면 이후에는 저장할 때마다 자동으로 화면이 새로 고쳐진다.

## 3. Claude Code 기능 익히기: 화면을 보여 주며 다듬기

### 3-1. 스크린샷으로 피드백하기

화면 디자인은 말로 설명하기 어렵다. 실행 중인 앱의 **스크린샷**을 찍어 Claude Code에게 붙여 넣으면, AI가 화면을 보고 무엇을 고쳐야 할지 이해한다.

**스크린샷 찍기**

| 운영체제 | 방법 |
|---|---|
| macOS | `Cmd+Shift+4`로 영역을 선택하면 바탕화면에 파일로 저장된다. `Ctrl+Cmd+Shift+4`로 선택하면 파일 대신 클립보드에 복사된다. |
| Windows | `Win+Shift+S`로 영역을 선택하면 클립보드에 복사된다. |

**Claude Code에 붙여 넣기**

| 터미널(CLI) | VS Code 확장 |
|---|---|
| 스크린샷 파일을 터미널로 끌어다 놓거나, 클립보드에 복사한 뒤 `Ctrl+V` (macOS도 `Cmd+V`가 아닌 `Ctrl+V`) | 입력창에 끌어다 놓거나 붙여 넣기 |

이미지를 붙인 뒤 요청을 이어서 쓴다.

```
(스크린샷) 이 화면에서 차트가 너무 작아. 화면 너비에 맞게 키워 줘.
```

### 3-2. 디자인 용어를 몰라도 된다

"여백", "정렬", "강조색" 같은 용어를 몰라도 괜찮다. 느낌을 말하는 것으로 시작하고, 결과를 보며 구체화한다.

| 처음 요청 (느낌) | 결과를 보고 구체화 |
|---|---|
| 더 깔끔하게 해 줘 | 지표 카드 사이 간격을 넓히고, 차트 제목 글씨를 조금 줄여 줘. |
| 은행 앱처럼 만들어 줘 | 색은 남색 계열로, 숫자는 크고 굵게, 장식은 빼 줘. |
| 보기 편하게 해 줘 | 필터를 왼쪽 사이드바로 옮기고, 표는 접어 두었다가 필요할 때 펼치게 해 줘. |

> 💡 "어떻게 하면 더 보기 좋아질지 세 가지 제안해 줘. 아직 고치지는 마."처럼 AI에게 **아이디어를 먼저 물어보는** 것도 좋은 방법이다.

### 3-3. 좋은 화면 피드백의 요령

2장에서 배운 수정 요청 방법이 화면에도 그대로 적용된다.

1. **어디의**: "오른쪽 위의 지역별 매출 차트"
2. **무엇이**: "막대가 가나다순이라 어느 지역이 1등인지 바로 안 보여."
3. **어떻게 바뀌길 원하는지**: "매출이 큰 순서로 정렬해 줘."

한 번에 여러 가지를 고치기보다 **한두 가지씩** 요청하고 화면으로 확인한다.

### 3-4. 앱 실행은 두 번째 터미널에서

Streamlit 앱은 `Ctrl+C`로 끄기 전까지 **계속 실행**되는 프로그램이다. Claude Code에게 실행을 맡기면 대화가 멈춘 것처럼 보일 수 있다. 2장의 숫자 맞추기 게임처럼 **두 번째 터미널**에서 내가 직접 실행해 두고, Claude Code와는 첫 번째 터미널에서 대화한다.

| 터미널 | 용도 |
|---|---|
| 첫 번째 터미널 | Claude Code와 대화 |
| 두 번째 터미널 | `uv run streamlit run app.py`로 앱을 켜 둔다 |

Claude Code가 코드를 고치면, 앱은 켜 둔 채로 브라우저에서 **Rerun**(또는 Always rerun)으로 바뀐 화면을 확인한다.

## 4. 실습: 나만의 대시보드 웹 앱

### 4-1. 프로젝트 만들기

```bash
cd ~/vibe-coding
mkdir dashboard
cd dashboard
code .
```

VS Code에서 **터미널 → 새 터미널**을 열고 `claude`를 입력한다(VS Code 확장을 쓴다면 Claude Code 패널을 연다).

```
uv init --no-package로 이 폴더를 uv 프로젝트로 만들고, streamlit, pandas, openpyxl 패키지를 설치해 줘. 그리고 6장에서 만든 ../sales-report/data/sales_2026.xlsx 파일을 이 폴더의 data 폴더로 복사해 줘.
```

> 💡 6장의 데이터 파일이 없다면 "6장 교재처럼 날짜, 지역, 상품, 수량, 단가, 매출 열이 있는 가짜 판매 데이터 1,000건을 data/sales_2026.xlsx로 만들어 줘"라고 요청한다.

`/init`으로 CLAUDE.md를 만들고 규칙을 추가한다.

```
CLAUDE.md에 아래 규칙을 추가해 줘.
- 나는 코딩 초보자야. 설명은 쉬운 한국어로 해 줘.
- 코드에는 한국어 주석을 달아 줘.
- 파이썬 실행은 uv run을, 패키지 설치는 uv add를 사용해.
- Streamlit 앱은 네가 실행하지 마. 내가 두 번째 터미널에서 uv run streamlit run app.py로 실행해 둘게.
- 커밋 메시지는 한국어로 써 줘.
```

첫 커밋을 만든다.

### 4-2. 1단계: 첫 번째 Streamlit 앱

```
app.py에 Streamlit 앱을 만들어 줘. 제목은 "📊 판매 대시보드"로 하고, data/sales_2026.xlsx를 읽어서 월별 매출 합계를 선 차트로 보여 줘.
```

두 번째 터미널에서 앱을 실행한다.

```bash
uv run streamlit run app.py
```

브라우저에 제목과 선 차트가 나타나면 성공이다. 차트 위에 마우스를 올리면 월별 값이 표시된다.

> 💡 이제부터는 앱을 끄지 않고 켜 둔 채로 진행한다. Claude Code가 코드를 고칠 때마다 브라우저에서 **Rerun**을 누른다. 처음 한 번 **Always rerun**을 누르면 더 편하다.

### 4-3. 2단계: 파일 올리기 기능

지금은 프로그램이 정해진 파일만 읽는다. 사용자가 **자기 파일을 올릴 수** 있게 바꾼다.

```
data/sales_2026.xlsx를 직접 읽는 대신, 사용자가 화면에서 엑셀 파일을 올리게 바꿔 줘. 파일을 올리기 전에는 "엑셀 파일을 올리면 대시보드가 나타납니다"라는 안내만 보여 줘. 파일을 올리면 선 차트와 함께 데이터 표도 보여 줘.
```

브라우저에서 **Browse files**를 누르거나 `data/sales_2026.xlsx`를 화면으로 끌어다 놓아 올려 본다. 웹 앱이 된 덕분에 이제 터미널을 모르는 사람도 파일만 올리면 쓸 수 있다.

### 4-4. 3단계: 핵심 지표 카드

```
차트 위에 핵심 지표 세 개를 나란히 보여 줘: 총 매출(원), 판매 건수(건), 건당 평균 매출(원). 숫자에는 천 단위 쉼표를 넣어 줘.
```

6장에서 검증한 값과 비교한다. 예시 데이터라면 총 매출 **328,430,000원**, 판매 건수 **1,000건**이 나와야 한다.

### 4-5. 4단계: 사이드바 필터

```
왼쪽 사이드바에 필터를 만들어 줘.
- 지역: 여러 개를 고를 수 있게, 처음에는 모든 지역 선택
- 기간: 시작 월과 끝 월을 고르는 슬라이더, 처음에는 1~6월
필터를 바꾸면 지표, 차트, 표가 모두 고른 조건에 맞게 바뀌게 해 줘.
```

필터를 바꿔 가며 화면이 바뀌는지 확인한다. 그리고 6장의 검증 결과와 비교해 본다.

- 지역을 **서울**만, 기간을 **1~1월**로 고른다.
- 판매 건수 **27건**, 총 매출 **11,880,000원**이 나오면 6장에서 엑셀로 직접 계산한 값과 일치한다.

> 💡 웹 앱이라고 해서 검증을 건너뛰지 않는다. 화면이 멋져도 숫자가 틀리면 소용없다. 6장에서 검증해 둔 값이 있으면 이렇게 **필터로 같은 조건을 만들어 비교**하면 된다.

### 4-6. 5단계: 차트 추가와 배치

```
차트를 더 추가해 줘.
- 월별 매출(선 차트)과 지역별 매출(막대 차트)은 한 줄에 나란히
- 그 아래에 매출 상위 10개 상품(가로 막대 차트)
- 데이터 표는 맨 아래에 접어 두었다가 "데이터 보기"를 누르면 펼쳐지게
각 차트에 소제목을 달아 줘.
```

만들어진 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import pandas as pd
import streamlit as st

st.set_page_config(page_title="판매 대시보드", layout="wide")
st.title("📊 판매 대시보드")

# 1. 엑셀 파일 올리기
uploaded = st.file_uploader("판매 데이터 엑셀 파일을 올려 주세요", type=["xlsx"])
if uploaded is None:
    st.info("엑셀 파일을 올리면 대시보드가 나타납니다.")
    st.stop()                      # 파일이 없으면 여기서 멈춘다

df = pd.read_excel(uploaded)
df["월"] = df["날짜"].dt.month

# 2. 사이드바 필터
st.sidebar.header("필터")
regions = st.sidebar.multiselect(
    "지역", options=sorted(df["지역"].unique()), default=sorted(df["지역"].unique())
)
months = st.sidebar.slider("기간(월)", min_value=1, max_value=12, value=(1, 6))

filtered = df[df["지역"].isin(regions) & df["월"].between(months[0], months[1])]

# 3. 핵심 지표
col1, col2, col3 = st.columns(3)
col1.metric("총 매출", f"{filtered['매출'].sum():,}원")
col2.metric("판매 건수", f"{len(filtered):,}건")
col3.metric("건당 평균 매출", f"{filtered['매출'].mean():,.0f}원" if len(filtered) else "-")

# 4. 차트
left, right = st.columns(2)
with left:
    st.subheader("월별 매출")
    st.line_chart(filtered.groupby("월")["매출"].sum())
with right:
    st.subheader("지역별 매출")
    st.bar_chart(filtered.groupby("지역")["매출"].sum())

st.subheader("매출 상위 10개 상품")
top10 = filtered.groupby("상품")["매출"].sum().sort_values(ascending=False).head(10)
st.bar_chart(top10, horizontal=True)

# 5. 원본 표
with st.expander("데이터 보기"):
    st.dataframe(filtered, width="stretch")
```

#### 코드에서 개념 찾기

| 코드 | 하는 일 |
|---|---|
| `st.set_page_config(..., layout="wide")` | 화면을 브라우저 너비만큼 넓게 쓴다. |
| `st.file_uploader(..., type=["xlsx"])` | 엑셀 파일만 올릴 수 있는 버튼을 만든다. |
| `st.stop()` | 파일이 없으면 아래 코드를 실행하지 않고 멈춘다. |
| `st.sidebar.multiselect(...)` | 사이드바에 지역 선택 상자를 만든다. 고른 지역 목록이 `regions`에 담긴다. |
| `df["지역"].isin(regions)` | 고른 지역에 해당하는 행만 남긴다. |
| `df["월"].between(months[0], months[1])` | 고른 기간에 해당하는 행만 남긴다. |
| `st.columns(3)` | 화면을 세 칸으로 나눠 지표를 나란히 놓는다. |
| `with left:` | 이 아래 들여쓴 요소를 왼쪽 칸에 넣는다. |
| `st.expander("데이터 보기")` | 접었다 펼 수 있는 영역을 만든다. |

동작을 확인했으면 커밋한다.

```
대시보드가 잘 동작해. 커밋해 줘.
```

### 4-7. 6단계: 스크린샷으로 다듬기

브라우저에서 앱 화면의 스크린샷을 찍어 Claude Code에 붙여 넣고, 3-2와 3-3의 요령으로 다듬는다. 예를 들면 다음과 같다.

```
(스크린샷) 지역별 매출 막대가 매출이 큰 순서로 정렬되면 좋겠어.
```

```
(스크린샷) 이 화면을 더 깔끔하게 만들고 싶어. 어떻게 바꾸면 좋을지 세 가지 제안해 줘. 아직 고치지는 마.
```

```
(스크린샷) 지표 카드의 숫자 단위가 너무 길어. 총 매출은 "3억 2,843만 원"처럼 읽기 쉽게 보여 줘.
```

```
(스크린샷) 필터에서 지역을 하나도 고르지 않으면 화면이 이상해. 이럴 땐 "지역을 하나 이상 선택하세요"라고 안내해 줘.
```

한두 가지씩 고치고, 화면이 마음에 들 때마다 커밋한다.

> 💡 마지막 예시처럼 **일부러 이상하게 써 보는 것**도 중요하다. 지역을 모두 빼거나, 기간을 한 달로 줄이거나, 엉뚱한 엑셀 파일을 올려 본다. 사용자는 만든 사람이 예상하지 못한 방식으로 앱을 쓴다.

### 4-8. 7단계: 서로 써 보고 피드백하기

옆 사람과 노트북을 바꿔 서로의 앱을 써 본다. 써 보는 사람은 다음을 확인하고 의견을 말해 준다.

- 처음 보는 사람도 무엇을 해야 할지 알 수 있는가?
- 숫자와 차트가 한눈에 이해되는가?
- 이상하게 동작하는 곳은 없는가?

받은 의견 중 하나를 골라 고치고 커밋한 뒤, GitHub에 올린다. 10장에서 이 저장소로 앱을 인터넷에 배포한다.

```
GitHub에 vibe-dashboard라는 공개 저장소를 만들어서 올려 줘. 올리기 전에 어떤 파일이 올라가는지 목록을 먼저 보여 줘.
```

> 💡 `data/sales_2026.xlsx`는 가짜 데이터라 함께 올려도 괜찮다. 다른 사람이 앱을 시험해 볼 때 예시 파일로 쓸 수 있다. 실제 데이터라면 절대 올리지 않는다.

## 5. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| `streamlit: command not found` | `uv run streamlit run app.py`처럼 앞에 `uv run`을 붙인다. |
| 처음 실행했는데 터미널이 이메일을 묻고 멈춰 있다 | 아무것도 입력하지 않고 `Enter`를 누른다. |
| 브라우저가 열리지 않는다 | 브라우저 주소창에 `http://localhost:8501`을 직접 입력한다. |
| `Port 8501 is already in use` | 앱이 이미 다른 터미널에서 실행 중이다. 그 터미널에서 `Ctrl+C`로 끄거나, 이미 열린 브라우저 탭을 쓴다. |
| 코드를 고쳤는데 화면이 그대로다 | 브라우저 오른쪽 위의 **Rerun**을 누르거나, 브라우저를 새로 고친다. 파일을 저장했는지도 확인한다. |
| Claude Code가 앱을 실행하고 대화가 멈췄다 | 작업을 중단하고(CLI는 `Esc`), 두 번째 터미널에서 직접 실행한다. CLAUDE.md에 실행 규칙이 있는지 확인한다. |
| 화면에 빨간 오류 상자가 나타난다 | 오류 상자 안의 메시지(특히 마지막 줄)를 복사하거나 스크린샷을 찍어 Claude Code에게 보여 준다. |
| 차트의 한글이 네모(□)로 깨진다 | matplotlib으로 차트를 그리면 생길 수 있다. "Streamlit 기본 차트로 바꿔 줘" 또는 "한글이 깨지지 않게 고쳐 줘"라고 요청한다. |
| 파일을 올리면 `KeyError: '날짜'` 오류가 난다 | 올린 파일의 열 이름이 코드가 기대하는 이름과 다르다. 6장의 데이터 파일을 올렸는지 확인한다. |
| 필터를 바꿀 때마다 앱이 느리다 | "데이터를 한 번만 읽도록 캐시를 써 줘"라고 요청한다(`st.cache_data`). |

## 6. 정리

### 핵심 요약

1. 차트는 데이터의 흐름과 차이를 한눈에 보여 준다. **변화는 선, 비교는 막대, 순위는 가로 막대**로 그린다.
2. 좋은 차트에는 제목과 단위가 있고, 항목이 너무 많지 않으며, 순서에 의미가 있다.
3. **Streamlit**은 파이썬만으로 웹 앱을 만들게 해 준다. `st.○○()` 한 줄이 화면 요소 하나이고, 위에서 아래 순서로 나타난다.
4. Streamlit 앱은 `uv run streamlit run app.py`로 **두 번째 터미널에서** 켜 두고, 코드를 고칠 때마다 **Rerun**으로 확인한다.
5. 화면은 **스크린샷**을 보여 주며 다듬는다. 디자인 용어를 몰라도 느낌에서 시작해 결과를 보며 구체화하면 된다.

### 요청문 템플릿

**화면 수정**
```
(스크린샷) [어디의] [무엇이] [어떻게 문제인지]. [원하는 모습]으로 바꿔 줘.
```

**디자인 아이디어 얻기**
```
(스크린샷) 이 화면을 [더 깔끔하게 / 보기 편하게] 만들고 싶어. 어떻게 바꾸면 좋을지 세 가지 제안해 줘. 아직 고치지는 마.
```

**필터 추가**
```
사이드바에 [항목] 필터를 만들어 줘. [선택 방식]으로 고르게 하고, 필터를 바꾸면 지표, 차트, 표가 모두 바뀌게 해 줘.
```

### 용어 사전

| 용어 | 뜻 |
|---|---|
| 데이터 시각화 | 데이터를 차트나 그림으로 표현하는 것 |
| 대시보드 | 핵심 지표와 차트를 한 화면에 모아 보여 주는 화면 |
| 지표 | 상황을 한눈에 보여 주는 핵심 숫자 (총 매출, 판매 건수 등) |
| 웹 앱 | 웹 브라우저에서 동작하는 프로그램 |
| Streamlit | 파이썬만으로 웹 앱을 만드는 패키지 |
| 사이드바 | 화면 왼쪽에 붙어 있는 좁은 영역. 주로 필터를 둔다. |
| 필터 | 조건에 맞는 데이터만 골라 보는 기능 |
| localhost | 내 컴퓨터를 가리키는 주소 |
| 배포 | 내가 만든 앱을 인터넷에 올려 다른 사람도 쓸 수 있게 하는 것 (10장) |

### 스스로 점검하기

- [ ] 보여 주고 싶은 내용에 맞는 차트 종류를 고를 수 있다.
- [ ] 웹 앱과 터미널 프로그램의 차이를 설명할 수 있다.
- [ ] Streamlit 코드에서 제목, 지표, 차트, 필터를 만드는 부분을 찾을 수 있다.
- [ ] `uv run streamlit run app.py`로 앱을 실행하고, `Ctrl+C`로 끌 수 있다.
- [ ] 필터로 6장과 같은 조건을 만들어 숫자가 일치하는지 확인했다.
- [ ] 스크린샷을 붙여 넣어 화면 수정을 요청했다.
- [ ] 다른 사람에게 앱을 써 보게 하고 의견을 반영했다.

## 7. 과제

9장부터 진행할 **최종 프로젝트 아이디어 3개**를 생각해 온다.

### 작성 방법

1. 내 업무나 생활에서 **불편한 점, 반복되는 일, 있으면 좋겠는 도구**를 떠올린다.
2. 아이디어마다 아래 한 장 기획서 양식으로 간단히 정리한다.
3. 지금까지 배운 것(파일 저장, 엑셀, API, 웹 앱)으로 만들 수 있는지 생각해 본다. 잘 모르겠으면 Claude Code에게 "이 아이디어를 지금까지 배운 것으로 만들 수 있을지, 어려운 부분은 무엇인지 알려 줘"라고 물어본다.

### 한 장 기획서 양식

```markdown
# 프로젝트 이름
## 누구의 어떤 문제를 해결하나요?
## 핵심 기능 (꼭 필요한 것 3개 이하)
## 있으면 좋은 기능 (시간이 남으면)
## 사용하는 데이터 / 외부 서비스
## 완성 기준 (무엇이 되면 "완성"인가?)
```

### 아이디어 예시

| 아이디어 | 활용하는 내용 |
|---|---|
| 가계부 분석기: 카드 내역 엑셀을 올리면 카테고리별 지출 차트 | 6장 엑셀, 8장 웹 앱 |
| 동네 맛집 기록장: 맛집을 기록하고 지도에 표시 | 4장 파일 저장, 8장 웹 앱 |
| 독서 기록과 연간 통계 | 4장 파일 저장, 8장 차트 |
| 동아리 출석 관리: 출석 체크와 출석률 차트 | 4장 파일 저장, 6장 엑셀, 8장 웹 앱 |
| 여행 준비 도우미: 여행지 날씨와 환율을 한 화면에 | 7장 API, 8장 웹 앱 |
