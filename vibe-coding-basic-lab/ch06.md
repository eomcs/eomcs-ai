## 1. 파이썬 코드 읽기: 표 데이터와 pandas

### 1-1. 무엇을 자동화할 수 있나

매번 같은 순서로 반복하는 컴퓨터 작업은 대부분 자동화할 수 있다.

| 반복 업무 | 사람이 할 때 | 자동화하면 |
|---|---|---|
| 매달 보고서 정리 | 엑셀을 열고 필터·합계·복사·붙여 넣기를 30분 동안 반복 | 프로그램 실행 한 번으로 몇 초 만에 끝 |
| 여러 파일 합치기 | 지점별 엑셀 20개를 하나씩 열어 복사 | 폴더 안의 파일을 한 번에 합침 |
| 파일 이름 일괄 변경 | `IMG_0001.jpg` 300개를 `2026-여행-001.jpg`로 하나씩 변경 | 규칙대로 한 번에 변경 |
| 데이터 정리 | 빈칸 지우기, 중복 지우기, 날짜 형식 맞추기 | 정해진 규칙대로 한 번에 정리 |

> 💡 자동화할 업무를 고르는 기준: **자주 반복되고**, **순서가 정해져 있고**, **실수하기 쉬운** 작업일수록 자동화 효과가 크다.

### 1-2. 표 형태 데이터

엑셀처럼 **행**(가로줄)과 **열**(세로줄)로 이루어진 데이터를 **표 형태 데이터**라고 한다.

| 날짜 | 지역 | 상품 | 수량 | 단가 | 매출 |
|---|---|---|---:|---:|---:|
| 2026-01-01 | 광주 | USB 허브 | 7 | 32,000 | 224,000 |
| 2026-01-01 | 대구 | 스마트워치 | 8 | 199,000 | 1,592,000 |
| 2026-01-01 | 서울 | 외장 SSD | 5 | 139,000 | 695,000 |

- **행** 하나는 판매 한 건이다.
- **열** 하나는 같은 종류의 정보(날짜, 지역, 매출 등)다.
- 맨 위 행은 각 열의 이름(**제목 행**)이다.

표 데이터는 주로 두 가지 파일 형식으로 저장한다.

| 형식 | 특징 | 열어 보는 프로그램 |
|---|---|---|
| CSV (`.csv`) | 값을 쉼표로 구분한 **글자 파일**. 서식·여러 시트가 없다. | 엑셀, 메모장, VS Code |
| 엑셀 (`.xlsx`) | 여러 **시트**, 색·글꼴 같은 **서식**을 담을 수 있다. | 엑셀, Numbers, Google 스프레드시트 |

### 1-3. pandas 맛보기

**pandas**는 파이썬에서 표 데이터를 다루는 가장 유명한 패키지다. 엑셀에서 하던 일을 코드로 할 수 있다. pandas는 표 하나를 **DataFrame**(데이터프레임)이라고 부르고, 보통 `df`라는 변수에 담는다.

```python
import pandas as pd                       # pandas를 pd라는 짧은 이름으로 불러온다

df = pd.read_excel("data/sales_2026.xlsx")   # 엑셀 파일을 읽어 표로 만든다
print(df.head())                          # 앞의 5행만 보여 준다
```

자주 보게 될 코드를 엑셀 작업과 비교하면 다음과 같다.

| 엑셀에서 하는 일 | pandas 코드 |
|---|---|
| 파일 열기 | `df = pd.read_excel("파일.xlsx")` / `pd.read_csv("파일.csv")` |
| 행 개수 확인 | `len(df)` |
| 특정 열만 보기 | `df["매출"]` |
| 필터 (서울만 보기) | `df[df["지역"] == "서울"]` |
| 새 열 추가 | `df["월"] = df["날짜"].dt.month` |
| 열 합계 | `df["매출"].sum()` |
| 부분합 (상품별 합계) | `df.groupby("상품")["매출"].sum()` |
| 피벗 테이블 | `pd.pivot_table(df, index="지역", columns="월", values="매출", aggfunc="sum")` |
| 정렬 (큰 순서) | `df.sort_values("매출", ascending=False)` |
| 다른 이름으로 저장 | `df.to_excel("결과.xlsx", index=False)` |

> 💡 **피벗 테이블**은 데이터를 기준에 따라 묶어서 요약한 표다. 이 장의 결과물인 "지역별 월별 합계"가 피벗 테이블이다. 행에는 지역, 열에는 월을 놓고, 칸마다 매출 합계를 계산했다.

### 1-4. openpyxl: 엑셀 서식 다루기

pandas는 **데이터**를 다루는 데 강하고, 색칠이나 열 너비 같은 **서식**은 **openpyxl** 패키지로 다룬다.

```python
from openpyxl import load_workbook
from openpyxl.styles import PatternFill

wb = load_workbook("output/report.xlsx")   # 엑셀 파일을 연다
ws = wb["상품별 매출"]                       # 시트를 고른다
yellow = PatternFill(start_color="FFFF00", end_color="FFFF00", fill_type="solid")
ws["A2"].fill = yellow                      # A2 칸을 노란색으로 칠한다
wb.save("output/report.xlsx")               # 저장한다
```

## 2. 결과 검증하기

### 2-1. AI는 그럴듯하지만 틀릴 수 있다

AI가 만든 보고서는 겉보기에 그럴듯하다. 숫자가 빼곡하고 표도 깔끔하다. 하지만 **계산이 틀려도 겉모습은 똑같이 그럴듯하다.** 데이터 작업에서 AI가 저지르기 쉬운 실수는 다음과 같다.

| 실수 | 예 |
|---|---|
| 계산 방법 착각 | 매출 **합계**를 구해야 하는데 판매 **건수**나 **평균**을 구했다. |
| 다른 열 계산 | **매출** 합계 대신 **수량** 합계를 구했다. |
| 기준 착각 | "상위 10개 상품"을 상품별 합계가 아니라 판매 한 건의 매출 기준으로 골랐다. |
| 데이터 누락 | 제목 행을 데이터로 읽거나, 빈칸이 있는 행을 빼고 계산했다. |
| 기간 착각 | 1월 데이터를 고를 때 1월 31일을 빼먹었다. |

이런 실수는 **오류 메시지 없이** 조용히 일어난다. 그래서 결과를 직접 확인해야 한다.

### 2-2. 검증하는 다섯 가지 방법

| 방법 | 확인하는 것 | 예 |
|---|---|---|
| ① 직접 계산해 비교 | 값 몇 개를 골라 엑셀에서 직접 계산한 값과 같은가? | 서울 1월 합계를 엑셀 필터로 직접 구해 비교 |
| ② 전체 합계 비교 | 요약표의 합계가 원본 전체 합계와 같은가? | 지역별 월별 합계를 모두 더하면 원본 매출 총합과 같아야 한다. |
| ③ 개수 비교 | 행 개수가 맞는가? | 월별 파일 6개의 행 수를 더하면 합친 파일의 행 수와 같아야 한다. |
| ④ 계산 과정 요청 | AI가 어떤 기준으로 계산했는가? | "서울 1월 합계를 계산 과정과 함께 보여 줘." |
| ⑤ 상식 점검 | 결과가 말이 되는가? | 단가 7,000원짜리 필름이 매출 1위라면 의심해 본다. |

> 💡 모든 값을 확인할 필요는 없다. **두세 개를 골라 직접 확인**하고, **전체 합계**와 **개수**가 맞는지만 봐도 대부분의 실수를 잡아낼 수 있다.

### 2-3. 엑셀에서 직접 계산하는 방법

**방법 1. 필터와 상태 표시줄**

1. 원본 파일을 엑셀에서 연다.
2. 제목 행을 선택하고 **데이터 → 필터**를 누른다.
3. "지역" 열에서 **서울**만, "날짜" 열에서 **1월**만 선택한다.
4. "매출" 열의 값을 드래그해 선택한다.
5. 엑셀 창 아래쪽 **상태 표시줄**에 표시되는 **합계**와 **개수**를 확인한다.

**방법 2. SUMIFS 함수**

빈 칸에 다음 수식을 입력한다. 날짜가 A열, 지역이 B열, 매출이 F열일 때의 예다.

```
=SUMIFS(F:F, B:B, "서울", A:A, ">="&DATE(2026,1,1), A:A, "<"&DATE(2026,2,1))
```

"지역이 서울이고, 날짜가 2026년 1월 1일 이상 2월 1일 미만인 행의 매출을 더하라"는 뜻이다.

> 💡 엑셀이 없다면 Numbers(macOS), Google 스프레드시트, LibreOffice Calc에서도 필터와 SUMIFS를 쓸 수 있다.

## 3. Claude Code로 데이터 다루기

### 3-1. 실제 데이터 대신 가짜 데이터로 연습한다

> ⚠️ Claude Code가 파일을 읽으면 그 내용이 AI 서비스로 전송된다. 회사의 실제 매출 자료, 고객 명단, 개인 정보가 담긴 파일은 Claude Code에게 읽히지 않는다. 회사의 보안 규정도 반드시 확인한다.

실습과 연습은 **진짜와 구조가 같은 가짜 데이터**로 한다. Claude Code에게 "이런 열이 있는 가짜 데이터를 만들어 줘"라고 요청하면 된다. 가짜 데이터로 프로그램을 완성한 뒤, 실제 업무에 쓸 때는 **내 컴퓨터에서 직접 실행만** 하면 된다.

### 3-2. 데이터 구조부터 확인한다

처음 보는 데이터로 작업할 때는 바로 계산을 요청하지 말고 **구조부터** 확인한다.

```
data/sales_2026.xlsx의 구조를 알려 줘. 열 이름, 각 열의 자료 종류, 행 개수, 앞의 5행을 보여 줘.
```

구조를 알아야 "어느 열로 무엇을 계산할지" 정확히 요청할 수 있다.

### 3-3. 원본 파일은 건드리지 않는다

자동화 프로그램이 원본 파일을 덮어쓰면 되돌릴 수 없다. 원본은 그대로 두고 결과는 **새 파일**로 저장하는 것이 원칙이다. 이 규칙을 CLAUDE.md에 적어 둔다.

```markdown
- data 폴더의 원본 파일은 절대 수정하지 말고, 결과는 output 폴더에 새 파일로 저장해.
```

### 3-4. 모호한 요청을 구체화한다

2장에서 배운 4요소가 데이터 작업에서 특히 중요하다. 같은 말도 여러 가지로 해석될 수 있기 때문이다.

| 모호한 요청 | 해석 1 | 해석 2 |
|---|---|---|
| 매출 상위 10개 상품 | 상품별 **매출 합계** 상위 10개 | 판매 **한 건의 매출**이 큰 10건 |
| 월별 실적 | 월별 **매출 합계** | 월별 **판매 건수** |
| 서울 데이터 | 서울 **지역** 판매 | 서울 **지점** 직원의 판매 |

요청할 때 **무엇을 기준으로, 어떤 계산(합계·평균·개수)을 할지** 분명히 쓴다.

### 3-5. 터미널(CLI)과 VS Code 확장의 사용법 비교

데이터 작업은 요청으로 진행하므로 터미널(CLI)과 VS Code 확장의 사용법이 같다. 다만 VS Code는 엑셀 파일(`.xlsx`)을 표로 보여 주지 못하므로 결과는 엑셀에서 연다.

| 기능 | 터미널(CLI) | VS Code 확장 |
|---|---|---|
| 데이터 작업 요청 | 입력창에 요청 | 입력창에 요청 |
| 엑셀 결과 열기 | "output/report.xlsx를 열어 줘"라고 요청하거나, 파일 탐색기(Finder)에서 더블클릭 | 같음 |
| CSV 결과 보기 | VS Code에서 바로 열기 | 같음 |

## 4. 실습: 엑셀 보고서 자동 정리기

### 4-1. 프로젝트 만들기

4장에서 배운 방법으로 새 프로젝트를 만든다.

```bash
cd ~/vibe-coding
mkdir sales-report
cd sales-report
code .
```

VS Code에서 **터미널 → 새 터미널**을 열고 `claude`를 입력한다(VS Code 확장을 쓴다면 Claude Code 패널을 연다).

```
uv init --no-package로 이 폴더를 uv 프로젝트로 만들고, pandas와 openpyxl 패키지를 설치해 줘. data 폴더와 output 폴더도 만들어 줘.
```

설치가 끝나면 `/init`으로 CLAUDE.md를 만들고 규칙을 추가한다.

```
CLAUDE.md에 아래 규칙을 추가해 줘.
- 나는 코딩 초보자야. 설명은 쉬운 한국어로 해 줘.
- 코드에는 한국어 주석을 달아 줘.
- 파이썬 실행은 uv run을, 패키지 설치는 uv add를 사용해.
- data 폴더의 원본 파일은 절대 수정하지 말고, 결과는 output 폴더에 새 파일로 저장해.
- 계산 결과를 알려 줄 때는 어떤 기준으로 계산했는지 함께 설명해 줘.
- 금액은 천 단위 쉼표를 넣어 보여 줘.
- 커밋 메시지는 한국어로 써 줘.
```

5장에서 배운 대로 첫 커밋을 만든다.

```
지금 상태를 첫 번째 커밋으로 저장해 줘.
```

> 💡 이 장의 프로그램은 사용자 입력을 받지 않으므로 Claude Code가 직접 실행해도 된다. 그래도 결과 파일은 **내가 직접 열어서** 확인한다.

### 4-2. 1단계: 가짜 판매 데이터 만들기

```
연습용 가짜 판매 데이터를 만드는 make_data.py를 만들고 실행해 줘.
- 열: 날짜, 지역, 상품, 수량, 단가, 매출
- 기간: 2026년 1월 1일 ~ 6월 30일
- 지역: 서울, 부산, 대구, 인천, 광주
- 상품: 전자 기기 액세서리 20종, 상품마다 단가는 고정
- 수량은 1~10개, 매출은 수량 × 단가
- 1,000건을 만들어 data/sales_2026.xlsx로 저장
- 실행할 때마다 같은 데이터가 나오게 해 줘.
```

만들어진 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import random
from datetime import date, timedelta

import pandas as pd

random.seed(42)   # 매번 같은 가짜 데이터가 만들어지도록 고정한다

regions = ["서울", "부산", "대구", "인천", "광주"]
products = {
    "무선 이어폰": 89000, "블루투스 스피커": 59000, "스마트워치": 199000,
    "보조배터리": 29000, "USB 충전기": 15000, "노트북 거치대": 35000,
    # ... (상품 20종)
}

rows = []
start = date(2026, 1, 1)
for _ in range(1000):
    day = start + timedelta(days=random.randint(0, 180))   # 1월 1일 ~ 6월 30일
    name = random.choice(list(products))
    quantity = random.randint(1, 10)
    price = products[name]
    rows.append({
        "날짜": day,
        "지역": random.choice(regions),
        "상품": name,
        "수량": quantity,
        "단가": price,
        "매출": quantity * price,
    })

df = pd.DataFrame(rows).sort_values("날짜")
df.to_excel("data/sales_2026.xlsx", index=False)
print(f"{len(df)}건의 판매 데이터를 data/sales_2026.xlsx에 저장했습니다.")
```

> 💡 `random.seed(42)`는 무작위 숫자를 만드는 출발점을 고정한다. 출발점이 같으면 실행할 때마다 똑같은 "무작위" 데이터가 나온다. 그래서 검증할 때 숫자가 바뀌지 않는다.

### 4-4. 3단계: 지역별·월별 합계 만들기

```
data/sales_2026.xlsx를 읽어서 지역별·월별 매출 합계 표를 만드는 report.py를 만들고 실행해 줘. 행은 지역, 열은 월(1~6월), 값은 매출 합계로 해 줘. 결과는 output/report.xlsx에 저장하고, 첫 번째 시트에는 원본 데이터, 두 번째 시트 "지역별 월별 합계"에는 합계 표를 넣어 줘.
```

만들어진 코드는 대략 다음과 같다.

```python
import pandas as pd

INPUT_FILE = "data/sales_2026.xlsx"
OUTPUT_FILE = "output/report.xlsx"

# 1. 원본 데이터를 읽는다
df = pd.read_excel(INPUT_FILE)

# 2. 날짜에서 "월"을 뽑아 새 열로 만든다 (예: 2026-01-15 → 1)
df["월"] = df["날짜"].dt.month

# 3. 지역별·월별 매출 합계 표를 만든다
summary = pd.pivot_table(
    df,
    index="지역",        # 행: 지역
    columns="월",        # 열: 월
    values="매출",       # 계산할 값: 매출
    aggfunc="sum",       # 계산 방법: 합계
)

# 4. 원본과 합계 표를 시트를 나눠 새 엑셀 파일로 저장한다
with pd.ExcelWriter(OUTPUT_FILE) as writer:
    df.to_excel(writer, sheet_name="원본", index=False)
    summary.to_excel(writer, sheet_name="지역별 월별 합계")

print(f"보고서를 {OUTPUT_FILE}에 저장했습니다.")
```

#### 코드에서 개념 찾기

| 코드 | 하는 일 |
|---|---|
| `pd.read_excel(INPUT_FILE)` | 원본 엑셀 파일을 읽어 표(DataFrame)로 만든다. |
| `df["날짜"].dt.month` | 날짜 열에서 월만 뽑는다. |
| `pd.pivot_table(...)` | 지역(행)과 월(열)로 묶어 매출 합계를 계산한다. |
| `aggfunc="sum"` | 계산 방법이 **합계**임을 정한다. `"mean"`이면 평균, `"count"`면 개수다. |
| `pd.ExcelWriter(...)` | 시트가 여러 개인 엑셀 파일을 만든다. |
| `sheet_name="..."` | 시트 이름을 정한다. |

`output/report.xlsx`를 엑셀에서 열어 두 시트가 모두 있는지 확인한다.

### 4-5. 4단계: 결과 검증하기

이 장에서 가장 중요한 단계다. 2-2의 방법으로 보고서가 맞는지 확인한다.

**① 계산 과정 요청**

```
결과가 맞는지 확인하고 싶어. 서울 지역 1월 합계를 계산 과정과 함께 보여 줘. 몇 건을 더했는지도 알려 줘.
```

**② 직접 계산해 비교**

2-3의 방법으로 원본 파일(`data/sales_2026.xlsx`)에서 서울 1월 매출 합계를 직접 구한다. 보고서의 값, Claude Code가 알려 준 값과 비교한다. 예시 데이터에서는 세 값이 모두 **27건, 11,880,000원**으로 같다.

**③ 전체 합계 비교**

```
원본 데이터의 매출 총합과, 지역별 월별 합계 표의 모든 칸을 더한 값이 같은지 확인해 줘.
```

예시 데이터에서는 둘 다 **328,430,000원**이다. 두 값이 다르면 어딘가에서 데이터가 빠졌거나 중복된 것이다.

> 💡 예시의 숫자는 교재를 만들 때의 결과다. 내 데이터는 Claude Code가 만든 코드에 따라 숫자가 다를 수 있다. 숫자가 같은지가 아니라, **세 가지 방법으로 구한 값이 서로 일치하는지**를 확인한다.

**검증 실습: 틀린 결과 찾아보기**

`report.py`의 `aggfunc="sum"`을 VS Code에서 직접 `aggfunc="mean"`으로 바꾸고 다시 실행해 본다. 표는 여전히 그럴듯해 보이지만, ③ 전체 합계 비교를 해 보면 값이 맞지 않는다. 확인이 끝나면 5장에서 배운 대로 되돌린다.

## 5. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| `ModuleNotFoundError: No module named 'pandas'` | `uv run`으로 실행했는지 확인한다. `pyproject.toml`에 `pandas`, `openpyxl`이 있는지 확인한다. |
| `FileNotFoundError` | 프로젝트 폴더(`sales-report`)에서 실행했는지, `data` 폴더에 파일이 있는지 확인한다. |
| `PermissionError` 오류가 난다 | 결과 파일이 엑셀에서 열려 있으면 덮어쓸 수 없다. 엑셀을 닫고 다시 실행한다. |
| 엑셀에서 한글이 깨진다 (CSV 파일) | CSV를 엑셀에서 열 때 생기는 문제다. "CSV를 저장할 때 엑셀에서 한글이 깨지지 않게 utf-8-sig로 저장해 줘"라고 요청한다. |
| 날짜가 숫자(예: 46023)로 보인다 | 엑셀이 날짜를 숫자로 저장한 것이다. "날짜 열을 날짜 형식으로 읽어 줘"라고 요청한다. |
| 합계가 직접 계산한 값과 다르다 | 계산 기준(합계·평균·개수, 어느 열인지, 기간)을 Claude Code에게 설명하게 하고, 2-1의 실수 목록과 비교한다. |
| 원본 파일이 바뀌었다 | 5장에서 배운 대로 "data 폴더의 파일을 마지막 커밋 상태로 되돌려 줘"라고 요청한다. CLAUDE.md에 원본 보존 규칙이 있는지 확인한다. |
| 기존 시트가 사라졌다 | 시트를 추가할 때 파일을 새로 만들면서 덮어쓴 것이다. "기존 시트는 그대로 두고 시트만 추가해 줘"라고 다시 요청한다. |

## 6. 정리

### 핵심 요약

1. **자주 반복되고, 순서가 정해져 있고, 실수하기 쉬운** 파일 작업은 자동화하기 좋다.
2. **pandas**로 엑셀·CSV를 읽고, 필터·합계·피벗 테이블·정렬을 하고, 새 파일로 저장한다. 서식은 **openpyxl**로 다룬다.
3. AI의 계산은 **틀려도 그럴듯해 보인다.** 값 몇 개를 직접 계산하고, 전체 합계와 개수를 비교해서 검증한다.
4. 실제 업무 데이터는 Claude Code에게 읽히지 않는다. **가짜 데이터**로 프로그램을 완성하고, 실제 데이터에는 실행만 한다.
5. 원본 파일은 건드리지 않고, 결과는 항상 **새 파일**로 저장한다.

### 요청문 템플릿

**데이터 구조 확인**
```
[파일 이름]의 구조를 알려 줘. 열 이름, 각 열의 자료 종류, 행 개수, 앞의 5행을 보여 줘.
```

**가짜 데이터 만들기**
```
연습용 가짜 데이터를 만들어 줘. 열은 [열 목록], [행 개수]건, [기간·범위 조건]으로 [파일 이름]에 저장해 줘. 실행할 때마다 같은 데이터가 나오게 해 줘.
```

**결과 검증**
```
결과가 맞는지 확인하고 싶어. [항목 하나]의 값을 계산 과정과 함께 보여 주고, 원본 전체 합계와 결과 표의 합계가 같은지도 확인해 줘.
```

| 검증 | 결과가 맞는지 직접 확인하는 것 |
| 가짜 데이터 | 실제 데이터와 구조는 같지만 내용은 만들어 낸 연습용 데이터 |

### 진행 방법

1. 자동화할 작업을 고르고, 사람이 할 때의 순서를 단계별로 적는다.
2. 실제 파일과 **구조가 같은 가짜 데이터**를 Claude Code에게 만들어 달라고 요청한다. 실제 파일의 열 이름과 형식만 알려 주고, 실제 내용은 알려 주지 않는다.
3. 가짜 데이터로 자동화 프로그램을 만든다. 큰 작업은 Plan 모드로 계획부터 확인한다.
4. 결과를 2-2의 방법 중 **두 가지 이상**으로 검증한다.
5. 기능이 동작할 때마다 커밋한다.

### 아이디어 예시

- 매달 받는 카드 사용 내역을 카테고리별 지출 합계로 정리하기
- 여러 명이 제출한 설문 결과 엑셀 파일을 하나로 합치고 문항별로 집계하기
- 사진 파일 이름을 촬영 날짜 순서대로 일괄 변경하기
- 출석부 엑셀에서 결석이 3회 이상인 사람만 뽑아 새 파일로 만들기

### 제출할 것

1. 자동화한 작업 설명 (사람이 할 때의 순서와 걸리는 시간)
2. 완성된 프로그램과 가짜 데이터 파일 (GitHub 저장소 주소로 제출해도 된다)
3. 검증 기록: 어떤 방법으로 확인했고, 결과가 일치했는지

> 💡 가짜 데이터로 완성한 프로그램을 실제 파일에 쓸 때는 Claude Code를 거치지 않고 **두 번째 터미널에서 직접** `uv run`으로 실행한다. 실행 전에 실제 파일을 **복사해 두는** 것도 잊지 않는다.
