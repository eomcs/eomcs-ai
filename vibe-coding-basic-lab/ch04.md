## 1. 파이썬 코드 읽기: 파일, 모듈, 패키지

### 1-1. 왜 파일에 저장해야 하는가

2장의 숫자 맞추기 게임에서 최고 기록은 프로그램을 끄면 사라졌다. 변수에 담긴 값은 **프로그램이 실행되는 동안에만** 컴퓨터의 기억 공간(메모리)에 머물기 때문이다.

| 저장 위치 | 비유 | 프로그램을 끄면 |
|---|---|---|
| 변수(메모리) | 화이트보드 | 지워진다 |
| 파일(디스크) | 공책 | 남는다 |

프로그램을 껐다 켜도 데이터를 유지하려면 **파일에 저장**하고, 다음에 실행할 때 **파일에서 불러와야** 한다.

### 1-2. 파일 쓰기와 읽기: `open()`

```python
# 파일에 쓰기
with open("memo.txt", "w", encoding="utf-8") as f:
    f.write("오늘 할 일: 장보기")

# 파일에서 읽기
with open("memo.txt", "r", encoding="utf-8") as f:
    text = f.read()

print(text)   # 오늘 할 일: 장보기
```

| 코드 | 의미 |
|---|---|
| `open("memo.txt", ...)` | `memo.txt` 파일을 연다. |
| `"w"` | 쓰기(write) 모드. 파일이 없으면 새로 만들고, 있으면 **내용을 지우고** 새로 쓴다. |
| `"r"` | 읽기(read) 모드. 파일 내용을 읽는다. |
| `encoding="utf-8"` | 한글이 깨지지 않도록 글자 저장 방식을 정한다. 특히 Windows에서 중요하다. |
| `with ... as f:` | 파일을 열어 `f`라는 이름으로 쓰고, 들여쓴 부분이 끝나면 **자동으로 닫는다**. |

> 💡 `with`는 "빌린 책은 다 읽으면 자동으로 반납"하는 장치다. 파일을 닫는 것을 잊어도 안전하다.

### 1-3. JSON: 리스트와 딕셔너리를 그대로 저장하기

할 일 목록처럼 여러 항목이 있는 데이터는 글자 한 줄로 저장하기 어렵다. 이럴 때 **JSON** 형식을 쓴다. JSON은 3장에서 배운 리스트·딕셔너리와 거의 같은 모양으로 데이터를 파일에 저장한다.

```python
import json

todos = [
    {"title": "장보기", "done": True},
    {"title": "운동 30분", "done": False},
]

# 저장하기
with open("todos.json", "w", encoding="utf-8") as f:
    json.dump(todos, f, ensure_ascii=False, indent=2)

# 불러오기
with open("todos.json", "r", encoding="utf-8") as f:
    todos = json.load(f)
```

저장된 `todos.json` 파일을 VS Code에서 열면 다음과 같이 보인다.

```json
[
  {
    "title": "장보기",
    "done": true
  },
  {
    "title": "운동 30분",
    "done": false
  }
]
```

| 코드 | 의미 |
|---|---|
| `json.dump(데이터, f)` | 데이터를 JSON 형식으로 파일에 저장한다. |
| `json.load(f)` | JSON 파일을 읽어 리스트·딕셔너리로 되돌린다. |
| `ensure_ascii=False` | 한글을 알아볼 수 있는 글자 그대로 저장한다. |
| `indent=2` | 사람이 읽기 좋게 줄을 바꾸고 2칸씩 들여쓴다. |

> 💡 파이썬의 `True`/`False`는 JSON 파일에서 `true`/`false`(소문자)로 저장된다. 불러오면 다시 `True`/`False`가 된다.

### 1-4. 모듈: 남이 만들어 둔 도구 꺼내 쓰기

**모듈**은 다른 사람이 미리 만들어 둔 기능을 담은 파이썬 파일이다. `import`로 불러와서 쓴다.

```python
import random    # 무작위 숫자 (2장)
import json      # JSON 저장·불러오기
import os        # 파일·폴더 다루기
```

`random`, `json`, `os`처럼 파이썬을 설치하면 함께 들어 있는 모듈을 **표준 라이브러리**라고 한다. 따로 설치하지 않아도 바로 쓸 수 있다.

### 1-5. 패키지: 인터넷에서 내려받아 쓰는 도구

표준 라이브러리에 없는 기능은 다른 사람이 만들어 인터넷에 공개한 **패키지**를 내려받아 쓴다. 스마트폰에 기본 앱이 있고, 필요한 앱은 앱 스토어에서 내려받는 것과 같다.

| 스마트폰 | 파이썬 |
|---|---|
| 기본 앱 (전화, 카메라) | 표준 라이브러리 (`random`, `json`) |
| 앱 스토어 | PyPI (파이썬 패키지 저장소, pypi.org) |
| 앱 설치 | 패키지 설치 (`uv add 패키지이름`) |

이 과정에서 쓸 패키지 예시는 다음과 같다.

| 패키지 | 하는 일 | 사용하는 장 |
|---|---|---|
| `rich` | 터미널 화면을 표와 색으로 꾸민다 | 4장 |
| `pandas`, `openpyxl` | 엑셀·표 데이터를 다룬다 | 6장 |
| `requests` | 인터넷에서 데이터를 받아 온다 | 7장 |
| `streamlit` | 웹 앱을 만든다 | 8장 |

## 2. 가상환경과 uv

### 2-1. 가상환경이 필요한 이유

패키지를 컴퓨터 전체에 설치하면 문제가 생길 수 있다.

- A 프로젝트는 어떤 패키지의 1.0 버전이 필요하고, B 프로젝트는 2.0 버전이 필요하면 **서로 충돌**한다.
- 어떤 프로젝트에 무슨 패키지가 필요한지 기록이 남지 않아, **다른 컴퓨터에서 같은 환경을 만들기 어렵다**.

**가상환경**은 프로젝트마다 따로 쓰는 **독립된 도구 상자**다. 프로젝트 A의 도구 상자와 프로젝트 B의 도구 상자가 분리되어 있으니 서로 영향을 주지 않는다.

### 2-2. uv란?

**uv**는 파이썬 프로젝트에 필요한 일을 한 번에 처리해 주는 도구다.

- 필요한 버전의 **파이썬을 설치**한다.
- 프로젝트마다 **가상환경을 만들고 관리**한다.
- **패키지를 설치**하고, 설치한 목록을 자동으로 기록한다.

가장 큰 장점은 `uv run`으로 실행하면 가상환경을 알아서 사용한다는 것이다. 가상환경을 직접 켜고 끌 필요가 없어서 초보자가 자주 겪는 실수가 줄어든다.

### 2-3. uv 설치

Claude Code에게 "uv가 설치되어 있는지 확인하고, 없으면 설치해 줘"라고 요청하면 된다. 직접 설치하려면 터미널에 다음 명령을 입력한다.

**macOS**
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows (PowerShell)**
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

설치가 끝나면 **터미널을 닫았다가 새로 열고** 확인한다.

```bash
uv --version
```

### 2-4. uv 기본 명령

명령은 macOS와 Windows가 같다. 외울 필요는 없고, Claude Code가 실행하는 명령을 보고 무슨 일을 하는지 알아보면 된다.

| 작업 | 명령 |
|---|---|
| 새 프로젝트 만들기 | `uv init --no-package` |
| 패키지 설치 (목록 자동 기록) | `uv add 패키지이름` |
| 프로그램 실행 | `uv run 파일이름.py` |
| 다른 컴퓨터에서 같은 환경 만들기 | `uv sync` |
| 파이썬 설치 | `uv python install` |

> 💡 `--no-package`는 "배포용 패키지가 아니라 간단한 프로그램용 프로젝트로 만들라"는 뜻이다. 이 옵션을 빼면 uv 버전에 따라 `src` 폴더가 있는 복잡한 구조가 만들어질 수 있다.

### 2-5. uv 프로젝트의 구성

`uv init --no-package`를 실행하고 프로그램을 한 번 실행하면 폴더에 다음 파일들이 생긴다.

| 파일·폴더 | 역할 |
|---|---|
| `main.py` | 프로그램 코드를 작성하는 파일 |
| `pyproject.toml` | 프로젝트 정보와 **필요한 패키지 목록** |
| `uv.lock` | 설치된 패키지의 **정확한 버전** 기록 (직접 고치지 않는다) |
| `.python-version` | 이 프로젝트가 쓰는 파이썬 버전 |
| `.venv/` | 가상환경(도구 상자) 폴더 (직접 고치지 않는다) |
| `README.md` | 프로젝트 설명서 |
| `.gitignore` | Git에 올리지 않을 파일 목록 (5장에서 배운다) |

`uv add rich`로 패키지를 설치하면 `pyproject.toml`에 다음과 같이 기록된다.

```toml
[project]
name = "todo"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.13"
dependencies = [
    "rich>=15.0.0",
]
```

`dependencies`(의존성)가 이 프로젝트에 필요한 패키지 목록이다. 다른 컴퓨터에서는 이 파일과 `uv.lock`만 있으면 `uv sync` 한 번으로 같은 환경을 만들 수 있다.

> 💡 `uv init`은 Git 저장소(숨김 폴더 `.git`)도 함께 만든다. Git은 5장에서 배운다.

## 3. Claude Code 기능 익히기: CLAUDE.md

### 3-1. CLAUDE.md란?

2장과 3장에서 요청할 때마다 "쉬운 말로 설명해 줘", "실행은 내가 직접 해 볼게" 같은 말을 반복했다. **CLAUDE.md**는 이렇게 **매번 반복해서 말해야 하는 것을 적어 두는 메모**다.

- 프로젝트 폴더에 `CLAUDE.md` 파일을 두면, Claude Code는 대화를 시작할 때 이 파일을 **자동으로 읽는다**.
- 새로 온 직원에게 건네는 **업무 인수인계서**와 같다. 프로젝트가 무엇인지, 어떤 규칙을 지켜야 하는지 적어 둔다.

### 3-2. `/init`으로 CLAUDE.md 만들기

Claude Code 입력창에 `/init`을 입력하면 Claude Code가 프로젝트 폴더를 살펴보고 `CLAUDE.md` 초안을 만들어 준다. 대략 다음과 같은 내용이 담긴다.

```markdown
# CLAUDE.md

## 프로젝트 개요
터미널에서 동작하는 파이썬 프로그램이다. uv로 관리한다.

## 명령
- 실행: `uv run main.py`
- 패키지 설치: `uv add <패키지이름>`

## 구조
- `main.py`: 프로그램 시작 파일
```

> 💡 초안이 영어로 만들어질 수도 있다. "CLAUDE.md를 한국어로 바꿔 줘"라고 요청하면 된다.

### 3-3. 나만의 규칙 추가하기

초안을 읽어 본 뒤 내가 원하는 규칙을 추가한다. VS Code에서 `CLAUDE.md`를 열어 직접 고쳐도 되고, Claude Code에게 요청해도 된다.

```markdown
## 규칙
- 나는 코딩 초보자야. 설명은 쉬운 한국어로 해 줘.
- 코드에는 한국어 주석을 달아 줘.
- 새 패키지를 설치하기 전에 왜 필요한지 먼저 알려 줘.
- 파이썬 실행은 `uv run`을, 패키지 설치는 `uv add`를 사용해.
- 사용자 입력을 받는 프로그램은 네가 실행하지 말고, 내가 실행할 명령만 알려 줘.
```

**좋은 규칙을 쓰는 요령**
- **짧고 구체적으로** 쓴다. "잘 해 줘"보다 "코드에는 한국어 주석을 달아 줘"가 낫다.
- 같은 말을 **두 번 이상 반복하게 되면** CLAUDE.md에 추가한다.
- 너무 길게 쓰지 않는다. 꼭 필요한 규칙만 남긴다.

> 💡 CLAUDE.md는 대화를 시작할 때 읽힌다. 규칙을 바꾼 뒤에는 대화를 새로 시작하면(`/clear` 또는 새 대화) 확실하게 반영된다.

### 3-4. 터미널(CLI)과 VS Code 확장의 사용법 비교

| 기능 | 터미널(CLI) | VS Code 확장 |
|---|---|---|
| CLAUDE.md 만들기 | `/init` 입력 | `/init` 입력. 동작하지 않으면 "이 프로젝트의 CLAUDE.md를 만들어 줘"라고 요청 |
| CLAUDE.md 고치기 | VS Code에서 직접 고치기, `/memory` 입력, 또는 Claude Code에게 요청 | VS Code에서 직접 고치기 또는 Claude Code에게 요청 |
| 규칙 반영 | `/clear` 후 새로 시작 | **새 대화** 버튼 |

## 4. 실습: 할 일 관리 프로그램

### 4-1. 프로젝트 폴더 만들기

이번에는 `vibe-coding` 폴더 안에 `todo`라는 **프로젝트 전용 폴더**를 만든다. 프로젝트마다 폴더를 따로 두면 파일이 섞이지 않고, CLAUDE.md와 가상환경도 프로젝트별로 관리할 수 있다.

```bash
cd ~/vibe-coding
mkdir todo
cd todo
code .
```

VS Code에서 **터미널 → 새 터미널**을 열고 `claude`를 입력한다(VS Code 확장을 쓴다면 Claude Code 패널을 연다).

> ⚠️ 반드시 `todo` 폴더를 연 상태에서 시작한다. 왼쪽 탐색기 맨 위에 `TODO`가 보여야 한다.

### 4-2. 1단계: uv 프로젝트 만들기

```
uv가 설치되어 있는지 확인하고, 없으면 설치해 줘. 그다음 이 폴더를 uv init --no-package로 uv 프로젝트로 만들어 줘. 실행하는 명령마다 무슨 일을 하는지 설명해 줘.
```

Claude Code가 명령을 실행할 때마다 허락을 구한다. 설명을 읽고 승인한다. 작업이 끝나면 VS Code 탐색기에서 2-5의 파일들이 생겼는지 확인하고, `main.py`를 열어 본다.

```python
def main():
    print("Hello from todo!")


if __name__ == "__main__":
    main()
```

두 번째 터미널을 열고 직접 실행해 본다.

```bash
uv run main.py
```

`Hello from todo!`가 출력되면 성공이다. 처음 실행하면 uv가 가상환경(`.venv`)을 만드느라 조금 시간이 걸린다.

> 💡 `if __name__ == "__main__":`은 "이 파일을 직접 실행했을 때 `main()` 함수를 호출하라"는 뜻이다. 지금은 **프로그램의 시작점**이라고 이해하면 충분하다.

### 4-5. 4단계: 파일에 저장하기

```
할 일 목록을 todos.json 파일에 저장해 줘. 할 일을 추가·완료·삭제할 때마다 바로 저장하고, 프로그램을 시작할 때 파일에서 불러와 줘. 파일이 없으면 빈 목록으로 시작해 줘.
```

만들어진 코드는 대략 다음과 같다. AI마다 조금씩 다르게 만들기 때문에 똑같지 않아도 괜찮다.

```python
import json
import os

DATA_FILE = "todos.json"   # 할 일을 저장할 파일 이름


def load_todos():
    """파일에서 할 일 목록을 불러온다. 파일이 없으면 빈 목록을 돌려준다."""
    if not os.path.exists(DATA_FILE):
        return []
    with open(DATA_FILE, "r", encoding="utf-8") as f:
        return json.load(f)


def save_todos(todos):
    """할 일 목록을 파일에 저장한다."""
    with open(DATA_FILE, "w", encoding="utf-8") as f:
        json.dump(todos, f, ensure_ascii=False, indent=2)


def show_todos(todos):
    """할 일 목록을 번호와 함께 보여 준다."""
    if not todos:
        print("할 일이 없습니다.")
        return
    for i, todo in enumerate(todos, start=1):
        mark = "✔" if todo["done"] else " "
        print(f"{i}. [{mark}] {todo['title']}")


def main():
    todos = load_todos()   # 시작할 때 파일에서 불러온다

    while True:
        print("\n=== 할 일 관리 ===")
        print("1. 목록 보기  2. 추가  3. 완료  4. 삭제  5. 종료")
        choice = input("선택: ")

        if choice == "1":
            show_todos(todos)
        elif choice == "2":
            title = input("할 일: ")
            todos.append({"title": title, "done": False})
            save_todos(todos)
            print("추가했습니다.")
        elif choice == "3":
            show_todos(todos)
            number = int(input("완료할 번호: "))
            todos[number - 1]["done"] = True
            save_todos(todos)
            print("완료 처리했습니다.")
        elif choice == "4":
            show_todos(todos)
            number = int(input("삭제할 번호: "))
            removed = todos.pop(number - 1)
            save_todos(todos)
            print(f"'{removed['title']}'을(를) 삭제했습니다.")
        elif choice == "5":
            print("종료합니다.")
            break
        else:
            print("1~5 중에서 선택하세요.")


if __name__ == "__main__":
    main()
```

#### 코드에서 개념 찾기

| 개념 | 코드 | 하는 일 |
|---|---|---|
| 모듈 | `import json`, `import os` | JSON 저장과 파일 확인 도구를 불러온다. |
| 파일 확인 | `os.path.exists(DATA_FILE)` | 저장 파일이 있는지 확인한다. |
| 파일 읽기 | `open(..., "r", ...)`, `json.load(f)` | 파일에서 할 일 목록을 불러온다. |
| 파일 쓰기 | `open(..., "w", ...)`, `json.dump(...)` | 할 일 목록을 파일에 저장한다. |
| 리스트 + 딕셔너리 | `{"title": title, "done": False}` | 할 일 하나를 딕셔너리로 만들어 리스트에 넣는다. |
| 번호 매기기 | `enumerate(todos, start=1)` | 목록을 1번부터 번호를 붙여 꺼낸다. |
| 인덱스 | `todos[number - 1]` | 사용자가 말한 번호(1부터)를 인덱스(0부터)로 바꾼다. |
| 꺼내서 지우기 | `todos.pop(number - 1)` | 해당 번호의 할 일을 리스트에서 꺼내며 지운다. |

#### 저장되는지 확인하기

1. 두 번째 터미널에서 `uv run main.py`로 실행하고 할 일을 세 개 추가한다.
2. 하나를 완료 처리하고 5번으로 종료한다.
3. VS Code 탐색기에 `todos.json`이 생겼는지 확인하고 열어 본다.
4. 다시 `uv run main.py`로 실행하고 1번으로 목록을 본다. 할 일이 그대로 남아 있으면 성공이다.

> 💡 "저장 기능을 만들었다"는 AI의 말만 믿지 않는다. **껐다 켜서 직접 확인**하는 것이 검증이다.

### 4-6. 5단계: 외부 패키지로 보기 좋게 만들기

```
할 일 목록을 터미널에서 표 형태로 보기 좋게 보여 주고 싶어. rich 패키지를 설치해서 번호, 상태, 할 일을 표로 보여 줘. 완료된 할 일은 상태를 초록색으로 표시해 줘.
```

CLAUDE.md에 "패키지를 설치하기 전에 왜 필요한지 먼저 알려 줘"라는 규칙을 넣었으므로, Claude Code가 `rich`가 무엇인지 설명한 뒤 `uv add rich` 실행 허락을 구할 것이다.

설치가 끝나면 다음을 확인한다.

- `pyproject.toml`의 `dependencies`에 `rich`가 추가되었는가?
- `uv run main.py`로 실행하고 1번을 고르면 이 장의 결과물처럼 표가 나오는가?

> ⚠️ 이제 `python3 main.py`(Windows는 `python main.py`)로 실행하면 `ModuleNotFoundError: No module named 'rich'` 오류가 난다. `rich`는 이 프로젝트의 가상환경에만 설치되어 있기 때문이다. uv 프로젝트는 항상 **`uv run`** 으로 실행한다.

### 4-7. 6단계: 잘못된 입력 처리하기

2장과 3장에서 배운 대로 일부러 잘못된 값을 넣어 본다.

- 완료할 번호에 `abc`를 입력한다 → `ValueError`
- 할 일이 3개인데 완료할 번호에 `10`을 입력한다 → `IndexError`

오류 메시지를 읽어 보고, 다음과 같이 요청한다.

```
완료나 삭제할 번호를 입력할 때 숫자가 아니거나 없는 번호를 입력하면 프로그램이 멈춰. 이럴 땐 "올바른 번호를 입력하세요"라고 안내하고 메뉴로 돌아가게 고쳐 줘. 할 일이 하나도 없을 때 완료나 삭제를 고르면 "할 일이 없습니다"라고만 알려 줘.
```

수정 후 같은 값을 다시 입력해서 프로그램이 멈추지 않는지 확인한다.

### 4-8. 마무리: CLAUDE.md 업데이트하기

프로그램이 완성되었으니 CLAUDE.md에도 프로그램 내용을 기록해 둔다. 다음에 이 프로젝트에서 작업할 때 Claude Code가 구조를 빠르게 파악할 수 있다.

## 5. 문제가 생겼을 때

| 증상 | 해결 방법 |
|---|---|
| `uv: command not found` 또는 "인식할 수 없는 명령" | 터미널을 완전히 닫고 새로 연다. 그래도 안 되면 uv를 다시 설치한다. |
| `src` 폴더가 생기고 `main.py`가 없다 | `--no-package` 없이 `uv init`을 실행한 것이다. Claude Code에게 "이 폴더를 uv init --no-package 구조로 다시 만들어 줘"라고 요청한다. |
| `ModuleNotFoundError: No module named 'rich'` | `uv run main.py`로 실행했는지 확인한다. 그래도 나면 `uv add rich`가 실행되었는지 `pyproject.toml`을 확인한다. |
| 껐다 켰더니 할 일이 사라졌다 | 추가·완료·삭제 후에 저장하는지, 시작할 때 불러오는지 확인해 달라고 요청한다. `todo` 폴더에서 실행했는지도 확인한다. |
| `todos.json`이 엉뚱한 폴더에 생겼다 | 프로그램을 다른 폴더에서 실행한 것이다. `pwd`로 위치를 확인하고 `todo` 폴더에서 실행한다. |
| `JSONDecodeError` 오류가 난다 | `todos.json`을 직접 고치다 형식이 깨진 것이다. 파일 내용을 Claude Code에게 보여 주고 고쳐 달라고 하거나, 파일을 지우고 새로 시작한다. |
| 한글이 깨져서 저장된다 | 파일을 열 때 `encoding="utf-8"`, 저장할 때 `ensure_ascii=False`를 쓰는지 확인해 달라고 요청한다. |
| Claude Code가 CLAUDE.md 규칙을 따르지 않는다 | `CLAUDE.md`가 `todo` 폴더 바로 안에 있는지 확인하고, 대화를 새로 시작한다. 규칙을 더 짧고 구체적으로 고친다. |

## 6. 정리

### 핵심 요약

1. 변수에 담긴 데이터는 프로그램이 끝나면 사라진다. 남기려면 **파일에 저장**하고 시작할 때 **불러온다**.
2. 리스트·딕셔너리는 **JSON** 형식으로 저장하면 편하다(`json.dump`, `json.load`).
3. **모듈**은 `import`로 불러 쓰는 도구이고, 표준 라이브러리에 없는 기능은 **패키지**를 설치해서 쓴다.
4. **가상환경**은 프로젝트마다 따로 쓰는 도구 상자다. **uv**가 가상환경, 패키지, 파이썬 버전을 한 번에 관리한다.
5. **CLAUDE.md**에 반복되는 요청과 프로젝트 정보를 적어 두면 Claude Code가 대화를 시작할 때마다 읽는다.

### 요청문 템플릿

**새 프로젝트 시작**
```
uv init --no-package로 이 폴더를 uv 프로젝트로 만들고, /init으로 CLAUDE.md를 만들어 줘.
```

**패키지가 필요한 기능 요청**
```
[원하는 기능]을 만들고 싶어. 필요한 패키지가 있으면 무엇인지, 왜 필요한지 먼저 알려 주고 설치해 줘.
```

**CLAUDE.md 규칙 추가**
```
CLAUDE.md에 "[규칙]" 규칙을 추가해 줘.
```

### 용어 사전

| 용어 | 뜻 |
|---|---|
| 파일 입출력 | 파일에 데이터를 쓰고(출력) 읽는(입력) 것 |
| JSON | 리스트·딕셔너리 모양으로 데이터를 저장하는 파일 형식 |
| 모듈 | 기능을 담은 파이썬 파일. `import`로 불러온다. |
| 표준 라이브러리 | 파이썬에 기본으로 들어 있는 모듈 모음 |
| 패키지 | 다른 사람이 만들어 공개한 기능 묶음. 설치해서 쓴다. |
| PyPI | 파이썬 패키지가 모여 있는 인터넷 저장소 |
| 가상환경 | 프로젝트마다 따로 쓰는 독립된 파이썬 환경 |
| uv | 파이썬 설치, 가상환경, 패키지를 관리하는 도구 |
| 의존성 | 프로젝트가 동작하는 데 필요한 패키지. `pyproject.toml`에 기록된다. |
| CLAUDE.md | Claude Code가 대화를 시작할 때 자동으로 읽는 프로젝트 메모 |

- 기능을 추가할 때마다 껐다 켜서 마감일이 `todos.json`에 저장되는지 확인한다.
